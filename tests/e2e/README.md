# Замороженный crash-test e2e (T3.89, ADR 0042 п. 5)

Набор сценариев e2e зафиксирован хешем до написания кода. Движок сверяет
хеш при каждом запуске и отказывается работать, если набор изменился без
пересмотра решения. Запрещено тихо убрать, переименовать или добавить сценарий,
чтобы пройти проверку.

Общий прогон и честные ограничения описаны в `docs/e2e/README.md`. Здесь
описана только заморозка набора.

## Что зафиксировано

Источник истины — срез `e2eScenarios` в `e2e_test.go`. Каждый его элемент
связывает имя сценария с функцией, которую запускает `TestE2E`. Хеш считается
по отсортированным именам, соединённым переводом строки без завершающего
перевода строки:

```
sha256(sort(names).join("\n"))
```

Замороженное значение лежит в константе `frozenScenarioHash` и записано до
первого прогона:

```
ec28944e71a04357e310438abcb4544034734a9ef3c424644da811d2b31563d8
```

На момент записи в наборе пять сценариев:

| Имя | Что делает |
| --- | --- |
| `repo_plugin_skeleton` | диагностика каркаса плагина в репозитории |
| `mcp_go_sdk_CommandTransport` | MCP `initialize`, `tools/list`, `tools/call` через go-sdk |
| `mcp_inspector_optional` | опциональный MCP Inspector |
| `opencode_wake_with_reference_plugin` | пробуждение сессии эталонным плагином из `fixtures` |
| `negative_control_stub_handler_must_fail` | заглушка обязана провалить ту же проверку |

## Проверка и отказ

- `TestFrozenCrashTestScenarios` сравнивает текущий хеш с замороженным. Он не
  требует opencode и токена, поэтому запускается в CI отдельной тестовой
  функцией.
- `TestE2E` вызывает `verifyFrozenScenarios()` до любой работы с opencode. При
  расхождении движок падает с сообщением об изменённом наборе и не запускает
  сценарии.
- Сообщение об ошибке печатает замороженный и текущий хеш, полный список
  сценариев и файл, где нужно явно обновить константу.

Чтобы изменить набор, нужно пересмотреть решение и в одном коммите обновить
`e2eScenarios` и `frozenScenarioHash`. Случайная правка одного списка без
обновления хеша делает прогон красным.

## CI

Прогон идёт в джобе `e2e` из `.github/workflows/ci.yml` через `bash tests/e2e/run.sh`,
то есть `go test -tags=e2e ./tests/e2e -count=1 -v`. Обе тестовые функции
попадают в этот вызов. У джобы стоит `continue-on-error: true`: нарушение
заморозки проваливает саму джобу, но по текущей конфигурации не блокирует merge.
Заморозка сценариев не заменяет ADR 0010 и не добавляет требование тестов в
каждую карточку.
