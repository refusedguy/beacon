# Night shift

## Процедура разбора issue

1. Прочитать issue и все существующие комментарии: `gh issue view N --comments`. Не дублировать уже сказанное.
2. Определить карточку, зависимости и владельцев файлов. Работать в своей ветке и worktree, не трогать файлы вне карточки.
3. Сделать фичу, открыть PR в `main` и дождаться CI. Локальные тесты не являются гейтом.
4. Комментировать только при новом факте: хеш влитого PR, измерение, решение владельца или блокер. Формат: дата, один абзац, доказательство. Устаревший коммент обновить через `gh api PATCH`, а не новым комментом. Нечего добавить: не комментировать.
5. Перед закрытием issue сверить комментарии и статус PR, устранить противоречия.
