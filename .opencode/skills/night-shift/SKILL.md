# Night shift

Внешний трекер это адаптер с контрактом из семи операций. См.
`references/tracker-contract.md`. Команды `gh` ниже одна из реализаций
контракта, не сам контракт.

## Процедура разбора issue

1. Прочитать issue и все существующие комментарии через адаптер трекера,
   операция 2 контракта. Пример реализации: `gh issue view N --comments`.
   Не дублировать уже сказанное.
2. Определить карточку, зависимости и владельцев файлов. Работать в своей ветке и worktree, не трогать файлы вне карточки.
3. Сделать фичу, открыть PR в `main` и дождаться CI. Перед мержем прочитать `references/pr-readiness.md`.
4. Комментировать только при новом факте. Перед комментарием прочитать `references/comment-rules.md`. Не вставлять в комментарий сырые логи и токены. Токен не передаётся дочернему агенту.
5. Перед закрытием issue сверить комментарии и статус PR, устранить противоречия.
6. Перед завершением хода проверить маркер правок. Если файлы менялись после последней консультации, провести консультацию и сообщить её вердикт одной строкой.
