# Критерии готовности PR в ночной смене

Справочник для смены. Читать перед мержем PR или перед тем, как считать PR готовым.
`SKILL.md` держит только ссылку на этот файл, полный текст загружается только перед
действием (progressive disclosure, ADR 0035 п3).

## Главное правило

Мерж или комментарий о готовности допускается только при наличии НОВОГО факта.
Детерминированная проверка по ADR 0035 п5 отклоняет действие, если в тексте нет
хеша влитого PR, измерения, решения владельца или блокера.

## Найденный PR или коммит

Перед началом работы проверить, нет ли уже открытого PR или влитого коммита с
тем же симптомом. Проверка идёт до шага «сделать фичу».

Если такой PR или коммит найден, задача переводится в режим проверки. В режиме
проверки симптом воспроизводится на реальном артефакте, а изменение в найденном
PR сверяется с нужным решением. Новый PR с тем же решением не открывается. В
карточку записывается номер найденного PR или полный хеш влитого коммита и
результат проверки.

Проверка найденного PR не отменяет главное правило. Комментарий о готовности
по-прежнему требует нового факта.

## Неудачная публикация и компенсация

Создание PR или публикация отчёта может не дойти до целевого треда. Такой результат
не считается готовностью. Агент не заявляет об успехе, пока публикация не подтверждена.

Перед публикацией агент запоминает идентификатор созданного внешнего артефакта
и состояние ветки. После публикации агент читает тот же тред и проверяет, что
отчёт появился под исходным сообщением. Если отчёт не дошёл, агент применяет
компенсацию. Он откатывает внешний артефакт и повторно читает его состояние,
чтобы подтвердить откат. Затем агент выставляет статус с причиной и сохраняет
состояние ветки в выводе.

Компенсация не отменяет главное правило. Комментарий о готовности по-прежнему
требует нового факта.

## Чек-лист готовности

PR готов к мержу, когда выполнены все условия:

1. **CI зелёный.** Обязательные job (`build`, `test`, `gates`) прошли. Job `e2e`
   пока `continue-on-error` и не блокирует мерж (см. `.github/workflows/ci.yml`).
2. **Ветка актуальна.** `feat/*` перебазирована или слита с актуальной `main`,
   конфликты разрешены.
3. **Новый факт есть.** В тексте мержа или комментария есть хеш PR, измерение,
   решение владельца или снятый блокер. Шаблонный комментарий без факта не
   проходит проверку.
4. **Нет открытых блокеров.** Все блокеры из issue сняты или явно перенесены в
   новую задачу со ссылкой.
5. **Границы соблюдены.** Изменения только в файлах из «Владелец файлов» своей
   карточки; карточка и ADR не изменены; коммит от нужного автора.
6. **Изменение проверено.** Результат проверен по реальному артефакту, а не только
   «компилируется» (principle-prove-it-works).
7. **Публикация подтверждена.** PR создан, отчёт прочитан в целевом треде. При
   неудачной публикации внешний артефакт откачен, состояние отката проверено,
   статус с причиной выставлен. Неудачная публикация без компенсации готовностью
   не считается.

## Что блокирует мерж

- Красный или незавершённый обязательный job CI.
- Неразрешённые конфликты с `main`.
- Открытый блокер без решения владельца.
- Комментарий или описание мержа без нового факта.
- Изменения вне прав владельца карточки или правки самой карточки/ADR.
- Неудачная публикация отчёта или PR без компенсации внешнего артефакта,
  проверки отката и статуса с причиной.
