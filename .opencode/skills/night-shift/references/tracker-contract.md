# Контракт адаптера трекера

Этот файл задаёт адаптер трекера как контракт с семью операциями. Конкретный
сервис не важен: GitHub Issues и Linear реализуют один контракт. Команды `gh`
в этом репозитории одна из реализаций, не часть контракта. Контракт покрывает
поиск по тексту, обновление без замены несвязанных полей и остальные операции
ниже. Читать перед работой с issue и комментариями.

Источник: `docs/research/comp-cursor-plugins.md`, benny
`triage-issue-reports/SKILL.md`, раздел 6.

## Операции контракта

Адаптер обязан предоставлять семь операций.

1. Поиск по тексту, по состоянию, по метке, по URL источника и по диапазону дат.
2. Чтение одной issue и её ссылок.
3. Создание issue с заголовком, телом, состоянием, метками и URL источника.
4. Обновление существующей issue без замены несвязанных полей.
5. Добавление ссылки на источник и заметки о повторе.
6. Отмена, закрытие или удаление issue, созданной этим прогоном, если передача
   в другой сервис не удалась.
7. Разрешение настроенных команды, проекта, состояния и меток во время
   выполнения. Не выдумывать идентификаторы, не создавать метки, не назначать
   владельцев и не ставить приоритет без явного требования конфига.

## Отказ при отсутствии операции

Если нужной операции нет, прекратить эту запись. Не подменять её прямой
командой вендора и не создавать частичную запись.

## Реализации

`gh issue view N --comments` реализует операцию 2. Команда
`gh api PATCH /repos/.../issues/comments/<id>` реализует операцию 5 для
комментариев. Другая реализация допустима, пока она покрывает контракт.
