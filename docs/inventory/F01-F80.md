## §5.1 Идентификаторы, идемпотентность, безопасность (F01-F12)

| ID | Фича | Описание из отчёта | Раздел | Источник в отчёте |
| --- | --- | --- | --- | --- |
| F01 | `clientRequestId` на каждый вызов | T3 выводит из него стабильные command, thread и message ID; повтор после ошибки или потери ответа возвращает тот же durable work. Crush использует generation на каждый run сабагента и игнорирует stale settle. | §5.1 | T3, Crush |
| F02 | ID создаётся до внешнего вызова | OpenRig генерирует `qitem-...` до отправки и переиспользует при неизвестном исходе. T3 фиксирует receipt в транзакции. | §5.1 | OpenRig, T3 |
| F03 | App-owned ID, провайдерский ID как ref | T3: app ids primary, provider events никогда не переписываются под другой провайдер. | §5.1 | T3 |
| F04 | Typed failure результат | T3 перечисляет 14 Typed отказов вместо строки ошибки. Beacon может вернуть структуру вместо текста. | §5.1 | T3 |
| F05 | Capability discovery до вызова | `orchestrator_capabilities` возвращает доступных провайдеров, модели, режимы и feature flags; недоступный провайдер объясняет причину (нет адаптера, выключен, нет бинарника, нет авторизации). | §5.1 | T3 |
| F06 | Привилегированный потолок ребёнка | T3 запрещает расширять runtime и interaction mode; OMA egress policy позволяет детям только ужесточать; compozy gate требует подтверждения. | §5.1 | T3, OMA, Compozy |
| F07 | Scope-токены с TTL и idle expiry | T3 выдаёт токен на environment + thread + provider instance + provider session и отзывает при освобождении сессии; сырой токен не сохраняется. | §5.1 | T3 |
| F08 | Явная проверка capability в каждом handler | Аутентификация socket не даёт права на все методы (T3), канал MCP требует opt-in (Crush), webhook требует signature (T3, compozy). | §5.1 | T3, Crush, Compozy |
| F09 | Provenance в каждом результате | T3 пишет `createdBy` и `creationSource` (`agent`/`mcp` против `provider`), отделяя авторство от ingress. | §5.1 | T3 |
| F10 | Ссылки вместо ID в тексте | `<t3-thread://v2/...>` открывается клиентом и не требует от модели форматировать ID или запоминать title. | §5.1 | T3 |
| F11 | Ограничение размера ответа инструмента | T3 останавливает `t3_thread_read` около 30 000 символов и отдаёт `hasMore`/`earlierPosition`, потому что Claude Code сохраняет слишком большие MCP-результаты в файл. | §5.1 | T3 |
| F12 | Короткий список моделей в capability | T3 намеренно не отдаёт сотни моделей в контекст, а предоставляет `search` и `omittedModels`. | §5.1 | T3 |
