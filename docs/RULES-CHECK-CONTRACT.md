# Контракт проверки правил

Этот файл задаёт семантику вердикта rules gate в Beacon и служит каноническим источником. Workflow, навыки и примеры обязаны следовать этому файлу. Если пример расходится с контрактом, верен контракт.

Контракт опирается на ADR 0240, ADR 0235, ADR 0236 и ADR 0237. Код Harbor в Beacon не переносится.

## Вердикт и блокировка

Rules gate возвращает ровно один вердикт: `PASS`, `WARN` или `FAIL`.

`PASS` означает, что найдено хотя бы одно применимое правило, проверка прошла по изменённым файлам или diff, и явных нарушений нет.

`WARN` означает, что проверка не нашла применимых правил, доказательства неоднозначны, изменённых файлов нет или отсутствует дополнительный файл правил. Вердикт `WARN` не блокирует.

`FAIL` означает, что изменённые файлы или diff явно нарушают жёсткое правило. Вердикт `FAIL` блокирует.

Только `FAIL` даёт `blocking: true`. В вердиктах `PASS` и `WARN` поле `blocking` равно `false`.

Проверка правил не заменяет обзор кода и verify.

## Привязка нарушений

Каждое блокирующее нарушение привязано к тексту правила и к конкретному файлу или фрагменту diff. Правило, которое звучит как предпочтение, слишком обще или не проверяется уверенно по diff, не поднимается выше `WARN`. Отсутствующие дополнительные файлы правил и частично настроенная иерархия правил дают `WARN`, а не `FAIL`.

## Состав отчёта

Отчёт содержит разделы в следующем порядке:

- общий вердикт
- число проверенных файлов
- результаты проверки правил
- блокирующие нарушения
- предлагаемые исправления
- предлагаемые обновления правил

После человекочитаемого отчёта идёт ровно один финальный fence `aif-gate-result` с JSON. Оркестратор читает последний fence в выводе.

## Машиночитаемый результат

Схема полей определена в ADR 0237. Обязательные поля: `schema_version` со значением `1`, `gate` со значением `rules`, `status`, `blocking`, `blockers`, `affected_files` и `suggested_next`.

Поле `status` использует строчные значения `pass`, `warn` и `fail`. Вердикт отчёта задаёт значение поля: `PASS` даёт `pass`, `WARN` даёт `warn`, `FAIL` даёт `fail`. В человекочитаемом отчёте вердикт остаётся в верхнем регистре.

В `blockers` попадают только жёсткие нарушения, которые дают вердикт `FAIL`. Каждая запись содержит `id`, `severity`, `file` и `summary`. В `affected_files` попадают проверенные или изменённые пути. Поле `suggested_next` содержит разрешённую команду Beacon или `null`, когда подходящей команды нет.

Пример для вердикта `WARN`:

```aif-gate-result
{
  "schema_version": 1,
  "gate": "rules",
  "status": "warn",
  "blocking": false,
  "blockers": [],
  "affected_files": [],
  "suggested_next": null
}
```

Пример для вердикта `FAIL`:

```aif-gate-result
{
  "schema_version": 1,
  "gate": "rules",
  "status": "fail",
  "blocking": true,
  "blockers": [
    {
      "id": "R-LAYER",
      "severity": "error",
      "file": "cmd/beacon/newcmd.go",
      "summary": "Правило 'cmd/beacon: без os.ReadFile, os.WriteFile, net/http, os/exec' нарушено импортом os/exec"
    }
  ],
  "affected_files": ["cmd/beacon/newcmd.go"],
  "suggested_next": null
}
```

## Граница только для чтения

Проверка правил не изменяет файлы правил и исходники. Отсутствующие дополнительные файлы правил оставляют вердикт `WARN`. Обновление правил идёт через канонические места правил, то есть AGENTS.md и ключ `beacon/survival-rules`, а не через саму проверку.
