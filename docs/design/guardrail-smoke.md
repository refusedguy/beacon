# Негативный контроль для guardrail-хуков

Каждая проверка в `.githooks/pre-commit` имеет зафиксированный негативный прогон. Прогон задаёт минимальный вход, ожидаемый код выхода и ожидаемое сообщение в stderr. Чтение текста хука доказательством не считается.

## Измерение до выбора

Baseline на `origin/main` `0ce4ba29`: `git grep -i -c 'negative control' origin/main -- .githooks` возвращает 0. Совпадения в `docs/tasks/` и `docs/adrs/0094-seven-tools.md` описывают проверки MCP-контракта и batch-apply, а не smoke-прогон хуков. Негативных прогонов для четырёх проверок в дереве нет.

## Негативные прогоны

Таблица описывает четыре проверки из `.githooks/pre-commit:5-49`. Второй столбец даёт минимальный негативный вход, третий фиксирует ожидаемый код выхода и сообщение.

| Проверка | Минимальный негативный вход | Ожидаемый код выхода и сообщение |
| --- | --- | --- |
| Запрет коммита в main | Текущая ветка `main`, `BEACON_ALLOW_MAIN_COMMIT` не задан, `git commit -m smoke` | Код выхода 1, в stderr `FORBIDDEN: create a feature branch/worktree, never commit to main directly!` |
| gofmt по staged Go | В тестовом репозитории изменить `.go` без форматирования, выполнить `git add` и `git commit` | Код выхода 1, в stderr `FORBIDDEN: staged Go files are not gofmt'ed:`, имя файла и `Fix: gofmt -w <files>` |
| Запрет staging worktree и баз | Выполнить `git add worktrees/probe.txt` и `git commit` | Код выхода 1, в stderr `FORBIDDEN: staging worktree output, a DB or the local beacon binary:` и имя файла |
| Fail-closed индекс карточек | Изменить карточку без пересборки индекса, затем выполнить `git add` и `git commit` | Код выхода 1, в stderr `FORBIDDEN:` с текстом ошибки `cardindex` и строка `Reason: сгенерированный индекс карточек устарел или не собирается. Обновите его через go run ./tools/roadmap-sync --write.` |

Если `go` отсутствует, четвёртая проверка даёт код выхода 1 и сообщение `FORBIDDEN: go не найден, нельзя проверить сгенерированный индекс карточек`.

Проверка аренды файлов после строки 49 работает fail-open и в таблицу не входит.

## Правило для новых проверок

Автор не помечает новую проверку готовой, пока не записал в таблицу негативный вход, ожидаемый код выхода и ожидаемое сообщение и не прогнал проверку локально. Если прогон дал другой код или другое сообщение, автор правит проверку и повторяет прогон. Проверка, описанная только текстом хука, готовой не считается.

## Где прогонять

Агент делает smoke-прогон локально в отдельном тестовом репозитории. Рабочее дерево с чужими файлами для прогона непригодно: коммит в main и staging чужих файлов могут затронуть чужие изменения. Тестовый репозиторий содержит только файлы, нужные для конкретной проверки. Сам хук в рамках карточки не меняется.
