# Решение STD-07: малые копии функций в разных пакетах

Режим документа: explanation. Здесь зафиксировано решение по четырём парам функций из карточки STD-07 и условия пересмотра. Код, карточки задач и индексы в этом PR не меняются.

## Решение

Оставить все четыре пары как граничные зеркала. Объединение не преследовать. Новый общий пакет не создавать. Поведение функций, строки сообщений об ошибках и направление импортов остаются прежними.

## Причины

1. Все семь OwnerFiles карточки заняты открытыми задачами. Занятость проверена по открытым PR на 23 ноября 2026 года.

   | OwnerFile | Задача | Подтверждение |
   | --- | --- | --- |
   | `internal/app/orchestrator/checkall.go` | TBL-03 | PR 2227 открыт, файл в PR |
   | `internal/infra/github/graphql.go` | RSOL-07 | PR 2255 открыт, файл в PR |
   | `internal/tui/board.go` | TBL-04 | PR 2234 открыт |
   | `cmd/beacon/task.go` | VCI-05 и BP-15 | PR 2221 открыт |
   | `internal/infra/mcp/tool_watch_pr.go` | TCG-03 | PR 2238 открыт |
   | `internal/infra/httpapi/server.go` | Фаза 2 | PR 2172 открыт, файл в PR |
   | `internal/infra/server/events.go` | Фаза 2 | По данным исполнителя, та же волна. Отдельного открытого PR с этим файлом не найдено |

   Правка любого из этих файлов сейчас создала бы конфликт с чужой работой.

2. Вывод агента: объединение потребует импорта через границу слоёв. `splitRepo` соединяет `internal/app` и `internal/infra`, `oneLine` соединяет `internal/tui` и `cmd/beacon`, `normalizeConfigKey` соединяет `internal/app` и `internal/infra/mcp`, `sanitizeEventName` соединяет два пакета `internal/infra`. Правила «Слои» в `AGENTS.md` запрещают такой импорт. Новый нейтральный пакет требует отдельного решения владельца и добавляет слой ради шестистроковых функций.

3. Измеренной выгоды от объединения нет. Все четыре функции чистые и короткие. `splitRepo` совпадает побайтово, `sanitizeEventName` отличается только именем локальной переменной и переносом строки. Замена тел на вызовы stdlib сохранит поведение, но не даст измеренного эффекта. Бэклог в строке 414 уже рекомендует оставить эти четыре пары в покое, а строка 421 ставит STD-07 после решения владельца.

4. Затраты на правку сейчас больше, чем экономия строк. Карточка оценивает экономию в 0 строк при оставлении зеркал и до 30 строк при замене тел. Правка семи файлов с открытыми PR потребовала бы согласования с владельцами этих правок ради этой экономии.

## Условие пересмотра

Решение пересматривается после того, как PR 2227, PR 2234 и PR 2221 влиты, а RSOL-07 и Фаза 2, включая PR 2172, закрыты. К этому моменту все семь OwnerFiles должны быть свободны. Дополнительное условие: новое измерение показывает, что расхождение копий вызвало ошибку или что одну правку приходится вносить в обе копии. Измерение называет сценарий, лимитер и данные. Без него зеркала остаются.

Пересмотр оформляется новой карточкой со ссылкой на этот документ. Текущую карточку STD-07 в работу не возвращают.

## Проверка фактов

База: свежий `origin/main`, коммит `79dc16941bdbb5ff312f85e8602dda0e67be1a2a`. Перед проверкой выполнен `git fetch origin main`.

Позиции функций получены командой `git show origin/main:<путь> | rg -n 'func <имя>'` по семи явным путям из OwnerFiles. Тела `splitRepo` и `sanitizeEventName` сверены по фрагментам тех же файлов. Состояние PR проверено через `gh pr view` для номеров 2172, 2221, 2227, 2234, 2238 и 2255. Рекомендация и порядок волн взяты из строк 414 и 421 файла `/tmp/opencode/backlog/13-gof-fp.md`.

Локально не запускались `go test`, `go build`, `beacon gates`. Рекурсивный поиск не применялся.
