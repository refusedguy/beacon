# Схема beacon.agent-registry/v1

Авторский файл реестра агентов лежит по пути `.beacon/agents.yaml`. Beacon ищет его от текущего каталога вверх до каталога с `.git` (T5.14). Это слой авторской конфигурации. Состояние реестра лежит отдельно, в project-scoped базе рядом с Watch и обязательствами (ADR 0086, T5.1). Авторский файл не хранит состояния сессий, вердикты Watch и факты доставки wake.

Полное имя схемы `beacon.agent-registry/v1` складывается из поля `schema` со значением `beacon.agent-registry` и поля `version` со значением `1`. Валидатор появится в T5.12. Правила ниже задают контракт, которому он должен следовать.

## Поля верхнего уровня

| Поле | Тип | Обязательно | Назначение |
| --- | --- | --- | --- |
| `schema` | строка | да | Идентификатор схемы, только `beacon.agent-registry`. |
| `version` | целое число | да | Версия схемы. Эта редакция принимает только `1`. |
| `project` | строка | да | Ключ проекта, к которому относится файл. |
| `defaults` | объект | нет | Значения по умолчанию для записей `roster`. |
| `roster` | список | да | Объявления агентов проекта. |
| `configurations` | объект | да | Именованные конфигурации и рекомендуемая из них. |
| `limits` | объект | нет | Квоты и бюджеты реестра. |

Любой неизвестный ключ на любом уровне это ошибка. В сообщении об ошибке называется имя поля, а не весь файл (T5.12).

## `schema` и `version`

Значение `schema` фиксировано. Другой идентификатор означает другой формат и отклоняется.

Версия `1` это единственная версия, которую принимает текущий код. T5.19 описывает миграцию версии 1 в версию 2 и предупреждение для старого конфига. Неизвестная версия не принимается молча. Загрузка прерывается с сообщением, в котором названы полученное и ожидаемое значения.

## `project`

Поле задаёт ключ проекта в формате `<имя папки>-<восемь шестнадцатеричных символов>`. Восемь символов это первые восемь байт SHA-256 от абсолютного пути к корню git. Тот же ключ использует `stateDir` из ADR 0011, поэтому два каталога с одинаковыми именами получают разные ключи (T5.14).

При загрузке конфига Beacon сравнивает `project` с ключом текущего проекта. При несовпадении файл не применяется. Флаг `--project` и переменная `BEACON_STATE_DIR` меняют разрешение ключа по правилам T5.14. Вне git используется глобальный конфиг (T5.14).

## `defaults`

Блок задаёт значения, которые наследуют записи `roster`, если в записи нет своего поля.

| Поле | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `adapter` | строка | `opencode` | Адаптер доставки wake. |
| `model` | строка | пустая строка | Модель, под которой запускается агент. |
| `mode` | строка | `subagent` | Режим сессии, `subagent` или `primary` (T5.20). |
| `worktree_root` | строка | `.beacon/worktrees` | Каталог для ворктри. Путь указан относительно корня проекта. |
| `capabilities` | список строк | пустой список | Возможности, добавляемые каждой записи roster. |

Пути в `worktree_root` и в полях записей обязаны быть относительными. Абсолютный путь и сегмент `..` отклоняются (T5.12). Имена capabilities берутся из словаря T5.20. Пустая строка `model` означает, что модель выбирает среда исполнения, а не авторский файл.

## `roster`

Список объявлений агентов. Каждая запись имеет следующие поля.

| Поле | Тип | Обязательно | Назначение |
| --- | --- | --- | --- |
| `id` | строка | да | Уникальный идентификатор агента внутри проекта. |
| `role` | строка | да | `orchestrator` или `executor` (T5.20). |
| `runtime` | строка | да | `subagent` или `primary` (T5.20). |
| `capabilities` | список строк | нет | Возможности агента из словаря T5.20. |
| `adapter` | строка | нет | Переопределяет `defaults.adapter`. |
| `model` | строка | нет | Переопределяет `defaults.model`. |
| `mode` | строка | нет | Переопределяет `defaults.mode`. |
| `use_when` | строка | нет | Условие, при котором выбирается агент. |
| `why` | строка | нет | Причина присутствия агента в roster. |

Пустой `id`, пустой `role` и пустой `runtime` отклоняются. Повтор `id` в roster тоже ошибка. Поля `use_when` и `why` это произвольный текст для ревью, на выбор агента они не влияют (T3.353).

Канонический идентификатор конфигурации вычисляется из записей roster, а не хранится в файле. Для выбранного набора записей Beacon сортирует их по `id`, берёт пары `id=runtime` и соединяет их запятыми без пробелов (T5.2, T5.15). Псевдонимы и поля `capabilities`, `model`, `adapter` в идентификатор не входят.

Capability index не пишется в YAML. Beacon строит его из зарегистрированных исполнителей (T5.4, T5.23). Пустой индекс при непустом roster это ошибка, и двухсторонняя сверка обязана её найти (T5.24).

## `configurations`

Блок хранит именованные наборы записей roster и выбор по умолчанию.

```yaml
configurations:
  presets:
    default: [orchestrator, executor]
    review: [orchestrator]
  recommended: default
```

Ключи `presets` это псевдонимы. Значение каждого псевдонима это список `id` из roster. Beacon требует, чтобы каждый `id` существовал, а псевдоним не совпадал с каноническим идентификатором другой конфигурации (T5.16). Ссылка на несуществующего агента или неизвестный preset отклоняется с именем поля.

Поле `recommended` содержит ровно один псевдоним из `presets` или `null`, когда рекомендации нет. Псевдоним не заменяет канонический идентификатор. Идентификатор конфигурации остаётся вычисляемым значением `id=runtime`, и псевдоним в него не входит (T5.2, T5.15).

## `limits`

Блок задаёт неотрицательные целые числа. Отрицательное значение, дробь и число вне диапазона отклоняются по имени поля (T5.17).

| Поле | По умолчанию | Назначение |
| --- | --- | --- |
| `max_parallel_polls` | `15` | Число параллельных опросов проверок PR. Пятнадцать процессов `gh pr checks --watch` дают 5400 запросов в час при лимите 5000, поэтому один сервис читает проверки батчем (ADR 0033, T5.8). |
| `max_watches_per_subscriber` | `50` | Действующий потолок на подписчика из `internal/domain/fanout.go`. |
| `max_active_watches` | `200` | Действующий глобальный потолок из `internal/domain/fanout.go`. |
| `max_subscribers_per_watch` | `50` | Действующий потолок подписчиков на Watch из `internal/domain/fanout.go`. |
| `max_config_bytes` | `65536` | Предел размера авторского файла (T5.18). |

Значения трёх потолков Watch совпадают с константами домена. Конфиг не поднимает их выше этих констант. Лимиты не добавляют запросов к модели и сохраняют параллелизм в пятнадцать и более агентов (T5.8).

Файл не содержит полей `token`, `key`, `password` и не ссылается на `auth.json`. Secretguard находит такое поле по имени и называет строку, не печатая значение (T5.18).

## Пример из проекта

Файл `.beacon/agents.yaml` для проекта `beacon-impl` со всеми обязательными блоками:

```yaml
schema: beacon.agent-registry
version: 1
project: beacon-impl-1a2b3c4d
defaults:
  adapter: opencode
  model: opencode/hy4-flash-free
  mode: subagent
  worktree_root: .beacon/worktrees
  capabilities: []
roster:
  - id: executor
    role: executor
    runtime: subagent
    capabilities: [watch, read-verdict, ci-retry, rebase, ack, spawn]
    use_when: "есть карточка с владельцем файлов"
    why: "исполнитель доводит карточку до PR и завершает ход фразой waiting, watchID"
  - id: orchestrator
    role: orchestrator
    runtime: primary
    capabilities: [review, merge]
    use_when: "есть PR с Verdict=ready"
    why: "оркестратор мержит только после прочитанного вердикта"
configurations:
  presets:
    default: [executor, orchestrator]
    review: [orchestrator]
  recommended: default
limits:
  max_parallel_polls: 15
  max_watches_per_subscriber: 50
  max_active_watches: 200
  max_subscribers_per_watch: 50
  max_config_bytes: 65536
```

Проверка примера проходит по правилам этого документа. В файле ровно семь ключей верхнего уровня и нет неизвестных. `schema` и `version` имеют фиксированные значения. `project` соответствует формату ключа. Все `id`, `role` и `runtime` непусты, `id` уникальны. Пути относительные и без `..`. Все capabilities из словаря T5.20. Каждый псевдоним ссылается на существующие записи, `recommended` указывает на один псевдоним. Все лимиты целые и неотрицательные. Поля `use_when` и `why` не хранят токены и пути к `auth.json`.

Канонический идентификатор preset `default` для этого примера это `executor=subagent,orchestrator=primary`. Порядок определяется сортировкой по `id`, поэтому перестановка записей в `roster` не меняет идентификатор.

## Связь с карточками

| Карточка | Что использует схему |
| --- | --- |
| T5.12 | Отклоняет неизвестные ключи, абсолютные пути, `..`, пустые `id` и роли. |
| T5.13 | Считает SHA-256 канонического JSON авторского файла. |
| T5.14 | Ищет `.beacon/agents.yaml` и сверяет `project` с ключом проекта. |
| T5.15 | Строит идентификатор `id=runtime` из `roster`. |
| T5.16 | Проверяет псевдонимы и `recommended`. |
| T5.17 | Проверяет диапазоны и типы полей `limits`. |
| T5.18 | Ограничивает размер файла и ищет имена полей секретов. |
| T5.20 | Даёт словарь ролей, runtime и capabilities. |
| T5.23, T5.24 | Строят и сверяют capability index по `roster`. |
