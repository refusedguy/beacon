# Однострочная сводка активности сессии

Решение по карточке CO-05. Источник приёма: Claude Code Agent view, <https://code.claude.com/docs/en/agent-view.md>. В Agent view строка сессии показывает Working, Needs input, Idle, Completed и Stopped, а группа Ready for review отделяет PR с открытым ревью или красными проверками. Для короткого текста используется модель класса Haiku. Пока сессия работает, текст обновляется не чаще раза в 15 секунд из собственного вывода сессии. Раз в несколько минут модель переписывает сводку заново. В peek panel показывается время ожидания, например `waiting 3m`.

## Измерение до выбора

База из карточки: `git grep -n -i -E 'row summar|status summar|stall' origin/main -- docs internal cmd` на коммите `2d34645b` дал 0 совпадений. В `cmd/beacon/watch.go:87` сессия имеет состояния idle, retry или busy. Тест `TestW69ReadinessComesFromVerdictNotIdle` прямо запрещает считать idle признаком готовности.

Вывод: готового ряда сводки в beacon нет. Добавлять его нужно в новом файле, не переделывая вердикты Watch.

## Два варианта

| Свойство | Детерминированная сводка | Модель класса Haiku |
| --- | --- | --- |
| Источник текста | Последняя осмысленная строка вывода сессии | Вывод сессии, переписанный моделью |
| Задержка | Мгновенная, без запроса | Задержка запроса и лимит токенов |
| Частота обновления | Не чаще раза в 15 секунд | Раз в несколько минут |
| Стоимость | Ноль запросов | Один запрос на переписывание |
| Стабильность | Одинаковый ввод даёт одинаковый текст | Один и тот же ввод может дать разный текст |
| Что ловит | Паузу в выводе через `NoOutputFor` и `stalled` | Смысл длинного вывода, который не виден в одной строке |

Выбран детерминированный вариант. Он закрывает обе части цели оркестратора: дать одну строку о сессии и заметить агента без вывода. Строка берётся из вывода, который сессия уже произвела. Запрос к модели для этого не нужен.

## Условие перехода к модели

Платить за модель стоит, когда выполняются два условия вместе.

1. Одна последняя строка не передаёт смысл работы. Пример: агент печатает длинный вывод тестов, и оркестратору нужно знать, какой именно тест упал и что агент уже испробовал.
2. Оркестратор реально принимает решение по этой сводке, а не только показывает её в таблице. Пример: сводка попадает в запрос планировщику при выборе следующей задачи.

Если выполняется только первое условие, детерминированная строка остаётся достаточной. Пока сводка служит средством наблюдения, модель добавляет задержку и нестабильность без выигрыша в решении.

## Граница сводки

`ActivitySummary` описывает наблюдение. Поля `State`, `OneLine`, `LastOutputAt` и `NoOutputFor` не являются источником готовности. Значения `active`, `idle` и `stalled` остаются метками активности. Готовность задачи по-прежнему определяет вердикт Watch.

`BuildSummary` не меняет вердикт и не добавляет состояние ready. Пауза в выводе увеличивает `NoOutputFor` и после порога ставит `stalled`. Возврат вывода снимает `stalled`. Тесты в `internal/app/session/activity_summary_test.go` закрепляют частотный предел 15 секунд, рост `NoOutputFor` при паузе, снятие `stalled` и то, что idle не превращается в ready.
