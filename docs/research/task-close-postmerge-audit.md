## 2. MERGED и обычная карточка после #1233

Частично исправлено. Порт `CardLinks` больше не ограничен wiring-карточками. В `cmd/beacon/mcp.go` функция `deferredCardLinks.CloseMerged` (строка 56) после обхода отложенных проводок вызывает `linkedCardID` (строка 97) и `closeLinkedCardFile` (строка 157). Адаптер привязан в `mcp.go:1898` через `WithCardLinks`. Cibridge вызывает порт только для `VerdictMerged` (`internal/infra/cibridge/verdict_applier.go:427-440`). То есть карточка со строкой в `card_links` при merge теперь переходит в `done`.

Оставшийся разрыв: строка в `card_links` создаётся только когда вызывающий явно передал `cardID` в `beacon_watch_pr` (`cmd/beacon/mcp.go:521`, `:527`). `beacon_task_claim` такую строку не пишет (`internal/infra/mcp/tool_task_claim.go:37-49`, `:169-227`). Карточки, взятые через claim, карточки уже в `in_progress` и Watch, зарегистрированные без `cardID`, по-прежнему не закрываются при merge.

Прямое доказательство: у всех 17 карточек, закрытых в рабочем дереве вручную, стоит `Итог: Уже влито в PR #NNNN` и `Доказательство: <SHA> … merge-base --is-ancestor=0`. Маркер авто-закрытия `PR #NNN MERGED`, который пишет `closeLinkedCardFile`, у них отсутствует. Новых таких маркеров между рабочим деревом и `origin/main` нет.

## 3. «Дубликат» против «Дублирует»

- В main из #1215 каноническое поле «Дубликат»: `internal/infra/taskstore/close.go:53`, `:88`, `:101` и `internal/infra/taskstore/store.go:204`.
- В main из #1233 `cmd/beacon/task.go:506` пишет `setCardField(newText, "Дублирует", report.duplicateOf)`. Поле «Дублирует» не входит в набор разбираемых, поэтому остаётся в `Extra`, а валидация `duplicate` видит только «Дубликат».
- Исправление готово в `885ba123` на ветке `origin/fix/closewire`: `fix(tasks): route task done through CloseCard`. Коммит убирает прямую запись «Дублирует» и передаёт `DuplicateOf` в `taskstore.CloseCardOptions`, после чего пишется каноническое поле. В main коммита нет, база ветки — `5962774b` (#1253).
- Отдельный нюанс по #1229: handler в `tool_task_close.go` хранит `reason` и `duplicateOf` в sidecar-ledger (`tool_task_close.go:13`, `:156-166`, `:233-281`), а не в карточке. Чтобы обойти конфликт полей, он не записывает в карточку ни «Дубликат», ни «Дублирует». При закрытии через MCP поле «Дубликат» в самой карточке останется пустым.

Кто исправляет: отдельный fixer уже создал `885ba123` в `origin/fix/closewire`. Требуется его merge в main.
