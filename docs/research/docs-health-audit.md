# Аудит здоровья документации

Снимок: main `d3b1bfb1`, 2026-11-21. Первичные источники: файлы в `docs/`, `git log`, `tools/roadmap-sync`, `tools/beacon-gates/docsgate`, `.github/workflows/docs.yml`, `internal/infra/batchapply/apply.go`. Отчёт не покрывает duplicate, solid и deadcode аудиты, они лежат в соседних файлах этого каталога. Здесь рассматриваются только целостность и актуальность документации.

## Пять главных находок

1. `roadmap-sync` считает docs-only PR реализацией. Карточка T5.52 получает `todo -> done` в dry run из-за recheck PR #1000, хотя настоящая реализация в коммите `13f8558c` (#1107) не лежит на main. Это прямой механизм ложной premise.
2. 34 номера ADR имеют две или три разные записи. Например, `0091-checked-stop.md` и `0091-mcp.md` описывают разные решения под одним номером, и десять карточек ссылаются на неоднозначный `ADR 0091`.
3. Карточки содержат 182 ссылки на ADR с номерами 0292, 0295, 0298, 0301, 0304, 0307, 0310, 0313, 0316, 0319, 0322. Таких файлов нет, максимум реального номера 0267.
4. `ROADMAP_STATUS.md` печатает 420 done, 332 dropped, 143 todo и дату 2026-11-20. Dry run `roadmap-sync` даёт 569 done, 326 dropped, 0 todo. Расхождение 149 карточек в одну сторону.
5. Docs gate информационный (`continue-on-error: true`) и его exception таблица заполнена полностью, 40 из 40. Он проверяет структуру и дубли номеров, но не проверяет ссылки, отсутствующие ADR и расхождение статусов с git.

## 2. Устаревшие ссылки

### 2.1 Ссылки на несуществующие ADR

Проверка по регулярному выражению `ADR[-\s]?(\d{4})` по всем `docs/**/*.md` нашла 182 вхождения одиннадцати номеров, для которых нет файла. Большинство находятся в карточках `HD-001` до `HD-122`. Примеры: `HD-001` ссылается на `ADR 0292`, `HD-017` на `ADR 0295`, `HD-025` на `ADR 0298`. Многие из этих карточек имеют статус `dropped` и в подтверждении прямо пишут `referenced ADR 0292 missing`. То есть карточки были сгенерированы под запланированные ADR, которые так и не создали. Дубли ссылок внутри одной карточки тоже есть, например `HD-031` ссылается на `ADR 0298` трижды.

### 2.2 Сломанные локальные ссылки в FACTS.md

Шесть ссылок не разрешаются из каталога `docs/`:

- `README.md` и `AGENTS.md`, строка 45 и 167.
- `cmd/beacon/observe.go`, строка 80.
- `evals/main.go`, строки 172, 178, 181.

Причина в генераторе. `internal/infra/batchapply/apply.go:254` делает `strings.TrimPrefix(f.owner, "docs/")`. Для владельцев внутри `docs/` это даёт правильный путь от `docs/FACTS.md`, например `docs/tasks/RS-MCP-07.md` превращается в `tasks/RS-MCP-07.md`. Для владельцев в корне репозитория префикс не снимается, и ссылка указывает в несуществующий `docs/README.md`. Fix: для owner без префикса `docs/` добавлять `../`.

### 2.3 Прочие ссылки

`ROADMAP_STATUS.md` перечисляет в `OwnerFiles` файлы `docs/SKILL-MAP.md` и `docs/AGENT-RULES.md`, которых нет. Это ожидаемо для карточек `HD-105` и `HD-119` со статусом `todo`, вопрос лишь в том, что реестр выглядит как описание существующих файлов. Плохая формулировка, не ошибка пути.

## 3. Конфликтующие утверждения между ADR и карточками

### 3.1 Дубли номеров ADR

34 номера имеют по два, а `0185` по три файла. Первая серия `0069` до `0095` описывает wake и registry, вторая серия тех же номеров описывает plugin boundary и delivery. Примеры из проверки:

- `0091-checked-stop.md` это "Проверенный останов исполнителя", `0091-mcp.md` это "MCP не обещает пробуждения модели". Оба `accepted`.
- `0185-mcp-beacon-wake.md`, `0185-otel-tracing.md`, `0185-untitled.md`.
- `0260-fixer.md` и `0260-fix-watch.md`.

Десять карточек пишут `Ссылка: ADR 0091`, в том числе `T5.50`, `T5.51`, `T5.52`, `T3.269`. Читатель не может получить, какая из двух записей имеется в виду. Карточка `T5.52` цитирует требование вернуть `stop_uncertain`, что соответствует `0091-checked-stop.md`, но в поле указан только номер.

### 3.2 Индекс в docs/adrs/README.md

Индекс содержит 299 строк против 302 numbered файлов. Одинаковые номера повторяются как отдельные строки, `0185` три раза, `0260`, `0200`, `0199` и другие два раза. Статусы противоречат друг другу внутри одного номера, например `0092` показан и `accepted`, и `proposed`, а `0156` и `0157` имеют по две строки с разными темами. Индекс ведётся вручную и отстал от файлов.

### 3.3 Имена untitled

66 файлов называются `NNNN-untitled.md`, хотя внутри у них нормальный заголовок. Пример: `0240-untitled.md` начинается с `# ADR 240: Проверка правил без полного обзора`. Файл `0090-untitled.md` имеет заголовок `# ADR 90: Честная доставка и неизменная лестница` и при этом дублирует номер `0090` с `0090-registry-lifecycle.md`. Поиск по имени не находит тему, а дубль номера не видно без чтения содержимого.

### 3.4 Карточка T5.52 против истории коммитов

Premise в `docs/tasks/T5.52.md` утверждает `дубля нет`, `0 коммитов` и `0 открытых PR`, с базой `7c43ec2`. В истории репозитория есть `13f8558c` с subject `T5.52: report uncertain registry stop with stopPhase (#1107)`, который меняет `cmd/beacon/main.go`, `cmd/beacon/registry_stop.go` и тест. Коммит существует в ветках `fix/an*`, но не на main (`git merge-base --is-ancestor 13f8558c main` возвращает NO). Карточка остаётся `todo`, и это корректно с точки зрения main. Проблема в том, что вывод `0 коммитов` не различает "реализации нет" и "реализация есть, но не влита". Исполнитель, который поверит premise, пропустит готовый PR #1107.

## 6. Механический признак: реализация влита против docs перепроверки

### 6.1 Текущий признак и его дефект

`tools/roadmap-sync/main.go:212` (`scanGitLog`) собирает ID карточек из subject коммитов, у которых есть `(#NNNN)`. `resolveStatus` на строке 230 повышает карточку до done, если её ID попал в этот набор. Recheck коммиты проходят тот же фильтр:

- `711fb022 docs(tasks): T5.49/T5.52/T5.55 premise rechecked on fresh main, blockers named (#1000)` меняет только три файла в `docs/tasks/`.
- `aafc5f2c` (#1100) и `800eea13` (#1092) меняют только `docs/tasks/T5.49.md`, `T5.52.md`, `T5.55.md`.
- все три содержат ID T5.52 и PR suffix, поэтому каждый из них отдельно доказательство merged для T5.52.

`resolveDuplicateCards` на строке 301 усиливает эффект. Он повышает todo карточку до done, если её `OwnerFiles` пересекается с уже done карточкой. Ошибка в первом шаге распространяется на соседние карточки.

### 6.2 Предлагаемый признак

Карточка считается implementation merged, если существует коммит C на main, для которого выполняются все условия.

1. Subject C содержит `(#NNNN)`.
2. Subject C содержит ID карточки.
3. Diff C меняет хотя бы один путь из поля `Владелец файлов` карточки, и этот путь не начинается с `docs/`.
4. Subject C не является recheck. Recheck определяется префиксом `docs(` или словами `premise rechecked`, `baseline refreshed`, `keep todo`, `refresh`.

Условие 3 отсекает docs-only PR, потому что OwnerFiles карточек это код и тесты. Условие 4 отсекает recheck даже если он задел код ради обновления baseline. Проверка коммита на main оставляет гипотетические PR из веток `fix/*` вне счётчика, что корректно для статуса карточки.

### 6.3 Постоянная метка в карточке

Вычисляемого признака достаточно для разового прогона, но карточке нужен и явный маркер. Предлагаю поле `Impl-PR:` с номером PR, который изменил OwnerFiles.

- Recheck PR пишет `Premise:`, `baseline:` и явную строку `keep todo`, но не трогает `Статус:` и не заполняет `Impl-PR:`.
- Implementation PR заполняет `Impl-PR: #NNNN` и меняет `Статус: done`.
- `roadmap-sync` при `--write` повышает карточку до done только если есть `Impl-PR` или выполнены условия 1 до 4.

Тогда фраза `дубля нет, 0 коммитов` в Premise заменяется проверяемым утверждением `Impl-PR не задан, реализация на main не найдена`. Карточка T5.52 получила бы `Impl-PR: #1107` только после влития PR, а до этого осталась бы todo с честной формулировкой.

### 6.4 Куда добавить проверку

В `docsgate` есть rule `DOC-ADR-DUP`, `DOC-TASK-STATUS`, `DOC-TASK-FIELD`. Добавить `DOC-PREMISE-STALE`: если карточка `todo` имеет Premise с `0 коммитов` или `дубля нет`, а по условиям 1 до 4 на main есть коммит, поднять finding. Для FACTS.md добавить проверку разрешения локальных ссылок на этапе генерации, это закроет шесть сломанных путей. Docs gate пока информационный, поэтому новые rules не заблокируют PR, но дадут видимый сигнал.

## 8. Что не вошло

Здесь не проверялись дубли кода, архитектурные нарушения и мёртвый код. Для этого есть `duplicate-audit.md`, `solid-gof-audit.md` и `deadcode-audit.md` в том же каталоге. Пересечение только одно: дубли номеров ADR здесь рассматриваются как проблема навигации и целостности ссылок, а не как дублирование исходного кода.
