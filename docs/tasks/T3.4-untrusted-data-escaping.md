# T3.4. Экранирование недоверенных данных в тексте prompt

Статус: done
Фаза: P3
Тип: task
Владелец файлов: tests/adapter/untrusted-escaping.test.js
Зависимости: T3.3
Ссылка: ADR 0006
Агент: нет
Время: 2026-11-19T20:30:00Z

Цель: Не допускать сырые имена проверок, PR и веток в текст prompt и не давать данным превращаться в инструкции.

Контекст: WORKER-PROMPT §4.4 требует шаблон prompt, экранированные имена проверок, PR и веток как untrusted data, обрезку длины и обёртку `<beacon-event>`. Никаких инструкций из данных быть не может. BEACON-AUDIT в приёмке P3 указывает, что текст prompt не должен содержать сырые имена проверок без экранирования (§13, T3.1). ADR 0006 держит всю специфику OpenCode в адаптере, значит правило экранирования живёт в плагине, а не в ядре. Файл плагина принадлежит T3.1, эта карточка владеет тестом и добавляет функцию экранирования через зависимость от T3.3.

Шаги:
1. Добавить функцию экранирования полей: убрать управляющие символы, заменить `<`, `>`, `&` и кавычки на безопасные последовательности до вставки в шаблон.
2. Ограничить длину каждого поля и общую длину prompt, сохранив обёртку `<beacon-event>`.
3. Подготовить фикстуры имён с `<script>`, с фразой `ignore previous instructions`, с переводами строк и с кавычками.
4. Тест собирает prompt из фикстур и проверяет отсутствие сырых маркеров и наличие обёртки.

Проверка: `node --test tests/adapter/untrusted-escaping.test.js` проходит. Если сырой маркер из фикстуры появляется в тексте prompt, тест падает. Длина prompt не превышает заданный предел.

Приёмка: Сырые недоверенные имена в prompt отсутствуют. Обёртка `<beacon-event>` сохранена. Длина ограничена. Инструкции из данных не попадают в prompt.

Гейт: P3. Санитизация проверяется перед первым canary.
