# HD-076. Rerun только для флейков
Premise: проверено 2026-11-20, дубль. Ограничение повторных прогонов уже в main и живёт в движке вердиктов, а не в OwnerFiles карточки. internal/domain/verdict.go реализует flakyRetryChecks и WakeKind RerunChecks: VerdictRetry выдаётся только когда каждый упавший чек совпадает с glob-шаблоном Flaky.Names и не исчерпал бюджет Flaky.MaxRetries; при нефлейковом провале Evaluate возвращает VerdictKeepWorking, то есть rerun по census красному и rerun без классификации невозможны по построению. internal/infra/mcp/tool_get_result.go для VerdictRetry отдаёт gh run rerun --failed с подсказкой «rerun only the failed jobs», internal/infra/wake/notify.go относит упоминания флейка к TriageMainBroken. Список допустимых флейков описан в Flaky.Names и Flaky.MaxRetries, docs/gates/G2-canary.md §2 зафиксировал бюджет из .beacon/flaky.json, вердикт retry и то, что агент сам выполняет rerun без превышения бюджета; ADR 0246 требует «повторный rerun только для timing flakes», docs/templates/executor-task.md закрепляет rerun-owner = agent. Упомянутый PR #394 лишь закрыл карточку в main без обоснования. Ни tools/beacon-gates/gate/gate.go и config/baseline.json, ни назначенные evals/main.go и evals/README.md не содержат логики rerun и не владеют этим поведением: новый код создал бы вторую копию классификации. Ссылка на ADR 0310 ведёт в отсутствующий файл, актуальный ADR 0246. Код не писал, дубль не создавал.
