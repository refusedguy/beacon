Goal: add config hot reload so changing .beacon/config.yaml does not require killing the MCP daemon and reconnecting OpenCode. No JS or docs edits.

Evidence:
- After I changed harness.model in .beacon/config.yaml, the running beacon mcp daemon kept the old harness settings. Killing the daemon made all ten beacon_* tools disappear from the session until the operator reconnected OpenCode. That is not acceptable.
- cmd/beacon/mcp.go wires the harness once at startup from the config file. cmd/beacon/main.go resolveModel is called at that moment from BEACON_MODEL, cfg.Harness.Model or the parent session. There is no watcher on .beacon/config.yaml.
- The project already has tickers for the daemon heartbeat, reconciler and SSE, so a config watcher fits the existing pattern.

Steps:
1. Add a config watcher in cmd/beacon that checks the config file mtime or content hash on a short interval and reloads it. Apply live-safe fields to the running services without restarting the MCP server: harness model reference, token, endpoint, worker instructions, concurrency limits, required checks and merge settings.
2. Use a mutex or atomic swap so a reload cannot race with an active dispatch or reconcile. Never mutate a map that a running worker reads concurrently.
3. If a field cannot be applied live, keep the old value, emit one clear WARN naming the field, and tell the operator to restart only when that field changes. Do not log tokens or endpoint credentials.
4. Make the watcher fail closed on a malformed config: keep the last good config and warn. A partial or empty config must never be applied.
5. Tests in cmd/beacon: changing the config file updates the running harness model without a new process; an invalid config is ignored and the previous model stays; token values never appear in stdout or stderr; no reload happens when the file is unchanged; MCP stdio service keeps serving during reload.
6. Keep funlen <= 80 lines, statements <= 40, complexity <= 20. Run gofmt -w, targeted go test ./cmd/beacon ./internal/infra/config and go test . for arch. Leave full lint to CI.
7. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Accept: only cmd/beacon/mcp.go, cmd/beacon/main.go, cmd/beacon/config_watch.go, cmd/beacon/config_watch_test.go and internal/infra/config/config.go with its test if needed. No plugin JS, no docs, no task card edits.
