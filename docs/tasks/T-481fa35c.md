Goal: one command that answers what happened on a shift without reading decision rows and timelines by hand.
Evidence: beacon status --snapshot returns active runs, bounded recent and aggregate counters but no time window. An audit proposed a read-only report grouping merges, blocks, opened and resolved BaseIncident records, fixer attempts, orphan closures and runs still stalled at the end of the window. run_events and decisions have indexes on at; Store.ListDecisions at internal/infra/sqlite/store.go currently takes run IDs, not a time range.
Steps: add a narrow read port for time-range queries of decisions, events, incidents and terminal runs; add an app.ReportService that groups them into a short snapshot for a since duration; add beacon report --since <duration> in cmd/beacon/commands.go with a JSON and text form; do not change the daemon API or the standard snapshot shape; add tests for empty window, mixed events and an open incident crossing the boundary.
Accept: an operator after a shift gets one bounded report with counts and the IDs that still need attention.
