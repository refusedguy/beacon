Context: the panel polls every 5 seconds. OpenCode 2.3.2 supports `reg.events.emit` on the server and `rpc.events.on` in the TUI, but BeaconStatusRpc declares no events. The operator is concerned events may stall because the Beacon daemon runs in the background, so a polling fallback must remain.

Goal: near-instant panel refresh with a reliable fallback, plus a small live metrics readout.

Steps:
1. Add a `runChanged` event to `BeaconStatusRpc` and emit it from the server plugin when the reconciler observes a run change. If the server plugin cannot see reconciler events directly, emit on each successful snapshot diff and dedupe by run ID and SHA.
2. In the TUI, subscribe with `rpc.events.on("runChanged", ...)` and refetch the batched snapshot on each event. Check the event location so a different project does not refresh this panel.
3. Keep the 5-second poll as fallback. If no event arrives within 30 seconds, resume polling. On subscription error, abort and resubscribe with backoff. Clear timers and subscriptions in `setup` cleanup.
4. Add a compact metrics line to `home.footer.status` driven by the same batched snapshot: active runs, blocked count, rebase count, fix count, last update time. Do not add a second polling loop.
5. Tests: event triggers exactly one refetch, no event falls back to polling, stale event from another location is ignored, cleanup leaves no timers or subscriptions. Run `node --check` and `node --test`.
6. Open a PR and call beacon_watch_pr with the real run ID and PR number.

Check: a run change updates the panel without waiting 5 seconds, and the panel still refreshes when events stop.

Accept: do not change Go code or dispatch logic. Keep files under 350 lines. Do not edit AGENTS.md or another card.
