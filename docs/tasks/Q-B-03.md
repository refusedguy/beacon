## Решение
- Оба change проверены в main. Дубль кода PR #872 и #874 не создан.
- Причина расхождения находится в адаптере `cmd/beacon/mcp.go:825`. Когда `ClaimDelivery` возвращает false, адаптер сразу отдаёт Duplicate и не вызывает `RecordDelivery`. После рестарта `Filter.Restore` кладёт ID из журнала в `deliveries`, поэтому изменённое тело не доходит до журнала и Conflict теряется.
- Правка в `filters.go`. `Filter` хранит множество `restored`. `Restore` помечает ID, прочитанный из журнала. `ClaimDelivery` пропускает такой ID дальше, чтобы `RecordDelivery` сравнил тела и вернул Duplicate и Conflict. ID, заявленный в текущем процессе, по-прежнему отсекается быстро. Второй эффект не появляется из-за `INSERT OR IGNORE` в журнале.
- Интеграционный тест `internal/infra/webhook/restart_conflict_test.go` прогоняет подписанную доставку через Receiver, затем рестарт с восстановлением индекса и повтор с другим телом. Тест проверяет Duplicate и Conflict, отдельное событие `webhook-conflict`, затем обычный Duplicate для прежнего тела и ровно один Created.
- RS-WK-03 и RS-WK-04 не правил. Их OwnerFiles и статусы лежат вне этой карточки. Их блокеры сняты влитыми PR #872 и #874. Статус карточки сейчас todo, Beacon поставит done при мерже.
- gofmt применён к своим .go файлам. go test и go build локально не запускались, проверка идёт в CI.
