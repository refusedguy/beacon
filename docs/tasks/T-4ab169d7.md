Goal: restore a clean baseline on unchanged code after the inner-three spread change produced false verdicts.

Evidence: PR #2786 at head 2a11b701, advisory run 45993675938. With spread computed from s[1..3], harness-spawn reported regression +40.25% and http-frame-emission reported gain -26.80% on identical code. Both ranges overlapped. The previous full-range spread blocked them but also blocked genuine gains when one base sample spiked to 74.892 ms.

Steps, all in .github/workflows/ci.yml Build comparison comment:
1. Keep five sorted medians s[0..4] per side. Compute the decisive spread as 100 * min(s[3]-s[0], s[4]-s[1]) / median(s). This removes exactly one extreme sample from either end and keeps the rest of the observed spread.
2. Keep the trimmed inner-three value as supporting text only if useful, but do not use it as the decisive spread.
3. Keep the allocation, B/op and deterministic call-count override rules unchanged. Keep the 25 percent floor cap and the warm-cache removal unchanged.

Accept: rerunning PR #2786 on unchanged code yields flat for every row, with no gain or regression. The fix PR must NOT carry the perf label. No local execution.
