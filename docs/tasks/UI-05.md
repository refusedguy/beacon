# UI-05. Общая модель данных UI
Статус: dropped
Фаза: P1
Тип: task
Владелец файлов: internal/ui/model/domain.go
Зависимости: UI-01
Ссылка: ADR 0072 (proposed)
Агент: нет
Время: нет
Цель: Все экраны используют одни типы Watch, obligation, verdict и revision.
Контекст: Без общей модели каждый экран по-своему трактует delivered, claimed и read.
Шаги: Описать типы и преобразование из строк state. Разделить delivered, claimed и read тремя полями.
Проверка: Тест показывает, что ack не меняет delivered и что claimed не равно read.
Приёмка: Ни один экран не выводит поле, отсутствующее в модели.

## Подтверждение
- PR #394 DROPPED: Общая модель уже в internal/domain (Watch, Obligation, Verdict, Revision) и в mcp.StateSnapshot; delivered/claimed/read разделены в store (ADR 0014). Отдельный бинарник beacon-ui и пакет internal/ui в main отсутствуют; принятый ADR 0060 прямо отклоняет собственный TUI и веб-интерфейс ("Свой TUI или веб-интерфейс не создаётся"), ядро MCP-only (ADR 0086) с контрактом ровно семи инструментов (ADR 0094). Ссылка карточки на "ADR 0072 (proposed)" неверна: ADR 0072 принят и описывает авто-мерж, а ADR 0092-tui только proposed и противоречит ADR 0060.
