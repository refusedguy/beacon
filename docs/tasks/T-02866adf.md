Goal: A harness event for a known run triggers a runs read.

Evidence: final-15. applyEvent writes ev.At into Run.UpdatedAt, which View never renders, then returns no reload. Real harness events always carry run_id, so state transitions leave the list stale.

Steps: Treat every event as a notification and schedule a runs read, or fold only fields the daemon actually sends and re-read the rest.

Check: A fixture event for a known run changes the rendered row after the read.

Accept: Follow the documented contract that events are notifications only.
