Цель: Закрывать Watch с устаревшим headSHA в начале цикла, а не при следующей публикации вердикта.
Контекст: В корпусе 206 событий `head_changed` и 412 записей с этим словом. Два `actor_error` от `watch_pr-head` сообщают `INVALID_INPUT: watch_pr: headSHA is required when no CI provider is configured`. Механизм перехода есть: `internal/infra/cibridge/verdict_applier.go:16` вызывает `domain.HeadChangedEvent`, `internal/domain/transition.go:312` закрывает Watch и создаёт `EffectCreateWatch`, `internal/infra/mcp/tool_watch_pr.go:780` переносит подписчиков. `internal/app/orchestrator/checkall.go:893` сравнивает headSHA только при публикации вердикта. Push между циклами оставляет Watch на старом PR до ближайшего вердикта.
Шаги: Сравнивать `HeadRefOid` из провайдера с `Watch.HeadSHA` на каждом цикле до публикации вердикта. При расхождении вызывать `handleHeadChanged` сразу. Если провайдер вернул ошибку, не закрывать Watch, а писать предупреждение с причиной. Повторно использовать существующий переход и перенос подписчиков без нового механизма. Добавить eval на push между циклами.
Проверка: Eval с изменённым `HeadRefOid` создаёт Watch с новым SHA до публикации вердикта. Старый Watch закрыт с причиной `head_changed`. Ошибка провайдера не закрывает Watch.
Приёмка: Watch не опрашивает старый PR после push дольше одного цикла.
