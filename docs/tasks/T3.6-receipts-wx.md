# T3.6. Квитанции в receipts/ через open wx, одна на событие и попытку

Цель: Записывать квитанцию в подкаталог `receipts/` через атомарное `open` с флагом `wx`, по одному файлу на событие и попытку.

Контекст: ADR 0014 указывает, что плагин после вызова `ctx.session.prompt` пишет квитанцию в подкаталог `receipts/` внутри каталога состояния Beacon, одна квитанция на событие и попытку, создание атомарное через флаг `wx`, Beacon читает только целые строки. ADR 0015 уточняет, что плагин не знает схему базы и переносит факт в базу через Beacon одной транзакцией. ADR 0011 задаёт каталог `$XDG_STATE_HOME/beacon` с правами 0700 и запрещает менять конфиг OpenCode без разрешения владельца. WORKER-PROMPT §4.4 задаёт строку `{obligationID, attempt, outcome: posted|transport-failed, at}` и идемпотентность по `(obligationID, attempt)`. Отсутствие квитанции это indeterminate, а не failed (ADR 0014). Файл плагина принадлежит T3.1, эта карточка владеет тестом и фикстурами.

Шаги:
1. После попытки prompt создать файл `receipts/<obligationID>.<attempt>` через `open(path, "wx", 0o600)`.
2. Записать одну строку JSON с полями `obligationID`, `attempt`, `outcome`, `at`. Outcome равен `posted` при успешном prompt и `transport-failed` при ошибке.
3. При `EEXIST` пропустить запись: повтор той же пары не создаёт второй эффект.
4. Тест: первая запись создаёт один файл, вторая с тем же ключом получает `EEXIST` и оставляет один файл, отдельный тест проверяет `transport-failed`.

Проверка: `node --test tests/adapter/receipts-wx.test.js` проходит. Тест проверяет число файлов в `receipts/`, режим 0600 и содержимое строки. Проверка каталога `~/.config/opencode` до и после теста не показывает новых записей.

Приёмка: Одна квитанция на событие и попытку. Создание через `wx` с режимом 0600. Повтор с тем же ключом не создаёт второй файл. Чужие конфиги не изменены.

Гейт: G2. Квитанции нужны лестнице T3.9 до первого canary.
