Цель: Продолжать проход после провала одной задачи и сообщать причину и действие для каждой не обработанной задачи.

Контекст: В OpenRig `packages/daemon/src/domain/crash-cart-conductor.ts:14` объявляет закрытый набор исходов с отдельным `not_attempted`. `:49-90` обходит единицы в заданном порядке, продолжает после провала, проверяет отмену только на границе и записывает `reason` и `remediation` для незапущенных. `:161-220` выбирает между принятием живых сессий и восстановлением из снапшота, а `:277-299` ставит kernel Watch первым. `:352-371` считает все четыре исхода отдельно.

В beacon `internal/app/tasks/night_shift.go:191-193` прямо говорит, что ошибка одной issue обрывает проход. `:210-214` возвращает ошибку сразу после `triageIssue`, поэтому остаток бэклога не получает ни диагноза, ни действия. `internal/app/orchestrator/daemon.go:83-84`, `:111-126` логирует и глотает ошибки шагов, но тоже не формирует исход по каждой единице. Атомарная идемпотентность в `night_shift.go:6-11` уже есть и должна сохраниться.

Шаги: Заменить обрыв прохода на накопление результата по каждой issue. Добавить triple `failed` с причиной и `not_attempted` с действием в `Result`. Отмену проверять только на границе единицы, уже начатую работу не прерывать. Передать упорядоченный список в daemon-отчёт. Для kernel-задачи добавить признак приоритета без изменения существующего контракта `PlanTriage`.

Проверка: Измеримая. Три кандидата, второй принудительно проваливается. `Run` возвращает три строки с исходами `delegated`, `failed` с причиной и `not_attempted` с действием; сейчас возвращается ошибка и одна delegation. Проход с отменой после первой задачи помечает остальные как `not_attempted`, а не как пропущенные без причины. Повторный проход с возвращённым `State` не создаёт новых delegations.

Приёмка: Ошибки чтения бэклога остаются фатальными. Идемпотентность по issue ID и по Watch сохраняется. Формат `beacon workload --format json` не ломается.
