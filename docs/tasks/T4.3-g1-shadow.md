# T4.3. G1 shadow: Beacon наблюдает, никто не будится

Статус: todo
Фаза: P4
Тип: task
Владелец файлов: docs/gates/G1-shadow.md
Зависимости: T4.1, T4.2
Ссылка: ADR 0018
Агент: нет
Время: нет

Цель: Провести shadow-прогон, в котором Beacon пишет вердикты по реальным PR, а `gh --watch` продолжает работать как раньше и ни один агент не будится.

Контекст: ADR 0018 задаёт G1: Beacon наблюдает, `gh --watch` работает как раньше, никто не будится. Выход гейта это не менее 20 реальных PR, ноль расхождений вердикта с фактом `gh` и SLO в норме. WORKER-PROMPT §6 повторяет те же критерии. BEACON-AUDIT в таблице гейтов добавляет, что p95 и бюджет должны быть в SLO (§11). ADR 0018 требует, чтобы все SLO измерялись до перехода на следующий гейт, и запрещает проходить гейт самовольно. ADR 0001 объясняет параллельный прогон как проверку надёжности: расхождение видно до того, как старый механизм убран.

Шаги:
1. Запустить Beacon в режиме наблюдения на не менее чем 20 реальных PR, не отправляя уведомления подписчикам.
2. Для каждого PR записать вердикт Beacon и факт, который показывает `gh`, в таблицу расхождений.
3. Приложить числа SLO из T4.2: VmHWM, p95, поинты в час, рестарт.
4. Записать в `docs/gates/G1-shadow.md` число PR, число расхождений, метрики и решение владельца о переходе.
5. Не изменять конфиг агентов и не удалять `gh --watch` из инструкций.

Проверка: В отчёте не менее 20 строк PR и ноль расхождений. В логах нет событий `session.execution.started`, вызванных Beacon. Значения SLO из T4.2 приложены к отчёту.

Приёмка: G1 пройден по критериям ADR 0018: 20 реальных PR, ноль расхождений, SLO в норме, никто не разбужен. Переход на G2 подтверждён владельцем, воркер гейт не открыл сам.

Гейт: G1. Следующий шаг G2 после решения владельца.
