# T3.284. Core app human answer
Статус: done
Premise: PR #839 (merge 79c1b40, 2026-11-21) влил в main контракт HumanDecideContract = "beacon.human-decide.v1", поля contract и actor, проверку версии с 400 UNSUPPORTED_CONTRACT и эхо версии в DecisionResult. PR #1136 добавляет локально проверяемый срез per-app credentials: ключ приложения отображается в список разрешённых actors, и human-decide отклоняет запрос от чужого actor. Живого внешнего приложения в репозитории нет, поэтому приёмка проверяется на фейковом клиенте.
Baseline: origin/main @ 92bfc55.
Фаза: P3
Тип: task
Владелец файлов: internal/infra/httpapi/server.go, internal/infra/httpapi/client.go, internal/infra/httpapi/server_test.go, docs/tasks/T3.284.md
Зависимости: T3.275 остаётся dropped, выдача ключей приложениям не воскрешена
Ссылка: ADR 0094
Агент: executor
Время: нет
Цель: Дать внешним приложениям читать и отвечать на вопросы.
Контекст: Core app human-answer job v1 в OpenRig определяет access, identity и discover, read, answer с refresh и recovery.
Шаги: Спроектировать versioned контракт с credentials приложения и permitted actors, не per-person logins.
Проверка: Ответ записывается через тот же путь, что и TUI.
Приёмка: Внешнее приложение не может ответить на чужой вопрос.

## Реализация в PR #1136
- AppCredentials: `map[appKey][]permittedActor`. Карту передаёт composition root через `httpapi.Config.Credentials`; сервер ключи не выдаёт.
- Поле `appKey` добавлено в `Decision` и в `ClientDecision`/`decideWire`, поэтому клиент может объявить приложение.
- В `handleDecide` после проверки версии контракта: при непустом `appKey` и заданной карте ключ должен быть известен и содержать `actor` в своём списке. Иначе ответ 403 `ACTOR_NOT_PERMITTED`, sink не вызывается. Вызов без `appKey` сохраняет локальный путь TUI; при nil-карте ключ игнорируется.
- Контракт v1, проверка `UNSUPPORTED_CONTRACT` и эхо версии не изменены. T3.275 остаётся dropped.

## Тест
- `TestHumanDecideAppCredentials`: разрешённый actor проходит и получает `beacon.human-decide.v1` в ответе; чужой actor и неизвестный ключ получают 403 `ACTOR_NOT_PERMITTED` и не доходят до sink; несовпадение версии контракта по-прежнему даёт 400 `UNSUPPORTED_CONTRACT` до проверки actor.
- `TestHumanDecideAppCredentialsViaFakeClient`: тот же путь через `ProjectionClient` с фейковым `ClientDoer`. Клиент передаёт `appKey`, сервер отклоняет чужого actor.
- gofmt применён к трём .go. `go test` и `go build` локально не запускались по условию задачи, проверка идёт в CI.
