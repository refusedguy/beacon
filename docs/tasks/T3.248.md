# T3.248. Broadcast по адресам
Premise: проверено 2026-11-21, функционал в origin/main отсутствует, дубль не создан. Карточка просит резолвер адресов pod, rig, global и списка и частичные ошибки с указанием отказавшего адреса; в контексте указан OpenRig resolveSessions. В origin/main нет ни типа адреса, ни парсера, ни резолвера, ни модели pod, rig, global, seat или topology: `git grep 'resolveSessions' origin/main -- '*.go'` дал 0 файлов. internal/infra/wake/deliver.go доставляет wake только на точный ses_...: `SubscriberTarget` (строка 302) принимает лишь subscriber.ID на том же Watch с ролью executor, orchestrator или fixer и прямо запрещает подмену: "No caller session, _meta value, notify target or role-wide broadcast can stand in for that id" (строка 300). `Deliver` требует `ObligationKey(watchID, revision, sessionID) == p.ObligationID`, то есть владелец привязан к сессии, а не к стабильному адресу роли; `ValidateT210Target` (строка 871) проводит ту же проверку. В internal/infra/mcp/tool_wake.go есть флаг Broadcast, но он описывает семантику дверного звонка: сообщение не адресуется одной почте и не звонит, а не таргетинг по pod, rig, global. Зависимость T3.241 в main остаётся todo и уже несёт Premise с тем же выводом: адресной модели и seat в Beacon нет, маршрутизация по роли запрещена, реализация потребовала бы доменных изменений вне OwnerFiles. Сёстры T3.266, T3.267, T3.268, T3.291, T3.321, T3.322, T3.323, T3.353 и T3.357 сняты PR #394 с формулировкой "tmux нет, нет seat/topology, заглушка deliver.go". Проверка "один недоступный получатель не отменяет остальным" и приёмка предсказуемой массовой рассылки требуют реальной среды с несколькими адресатами и работающего резолвера адресов; фейковый PromptFunc проверяет только доставку wake на одну сессию, а не разрешение адресов pod, rig, global и списка. Локальная реализация в OwnerFiles потребовала бы выдумать модель адресов и topology вне OwnerFiles и нарушила бы явный запрет role-wide broadcast в SubscriberTarget. Ссылка на ADR 0084 не соответствует теме: docs/adrs/0084-lease-obligation-release-fail.md про lease на obligation с путями release и fail, а не про broadcast или адреса. Статус todo сохранён, карточка остаётся неподтверждённым спайком до появления адресной модели, resolveSessions или расширения OwnerFiles, блокер возвращён оркестратору. OwnerFiles не менял, код не писал, gofmt не применял, правка только текстовая.
baseline: `git grep -n 'resolveSessions' origin/main -- '*.go'` = 0 совпадений; `grep -ciE 'broadcast|address' internal/infra/wake/deliver.go` = 12, из них конструктивный запрет только в комментарии SubscriberTarget строка 300; `grep -n 'role-wide broadcast' internal/infra/wake/deliver.go` = строка 300; `git log origin/main --oneline --grep='T3\.248'` = 0 коммитов; `gh pr list --repo refusedguy/beacon --state all --search 'T3.248'` = 0 PR; `git diff origin/main -- internal/infra/wake/deliver.go internal/infra/wake/deliver_test.go` = 0 строк; `git show origin/main:docs/tasks/T3.241.md | grep '^Статус:'` = todo; ADR 0084 про lease obligation, не про broadcast.
