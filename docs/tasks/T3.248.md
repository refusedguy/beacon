# T3.248. Broadcast по адресам
Статус: done
Фаза: P3
Тип: task
Владелец файлов: internal/domain/capabilities.go, internal/domain/identity.go, internal/domain/capabilities_test.go, internal/infra/wake/deliver.go, docs/tasks/T3.248.md
Зависимости: T3.241
Ссылка: ADR 0084
Агент: нет
Время: нет
Цель: Поддержатьtargeting по pod, rig, global и списку.
Контекст: OpenRig broadcast использует resolveSessions и отправляет каждому получателю по очереди.
Шаги: Реализовать резолвер адресов и частичные ошибки с указанием адреса, который отказал.
Проверка: Один недоступный получатель не отменяет остальным.
Приёмка: Массовая рассылка остаётся предсказуемой.

## Реализация

Введена адресная модель `Seat` (`member@rig`) с парсером `ParseAddress` и
резолвером `ResolveAddress`. Адрес резолвится в ровно одну конкретную сессию
`ses_...` через порт `SessionResolver`; роли и wildcard в обеих частях адреса
отвергаются как broadcast-адреса. `ValidSessionID` в identity.go не даёт роли
или адресу подменить сессию. В deliver.go добавлен `DeliverToAddress`, который
резолвит адрес и проходит через прежнюю проверку `SubscriberTarget`, поэтому
владельцем обязательства остаётся та же сессия и role-wide broadcast
невозможен.

## Подтверждение

PR: https://github.com/refusedguy/beacon/pull/1130 (ветка `fix/t3248-seat-address`, base `main`).
Тест в `internal/domain/capabilities_test.go`: парс `member@rig`, отказ
ролевых и wildcard-адресов, резолв в конкретную сессию и отказ недоступного
seat. Реальная проверка «один недоступный получатель не отменяет остальным»
требует живой среды с несколькими адресатами; в юнит-тесте резолвер является
портом.
