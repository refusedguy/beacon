# S4.007. Очередь follow-up
Статус: dropped
Фаза: P3
Тип: task
Владелец файлов: internal/infra/server/followups/queue.go
Зависимости: S4.005, S2.010
Ссылка: ADR 0082
Агент: нет
Время: нет
Цель: Сообщения в неактивный turn ждут своей очереди и не дублируются.
Контекст: Сетевой повтор может создать второй follow-up.
Шаги: FIFO по сессии, idempotency key, статусы queued, delivered, cancelled.
Проверка: Тест повтора с тем же ключом.
Приёмка: Два повтора дают один follow-up.

## Подтверждение
- PR #394 DROPPED: очередь follow-up дублирует queue delivery и идемпотентность (ADR 0028, 0077); followups/queue.go отсутствует, ADR 0094.
