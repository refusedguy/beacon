Context: every time Beacon removes a worktree, OpenCode keeps a row in its `worktree` table. On the next `LocationServiceMap.reload` it calls `realPath` on the missing directory and throws `DirectoryNotFoundError`. This has required manual sqlite deletes at least three times today. OpenCode v2.3.2 exposes `POST /api/worktree/refresh` with `{"projectID":"..."}`, which removes rows whose directories no longer exist and is idempotent. `DELETE /api/worktree` is NOT safe for a missing directory because it calls `git.repo.discover` first.

Goal: worktree removal never leaves a stale OpenCode registration.

Steps:
1. Add `RefreshWorktrees(ctx)` to `harnesses/opencode/opencode.go`. Use the existing `h.do(ctx, method, path, body)` helper against `h.Endpoint`. Resolve `projectID` via `GET /api/project` by matching the project canonical path against the repo, then call `POST /api/worktree/refresh`. Add it to the harness port in `pkg/core/ports.go` only if needed, and keep other providers as no-ops.
2. Wire the new method from `cmd/beacon/main.go` into `internal/infra/workspace/git_worktree.go`. Call it after a successful `git worktree remove` in both `Remove` and `ForceRemove`. Treat 204 and 400/404 as success. Log network errors as warnings so a refresh failure never fails the removal itself.
3. Add a behavior test in `internal/infra/workspace/git_worktree_test.go` using an `httptest` OpenCode server: create and remove a real worktree, assert a POST to `/api/worktree/refresh` with the matching projectID; remove a directory out of band and assert `Remove` still succeeds and refreshes; assert a failing refresh does not fail removal.
4. Run `gofmt -w`, `go test ./...`, `go vet ./...`. Keep production files under 350 lines.
5. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Check: after a worktree is deleted, `/api/worktree/refresh` is called and no `DirectoryNotFoundError` appears on the next location reload.
