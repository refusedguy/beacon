# CA-23. Повтор записи при блокировке с экспоненциальной задержкой
Статус: todo
Фаза: P2
Тип: task
Владелец файлов: internal/app/taskcli/state_filestore.go
Зависимости: 
Ссылка: docs/research/comp-aider.md
Агент: нет
Время: нет
Цель: Повторять запись состояния при временной ошибке блокировки с ростом задержки.
Контекст: Источник: docs/research/comp-aider.md, дополнение к CA-04. aider пишет файл до 5 раз, при `PermissionError` ждёт 0.1 секунды и удваивает задержку, а остальные `OSError` не повторяет (`aider/io.py:478-507`). В beacon хранилище состояния берёт эксклюзивный flock на дескрипторе (`internal/app/taskcli/state_filestore.go:15-66`) и не имеет повторной попытки при отказе открытия или записи. Baseline: один временный отказ равен потере операции.
Шаги: Добавить обёртку записи с 5 попытками и экспоненциальной задержкой от 0.1 секунды. Повторять только временные ошибки блокировки. Сохранить idempotency по ключу и одинаковый результат при повторе.
Проверка: Смоделировать 4 временных отказа подряд и один постоянный. Требовать, что temporary случай завершается успешно с 5 попытками, постоянный завершается ошибкой ровно после 5, а задержки равны 0.1, 0.2, 0.4, 0.8. Baseline: отказ на первой попытке.
Приёмка: Временная блокировка переживается за 5 попыток, постоянная ошибка не маскируется, задержки совпадают с ожидаемыми.
