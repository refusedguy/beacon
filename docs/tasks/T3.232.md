# T3.232. waitFor, waitForMain и идемпотентность мержа
Статус: done
Фаза: P3
Тип: task
Владелец файлов: internal/infra/merge/executor.go, internal/infra/merge/executor_test.go, evals/main.go
Зависимости: T3.231
Ссылка: ADR 0072
Агент: нет
Время: нет
Цель: Задержать мерж пока зависимости и головной PR не в main, и сделать мерж идемпотентным по паре watchID и revision.
Контекст: ADR 0072 п2, п6 и п7. Кейсы W16 и W17 проверяют эталонную модель. Условие «в main» относится и к зависимостям waitFor, и к самому watch-PR через waitForMain. Журнал мержа лежит рядом с обязательствами ADR 0028, но не подменяет obligationID.
Шаги: Реализовать в internal/infra/merge проверку waitFor и waitForMain по фактам Watch; вести журнал выполненных мержей по ключу watchID:revision; не писать вторую запись при повторе пары и разрешать мерж при новой ревизии или другом watchID; написать unit-тесты; перенести кейсы W16 и W17 на реальный код, сохранив негативные контроли; приложить команду и вывод к PR.
Проверка: go test ./internal/infra/merge; GO=/tmp/opencode/go126/bin/go bash evals/run.sh
Приёмка: Каждое невыполненное условие waitFor и waitForMain блокирует мерж; при выполнении всех условий мерж происходит; повтор пары даёт noop; новая ревизия и другой watchID мержат; W16 и W17 зелёные с негативным контролем; локальный прогон приложен к PR.
