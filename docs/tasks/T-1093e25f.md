Goal: Only session create and the initial prompt stay on the Dispatch critical path.

Evidence: dispatch-05. Spawn performs five synchronous HTTP calls: model lookup, POST /api/session, move, model and prompt. The move and model calls repeat values already sent at creation, and the prompt call reads the full body, so a slow turn lands on the button.

Steps: Keep create, ID parsing, binding and the prompt needed for claim consistency. Queue move and model after the tool returns with their 404 and 409 tolerance. If the prompt response can be decoupled safely, do so without changing the claim.

Check: Dispatch returns after fewer round trips and the worker still receives all configuration.

Accept: High risk. Do not break the worker claim or persisted session ID.
