Goal: stop counting pending as failure and use the wall time provided by the Go side. No Go edits.

Evidence: ui_alerts.js:162 sets failed = list.length - passed, so four pending checks render as "4 failed · 0/4" while the rows themselves correctly show the pending marker. Go emits only success, failure, pending and skipped (pkg/core/verdict.go:8-15). ui_model.js CHECK_SPEC at :65-68 keeps only name, state and durationSeconds.

Scope: .opencode/plugins/beacon-project/ui_model.js, ui_alerts.js, ui_ci_wall_time_test.js.

Steps:
1. Add ciWallSeconds to RUN_SPEC from ci_wall_seconds.
2. Rewrite checksSummary into four buckets: success, failure with aliases failed/error, pending with aliases in_progress/queued and any unknown state, skipped with alias neutral. Failed must not include pending or skipped. Header examples: "0/4 · 4 pending", "1 failed · 2/4 · 1 skipped", "5/5 · 31s".
3. Use ciWallSeconds when positive. Keep longest durationSeconds as fallback when the value is missing or zero. Keep the no-check case empty.
4. Do not change checkRow. Add tests for pending only, skipped only, mixed states, wall time present and wall time absent.
5. node --check every plugin JS file and node --test .opencode/plugins/beacon-project/*_test.js. Every file <= 350 lines. Open a PR, call beacon_watch_pr, do not self-merge.
