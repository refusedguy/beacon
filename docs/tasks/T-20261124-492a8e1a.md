Goal: let a docs-only PR merge even though CI skips all checks for paths-ignore. PR #2396 has no check runs because .github/workflows/ci.yml ignores docs/** and **.md. Beacon waits forever with "required checks not passed: build (missing), vet (missing), test (missing), lint (missing)".

Evidence: internal/infra/policy/configurable.go:58-79 treats every missing required check as a wait. The GitHub adapter returns observation checks; there is no notion of a skipped workflow or docs-only PR. The docs-only card T-20261124-9961f5a5 has been in waiting_ci for a long time with a green, docs-only diff.

Scope: internal/app/ports.go, internal/app/reconciler.go, internal/infra/policy/configurable.go and its test, internal/infra/scm/github.go and its tests.

Steps:
1. Add a narrow, explicit signal to core.Observation meaning "the provider reported no check runs because the workflow was skipped for this diff". Do not infer it from an empty check list alone.
2. Populate it only when the PR changed files are all under docs/ or are Markdown files that the workflow ignores. Use the GitHub changed-files API already available in the adapter. Keep the filter in one place.
3. In ChecksRule.Evaluate, allow a merge when that signal is true and no check is reported as failure. Keep the existing behavior for code changes and for a provider that cannot report changed files.
4. Tests: docs-only PR with no checks merges; code PR with no checks still waits; a reported failure still blocks; GitLab or a provider without changed files still waits; the policy result names the criterion when it waits.
5. Keep funlen <= 80 lines, statements <= 40, complexity <= 20. Run gofmt -w, targeted go test ./internal/app ./internal/infra/policy ./internal/infra/scm and root go test . for arch. Open a PR, call beacon_watch_pr, do not self-merge.
