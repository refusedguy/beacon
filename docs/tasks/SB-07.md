Цель: Различать тесты, которые должны начать проходить, и тесты, которые должны остаться зелёными.

Контекст: Источник: `swebench/harness/grading.py:85-109`, `:179-285`, `swebench/harness/constants/__init__.py:22-40`. SWE-bench хранит два отдельных списка F2P и P2P и применяет разные правила. Пропущенный тест P2P не считается регрессией (`grading.py:93-98`), а пропущенный F2P не считается решением (`:101-109`). `XFAIL` приравнен к успеху (`:85-90`). Итог считается отдельно: `compute_fail_to_pass` и `compute_pass_to_pass` (`:288-306`). В beacon `domain.Check` хранит только `State`, `Conclusion`, `Required` и `DetailsURL` (`internal/domain/types.go:155-161`). Нормализованный `Check` адаптера GitHub добавляет `CheckState`, включая `SKIPPED` (`internal/infra/github/errors.go:304-315`), но сводит всё в одно поле `Rollup` и список имён `Failures` (`errors.go:324-331`). Роли теста относительно задачи в модели нет. Поиск `git grep -c 'FAIL_TO_PASS' -- internal` даёт 0 файлов.

baseline: `rg -c 'FAIL_TO_PASS|PASS_TO_PASS' swebench/harness/grading.py` даёт 13 строк; `git grep -c -i 'fail_to_pass' -- internal` даёт 0.

Шаги: Добавить в модель наблюдения роль теста и его статус, включая `SKIPPED` и `XFAIL`. Развести правила для ролей в чистой функции оценки. Сохранять оба списка в доказательстве, чтобы переоценка из SB-06 видела их. Оставить существующий однозначный вердикт для внешних проверок без ролей. Не менять коды выхода ожидания и правила fail-closed.

Проверка: Подать два набора доказательств с одним и тем же пропущенным тестом. В первом наборе он помечен F2P, во втором P2P. Сейчас оба дают одинаковый результат. Цель: F2P даёт Fail, P2P даёт Pass. Повторить для `XFAIL` и требовать Pass в обеих ролях. Отдельно проверить, что непомеченные проверки по-прежнему оцениваются по коду выхода.

Приёмка: Решение о проверке учитывает роль теста, а не только общий код выхода.
