# T4.4. G2 canary: владелец применяет конфиг сам

Статус: done
Фаза: P4
Тип: task
Владелец файлов: docs/gates/G2-canary.md
Зависимости: T4.3, T3.7, T3.8
Ссылка: ADR 0018
Агент: нет
Время: 2026-11-19T20:30:00Z

Цель: Провести canary на трёх агентах, при этом конфиг и плагин применяет владелец, а воркер только выдаёт сниппет текстом.

Контекст: ADR 0018 задаёт G2: владелец сам применяет конфиг и плагин, три агента живут по новому циклу. Выход это не менее 10 PR, включая не менее одного принудительного rebase, одного флейк-retry и одного `kill -9` Beacon посреди ожидания, и ноль двойных мержей. WORKER-PROMPT §2 запрещает до G2 любые изменения `~/.config/opencode`, чужих конфигов и shell rc-файлов, сниппет установки выдаётся владельцу текстом. WORKER-PROMPT §4.7 даёт сниппет для V2: `mcp.servers`, а не `mcp.name`, в формате `{"mcp":{"servers":{"beacon":{"type":"local","command":["beacon","mcp"]}}}}` плюс файл плагина. ADR 0019 разрешает множество rebase в одной цепочке, не ограничивая их число.

Шаги:
1. Передать владельцу текст сниппета V2 и путь к плагину из T3.1. Не редактировать пользовательские конфиги.
2. После применения владельцем запустить трёх агентов с шаблонами T3.7 и T3.8.
3. Спровоцировать один принудительный rebase, один флейк-retry в рамках бюджета из `.beacon/flaky.json` и один `kill -9` Beacon посреди ожидания.
4. Записать в `docs/gates/G2-canary.md` список PR, три искусственных случая, число двойных мержей и факт применения конфига владельцем.

Проверка: В отчёте не менее 10 PR, три искусственных случая отмечены, число двойных мержей ноль. Проверка каталога `~/.config/opencode` показывает, что изменения внёс владелец, а не воркер. После `kill -9` обязательства восстановлены.

Приёмка: G2 пройден по критериям ADR 0018: 10 PR, rebase, флейк-retry, kill -9, ноль двойных мержей. Конфиг применён владельцем. Воркер не менял чужие конфиги.

Гейт: G2. Точка явной остановки, следующий гейт открывает владелец.
