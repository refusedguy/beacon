Context: the sidebar panel currently gets `{active, recent}` from `beacon status` and `beacon status --recent`, two separate CLI calls every 5 seconds. There is no single-run lookup, no event history, no decision history, no timing data and no metrics. The operator says the panel is uninformative: no time, no durations, too much text, and Beacon itself has no metrics. Per-call lookups would lag, so all data must arrive in ONE batched call.

Goal: one batched API that returns everything the panel needs, plus persistence for the history it reads.

Steps:
1. Define a single snapshot contract returned by one call, for example `beacon snapshot` or an extended `BeaconStatusRpc.snapshot`. It must contain: active runs, recent runs, per-run timeline, per-run decisions, and aggregate metrics. No N+1 per-run requests.
2. Persist structured decisions from `internal/app/decisionlog.go` and run events into sqlite, with new tables in `internal/infra/sqlite/schema.go` and store methods in `internal/infra/sqlite/store.go`. Keep stderr logging. Add migrations that do not rewrite existing rows.
3. Add timing to every run in the response: `created_at`, `updated_at`, and derived durations for time in waiting_ci, running and blocked where the data allows. If exact per-state durations require new event timestamps, capture them in the new event table.
4. Aggregate metrics that are derivable now: dispatch count and skip reasons, rebase count, fix count, merge count, blocked reasons, and CI wait where timestamps exist. Return them as numbers, not prose.
5. Extend `BeaconStatusRpc` in `.opencode/plugins/beacon-project/ui.js` with the new output shape and register the handler in `index.js`. Keep the old fields so the current panel still renders.
6. Tests: assert one batched call returns all sections, decisions and events are queryable from sqlite, metrics are numeric, and adding more runs does not increase the number of CLI/RPC calls. Run `gofmt -w`, targeted `go test` for changed packages, and `node --test` for plugin tests.
7. Open a PR and call beacon_watch_pr with the real run ID and PR number.

Check: one call returns runs with timestamps, per-run history, and numeric metrics; no extra call is made per run.

Accept: do not change dispatch or reconcile decision logic. Keep production files under 350 lines. Do not edit AGENTS.md or another card.
