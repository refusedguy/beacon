Goal: make beacon_control reliable under parallel calls and able to cancel several runs in one call. No JS or docs edits.

Evidence:
- Two beacon_control cancel calls issued in parallel: one returned "ok", the other returned "Error: database is locked (5) (SQLITE_BUSY)". The operator is right that this is not normal.
- internal/infra/sqlite/schema.go:117 sets busy_timeout(5000), WAL and foreign_keys on the DSN, and line 122 sets SetMaxOpenConns(4). A 5-second busy timeout still fails under the MCP server's concurrent control calls plus the reconciler and watchers.
- internal/infra/mcp/tool_control.go:25 handles exactly one run per call and forwards to sv.Remote or sv.Control with no retry and no batching. There is no per-id result, so a partial batch failure is invisible.
- A previous attempt to reconcile two PRs in parallel also hit "database is locked (5) (SQLITE_BUSY)".

Steps:
1. Add an optional run_ids array to ControlArgs while keeping the existing run_id for compatibility. When run_ids is present, apply the action to every id and return a result with per-id status instead of a single "ok". Reject an empty list with core invalid input.
2. Make the local control path serialize writes to the SQLite store, or retry only on SQLITE_BUSY with a short bounded backoff. Do not add a global mutex around unrelated read traffic. Preserve existing approve, unblock, cancel and retry behavior and their state transitions.
3. If sv.Remote is set, send the batch through the loopback API in one request if the API supports it; otherwise send sequentially and collect per-id outcomes without aborting on the first failure.
4. Tests in internal/infra/mcp/tool_control_test.go and internal/app/control_test.go: parallel cancel calls all succeed; a batch cancel reports per-id results; a transient SQLITE_BUSY is retried and succeeds; a persistent busy error returns a clear per-id failure; single-id behavior is unchanged. Update store tests only if a schema change is needed.
5. Keep funlen <= 80 lines, statements <= 40, complexity <= 20. Run gofmt -w, targeted go test ./internal/infra/mcp ./internal/app ./internal/infra/sqlite and go test . for arch. Leave full lint to CI.
6. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Accept: internal/infra/mcp/tool_control.go, its test if needed, internal/app/control.go, internal/app/control_test.go, internal/infra/sqlite/schema.go and store tests if needed. No plugin JS, no docs, no task card edits.
