Context: the operator cannot close the Beacon run-detail panel. OpenCode v2.3.2's own close controls use `<text onMouseUp={...}>✕</text>` (packages/tui/src/feature-plugins/sidebar/footer.tsx, packages/tui/src/ui/dialog.tsx). The `session.panel` host (component/panel-host.tsx) renders no close button; it passes `close` in the slot input and exposes `ctx.ui.panel.close()`. The plugin currently has no visible close control, so clicking a run opens the panel and it stays indefinitely.

Goal: a visible, native-looking ✕ close button on the detail panel plus a way to suppress the immediate reopen from the row click.

Steps:
1. In `ui.js`, render a header box inside the detail node with a title text and a ✕ text using `onMouseUp` that calls `ctx.ui.panel.close()` (or `input.close()` from the session.panel slot input). Style it with `theme.text.muted`, `selectable: false`, `wrapMode: none`.
2. Add a one-shot suppress guard so the row click that opened the panel does not immediately reopen it after closing. Expose a command/slash entry (or reuse the existing ctrl+g) to reopen on demand.
3. Keep all other behavior: compact rows, MAX_ROWS pool, theme colors, 16MB buffer, configurable options, module split. Keep `ui.js` and its test files under 350 lines.
4. Add a test in `ui_test.js` (or `ui_setup_test.js`): call the `session.panel` render callback with `{name: PANEL_NAME, close}`, find the text node with content ✕, invoke its `onMouseUp`, assert close was called once; then invoke a row's `onMouseDown` twice and assert the reopen is suppressed once and then allowed.
5. Run `node --check` and `node --test .opencode/plugins/beacon-project/*_test.js`. Report pass count. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Check: the detail panel shows a clickable ✕ and closing it dismisses the panel without an immediate reopen.

Accept: use only verified @opentui/solid APIs (onMouseUp, no onClick). Do not touch Go code or AGENTS.md. Keep files under 350 lines.
