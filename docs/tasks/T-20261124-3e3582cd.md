Goal: make Beacon task mutations safe when a tool call is cancelled, interrupted, or retried. The operator does not trust the current behavior and is right to question it.

Observed fact: a beacon_task_create batch call was interrupted in the harness. The tool response never arrived, but four task cards were created, committed and pushed. The caller could not tell whether the operation happened and had to inspect docs/tasks directly. This is a transaction boundary problem, not a bug in any single card.

Current code facts:
- internal/app/taskcreate.go CreateBatch writes all cards, syncs SQLite, commits and pushes as one batch, and resolves @N dependencies inside that batch. Create writes an epic plus its children as one graph.
- internal/infra/mcp/server.go handles beacon_task_create, beacon_task_update and beacon_task_delete over MCP.
- The MCP call context is cancelled when the tool call is aborted. There is no operation id in the input and no journal of the last completed mutation.

Steps:
1. Decide and document the contract: an interrupted create, update or delete must end in one of two states, either no card changed or all cards changed and pushed. Mid-state must not be left for the next call to clean up.
2. Add an optional operation_id to beacon_task_create, beacon_task_update and beacon_task_delete. If the server sees an id it has already completed, return the stored result for that id instead of writing again. Keep the idempotency key bounded and safe under concurrent calls.
3. Check the context before the commit and before the push. If cancellation is observed after a commit but before a push, finish the push in a detached bounded context or record a recoverable pending operation that the next call can complete. Never report failure after a successful push, and never report success before the push.
4. Add a compact result with created, updated or deleted ids and a status such as applied, duplicate or recovered. Say in the PR body what happens on a cancelled call.
5. Tests with a fake workspace: cancel before commit leaves no files; cancel after commit still pushes; a repeated operation_id returns the same result without duplicate cards; a batch with one bad id writes nothing.
6. Keep funlen <= 80 lines, statements <= 40, complexity <= 20. Run gofmt -w, targeted go test ./internal/app ./internal/infra/mcp and root go test . for arch. Open a PR, call beacon_watch_pr, do not self-merge.

Accept: internal/app/taskcreate.go, internal/app/taskupdate.go, internal/app/taskdelete.go and their tests, internal/infra/mcp/server.go and its tests, and internal/infra/workspace/git_worktree.go only if a detached push context is needed. No plugin JS, no docs, no task card edits.
