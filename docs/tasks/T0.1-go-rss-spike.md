# T0.1. Go каркас и замер RSS на 15/30/60 горутинах

Статус: done
Фаза: P0
Тип: task
Владелец файлов: tmp/p0-rss/go.mod, tmp/p0-rss/main.go, tmp/p0-rss/README.md
Зависимости: нет
Ссылка: ADR 0001
Агент: T0.1
Время: 2026-11-19T17:34:52+05:00

Цель: Получить таблицу VmHWM для 15, 30 и 60 горутин с одним общим HTTP-клиентом и проверить, укладывается ли процесс в 100 MB.

Контекст: Пятнадцать процессов `gh pr checks --watch` держали 668,8 MB RSS плюс около 62 MB оболочек, измерено и записано в ADR 0001 и WORKER-PROMPT §0. Цель SLO это VmHWM из /proc/pid/status меньше 100 MB при 60 Watch, замеры 15/30/60 с датой и конфигурацией (WORKER-PROMPT §5). Оценка от 15 до 25 MB остаётся оценкой, пока этот спайк не измерит её. Приёмка T0.1 в WORKER-PROMPT §6 требует подтвердить или опровергнуть число 21.5 MB. go-sdk создаёт горутину на вызов, пула на пять воркеров у него нет (отчёт A §3 и §6), поэтому память при росте числа долгих вызовов меряют на горутинах. Спайк живёт только в tmp, продакшн-конфигурация не трогается (WORKER-PROMPT §2).

Шаги:
1. Создать модуль tmp/p0-rss с одним main.go. Поднять один http.Client с общим Transport на все горутины.
2. Запустить три режима: 15, 30 и 60 горутин. Каждая горутина держит тикер и раз в тик делает один HTTP-запрос через общий клиент на httptest-сервер в той же программе, без сети GitHub.
3. В каждом режиме читать VmHWM и VmRSS из /proc/self/status после выхода на установившийся режим. Записать дату, версию Go, GOARCH, число горутин и оба значения в tmp/p0-rss/README.md.
4. Повторить каждый режим три раза и записать все три прогона, а не только последний.

Проверка: `go run . -goroutines=15`, `-goroutines=30` и `-goroutines=60` из каталога tmp/p0-rss печатают по строке таблицы с VmHWM. Отдельно `pgrep -f 'gh pr checks --watch'` в момент спайка возвращает 0.

Приёмка: Таблица с датой и конфигурацией лежит в tmp/p0-rss/README.md. VmHWM при 60 горутинах меньше 100 MB. Оценка 21.5 MB подтверждена или опровергнута числом из таблицы. Ни один процесс gh --watch не запущен.

Гейт: G0. Закрывает спайк RSS. Выход G0 общий: три спайка T0.1, T0.2 и T0.3 отчитываются владельцу, стоп до его подтверждения. Один T0.1 гейт не закрывает.
