# CV-08. Конечный бюджет повторных обращений ghci

Premise: проверено 2026-11-22 по `origin/main` `e2f34a060579d452c1ca6ca7845560b78b8b7629`. Источник: OpenHands `src/utils/transient-error-retry.ts:24-25` ограничивает повтор числом попыток меньше трёх, а `src/api/with-retry.ts:36-45` прекращает попытки по достижении `maxRetries`. Ограничение входит в само правило retry, а не в конфигурацию вызывающего кода.

Разрыв: `internal/infra/ghci/provider.go:210` увеличивает `e.consecutiveErrors` без upper bound. `:214-219` удваивает задержку до `maxBackoff` и каждый раз пишет новый `nextAllowed`. Счётчик используется только для лога и для ответа `throttleError` на `:143`. После 60 с провайдер опрашивает GitHub раз в минуту бесконечно, даже когда PR недоступен. В `internal/infra/ladder/transitions.go` у доставки уведомлений есть предел попыток, но до ghci он не дошёл.

baseline: `rg -n 'maxRetries|maxErrors|retryLimit|retryBudget' internal/infra/ghci/provider.go` = 0. `rg -n 'consecutiveErrors' internal/infra/ghci/provider.go` = 5, строки 53, 179, 191, 210, 220; ни одна не сравнивает счётчик с порогом. `rg -n 'NextRetryAt|attempts' internal/infra/ladder/transitions.go` даёт непустой результат, но это другая подсистема.
