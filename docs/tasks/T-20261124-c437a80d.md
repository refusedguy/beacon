Goal: make merge notifications appear in the orchestrator session immediately instead of waiting for the next session activation. No JS or docs edits.

Measured evidence:
- Beacon posts the notify prompt within 0.04-0.30 seconds of the merge. The 30s reconciler poll is not the cause.
- OpenCode 2.3.2 source: packages/core/src/session/session.ts:182 calls execution.wake(sessionID) only when input.resume !== false. harnesses/opencode/opencode.go NotifyParent sends "resume": false with delivery "queue", so the message is admitted to session_inbox but never scheduled for promotion.
- OpenCode promotes queued inputs only at an idle boundary (packages/core/src/session/inbox.ts:52-57, nextPromotable:470-480, promote:567-589). Mid-turn scope "steer" rejects queued prompts (runner/llm.ts:75,100).
- Measured notify-to-visible delays: PR #2378 111.7s, #2379 28.6s, #2380 499.7s, #2381 138.3s. PR #2380 and #2381 were admitted 6 minutes apart and both became visible in one drain 3 ms apart at 14:20:22. PR #2382's notification sat in session_inbox unpromoted.

Steps:
1. In harnesses/opencode/opencode.go NotifyParent, change "resume": false to "resume": true, or omit the field. Keep delivery "queue" so an informational ping does not interrupt a mid-turn agent. Do not switch to "steer".
2. Add a test with a fake OpenCode server that records the /api/session/<id>/prompt body and asserts resume is true (or absent) and delivery stays "queue", text is still redacted, and an empty session ID still returns without a request.
3. Keep funlen <= 80 lines, statements <= 40, complexity <= 20. Run gofmt -w and targeted go test ./... inside harnesses/opencode plus go test . at the root for arch. Leave full lint to CI.
4. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Accept: only harnesses/opencode/opencode.go and harnesses/opencode/opencode_test.go. No plugin JS, no docs, no task card edits.
