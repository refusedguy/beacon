## Goal
Record a run claim in the store before creating a worktree, and report a full-capacity call as a skip.

## Evidence
From T-5115e3a5: two Dispatcher instances have separate slotsMu and reserved maps and can both select one ready card, create one worktree and save two runs. Worktrees have multiple writers with no cross-process coordination. From T-7c7f30f9: beacon_dispatch returns cap_full with no skip when all slots are busy.

## Steps
Use one store-backed run claim as the authority before workspace creation. Emit a cap_full skip with requested n and active count using the planner skip type with its next action. Keep one outcome per candidate. Add tests in the new internal/app/dispatcher_claim_test.go that two dispatchers sharing one store claim at most one run per task.

## Accept
A CLI dispatch cannot race a daemon dispatch into two runs for one task, and a full-capacity call returns a skip rather than a bare cap_full refusal.
