Статус: done
Фаза: P3
Тип: task
Владелец файлов: cmd/beacon/catalog.go, cmd/beacon/main.go, cmd/beacon/main_test.go
Зависимости: 
Ссылка:

Время: нет
Цель: Сделать таблицу name к runner источником для catalog, list, what и dispatch, убрав расхождение между 15 записями, 28 case и 16 именами в тесте.
Контекст: Источник: docs/research/go-metaprogramming.md, находка 5 и рекомендация 4. Риск: низкий, но сигнатуры раннеров разные и потребуют адаптеров. Выгода 15-30 строк меньше, чем кажется.
baseline: до правки в cmd/beacon/catalog.go было 20 записей плюс три init-append из main.go, human.go и up.go, то есть 23. Диспетчер в main.go содержал 33 case, из них 32 реальные команды, при этом up был в каталоге без своего case. В main_test.go было два жёстко заданных перечня имён на 23 и 16 записей. Числа в исходнике карточки (15, 28, 16) относились к более раннему снимку.
Шаги: Описать реестр с адаптерами под общую сигнатуру. Перевести catalog и dispatch. Обновить main_test, чтобы он читал тот же реестр.
Проверка: CI зелёный, список команд из catalog совпадает с dispatch.
Приёмка: Три перечня команд заменены одним, поведение list и what не изменилось.

## Подтверждение

PR #1165: https://github.com/refusedguy/beacon/pull/1165. Таблица name-to-runner `runnerFor` лежит в cmd/beacon/main.go, `dispatch` читает её вместо switch. Функция `commands()` в cmd/beacon/catalog.go отдаёт записи каталога вместе с раннером, её используют list, what и тесты. Два жёстко заданных перечня имён в main_test.go удалены, добавлены проверки полноты реестра. Для `up`, который был в каталоге без dispatch-ветки, раннер подключён. Вывод `beacon list`, `beacon what` и CLI сохранён. `gofmt` применён к трём Go-файлам, `go test`, `go build` и gates оставлены CI.
