Goal: show why a PR is stuck without changing any run state.
Evidence: beacon_reconcile forces a real tick that can merge, rebase or wake an agent. core.Decide returns only the first verdict and criterion, so the decision record cannot show the full chain. An operator cannot safely ask whether the blocker is approvals, labels, required checks or review. A read-only explain path needs a fresh Observation, stored approvals and the configured criteria, all of which already exist. CommandRule.Evaluate runs shell code, so the explain path must skip or mark side-effect rules.
Steps: add an Explain method on the policy that walks every invariant and criterion and records name, verdict, reason and whether the rule has side effects; do not use core.Decide for the trace because it stops at the first failure; add an app service that observes the PR, collects approvals and runs the trace; expose beacon explain <pr> in cmd/beacon/commands.go as text and JSON with no writes to runs, cards or provider; add tests for every verdict, for a side-effect rule and for a missing run.
Accept: the command prints the full criterion chain and the actionable reason, and a before and after query of state.db shows no change.
