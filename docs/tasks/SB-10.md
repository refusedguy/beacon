Цель: Отвергать доказательство, в котором код выхода и строки лога описывают разные прогоны.

Контекст: Источник: `swebench/harness/grading.py:162-175`. Патч может напечатать собственные строки `PASSED` из хука conftest. Грейдер сверяет код тестовой команды с картой статусов и возвращает отказ, если код ненулевой, а в карте нет ни одного `FAILED` или `ERROR` (`:167-175`). Комментарий в `:162-165` называет причину: лог не описывает тот прогон, который действительно было. В beacon доказательство лежит в `ExternalEvidence` (`internal/domain/verdict.go:703-712`) и содержит только имя, код, флаг наблюдения и булево `Passed` (`verdict.go:696-701`). Карты статусов и строк лога в доказательстве нет. Поиск `git grep -c 'status_map' -- internal` даёт 0 файлов. SB-02 решает вопрос источника числа, а здесь решается вопрос согласованности двух каналов.

baseline: `rg -c 'status_map' swebench/harness/grading.py` даёт 23 строки; `git grep -c 'status_map' -- internal` даёт 0.

Шаги: Добавить в доказательство карту статусов из разобранного лога и признак её наличия. Проверять согласованность в чистой функции после разбора и до выставления вердикта. Возвращать отказ с причиной `evidence_mismatch`, когда код ненулевой, а карта не содержит отказов. Не менять treatment пустой карты из SB-01 и не подменять код из SB-02.

Проверка: Подать лог с тремя строками `PASSED` и кодом выхода 1. Сейчас вердикт `PASS`. Цель: вердикт `FAIL` с причиной `evidence_mismatch`. Негативный контроль: лог с `FAILED` и кодом 1 остаётся `FAIL` по обычному правилу, лог с `PASSED` и кодом 0 остаётся `PASS`.

Приёмка: Доказательство не принимается, когда два его канала противоречат друг другу.
