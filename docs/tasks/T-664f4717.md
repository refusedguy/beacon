Goal: a workflow job rename refreshes Beacon's required checks without a config edit or daemon restart.
Evidence: configWatcher.reload hashes only .beacon/config.yaml, while resolveRequiredChecks in internal/infra/config/config.go runs only from loadConfig on a config change. With merge.required_checks_mode: workflow the running daemon keeps stale required check names after a job rename or removal, so it waits for a check GitHub no longer reports and merge stalls until the config is touched or the process restarts.
Steps: add the active CI workflow file to the watcher's hash set alongside .beacon/config.yaml; when only the workflow changed, re-run required-check resolution and swap the live state without restarting harness or policy services; keep the existing rule that invalid config leaves the previous state live; add a test with a temp repo fixture that renames a job and asserts the live required checks update, plus a test that manual mode stays unchanged.
Accept: after a ci.yml job rename the daemon reports the new required check name within one watch interval, with no manual config touch and no restart.
