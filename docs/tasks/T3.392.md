# T3.392. Проекция blocked-поля в Watch оркестратора
Статус: todo
Фаза: P3
Тип: task
Владелец файлов: cmd/beacon/orchestrate.go, cmd/beacon/orchestrate_test.go
Зависимости: T3.390, T3.391
Ссылка: docs/adrs/0158-blocked-and-dependencies.md
Агент: executor
Время: нет
Цель: Передавать причину блокировки из domain Watch в Watch оркестратора, чтобы Decide видел BLOCKED_FIX_AGENT в production-пути.
Контекст: Проекция в orchestrate.go заполняет ID, Repo, PR, HeadSHA, Verdict, Revision и Policy. Поле Blocked не заполняется, поэтому заблокированный Watch выглядит обычным Ready и может попасть в мерж.
Шаги: Скопировать w.Blocked в Watch.Blocked через BlockedInfo, включая reason, blockedBy и failedChecks. Не мутировать domain Watch и не делиться срезом failedChecks с источником. Добавить тест проекции для blocked и для Watch без Blocked.
Проверка: go test ./cmd/beacon/... в CI. Тест проекции проверяет копирование failedChecks и отсутствие Blocked у обычного Watch.
Приёмка: Заблокированный Watch приходит в оркестратор с причиной и failedChecks. Изменение исходного среза после проекции не меняет решение. Обычный Watch сохраняет nil Blocked.
