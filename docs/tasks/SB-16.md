# SB-16. Исправление неверного действия до терминального отказа

Статус: todo
Фаза: P2
Тип: task
Владелец файлов: docs/templates/executor-task.md, internal/infra/mcp/tool_wait_result.go
Зависимости: 
Ссылка: docs/research/comp-swebench.md, раздел 1, строка «Действия агента»; исходник sweagent/sweagent/agent/agents.py
Агент: нет
Время: нет
Цель: Дать агенту ограниченное число попыток исправить неверный формат действия, запрещённое действие и синтаксис команды.

Контекст: Источник: `sweagent/sweagent/agent/agents.py:789-821`, `:1062-1125`, `:1211-1218`. Ошибки формата, блоклиста и синтаксиса bash попадают в handle_error_with_retry и отправляют модель повторный запрос с отдельным шаблоном. Попытка записывается в траекторию, но не в историю сообщений (`:1067`, `:1092`). Лимит `max_requeries` равен трём (`:149-161`). После его исчерпания прогон заканчивается с `exit_format` (`:1211-1218`). В beacon `WaitStopReason` имеет пять значений и не различает неверный формат действия (`internal/infra/mcp/tool_wait_result.go:95-154`). Шаблон исполнителя предписывает terminate по вердикту и не описывает повтор после собственной ошибки агента (`docs/templates/executor-task.md:180-202`). Бюджет `FlakyConfig.MaxRetries` в `internal/domain/verdict.go:391-397` относится к красным проверкам CI, а не к действиям агента. Поиск `git grep -c 'requery' -- internal` даёт 0 файлов.

baseline: `rg -c 'requery' sweagent/sweagent/agent/agents.py` даёт 11 строк; `git grep -c 'requery' -- internal cmd` даёт 0.

Шаги: Описать три исправимые ошибки действия и отдельный шаблон ответа для каждой. Ограничить число попыток константой и зафиксировать терминальный исход после её исчерпания. Хранить исправленные попытки в траектории, не добавляя их в видимую историю. Не смешивать с бюджетом повтора красных проверок и с кодами `WaitStopReason`. Не менять правило пробуждения только на keep_working, rebase и retry.

Проверка: Подать три неверных действия подряд, затем корректное. Сейчас агент получает terminate или общий red без различения причины. Цель: три исправления, корректное действие выполняется, а четвёртое неверное действие даёт терминальный `exit_format`. Негативный контроль: ошибка API или среды не вызывает исправление, а заканчивает прогон сразу.

Приёмка: Ошибка формата действия не расходует слот оркестратора, если агент исправил её сам.
