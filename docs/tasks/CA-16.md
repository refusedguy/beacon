# CA-16. Номера строк линтера с фрагментом кода в ответе
Статус: todo
Фаза: P2
Тип: task
Владелец файлов: internal/infra/github/annotations.go, internal/infra/github/rest.go
Зависимости: 
Ссылка: docs/research/comp-aider.md
Агент: нет
Время: нет
Цель: Прикладывать к диагностике фрагмент исходного кода с отмеченными строками.
Контекст: Источник: docs/research/comp-aider.md, дополнение к CA-05. aider извлекает из вывода линтера пары `filename:line`, сдвигает номер на единицу (`aider/linter.py:70-80`, `:272-285`) и рисует `TreeContext` с margins 3 и маркерами строк интереса (`:234-256`), добавляя заголовок «Fix any errors below» (`:111-116`). В beacon GraphQL-запрос получает `path`, `startLine`, `title`, `message` (`internal/infra/github/annotations.go:21-39`), REST-путь ограничивает excerpt 8 аннотациями и 2 КБ (`internal/infra/github/rest.go:30-34`), но фрагмент кода не приложен. Baseline: агент видит номер строки без окружающего кода.
Шаги: Дополнить failure excerpt фрагментом файла вокруг `startLine` с падением 3 строки. Отмечать целевую строку. Уложиться в существующий лимит 2 КБ и сохранить redaction. Не расширять контракт `FailedCheck` обязательными полями.
Проверка: Взять 10 аннотаций с известными строками. Требовать, что для 10 из 10 excerpt содержит ±3 строки исходника и маркер целевой строки, а размер не превышает 2048 байт. Baseline 0 из 10.
Приёмка: Все 10 excerpt содержат отмеченную строку с контекстом и укладываются в 2 КБ.
