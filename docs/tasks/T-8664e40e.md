Goal: stop a worker from receiving the same no-PR instruction on every turn forever.
Evidence: idle.go:37-60 claims idle-nudge:<runID>, calls Harness.Wake, then releases the claim immediately. The key has no SHA or turn count, so the next session.idle claims it again. The handler skips Reconciler.wake guards, so CanWake, sameObservation and EvAgentFixed never run and FixAttempts never advances. The run stays running with no PR while the agent burns tokens repeating the instruction. Every other trigger in the daemon has a hash, state guard, delivery claim or backoff; this path has none.
Steps: key the idle nudge claim by run ID plus observed head SHA or turn count and keep it until the run changes state; apply the same CanWake and sameObservation checks as Reconciler.wake; advance a bounded attempt counter and block with an explicit reason after the limit; release the claim on EvPRRegistered, EvCancel, EvMerged and terminal state; add a test with two consecutive idle events that asserts one wake and then a block.
Accept: two consecutive idle events on an unchanged run produce at most one nudge and then a visible block, and no agent loop can continue without operator action.
