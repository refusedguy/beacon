# T0.2. Цена GraphQL батча с merge-полями

Тип: task
Владелец файлов: tmp/p0-graphql/go.mod, tmp/p0-graphql/main.go, tmp/p0-graphql/queries/*.graphql, tmp/p0-graphql/README.md
Зависимости: нет
Ссылка: ADR 0004
Агент: нет

Цель: Измерить rateLimit.cost батча алиасов на 15, 50, 60 и 100 PR и выбрать размер чанка с запасом.

Контекст: Один батч на 15 PR стоит 1 поинт, измерено и записано в WORKER-PROMPT §0. Tier-1 запрашивает поля state, isDraft, headRefOid, baseRefName, mergeable, mergeStateStatus, reviewDecision и commits(last:1){nodes{commit{statusCheckRollup{state}}}}, чанк не больше 100 алиасов (WORKER-PROMPT §4.6). Измеренные пороги: state-only на 100 алиасах даёт 1 поинт, на 150 даёт 2; с contexts(first:10) 60 алиасов дают 1 поинт, 80 дают 2. Для tier-2 берётся contexts(first:50) с запасом. Фрагменты строго внутри contexts.nodes, прямые фрагменты на StatusCheckRollup падают с cannotSpreadFragment, проверено (WORKER-PROMPT §4.6). Лимит 500 поинтов в час на токен, счёт по rateLimit.cost каждого ответа (ADR 0004 и ADR 0013). Токен read-only из BEACON_GITHUB_TOKEN, он не персистится и не попадает в логи (WORKER-PROMPT §2).

Шаги:
1. Собрать программу в tmp/p0-graphql с отдельным http.Client для GraphQL. Читать токен из BEACON_GITHUB_TOKEN и не печатать его.
2. Собрать tier-1 запрос с N алиасами на реальные PR тестового репозитория с полями из WORKER-PROMPT §4.6. Прогнать N равными 15, 50, 60 и 100. Для каждого ответа записать rateLimit.cost и x-ratelimit-remaining.
3. Собрать tier-2 запрос с contexts(first:50) и фрагментами `... on CheckRun` и `... on StatusContext` внутри contexts.nodes. Проверить, что isRequired(pullRequestNumber:N) возвращает булево значение для обоих типов контекстов. Сохранить тела запросов в queries/.
4. Отдельно послать запрос с прямым фрагментом на StatusCheckRollup и зафиксировать текст ошибки cannotSpreadFragment как негативный контроль.
5. Записать таблицу cost по каждому N и по каждому tier в README.md. Выбрать размер чанка с запасом до ближайшего скачка цены.

Проверка: `go test ./...` в tmp/p0-graphql проверяет, что все четыре запроса разбираются как валидный GraphQL и что ответ содержит поле rateLimit. Негативный тест с прямым фрагментом ожидает cannotSpreadFragment. Запуск с токеном печатает таблицу cost без значения самого токена.

Приёмка: Таблица rateLimit.cost для 15, 50, 60 и 100 алиасов и для tier-2 записана с датой. Выбранный чанк имеет запас до скачка цены. Форма фрагментов внутри contexts.nodes валидна, isRequired работает для CheckRun и StatusContext. Негативный контроль с cannotSpreadFragment зафиксирован. Токен не попал в логи и файлы.

Гейт: G0. Закрывает спайк цены GraphQL. Выход G0 общий: T0.1, T0.2 и T0.3 отчитываются владельцу, стоп до его подтверждения.
