baseline: dmux собирает кандидатов из трёх источников: осиротевшие worktree, локальные ветки, удалённые ветки после `fetch --prune` (`src/utils/resumeBranches.ts:281-349`, `:254-260`). Beacon восстанавливает только по сохранённому sessionID (`cmd/beacon/attach.go:15-32`, `:156-177`) и по связке задачи с worktree (`cmd/beacon/agents.go:1039-1043`).

Цель: Найти работу, оставленную в ветке, даже если sessionID потерян и локального worktree нет.

Контекст: `getResumableBranches` в dmux объединяет три набора, помечает кандидата `isRemote`, когда есть только удалённая ветка (`resumeBranches.ts:346`), и сортирует по времени изменения worktree, затем по имени (`:262-279`, `:348`). Beacon умеет вывести имя ветки из task ID (`agents.go:949-955`), но не перечисляет ветки как кандидатов. `beacon attach --resume` читает `attach-sessions.json` и при отсутствии записи просит указать sessionID вручную (`attach.go:225-239`).

Шаги: Добавить в `internal/app/session/branch_candidates.go` типы кандидата и граничную функцию, которая получает уже собранные списки локальных веток, удалённых веток и worktree. Функция не вызывает git и не создаёт каталоги. Покрыть тестами удалённой ветки без локального checkout, ветки с worktree и сортировки. Команды `fetch --prune` и чтение worktree передать владельцу границы через `beacon_defer_wiring`.

Проверка: Для набора с одной удалённой веткой функция возвращает одного кандидата с признаком `remote`. Для ветки, занятой worktree, кандидат сохраняет путь и признак изменений. Повторный вызов не создаёт worktree и не меняет входные списки.

Приёмка: Агент видит ветку с неслитыми изменениями без знания sessionID. Restore по сохранённой сессии из `attach` работает как прежде.

Реализация: `CollectBranchCandidates` в `internal/app/session/branch_candidates.go` принимает уже собранные списки локальных веток, удалённых веток и worktree. Функция не вызывает git и не создаёт каталоги. Ветка с worktree сохраняет путь и признак изменений. Ветка, которая есть только на удалённом сервере, получает признак `remote`. Сортировка идёт по времени изменения worktree по убыванию, затем по имени. Входные списки функция не меняет, поэтому повторный вызов даёт тот же результат. Тесты покрывают удалённую ветку без локального checkout, ветку с worktree, сортировку и неизменность входных списков.

Отложенная проводка: `fetch --prune`, перечисление веток и чтение worktree остаются за владельцем границы. Их нужно подключить через `beacon_defer_wiring`. Путь восстановления по сохранённой сессии в `cmd/beacon/attach.go` не меняется.
