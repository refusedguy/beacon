Goal: stop raw CLI help and error dumps from flashing in the sidebar under Active. No Go edits.

Evidence:
- .opencode/plugins/beacon-project/ui.js:249 sets the error signal to errorMessage(cause) from a failed CLI status poll.
- .opencode/plugins/beacon-project/ui_model.js:350 returns error.message verbatim.
- .opencode/plugins/beacon-project/ui_view.js:197 renders "[stale] " + truncate(error, REASON_WIDTH) as a sidebar item. When execFile fails, error.message contains the full Cobra stderr with usage and "--help" plus newlines, so the sidebar briefly shows a wall of text near Active. The next successful poll clears it.
- The operator sees this intermittently, then everything is fine.

Steps:
1. Add a single sanitizer in the plugin, for example cleanErrorMessage in ui_model.js. Strip ANSI escapes, replace all whitespace runs including newlines with one space, trim, take only the first line or first 120 characters, and replace CLI usage noise with a short label like "beacon status temporarily unavailable". Never render raw stack traces, help text or JSON payloads in the sidebar.
2. Use the sanitizer in ui.js before setError, and keep the "[stale]" prefix from ui_view.js. The stale line must be one short line and must not wrap into a block.
3. Suppress a one-off failure: keep the previous good snapshot visible and only show the stale line after two consecutive failures. Clear it on the first success. Do not fire transition toasts on snapshots taken while stale.
4. Avoid the cause where practical: in mcp.js beaconCommand, do not trigger a rebuild on every resolution; cache the rebuild result per root and binary mtime so concurrent snapshot polls cannot race with build-beacon.sh. Keep the existing PATH fallback.
5. Tests in ui_model_test.js, ui_view_test.js and ui_setup_test.js: a multi-line error with "--help" produces one short line with no "--help"; two consecutive failures show stale, one failure does not; a success clears stale; existing snapshot, toast and slot-rebuild tests keep passing; beaconCommand resolves once for repeated calls with unchanged mtimes.
6. Every JS file stays <= 350 lines. Run node --check on every plugin JS file and node --test .opencode/plugins/beacon-project/*_test.js.
7. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Accept: only .opencode/plugins/beacon-project/**. No Go changes, no task card edits.
