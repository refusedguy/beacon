# T3.388. Workload оркестратора и проектная изоляция
Статус: todo
Фаза: P3
Тип: task
Владелец файлов: internal/domain/orchestrator.go, internal/domain/orchestrator_test.go
Зависимости: T3.387
Ссылка: docs/adrs/0157-orchestrator-entity.md
Агент: executor
Время: нет
Цель: Научить оркестратор считать workload по подпискам и гарантировать изоляцию между проектами.
Контекст: Daemon показывает четыре состояния Watch: ready, retry, blocked, watching. Оркестратор хранит только watchID, поэтому состояние он получает через явный аргумент, не встраивая Watch в сущность.
Шаги: Добавить тип Workload с четырьмя счётчиками ready/retry/blocked/watching и метод Total(). Реализовать Orchestrator.Workload(watches map[string]Watch): для каждой подписки найти Watch по ID и посчитать вердикт; blocked учитывать и по статусу. Пропускать неразрешённые ID и вердикты вне четырёх корзин. Покрыть тестами подсчёт, реакцию на Unregister, отсутствие мутаций Watch и изоляцию двух оркестраторов с разными ProjectKey при одном sessionID.
Проверка: go test ./internal/domain/... в CI, включая тесты проектной изоляции и инъективности Key.
Приёмка: Workload считает ровно четыре корзины по подпискам; другой проект не видит чужих подписок, слотов и workload; Register не меняет переданную карту Watch.
