Goal: stop Beacon from waiting forever or merging early after workflow formatting changes.
Evidence: hasContinueOnError at internal/infra/shared/workflow.go:87-95 trims lines and matches any continue-on-error true regardless of indentation, so a tolerant step in verify silently removes the gate; hasMatrix at :100-119 only recognizes strategy: followed by matrix:, so a differently formatted matrix job becomes a required name that GitHub never emits; DetectWorkflowJobNames at :15-37 unions names from every .github/workflows/*.y*ml, so a reusable workflow contributes inner job names that appear only as caller-qualified checks; ApplyDefaults at config.go:262 uses max_in_flight 20 and max_active_agents 0 while defaults() at :349 uses 20 and 4 and .beacon/config.yaml uses 10 and 5; the manual fallback at config.yaml:28-32 keeps build, vet, test, lint even when workflow mode hides them.
Steps: make continue-on-error detection indentation-aware so only job-level flags mark a job advisory; make matrix detection tolerate alternate valid orderings; give reusable workflow files a subdirectory or an explicit skip so their inner jobs are not required; make all default sources agree and add a test; validate at config load that the manual fallback contains only names that can exist in the workflow.
Accept: adding a tolerant step to a required job does not remove it, and no required name is produced that GitHub never reports. Work in your own worktree off current main. Never push to main. Never run go test, go build, go vet, linters, node tests or benchmarks locally. Open a PR without the perf label so mark-ready sets ready-to-merge. Call beacon_watch_pr. CI supplies every check.
