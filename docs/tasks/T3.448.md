# T3.448. Шаблоны: три состояния executor и тонкий оркестратор
Premise: проверено 2026-11-21. ADR 0258 принят и задаёт ровно три состояния executor: «в работе» → «жду» → «закончил», при этом «закончил» означает отвязку от мониторинга и залитый PR. В шаблоне исполнителя этого описания не было: `grep -cE '«в работе»|«жду»|«закончил»|три состояния' docs/templates/executor-task.md` по HEAD давал 0. В шаблоне оркестратора правило уже присутствовало в пяти местах: запрет чинить main, пробуждение по blocked:not_mine, вызовы beacon task new и beacon spawn. Вторую половину premises я не дублировал, а добавил в оркестратор явную привязку трёх состояний к wake и роль Beacon как инструмента. Живой зонд не нужен: карточка просит текст, приёмка сводится к наличию трёх состояний, роли Beacon как инструмента и запрета оркестратору чинить main. Реализовано в OwnerFiles: в executor-task.md добавлен раздел «Три состояния исполнителя» с таблицей переходов и смыслом отвязки, в orchestrator-task.md добавлен абзац о трёх состояниях и роли Beacon как инструмента. Существующие маркеры шаблонов и текст отчёта `waiting, watchID` не тронуты, новый раздел маркеров не вводит. Кода на Go нет, gofmt не применялся. Дубля нет: коммитов и PR по T3.448 нет.
baseline: `git log --all --oneline --grep='T3\.448'` = 0 коммитов; `gh pr list --repo refusedguy/beacon --state all --search 'T3.448'` = []; strict grep трёх состояний в executor-task.md по HEAD = 0; `grep -cE 'не чинит main|blocked:not_mine|beacon task new|beacon spawn' docs/templates/orchestrator-task.md` по HEAD = 5; `wc -l` до правки: executor-task.md 171, orchestrator-task.md 151; `grep -m1 '^Статус:' docs/adrs/0258-*.md` = accepted; после правки `git diff --stat` показывает только два файла OwnerFiles и карточку.
