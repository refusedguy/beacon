Goal: make the three most misleading canonical rows measure the production path they claim to measure.
Evidence: http-snapshot-assembly times SnapshotService.Snapshot plus json.Marshal from pre-read rows, but GET /api/v1/runs calls runsCache.snapshot which calls status.Active, NewWireRuns and json.Marshal and never calls groupHistory; a groupHistory change can win a gain that the HTTP path never executes. card-parse warms all 60 bodies so timed passes hit fieldCache and clone fields while yaml.Unmarshal and the line scan named by the limiter never run. scm-observe uses an in-process transport with empty check runs, empty reviews, one file and behind_by zero, so JSON decode, pagination and parallel fetchSignals work vanish. Also fix limiter labels: snapshot says JSON reflection but the timed function issues reads only; snapshot-reads says WAL page reads but the profile shows SQLite VM, syscalls and event sort; snapshot-total is a derived sum, not a measured pass.
Steps: drive http-snapshot-assembly through runsCache.snapshot with a real StatusService and a realistic active-run set; feed fresh card bodies to each card-parse pass or expose the uncached parse function with a corpus containing frontmatter and plan blocks; run scm-observe against a loopback server with populated checks, reviews, paginated files and compare payloads including the errgroup fanout; keep work and errs equal and update registry limiter strings to match what is measured; do not change verdict rules or merge gates in this card.
Accept: an advisory row for these keys attributes a gain to the production function named by its limiter, and a regression in that function cannot hide behind cache hits or empty fixtures.
