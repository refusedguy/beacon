# FTE-16. Подключить планировщик cron к расписаниям

baseline: internal/infra/server/scheduler.go:241-245 прямо говорит, что планировщик cron живёт в internal/app и ещё не подключён, ADR 0314. Для KindCron firstRunAt возвращает ближайшую минуту вместо времени из выражения.
Цель: Расписание с cron-выражением срабатывает в фиксированное время в заданном поясе, а пропущенный интервал не дублируется.
Контекст: docs/evals/e09-cron-fixed-time.md:947 требует один запуск в фиксированное время. Строка 948 требует, чтобы пропущенный интервал не дублировался. Строка 949 требует намерения в outbox. Сейчас firstRunAt для cron возвращает now.Truncate(time.Minute).Add(time.Minute), поэтому выражение 0 9 * * * не запускается в девять утра. Фикстурный тест scheduler_test.go:175 проверяет только ненулевое NextRunAt.
Шаги: Добавить чистый разбор пятиполевого cron-выражения и расчёт следующего срабатывания с учётом Timezone. Подключить его к firstRunAt вместо ближайшей минуты. Передавать результат в daemonNextRun для пропущенных интервалов. Сохранить запись намерения в outbox. Покрыть тестами фиксированное время, пояс, пропущенный интервал и невалидное выражение.
Проверка: Расписание 0 9 * * * в UTC даёт NextRunAt на 09:00 следующего дня. После остановки и повторного старта задача запускается один раз. Пропущенный интервал не создаёт дубль. Невалидное выражение отклоняется при создании.
Приёмка: Eval e09 проходит, CI зелёный.
