Goal: Dispatch and the snapshot read overlap instead of running as two process lifetimes in a row.

Evidence: dispatch-01 and dispatch-06. refresh sits in the finally block after the dispatch await, so the panel waits for beacon dispatch then beacon status --snapshot. A watcher event can add a third read through the inFlight guard.

Steps: Kick off the refresh alongside dispatch, accept one follow-up read from the watcher, and coalesce the two so only one final snapshot wins.

Check: The rendered run appears after one snapshot read, not two sequential ones.

Accept: Never show a run that dispatch did not create.
