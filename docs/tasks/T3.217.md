# T3.217. Адаптер Pi RPC
Статус: done
Premise: проверено 2026-11-21 на HEAD c9a0e3f (origin/main). В OwnerFiles не было провайдера Pi RPC: `internal/infra/wake/registry.go` держал AdapterPi на `unsupportedDeliverer`, `cmd/beacon/deliver.go` не выбирал адаптер по конфигу. Старый вывод про живой зонд не повторяем: здесь нужен адаптер с тестовым провайдером, а живой probe относится к T3.227. Добавлены интерфейс `PiProbe` и реализация `PiRPCProbe` поверх внедрённого `PiRPCConnection`, выбор адаптера по трём ключам конфига с фолбэком на текущий unsupported путь и тесты на моковом провайдере. Живой Pi-процесс не запускался: в среде его нет, слабый ПК разрешает только gofmt. Тесты прогоняет CI на PR.
baseline: на c9a0e3f `git grep -c -E 'PiProbe|PiRPC' HEAD -- internal/infra/wake/registry.go cmd/beacon/deliver.go` дал 0, моковых тестов Pi в `cmd/beacon/deliver_test.go` было 0, в `evals/main.go` была 1 проверка `21_w05_pi_honest_unsupported`. После правки: 1 интерфейс `PiProbe`, 1 реализация на внедрённом transport, 3 ключа конфига, 7 новых тестов.

Шаги: Проверить команды prompt, steer, followUp, abort, get_state, waitForIdle. Выяснить, пишет ли steer в спящую сессию или требует активного rpc-процесса.

Приёмка: steer и followUp различаются в отчёте, delivery по умолчанию queue через followUp.

## Подтверждение
- PR #394 DROPPED: Адаптер Pi RPC: в main только скелет в wake/deliver.go, живого wake через Pi нет ('НЕ ПРОВЕРЕНО', спайк W05); eval 21_w05 проверяет лишь честный unsupported, OwnerFiles заглушка deliver.go.
- Возврат в todo (пересмотр после Waves 6-8; низкий приоритет): в реестре wake есть AdapterPi, но живого wake через Pi нет, eval w05-pi-rpc-wake остаётся непроверенным спайком. Реестр адаптеров и контракт 7 инструментов допускают такую доставку; нужен живой probe с реальными OwnerFiles, иначе карточка останется незакрытым спайком.
- Адаптер с тестовым провайдером: `PiProbe` и `PiRPCProbe` живут в `internal/infra/wake/registry.go` и работают через внедрённый `PiRPCConnection`, без создания процесса. `cmd/beacon/deliver.go` выбирает Pi по `BEACON_DELIVER_ADAPTER=pi`, режим по `BEACON_DELIVER_PI_MODE`, таймаут по `BEACON_DELIVER_PI_TIMEOUT`; любая неверная конфигурация или отсутствие провайдера оставляет текущий unsupported путь. Тесты в `cmd/beacon/deliver_test.go` покрывают успешный RPC, ошибку, таймаут с тремя попытками и фолбэк. Проверка описана в `docs/evals/w05-pi-rpc-wake.md`. Живой probe остаётся в T3.227.
