Goal: make dispatch_open a single brake for manual and automatic dispatch, and give a queued card a slot when its path owner finishes.

Evidence: Dispatcher.Dispatch has two callers, cmd/beacon/commands.go and internal/infra/mcp/tool_dispatch.go, so a predicate placed only on the automatic path can be bypassed. A run claims every path in its card until it reaches a terminal state, which lets a one-file ci.yml card be skipped dozens of times by different holders. The dispatcher is the shared point for the brake and for waiter promotion.

Steps:
1. Apply the dispatch_open predicate at the top of Dispatcher.planDispatch and Dispatcher.planPromotion so manual dispatch cannot bypass the brake. Read the flag from the config section added by T-b1000001.
2. At the start of the next dispatch cycle, call the waitlist store method added by T-b1000003 to take the longest waiter for a released path and include that card in the cycle. Terminal runs drop out of the active run index, so their path claims release without a separate write.
3. Keep the active-run guard and the batch conflict check unchanged.
4. Add tests in internal/app/dispatch_gate_test.go for dispatch_open false starting nothing on both the manual and automatic paths, and for a queued card winning a slot after its holder closes.

Accept: dispatch_open false freezes intake while active runs keep reconciling, and a card queued for a busy path runs in the next cycle after that path is released.
