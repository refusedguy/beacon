# T3.378. workflow_run как дополнительный триггер
Premise: проверено 2026-11-21, дубль. Обработчик workflow_run уже влит в origin/main через PR #424 (commit 30dfa35) в файлах internal/infra/webhook/workflow_run.go и workflow_run_test.go. Он фильтрует действия requested, in_progress и completed, извлекает head_sha и pull_requests, отправляет в порт hint только с идентификаторами и action. Поле conclusion из тела не разбирается, поэтому failure не превращается в retry. Доставки с run_attempt больше единицы игнорируются. Десять тестов закрывают подпись HMAC, лимит тела, повторную доставку, fork без PR, все три действия и отказ от вердикта. matchWatch и намерение refresh уже в main через MapEvent и RefreshIntent.RecordRefresh в internal/infra/webhook/match.go (PR #483). T3.377 помечена done с этим же обоснованием, включая поле NoChecksSince и цикл перечитывания cibridge. Доставка события ускоряет перечитывание через hint, но вердикт по-прежнему публикуется после чтения состояния Watch. Новый код в OwnerFiles повторил бы существующий обработчик, поэтому его не писал.
baseline: `git ls-tree -r --name-only origin/main internal/infra/webhook/ | grep workflow_run` = 2 файла; `git log --oneline origin/main -- internal/infra/webhook/workflow_run.go` = 1 коммит (30dfa35, PR #424); `git log --all --grep=T3.378 | wc -l` = 0; `grep -ci conclusion internal/infra/webhook/workflow_run.go` = 1 (комментарий, поле не разбирается); `grep -c 'RunAttempt > 1' internal/infra/webhook/workflow_run.go` = 1; `grep -c '^func Test' internal/infra/webhook/workflow_run_test.go` = 10; `git grep 'func matchWatch' origin/main` = match.go:88; `git grep 'func MapEvent' origin/main` = match.go:101; `git grep 'NoChecksSince[[:space:]]*=' origin/main -- '*.go' | wc -l` = 0.

Цель: Использовать события GitHub Actions как подсказку о смене состояния проверок.
Контекст: У workflow_run три действия: requested, in_progress и completed. completed срабатывает независимо от успеха. WorkflowRun в go-github v93 содержит HeadSHA, Status, Conclusion, PullRequests, CheckSuiteID и RunAttempt.
Шаги: Добавить обработчик workflow_run с фильтром действия. Для completed и in_progress извлечь head_sha и pull_requests, вызвать тот же matchWatch и пометить Watch к перечитыванию. Для requested обновить NoChecksSince. Не брать conclusion из payload как вердикт.
Проверка: completed с conclusion failure не публикует retry; in_progress не меняет revision; run_attempt больше единицы не создаёт второй refresh.
Приёмка: Событие workflow_run ускоряет перечитывание, но не подменяет чтение состояния.

## Подтверждение
- Premise проверен 2026-11-21 по origin/main (bc45f86). Обработчик workflow_run влит в PR #424, matchWatch и refresh в PR #483, T3.377 уже помечена done как дубль. OwnerFiles не менял, дубль не создал.
