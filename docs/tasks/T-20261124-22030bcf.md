Context: `DirectoryNotFoundError` keeps recurring. PR #2343 added `RefreshWorktrees()` (POST /api/worktree/refresh) but it never fired for the observed removals: the worktree was deleted with a pre-fix binary, and the daemon needs an explicit rebuild/restart to pick up Go changes. Structural gaps remain: in `internal/infra/workspace/git_worktree.go`, `g.refresh(ctx)` runs only after a successful `git worktree remove` in `Remove` (line 250) and `ForceRemove` (260), so it is skipped when remove fails; the stale-path cleanup in `Create` (lines ~109, 123) never refreshes; refresh is never called at daemon startup; and `harnesses/opencode/opencode.go:351-377` silently no-ops when no project matches or the POST fails. Log evidence: zero `worktree/refresh` POSTs in opencode.log.

Goal: no stale OpenCode worktree registrations regardless of when/why a worktree disappears.

Steps:
1. In `git_worktree.go`, move `g.refresh(ctx)` into a deferred call in both `Remove` and `ForceRemove` so it fires on every exit path, including a failed `git worktree remove`. Add it to both stale-path cleanup branches in `Create`.
2. Call `RefreshWorktrees` once at daemon startup from `wireInfra` in `cmd/beacon/main.go` so already-stale rows are cleaned after a restart.
3. In `harnesses/opencode/opencode.go` `RefreshWorktrees`, log a warning when no project matches and when the refresh POST fails; call `POST /api/location/reload` after a successful refresh so the live OpenCode drops stale locations immediately.
4. Tests in `git_worktree_test.go`: delete `.git/worktrees/<name>` before `Remove` so `git worktree remove` fails; assert one refresh POST still fires. Assert Create's stale cleanup also refreshes. Assert startup call is wired.
5. Run `gofmt -w`, targeted `go test ./internal/infra/workspace ./harnesses/opencode ./cmd/beacon`.
6. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Check: after any worktree removal or daemon restart, `/api/location/reload` succeeds and no `DirectoryNotFoundError` appears.

Accept: no task card logic changes. Keep files under 350 lines. Do not edit AGENTS.md or another card.
