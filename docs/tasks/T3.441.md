# T3.441. Разделить метрики wake по инициатору
Premise: проверено 2026-11-21 по origin/main (e136a55), дубля нет, но приёмку не закрыть внутри OwnerFiles. Зависимость T3.417 в main имеет статус done: PR #808 (коммит 3d68c47) добавил FieldSource и WakeDeliveredSource в observe.go и вызов с source=daemon в deliver.go. Коммит прямо оговорил, что метки счётчика не менялись: source пишется только в поле события wake_delivered, а метка wake_delivered_total остаётся adapter. Карточка T3.441 просит именно label source в счётчиках wake, то есть вторую метку, а не поле лога. Метрика устроена с одной меткой: Metrics.Inc(name, labelValue string) принимает одно значение, имя метки зафиксировано в counterLabels в metrics.go:19-26 как CounterWakeDelivered: LabelAdapter, и metrics.go не входит в OwnerFiles карточки. Фиксированный тест coverage_test.go:23,41 требует ровно LabelAdapter и закрытый список имён счётчиков, а observe_test.go:63-64, metrics_test.go:20, snapshot_test.go:14 и cmd/beacon/observe_test.go:121 проверяют метку adapter и экспорт beacon_wake_delivered_total{adapter=...}. Все эти файлы вне OwnerFiles (observe.go, deliver.go). Вторую метку нельзя добавить, не затронув чужие файлы: придётся либо менять API Inc и counterLabels в metrics.go, либо переопределить метку adapter и сломать перечисленные тесты. Живой зонд не нужен, это вопрос устройства метрик, не рантайм-проверка.
