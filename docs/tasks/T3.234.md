# T3.234. Отдельный MCP entry для blocking wait
Premise: проверено 2026-11-21, требование уже в main. Блокирующее ожидание реализовано в internal/infra/mcp/tool_wait_result.go коммитом 0a5b13a, PR #234, карточка T3.134 в статусе done. Сервер регистрирует его напрямую, без отдельного входа. В server.go:512 вызов AttachWaitResult ставит реальный обработчик в единственный MCP-сервер beacon, а server.go:106-115 задаёт ровно восемь имён из ADR 0094. Проверка карточки закрыта документацией в main: README.md:89 и AGENTS.md:95 говорят, что в Code Mode инструменты доступны прямо как tools.beacon.<name>, включая beacon_wait_result. Модель видит прямое имя и не нуждается в опросе wait через скрипт. Два имени сервера это презентация на стороне клиента Code Mode, а не вторая регистрация в Go. В opencode.json репозитория объявлен один сервер beacon, имя t3-code-direct там отсутствует. Регистрация t3_thread_wait и delegate_task в OwnerFiles добавила бы имена сверх восьми, а девятое имя ADR 0094 запрещает без отдельного решения. Инструмента delegate_task в этом репозитории нет. Pending-work detection в main тоже отсутствует, ломать нечего. Шаг про presentation двух имён относится к конфигурации OpenCode вне OwnerFiles, поэтому код не писал, gofmt не применял, правка только текстовая. Статус изменён с todo на done.

Шаги: Выделить wait и delegate в отдельный registration, описать presentation инструментов с двумя именами сервера.

Приёмка: Оба имени разрешаются в one tool, pending-work detection не ломается.
