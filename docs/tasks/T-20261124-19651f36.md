Goal: let Beacon run tasks through a second harness, using ACP as the first concrete example, without OpenCode-specific code in pkg/core or internal/app.

This epic owns one deliverable: docs/decisions/0002-second-harness.md. Write the design record there. Do not change code in this card.

Context from four read-only investigations on main b9f287e0:
- pkg/core/ports.go defines AgentHarness with Spawn, Wake, Stop, IsAlive, NotifyParent and Events, plus the optional WorktreeRefresher. SpawnRequest already carries ParentSessionID and ModelRef.
- internal/app imports only pkg/core. No OpenCode type or /api/ path appears there. arch_test.go checks import direction but not concrete wiring in cmd.
- Concrete coupling lives in cmd/beacon: main.go:144 asserts h.(*opencode.Harness) to set Repo; main.go:248-249 builds opencode.New and assigns ModelRef; resolveModel at main.go:261-307 calls GET /api/session/<parent>, parses OpenCode JSON and hardcodes providerID opencode; doctor.go:291 imports opencode.ApplyAuth. idleWatcher in serve.go is a local interface only OpenCode implements.
- internal/infra/harness has a CLI harness that implements AgentHarness but ignores ParentSessionID and ModelRef and leaves Stop, IsAlive and NotifyParent as no-ops.
- The MCP tool catalog is harness neutral. The generated opencode.json permissions are host specific.

The plan attached to this epic creates five child cards in dependency order. Record those five cards and their dependency chain in the decision file. Do not edit child cards from this epic.

Accept: only docs/decisions/0002-second-harness.md and README.md. No code, no task card edits.
