Goal: restore merge progress after #2868 made conditional workflow jobs block every PR when GitHub reports them skipped or does not report them at all.
Evidence: after the 19:06 UTC restart with #2868 live, forced ticks show PR 2845 verdict wait with reason required checks not passed: mark-ready (skipped), perf-nightly (skipped), plugin-tui-smoke (skipped), vet (pending). PR 2842 shows the same three skipped jobs. PR 2861 shows all nine detected names as missing. checksource.Workflow derives names from every workflow job without a matrix or job-level continue-on-error, which includes mark-ready, perf-nightly and plugin-tui-smoke. Their `if` gates are false on ordinary PRs, so GitHub marks them skipped or omits them. configurable.go now accepts skipped only when the provider set WorkflowSkipped, and WorkflowSkipped is set only when Observe received zero checks at all, so the waiver never fires for a PR with real checks. The result is a permanent wait with no failing check.
Steps: make required-check detection describe the checks GitHub actually reports for the PR, or accept skipped and missing as pass when the workflow declares an `if` gate that did not apply, while still blocking a failed required check; keep the cancelled check blocking from T-78b0be80; keep a check that is genuinely expected and absent blocking, so do not blanket-allow missing; add tests for a PR with skipped conditional jobs, a PR with an omitted conditional job and a PR with a failed required job.
Accept: an ordinary PR with green real checks and skipped conditional jobs reaches merge instead of waiting forever, and a failed required check still blocks.
