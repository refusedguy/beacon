Goal: keep a card that loses a scope claim in a persisted waitlist so it can run after the path owner finishes.

Evidence: 2446 active_scope_overlap skips and 241 selected_scope_overlap skips out of 3982 decisions. planner.go:110-138 drops conflicts for one cycle and logs them, so nothing carries them forward. readyTasksQuery sorts by priority then ID, so the same cards lose every cycle. A one-file ci.yml card can be skipped dozens of times by different holders.

Steps:
1. Add a waitlist table in internal/infra/sqlite/schema.go keyed by scope path and card ID, with a waiting_since timestamp.
2. Add store methods in internal/infra/sqlite/store.go to insert or refresh a wait entry when a candidate loses on a write claim, to read the longest waiter for a set of paths, and to remove an entry once the card runs. Use waiting_since for aging so equal-priority cards keep their order.
3. Add tests in internal/infra/sqlite/waitlist_test.go for duplicate entries refreshing the same row, longest-waiter selection across paths, and removal after a card runs.

Accept: a wait entry survives a daemon restart, and the store can name the longest waiter for any claimed path without scanning task bodies.
