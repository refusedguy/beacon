# UI-15. Действие ack обязательства
Статус: dropped
Фаза: P1
Тип: task
Владелец файлов: internal/ui/actions/ack.go
Зависимости: UI-03, UI-08
Ссылка: ADR 0072 (proposed)
Агент: нет
Время: нет
Цель: Подтвердить obligation с явным решением.
Контекст: Протокол различает approve, reject и пустой ack, который сохраняет plain contract.
Шаги: Диалог с тремя вариантами. Отправить watchID, obligationID, decision и revision.
Проверка: Тест проверяет, что повторный ack с устаревшим revision отклоняется.
Приёмка: ack не меняет delivered и не закрывает Watch.

## Подтверждение
- PR #394 DROPPED: ack уже инструмент beacon_ack с decision approve/reject и revision; UI-диалог дублирует контракт семи инструментов. Отдельный бинарник beacon-ui и пакет internal/ui в main отсутствуют; принятый ADR 0060 прямо отклоняет собственный TUI и веб-интерфейс ("Свой TUI или веб-интерфейс не создаётся"), ядро MCP-only (ADR 0086) с контрактом ровно семи инструментов (ADR 0094). Ссылка карточки на "ADR 0072 (proposed)" неверна: ADR 0072 принят и описывает авто-мерж, а ADR 0092-tui только proposed и противоречит ADR 0060.
