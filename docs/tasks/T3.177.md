# T3.177. Регистрация MCP-сервера Beacon через ctx.mcp.transform
Статус: todo
Фаза: P3
Тип: task
Владелец файлов: .opencode/plugins/beacon-project/mcp.js, tests/adapter/beacon-project-mcp.test.js, cmd/beacon/doctor.go, cmd/beacon/state_dir_test.go
Зависимости: T3.176
Ссылка: ADR 0069
Агент: нет
Время: нет
Цель: Каждый экземпляр плагина поднимает MCP-сервер Beacon с корнем проекта из ctx.location.project.canonical
Контекст: ADR 0069, решения 3 и 5. Документация OpenCode V2 разрешает менять MCP только через ctx.mcp.transform с editor.set, editor.update и editor.remove, выставлять disabled false и вызывать ctx.mcp.reload после изменения входных данных. Сейчас сервер прописан в конфиге с фиксированным cwd, а Go сама выводит проект из os.Getwd и .git.
Шаги: Зарегистрировать сервер Beacon в ctx.mcp.transform, взяв корень из модуля location из T3.176; передать корень как рабочий каталог сервера, а если форма конфигурации не имеет поля cwd, передать его явным аргументом или переменной окружения; убрать фиксированный cwd Beacon из конфигурационных файлов репозитория; выставить disabled false и добавить вызов ctx.mcp.reload при смене входных данных; в stateDir() принимать корень явно и оставить BEACON_STATE_DIR и legacy-путь вне проекта; написать тесты на выбранный корень и на приоритет явного корня перед os.Getwd
Проверка: node --test tests/adapter/beacon-project-mcp.test.js и go test ./cmd/beacon
Приёмка: Из worktree сервер работает с каноническим корнем проекта, конфиг не содержит жёстко заданного cwd, явный корень в stateDir имеет приоритет перед вычисленным из каталога
