# T3.238. Единый контракт wake-бэкендов: webhook, schedule, channel, child, relay
Premise: проверено 2026-11-21, требование уже в main, дубль не создан. Единый контракт wake зафиксирован в принятом ADR 0085 (docs/adrs/0085-wakeport-wake.md): state(target) возвращает idle, settled или busy, wake(req) возвращает started, queued, delivered, duplicate, closed или unsupported, wait(target, cursor). Это в точности набор результатов из шагов карточки. Приёмка «ядро видит adapter и target как непрозрачные строки» закрыта принятым ADR 0088 (docs/adrs/0088-wakeadapter.md) и кодом internal/infra/mcp/tool_wake.go: порт WakeSender получает непрозрачную строку target, а в ядре нет имён агентов (ADR 0006 и ADR 0024). Проверка «повтор webhook не создаёт run» закрыта принятым ADR 0183 и internal/infra/store/webhook_events.go: RecordDeliveryResult различает Created, Duplicate и Conflict, входящий event_id дедуплицируется, HMAC-SHA256 проверяется на сыром теле constant-time. Подписанные задачи расписания закрыты HMAC-SHA256 в internal/domain/identity.go. Расписания интервала, времени и webhook лежат в internal/app/scheduler/schedule.go и binding.go, push-каналы в internal/infra/wake/notify.go, deliver.go и telegram.go. Проверка «более широкий режим target не повышает права» закрыта выбором бэкенда по конфигурации цели и разделением прав на wake, чтение статуса и управление воркерами из ADR 0085. OwnerFiles не менял, код не писал, правка только текстовая. Статус изменён с todo на done.
