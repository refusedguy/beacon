# T3.381. Оркестратор: запуск FIX-агента по blocked wake
Статус: todo
Фаза: P3
Тип: task
Владелец файлов: internal/app/orchestrator/orchestrator.go, internal/app/orchestrator/orchestrator_test.go, docs/templates/orchestrator-task.md
Зависимости: T3.379, T3.380
Ссылка: ADR 0155
Агент: нет
Время: нет
Цель: По вердикту blocked читать get_result и запускать FIX-агента с причиной и failedChecks.
Контекст: Оркестратор получает wake от ack с verdict=blocked. При retry исполнитель чинит свой PR, а FIX-агент чинит main, флейк или чужой тест. Идемпотентность по (watchID, revision) уже используется для мержа.
Шаги: Добавить VerdictBlocked и ветку в Run рядом с needsWake. Расширить Waker деталями reason и failedChecks. Перед спавном прочитать get_result и сверить revision. Записать спавн в ledger по (watchID, revision). Не мержить blocked и не трогать retry.
Проверка: Повторный wake с той же парой не создаёт второй спавн. При verdict retry FIX-агент не вызывается. После смены revision спавн возможен заново.
Приёмка: Wake содержит watchID, obligationID, revision, reason и failedChecks с name, conclusion и detailsUrl. Мерж blocked Watch закрыт.

Тип: task

Агент: нет
Время: нет
Цель: Поднять TracerProvider, MeterProvider и LoggerProvider с корректным Shutdown и включаемым OTLP-экспортом.
Контекст: otlptracegrpc.New или otlptracehttp.New, otlpmetricgrpc с PeriodicReader, otelslog.NewHandler. Resource собирается через resource.Merge с semconv.ServiceName. OTEL_EXPORTER_OTLP_PROTOCOL принимает grpc, http/protobuf и http/json.
Шаги: Включить экспорт по OTEL_EXPORTER_OTLP_ENDPOINT. Добавить разбор OTEL_RESOURCE_ATTRIBUTES, пропагатор TraceContext+Baggage, WithBatcher для трейсов и PeriodicReader для метрик. Shutdown всех провайдеров при выходе.

Приёмка: Локальный запуск не требует коллектора, а конфигурация читается только из стандартных env OTel.
