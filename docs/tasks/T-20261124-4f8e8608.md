Context: after PR #2340 the TUI panel loads, but shows `[stale] stdout maxBuffer le...` with Active 0 and Recent 0. Diagnosis: `.opencode/plugins/beacon-project/ui.js` uses `nodeExecFile` in `CliStatusSource.#exec` (lines 156-162) with no `maxBuffer`, so Node's 1 MiB default applies. The snapshot command at line 165 is `beacon status --snapshot`, which measured 2,699,347 bytes, about 2.7 MiB, while `status` is 3,090 and `status --recent` is 19,573. The call throws `RangeError: stdout maxBuffer exceeded`, `refresh()` catches it and calls `setError`, so the panel keeps the empty snapshot. sqlite has 3 active and 60 recent runs, so the data exists.

Goal: panel shows live runs and no `[stale]` line.

3. Run `node --check` and `node --test` on plugin tests. Report pass count.
4. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.
