baseline: dmux передаёт скрипту 10 именованных переменных `DMUX_*` (`src/utils/hooks.ts:35-56`, `:97-134`) и добавляет целевую ветку при мерже (`src/actions/merge/mergeExecution.ts:225-227`). В `origin/main` полезная нагрузка содержит три поля: `event`, `card_id`, `time` (`internal/app/taskcli/service.go:82-88`, `:131`).

Цель: Передать скрипту идентификаторы карточки, Watch, PR, ветки, worktree и целевой ветки в одном стабильном контракте.

Контекст: dmux собирает окружение из корня проекта, порта сервера, pane, slug, промпта, агента, пути worktree, имени ветки и дополнительных данных вызывающей стороны (`hooks.ts:97-134`). Дополнительные данные не меняют тип окружения: `DMUX_TARGET_BRANCH` добавляется только на мержах (`mergeExecution.ts:225-227`). Beacon пишет в stdin JSON с тремя полями (`service.go:82-88`) и не собирает окружение в `hookrun.Run` (`hookrun.go:9-15`). Скрипт не может отличить карточку от Watch и не знает, в какую ветку вливается PR.

Шаги: Описать в `internal/app/taskcli/hook_envelope.go` структуру контекста события с обязательными и необязательными полями, чистую функцию сборки переменных окружения и функцию проверки полноты. Запретить запись секретов из родительского окружения в контракт. Покрыть тестами событие мержа с целевой веткой и событие закрытия без неё. Подключение к `RunHooks` передать владельцу файла через `beacon_defer_wiring`.

Проверка: Тест проверяет, что скрипт получает `BEACON_CARD_ID`, `BEACON_WATCH_ID`, `BEACON_PR_NUMBER`, `BEACON_BRANCH`, `BEACON_WORKTREE_PATH` и `BEACON_TARGET_BRANCH`. Для закрытия карточки `BEACON_TARGET_BRANCH` отсутствует, а обязательные поля заполнены. Число обязательных полей фиксировано тестом.

Приёмка: Скрипт проект может принять решение по ветке и PR без обращения к API beacon. Три поля текущего контракта сохраняются для совместимости с #1551.
