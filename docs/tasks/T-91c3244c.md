Goal: a run bound to a PR must follow the PR head instead of looping forever on an observed SHA whose rebase fails, and merge.max_auto_rebases must take effect without a daemon restart.
Evidence: PR 2845 sat in waiting_ci for more than 100 minutes with head_sha and observed_sha c61447c while the PR head was 9cf67fb. The reconciler kept ticking but logged no new decision. Audit at HEAD 08f3ea57 shows the exact chain: handleNeedsRebase returns at internal/app/reconcile_observation.go:119 when obs.HasPending and at :122 when sameObservation, both before NoteObservationIdentity, so a force-push with a pending check never re-stamps the head. UpdateBranch then sends obs.HeadSHA from internal/app/reconciler.go:265 as expectedHeadOid at internal/infra/scm/github.go:481 with a stale value, GitHub rejects it with head sha didn't match the current head ref, and the run enters needs_agent_fix. The rebase path stamps the failed observation at reconciler.go:268 before calling wake at :271, so wakeWithEvent returns at :297 because sameObservation is now true; the fixer is never woken and the next tick is a no-op. Separately, cmd/beacon/main.go reads cfg.Merge.MaxAutoRebases only when services are built and config_watch.go restartFields omits it, so raising the cap from 2 to 12 needs a daemon restart.
Steps: stamp the observation before both early returns in handleNeedsRebase so a new head with a pending check is recorded, while keeping the no-rebase guard so a pending check does not spend a rebase attempt; move the rebase-failure observation stamp after the wake, or bypass sameObservation for that one wake and notify without spending a fix attempt; add max_auto_rebases to the runtime config path so a change updates the reconciler and policy without restart, or classify it in restartFields and make doctor name the restart; add tests for a new head with a pending check, a failed rebase that still wakes the fixer, and a watcher change of only max_auto_rebases.
Accept: after a force-push the run stamps the new head on the next 30s tick, UpdateBranch uses the current expectedHeadOid, a failed rebase wakes the fixer, and a live edit of merge.max_auto_rebases changes the effective cap without killing the daemon.
