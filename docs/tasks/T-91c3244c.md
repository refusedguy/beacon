Goal: stop stale head and stale wake from freezing a run, with one invariant for observation stamping.
Evidence: PR 2845 sat in waiting_ci for more than 100 minutes with head_sha and observed_sha c61447c while PR head was 9cf67fb. Audit at HEAD 08f3ea57 found the chain: internal/app/reconcile_observation.go:119-121 returns on HasPending and :122-124 returns on sameObservation before any NoteObservationIdentity; internal/app/reconciler.go:265 passes obs.HeadSHA as expectedHeadOid; on failure :268 stamps the observation before :271 calls wake, and wakeWithEvent at :294 sees sameObservation and drops the wake. The shipped invariant is: write observation identity in the same Store.Save that commits the decision produced from that observation, and only after every guard that can veto or defer the decision has passed. Pending checks are a guard defer, so leave them unstamped and re-evaluate on the next tick. A wake skipped for no slot or an incident must stay unstamped or the fix is lost. Terminalizing the run is the only exception.
Steps: keep the HasPending guard unstamped; stamp the changed head and base in the same save that applies EvRebased or another committed decision from that observation; in the rebase failure path save EvRebaseFailed with a zero observation, then call wake with the original observation so the dedup check sees a changed identity and delivers the wake; leave NoSlot, incident and no-attempt paths unstamped; add max_auto_rebases to the runtime config path so a change updates the reconciler and policy without restart, or classify it in restartFields and make doctor name the restart; add tests for pending checks staying unstamped, a committed decision stamping identity once, a failed rebase that wakes the fixer, and a watcher change of only max_auto_rebases.
Accept: after checks settle the run stamps the real head and UpdateBranch uses current expectedHeadOid; a failed automatic rebase wakes the fixer on the first attempt; a pending check does not consume a rebase or fix budget.
