# T3.285. ACP registry
Статус: done
Premise: проверено 2026-11-21 по origin/main (29da86b). В `internal/infra/registry/index.go` живёт производный индекс возможностей `CapabilityIndex` из ADR 0089, а не реестр ACP-агентов. Типов `ACPAgent` и `ACPAgentRegistry` в main нет. Зависимость T3.279 уже влита: PR #1132 добавил `ACPServer` с хендлерами `session/list`, `session/new` и `session/load` в `internal/infra/wake/acp.go`. Сервер не дублируется. Живое ACP-приложение OpenRig в этой среде недоступно, поэтому реестр проверен юнит-тестом на локальных записях.
baseline: на origin/main 29da86b: `git grep -n 'ACPAgentRegistry' origin/main -- internal/infra/registry` = 0; `git grep -n 'type CapabilityIndex' origin/main -- internal/infra/registry/index.go` = 1 (index.go:29); `git grep -n 'type ACPServer' origin/main -- internal/infra/wake/acp.go` = 1 (acp.go:874, PR #1132); `git grep -nE 'acp\.to|agent\.json' origin/main -- internal cmd` = 0. Индекс возможностей есть, реестра ACP-агентов нет, дубля сервера нет. Решение: тонкий слой над `CapabilityIndex` в существующем файле, без нового хранилища и без правки wake.

Цель: Зарегистрировать команду как агента в ACP приложениях.
Контекст: packages/acp/registry/agent.json в OpenRig позволяет приложению запустить custom agent command без аргументов.
Шаги: Собрать registry entry и fallback получателя через acp.to при отсутствии --to.
Проверка: Приложение без аргументов попадает к настроенному get receiver.
Приёмка: Установка сводится к добавлению custom agent в настройках приложения.

## Подтверждение
- PR #1142 (https://github.com/refusedguy/beacon/pull/1142): добавлены `ACPAgent` и `ACPAgentRegistry` в `internal/infra/registry/index.go`. Реестр использует `CapabilityIndex` для поиска по возможностям и хранит отображения имя агента и адрес. `Register` проверяет имя, адрес и возможности, заменяет старые записи и передаёт адрес новому владельцу. `FindByCapability`, `FindByAddress` и `List` возвращают копии и не меняют внутреннее состояние. Существующий `CapabilityIndex` не тронут.
- Тесты в `internal/infra/registry/index_test.go`: регистрация двух агентов, поиск по возможности и адресу, `List`, замена возможностей и адреса при повторной регистрации, передача адреса другому агенту, отвержение неполных записей и проверка копий на выходе.
- Исправлена транзакционность `Register`: проверка возможностей через `Upsert` идёт до правки `byName` и `byAddress`. Отклонённая повторная регистрация теперь не снимает старые записи, а неудачная передача адреса не удаляет прежнего владельца. Регрессионные тесты добавлены в `index_test.go`.
- `internal/infra/wake/acp.go` прочитан, но не изменён: сервер `acp serve` из T3.279 (PR #1132) уже в main. Дубля нет.
- gofmt применён к обоим Go-файлам. `go test` и `go build` локально не запускались, проверка идёт в CI по PR. Живой зонд с OpenRig недоступен.
- todo: подключение реестра к загрузчику `agent.json` и fallback через `acp.to` лежит в `cmd/beacon`, вне OwnerFiles этой карточки. Для него нужно решение владельца о том, кто читает конфиг приложения и где хранится адрес получателя.
