Goal: Make batch card creation atomic and faster.

Evidence: Each beacon_task_create batch currently writes one card file, syncs SQLite and publishes per card. The operator observes throughput falling with batch size and suspects per-file plus per-DB work instead of one transaction.

Scope: internal/app/taskcreate.go, internal/app/taskcreate_test.go, internal/infra/mcp/server.go, internal/infra/mcp/server_test.go.

Steps: Write all card files first, build one graph, sync SQLite once and publish once. Make rollback unpublish and remove all files in one operation. Keep ids and @N resolution stable. Add a timing test with 20 cards and a rollback test asserting no remote cards remain.

Accept: One batch produces one commit and one push, rollback is all or nothing, and 20 cards complete without per-card publish.

Open a PR, call beacon_watch_pr, do not self-merge.
