# CB-03. Пользовательские типы рёбер с границей длины из схемы

Цель: Позволить проектам добавлять свои типы рёбер, не расширяя ядро, и отклонять слишком длинные значения до записи.

Контекст: Источник, реальный код beads. `DependencyType.IsValid` в `internal/types/types.go:1531-1533` принимает любую непустую строку длиной не более `MaxDependencyTypeLen`. Константа на `types.go:1519-1526` выведена из ширины колонки `VARCHAR(32)` в схемах миграций, чтобы валидный тип не стал фильтром, который ничего не находит. Встроенные типы собраны в `AllDependencyTypes` на `types.go:1506-1517`, а `IsWellKnown` на `types.go:1537` используется только там, где пользовательский тип намеренно запрещён. Разрыв в beacon: `ValidEdgeKinds` и `IsValidEdgeKind` в `internal/infra/taskstore/edges.go:16-30` принимают ровно пять констант, а `AddEdge` на `edges.go:87` возвращает ошибку валидации для любого другого значения.

Шаги: Разделить проверку на две функции, как в beads: общая валидность по длине и список встроенных типов. Вынести предел длины в одну константу с пояснением, откуда она взялась. Оставить явный список для пользовательских команд, где произвольный тип нежелателен. Обновить тесты графа и проверку циклов.

Проверка: Измеримая. Ребро с типом `reviewed-by` длиной 11 символов добавляется и читается обратно. Ребро длиной 33 символа отклоняется до записи, число рёбер в графе не меняется. Список встроенных типов по-прежнему содержит пять значений. Проверка цикла работает для пользовательского типа так же, как для `blocks`.

Приёмка: Пять встроенных типов и их поведение не меняются. Внешние гейты `gh:pr`, `gh:run`, `timer`, `human` и `bead` остаются отдельной проверкой цели. AN-03 не дублируется.
