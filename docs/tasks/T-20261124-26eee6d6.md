Context: four green, mergeable PRs (#2325, #2331, #2335, #2342) are stuck in `waiting_ci` with reason `automatic rebase`. sqlite shows head_sha and observed_sha stale versus GitHub headRefOid for all four. Diagnosis: in `internal/app/reconciler.go`, `merge()` calls `Workspace.CommitPath` and `Store.Save`-adjacent work BEFORE `SCM.Merge`. `CommitPath` pushes from stale worktrees and all three dry-runs are rejected `non-fast-forward`; the error returns before `SCM.Merge` and before `Store.Save`. For PR #2342 the run has an empty `workspace_path`, so `checkPath` fails with `workspace path is empty`. Main is green (all five checks success). No run has a blocked incident and no approvals are needed.

Goal: a green mergeable PR merges even when its worktree is stale, missing, or empty.

Steps:
1. In `internal/app/reconciler.go` `merge()`, skip the workspace commit when `run.WorkspacePath == ""`. Do not mark a non-fixer run done from an empty path; still merge the PR.
2. When `CommitPath` fails with a `non-fast-forward` error, refresh the worktree from the remote branch and retry once before giving up. If the retry still fails, log a warning and continue to `SCM.Merge` rather than blocking the merge entirely.
3. Persist the observed head and base SHA even when the workspace step fails, so `sameObservation` does not re-trigger the same decision forever.
4. Add tests in `internal/app/reconciler_test.go`: a mergeable PR with empty workspace path reaches `merged`; a stale worktree with a non-fast-forward push still reaches `merged`; a failing workspace refresh is logged but does not block merge.
5. Run `gofmt -w`, targeted `go test ./internal/app` and `go test .`. Open a PR against main and call beacon_watch_pr. Do not self-merge.

Check: PRs #2325, #2331, #2335 and #2342 merge on the next reconcile tick without operator action.

Accept: do not change verdict rules or approval logic. Keep files under 350 lines. Do not edit AGENTS.md or another card.
