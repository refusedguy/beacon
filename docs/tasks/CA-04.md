# CA-04. Коммит после правки и безопасная отмена
Статус: todo
Фаза: P2
Тип: task
Владелец файлов: docs/templates/executor-task.md, internal/infra/worktree/headguard.go
Зависимости: 
Ссылка: docs/research/comp-aider.md
Агент: нет
Время: нет
Цель: Дать агенту контрольные точки на каждую правку и отмену, которая не трогает запушенные коммиты.
Контекст: Источник: docs/research/comp-aider.md, карточка CA-04. aider коммитит сразу после применения правок (`aider/coders/base_coder.py:1585-1594`) и отдельно коммитит исправления линтера (`base_coder.py:1599-1602`). `auto_commit` (`base_coder.py:2375-2400`) записывает хеш в `aider_commit_hashes`. Сообщение коммита строится из diff и контекста (`aider/repo.py:131-250`). Отмена (`aider/commands.py:560-655`) проверяет четыре условия: коммит сделан в этой сессии, коммит не слияние, файлы не грязные, коммит не запушен в `origin`. Затем команда возвращает файлы через `checkout HEAD~1` и двигает HEAD через `reset --soft HEAD~1` (`commands.py:623-644`). В beacon Git-работа сводится к жизненному циклу worktree и Watch. В таблице фаз есть одна фаза commit (`docs/templates/executor-task.md:16`). `GuardWatch` (`internal/infra/worktree/headguard.go:45-103`) защищает worktree по точному head, ветке, каталогу и предку, но не хранит точки восстановления для отдельных правок. Команды отмены правок в beacon нет. Baseline: 0 контрольных точек на правку и 1 коммит на ветку по сценарию `executor-task.md:16`.
Шаги: Зафиксировать в контракте исполнителя места, где агент делает коммит после правки и после исправления линтера. Хранить хеши коммитов сессии в состоянии worktree рядом с Watch. Добавить команду отмены, которая проверяет четыре условия aider и отклоняет отмену запушенного коммита. Возвращать файлы через `checkout` и двигать HEAD через `reset --soft`, сохраняя защиту `GuardWatch` по точному head и предку. Не менять модель одного PR на задачу.
Проверка: На временном git-репозитории сделать три последовательные правки, ожидать три коммита. Вызвать отмену дважды, ожидать HEAD на первом коммите и содержимое файла равным первому состоянию. Попытаться отменить запушенный коммит, ожидать отказ.
Приёмка: Три правки дают три контрольные точки. Две отмены возвращают HEAD и содержимое файла к первому состоянию. Отмена запушенного коммита отклоняется.
