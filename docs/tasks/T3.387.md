# T3.387. Доменная сущность Orchestrator
Статус: todo
Фаза: P3
Тип: task
Владелец файлов: internal/domain/orchestrator.go, internal/domain/orchestrator_test.go
Зависимости: 
Ссылка: docs/adrs/0157-orchestrator-entity.md
Агент: executor
Время: нет
Цель: Добавить отдельную доменную сущность Orchestrator с идентичностью сеанса, слотовым лимитом и подписками по watchID, не подменяя domain.Watch.
Контекст: Сейчас оркестратор существует только как RoleOrchestrator в Subscriber и как daemon в internal/app/orchestrator. Роль не хранит сессию, проект и занятые слоты. Watch остаётся единицей работы и должен остаться неизменным.
Шаги: Реализовать struct Orchestrator с полями ID (sessionID из _meta), Role, ProjectKey, SlotsTotal, SlotsUsed, Subscriptions []watchID, RegisteredAt. Добавить NewOrchestrator с валидацией и Clock, Key() с инъективным кодированием проекта и сеанса, CanAcceptTask по лимиту из конфига. Реализовать идемпотентные Register(watchID) и Unregister(watchID), поддерживающие SlotsUsed == len(Subscriptions).
Проверка: go test ./internal/domain/... в CI. Тесты на регистрацию, идемпотентность, лимит слотов и повторное использование слота.
Приёмка: Пустой watchID даёт INVALID_INPUT, переполнение даёт LIMIT_EXCEEDED, повторная регистрация и повторное снятие не меняют состояние; сущность не импортирует infra и не хранит Watch.
