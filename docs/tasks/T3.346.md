# T3.346. Migration parity
Premise: проверено 2026-11-21 по origin/main (3684714). Реализации startup-migrations-mirror и migration-fixture-parity в main не было. Зонд в wake потребовал бы второй копии корпуса или импорта internal/infra/store в нарушение ADR 0005. OwnerFiles расширены на пакет store, и зонд живёт рядом с корпусом миграций.

baseline: `git grep -n -iE 'ALL_MIGRATIONS|migration.?parity|fixture.?parity|startup.?migration' 3684714 -- internal '*.go'` не дал ни одной строки. `git log 3684714 --oneline --grep='T3\.346'` содержит только проверки premise: 78129ca и bc6b2e7. До PR #1150 реализационного PR по T3.346 не было. Корпус 0001..0006.sql и тесты в db_test.go лежат в internal/infra/store, схема инстанса строится при Open в том же пакете.

Цель: Проверять список миграций в тестовом fixture.
Контекст: startup-migrations-mirror требует, чтобы startup применял ровно ALL_MIGRATIONS. migration-fixture-parity требует, чтобы схема fixture совпадала со схемой инстанса.
Шаги: Добавлены allMigrations, TestStartupMigrationsMirror и TestMigrationFixtureParity. Исключения с причиной собраны в migrationFileExclusions и runtimeSchemaExclusions.
Проверка: Пропущенная миграция в fixture или лишний SQL-файл в корпусе проваливает TestStartupMigrationsMirror.
Приёмка: Схема таблиц, колонок и индексов fixture совпадает со схемой свежего инстанса, кроме исключений с причиной.

## Реализация в PR #1150
- `allMigrations` задаёт канонический корпус. `TestStartupMigrationsMirror` сверяет его со встроенными файлами и падает при расхождении.
- `TestMigrationFixtureParity` применяет корпус через `migrate` и сравнивает схему со свежим `Open`. Исключения: колонки `scope`, `type` и индекс `events_by_scope`. Их добавляет `ensureEventLog` поверх таблицы `events` из миграции 0004.
