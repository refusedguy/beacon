# CV-07. Разделение постоянных и временных ошибок в провайдере ghci

Premise: проверено 2026-11-22 по `origin/main` `e2f34a060579d452c1ca6ca7845560b78b8b7629`. Источник: OpenHands `src/api/with-retry.ts:18-30` объявляет 4xx постоянными ошибками запроса и разрешает повтор только для 408 и 429, для 5xx и для случаев без ответа сервера. `:36-40` задаёт три попытки и экспоненциальную задержку. Причина в комментарии: один и тот же запрос при ошибке валидации или авторизации получит тот же ответ.

Разрыв: `internal/infra/ghci/provider.go:206-219` увеличивает `consecutiveErrors` и удваивает `e.backoff` при любой ошибке `gh`. Комментарий на `:208` называет transient только TLS-таймауты и `exit status 1`, но проверки типа ошибки нет. Ошибка авторизации, отсутствующий репозиторий или неверный аргумент тоже переводят провайдер в backoff до 60 с и продолжают опрашивать тот же PR бесконечно. Классификатор в `internal/infra/github/errors.go:65-91` различает 429, 502 и 504, но к CLI-провайдеру он не подключён.

baseline: `rg -n 'isRetryable|Retryable|Auth|401|403|404' internal/infra/ghci/provider.go` = 0. `rg -n 'e.consecutiveErrors\+\+' internal/infra/ghci/provider.go` = 1, строка 210. `rg -n 'defaultJitter|jitterOr' internal/infra/github/errors.go` = 8, оба механизма живут в другом провайдере.
