Goal: add a second harness implementation that satisfies core.AgentHarness and can be selected by harness.provider: acp. This is the concrete proof that the architecture is portable.

Depends on the core ports card and the OpenCode adaptation card. Scope: harnesses/acp/**, go.work, cmd/beacon/main.go, cmd/beacon/main_test.go.

Steps:
1. Create harnesses/acp as its own Go module in go.work. It may import pkg/core only, never internal/.
2. Implement AgentHarness: Spawn, Wake, Stop, IsAlive, NotifyParent and Events. Implement only the capability ports that make sense for ACP. A no-op is acceptable for a capability ACP cannot provide, but name it in the card result.
3. Carry ParentSessionID and ModelRef from SpawnRequest into the ACP session so Beacon behavior stays the same.
4. Wire provider "acp" in cmd/beacon through a factory or registry entry. Do not add a second concrete branch that duplicates the OpenCode wiring.
5. Test against a fake ACP server: spawn, wake, stop, parent notify and an idle event. Add a compile-time assertion that the ACP harness satisfies core.AgentHarness.
6. Run gofmt -w, targeted go test in the new module, go test ./cmd/beacon and root go test . for arch. Open a PR, call beacon_watch_pr, do not self-merge.

Accept: only the listed paths. No plugin JS, no docs, no task card edits.
