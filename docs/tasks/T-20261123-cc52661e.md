Add an orchestrator-only MCP tool `beacon_task_update` that edits several task cards in one git commit and push. Input is `updates: [{id, title?, body?, scope?, depends?, priority?, kind?, require_review?, base_branch?, plan?}]`. Put the use case in a new `internal/app/taskupdate.go` with a `TaskUpdater` service. Rules: ignore any `status` field in input, since task flow belongs to Beacon; treat omitted fields as unchanged and report `unchanged` when nothing differs; return `not_found` for a missing card; refuse the whole batch if any task has an active run, leaving the tree untouched; write all changed cards with the existing Markdown frontmatter writer and reuse the base rebase and push helper from taskcreate. Return per-id statuses. Wire the tool in `internal/infra/mcp/server.go` next to `beacon_task_create` and restrict it in `opencode.json` with the same deny-by-default and allow-only-for-orchestrator/build permissions. Add MCP in-memory tests for single update, batch, not_found, unchanged, active-run refusal and rollback, plus app tests for frontmatter preservation. Update AGENTS.md only for the new tool signature. Keep production files under 350 lines. Run gofmt and targeted tests, open a PR and call beacon_watch_pr.
