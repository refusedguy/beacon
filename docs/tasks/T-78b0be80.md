Goal: match GitHub branch protection, which accepts success, skipped and neutral but not cancelled.
Evidence: checkState at internal/infra/scm/github.go:280-284 maps cancelled to CheckSkipped, and CheckSkipped passes in AllRequiredPass at verdict.go:185,196 and evaluateChecks at configurable.go:157. TestCheckStateMapsCancelledToSkipped pins the wrong behavior. With cancel-in-progress at ci.yml:23-25 a required check whose newest attempt on the head SHA is cancelled lets Decide return merge although that check never finished.
Steps: add CheckCancelled to pkg/core/verdict.go; map cancelled to it in checkState; count only CheckSuccess and CheckSkipped as passing in AllRequiredPass and evaluateChecks so a cancelled required check yields VerdictWait under required_checks; do not map cancelled to CheckPending because HasPending would then report a terminal check as running; update the SCM test and add a policy test that cancelled does not merge and skipped still does.
Accept: a cancelled required check blocks with wait, a genuinely skipped check still passes, and no test asserts cancelled is skipped.
