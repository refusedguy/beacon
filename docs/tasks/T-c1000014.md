## Goal
Keep a refused control action on screen until the operator takes the next action.

## Evidence
From T-7c7f30f9: the TUI overwrites refusal status on the next refresh, so the reason disappears before the operator can read it.

## Steps
Store the last refusal in a dedicated field on the model. Render it until the operator issues the next action, and clear it on a successful control. Add tests in the new ui/tui/model_refusal_test.go that a refusal survives several refresh messages.

## Accept
A refusal stays on screen across refreshes until a new action succeeds or fails.
