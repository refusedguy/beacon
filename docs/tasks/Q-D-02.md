Цель: Одна команда ставит хуки, конфиг и проверяет MCP в любом проекте.
Контекст: Premise: сейчас установка Beacon в новый репозиторий делается вручную. Требуется beacon init и пилот на Harbor-Harness с длинными проверками и SKIPPED job-ами.
Шаги: Реализовать команду, шаблоны .beacon/config.yaml и flaky.json, smoke проверку MCP, документировать пилот.
Проверка: gofmt, go test в CI.
Приёмка: beacon init в чистом репозитории создаёт все файлы и проходит проверку подключения.
Premise: проверено по origin/main, база 54d2123. Команды `beacon init` нет: `grep -c 'case "init"' cmd/beacon/main.go` даёт 0, файла `cmd/beacon/init.go` в дереве нет, runbookа `docs/runbooks/beacon-init.md` нет. Установка действительно делается вручную, дубля нет.
baseline: `git show origin/main:cmd/beacon/main.go | grep -c 'case "init"'` = 0; `git cat-file -e origin/main:cmd/beacon/init.go` = 1 (нет файла); `git cat-file -e origin/main:docs/runbooks/beacon-init.md` = 1 (нет файла); `git grep -c RegisterInit origin/main -- cmd/beacon` = 0.
Выполнено: `runInit` в `cmd/beacon/init.go` пишет `.githooks/pre-commit`, `.githooks/pre-push`, `.beacon/config.yaml` и `.beacon/flaky.json`, затем ставит `core.hooksPath` и проверяет MCP через in-memory транспорт: сервер, клиент, `tools/list` и сравнение с `ToolNames`. Повторный запуск без `--force` сохраняет существующие файлы. Ранбук в `docs/runbooks/beacon-init.md` описывает шаги и пилот.
Ограничение: dispatch в `cmd/beacon/main.go` и каталог в `cmd/beacon/catalog.go` не входят в OwnerFiles карточки. Добавлен только `RegisterInit`. Тест `TestT06ListJSONCatalog` в `cmd/beacon/main_test.go` жёстко ждёт 18 команд, поэтому запись в каталоге без правки чужого теста ломает CI (прецедент Q-A-02). Подключение dispatch и каталога остаётся за отдельной wiring-задачей.
Пилот: на внешний репозиторий без разрешения владельца не запускался. Ранбук фиксирует процедуру пилота с длинными проверками и SKIPPED job-ами.
Проверено локально: `gofmt -w cmd/beacon/init.go`, `git status --short` показывает только два новых файла в OwnerFiles. `go test` и `go build` по правилам этого репозитория не запускались, проверка идёт в CI.
