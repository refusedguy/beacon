Goal: repeated builds with unchanged inputs do no work and never leave a stale hash.
Evidence: build-beacon.sh always calls go build and writes build-sha after the build; install-beacon.sh hit ETXTBSY while the binary was running.
Steps: before building, compare a fresh compute_build_hash with .opencode/bin/beacon.build-sha and check the binary exists; on a match print the hash and exit; otherwise build to a temp file, rename over the destination, then write the hash; add a shell test that stubs go and asserts one invocation for two identical builds and a second after a source change.
Accept: two builds with unchanged sources invoke go once and build-sha always describes the binary on disk.
