Goal: keep the public-repo free-tier caches under quota and cut idle job usage without changing any Beacon required check.
Evidence: the repo has 109 live caches at about 10.57 GiB against the 10 GB included quota. 68 opencode-cli entries hold about 7.52 GiB because pull_request caches are scoped to refs/pull/<n>/merge and are not reusable across PRs; 57 entries use a legacy key with no reference in the repo. The changes job uses fetch-depth 0 and averages 2.67s, while dorny/paths-filter uses REST on pull_request events. Advisory passes run even when a PR edits ci.yml, which makes the verdict untrusted anyway; 2 of 42 perf PRs hit that case. benchstat install averages 4.7s and reaches 23s at worst. bench-baseline has no explicit retention and inherits 90 days. benchstat-nightly declares overwrite but names the artifact with github.run_number, so history accumulates. One PR run can put roughly 14 hosted jobs in flight against the Free plan cap of 20. The single concurrency group ci-${{ github.ref }} with cancel-in-progress: true is shared by pushes, schedule and dispatch, so a push on main cancels an in-flight nightly; on 27 November perf-nightly was cancelled after 17m43s. Peak concurrency hit exactly 20 hosted jobs in a 28-minute window with 31 runs and advisory duration grew from 90s to 220s under overlap.
Steps, all in .github/workflows/ci.yml: add a cache-cleanup job on pull_request: closed with job-level permissions actions: write that deletes caches under refs/pull/<number>/merge; set job-level continue-on-error: true on it because merge.required_checks_mode is workflow and every new job without a matrix or continue-on-error becomes a required check; gate the changes checkout step on github.event_name == 'push'; skip advisory passes when steps.trees.outputs.ci_changed == 'true' while keeping the inconclusive comment; cache the pinned benchstat binary against its version; set retention-days: 30 on bench-baseline; remove github.run_number from the benchstat-nightly artifact name so overwrite actually rolls it; remove the dead dispatch-only step in perf-nightly; split the concurrency group by event, for example ci-${{ github.event_name }}-${{ github.ref }}, with cancel-in-progress: false for schedule and dispatch and true for pull_request.
Accept: cache storage stays below the 10 GB quota with no eviction of active build caches, a push does not cancel an in-flight nightly, advisory remains advisory with continue-on-error, and every existing required check name stays identical. Do not rename or remove any gating job, do not remove continue-on-error from perf-pr-advisory or perf-noise-floor, do not change the ready-to-merge label step or the changes output names, and do not touch runner labels or hosted versus self-hosted placement in this card.
