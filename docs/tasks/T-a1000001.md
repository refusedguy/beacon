Goal: after an operator nudge the run carries a visible marker that guidance was delivered, and a real failure reason stays intact.

Evidence: Control.Nudge at internal/app/control.go:425-460 only calls HoldAgent, Store.Save and Harness.Wake. HoldAgent at pkg/core/run.go:284-285 sets AgentHeld but writes no reason or marker, so State and Reason stay unchanged. Run.Apply clears Reason on EvAgentFixed, EvChecksPassed and EvRebased with no explicit reason at pkg/core/run.go:392-395. In the live snapshot for run-ca9ae0df06c397f5cabe4923 and run-79d3aa2c9fc69bfeb51dac08 the reason still reads `unavailable: update branch: Variable $sha of type GitObjectID! was provided invalid value` after a nudge.

Steps: add a visible nudge marker to the Run type at pkg/core/run.go and the method that sets it. Apply that marker in Control.Nudge after the slot reservation and before Store.Save. Keep a real failure reason intact when the marker is written. Do not stamp observation identity on that save. Add internal/app/control_nudge_test.go proving that a nudge sets the marker on the saved run, keeps an existing failure reason, and still wakes the session.

Accept: the TUI shows the nudge marker after a nudge, and a nudge never replaces a real failure reason with a generic value.
