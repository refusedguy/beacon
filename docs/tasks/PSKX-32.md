# PSKX-32. Две правки как критерий теста

Цель: Оценивать тест двумя воображаемыми правками: сломанное поведение должно его уронить, смена внутренностей не должна; гнать код через публичный интерфейс и выводить ожидаемое из требования.
Контекст: Источник: `pstack/skills/principle-test-behavior-not-implementation/SKILL.md:9-16` (two imagined edits). `docs/runbooks/verification.md:50-62` описывает, какие факты наблюдают скрипты, но не содержит критерия качества теста и не проверяет, что тест упадёт при поломке поведения. baseline: `git grep -i -E 'поведение, а не реализацию|две правки' -- docs/runbooks/verification.md | wc -l` = 0 на `origin/main`. Карточка фиксирует приём в дереве beacon, не создаёт новый глобальный скилл и не меняет протокол Watch. Не дублирует PSK-01 (кандидаты), PSK-02 (адверсарии), PSK-03 (TLA Watch), CP-01..05, CM-01..05 или закрытые дубли HD-099/HD-105/HD-109. Риск: низкий.
Шаги: Добавить в runbook раздел «Критерий теста» с двумя правками: сломать наблюдаемое поведение и убедиться, что тест красный; заменить внутренности и убедиться, что тест зелёный. Запретить ожидаемое значение, вычисленное тем же кодом, и проверку данных, которые тест сам создал. Требовать проверку типа ошибки, на который ветвится вызывающий.
Проверка: `git grep -n -E 'поведение, а не реализацию|две правки' docs/runbooks/verification.md` находит критерий и обе правки.
Приёмка: Тест, который не падает на сломанном поведении, переписывается. Тест, привязанный к внутреннему вызову, удаляется.
