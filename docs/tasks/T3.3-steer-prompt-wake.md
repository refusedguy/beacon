# T3.3. Пробуждение сессии через ctx.session.prompt с delivery steer

Статус: todo
Фаза: P3
Тип: task
Владелец файлов: tests/adapter/steer-prompt.test.js
Зависимости: T0.3, T3.1
Ссылка: ADR 0006
Агент: нет
Время: нет

Цель: Вызвать `ctx.session.prompt` с `delivery: "steer"` по событию Beacon и доказать пробуждение фактом `session.execution.started`.

Контекст: WORKER-PROMPT §4.4 описывает оба канала: S1 через MCP push, `experimental.mcp.event`, `ctx.event.subscribe` и `ctx.session.prompt`, и S2 через events.jsonl с тем же вызовом prompt. Факт пробуждения это `session.execution.started`, а `session.inbox.delivered` подтверждает только попадание текста в историю. Synthetic с `resume:false` добавляет текст и не будит сессию (отчёт E §6, приёмка T0.3). Prompt-текст несёт указатель `watchID`, `obligationID`, `revision` и обёртку `<beacon-event>` (WORKER-PROMPT §4.4). Для S1 нужен heartbeat не реже 30 с из-за правила 60 секунд тишины в event stream, а progress-уведомления OpenCode игнорирует (WORKER-PROMPT §4.4). Файл плагина принадлежит T3.1, эта карточка владеет тестом.

Шаги:
1. На событие канала вызвать `ctx.session.prompt({sessionID, text, delivery: "steer"})`, где sessionID приходит из события.
2. Собрать текст prompt только из указателя и обёртки `<beacon-event>`, без содержимого проверок.
3. Если выбран S1, добавить heartbeat не реже 30 с и не продлевать wait через `onprogress`, который пустой.
4. Тест ловит `session.execution.started` через GET `/api/event` с sessionID тестовой сессии и ставит контрольный вызов с `resume:false`.

Проверка: `node --test tests/adapter/steer-prompt.test.js` проходит. Тест видит `session.execution.started` после prompt с нужным sessionID. В контроле с `resume:false` есть `session.inbox.delivered` и нет `session.execution.started`.

Приёмка: Факт `session.execution.started` записан как доказательство пробуждения. Контроль с resume:false отрицательный. Prompt несёт указатель, а не содержимое. Heartbeat S1 не реже 30 с, если канал S1.

Гейт: P3. Вход в T3.4 и T3.6.
