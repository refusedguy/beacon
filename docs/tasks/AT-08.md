# AT-08. beacon_pr_close_dup: закрытие дубля PR и удаление ветки
Статус: todo
Фаза: research
Тип: task
Владелец файлов: internal/infra/mcp/tool_pr_close_dup.go, internal/infra/mcp/tool_pr_close_dup_test.go, docs/tasks/AT-08.md
Зависимости: решение владельца по деструктивному MCP-инструменту
Ссылка: docs/research/research-agent-tooling-gaps.md, разделы 2 и 7
baseline: в advertised-наборе нет инструментов для `gh pr close` и `gh api branches DELETE`. Единственный деструктивный инструмент сегодня `beacon_cancel_watch` (`internal/infra/mcp/server.go:204-212`), и он закрывает Watch, а не PR.

Цель: дать агенту один kontrolируемый вызов для закрытия дублирующего PR и удаления его head-ветки.

Контекст: уборка дублей сегодня идёт руками через `gh pr close` и `gh api branches DELETE`.Оба действия необратимы и не имеют аудита в состоянии Beacon. Ошибочное закрытие живого PR ломает работу агента, поэтому инструмент проектируется с dry-run по умолчанию и проверкой связанного Watch.

Инструмент (сигнатура):

```go
type PRCloseDupInput struct {
    Repo        string `json:"repo" jsonschema:"owner/name; required"`
    PR          int    `json:"pr" jsonschema:"duplicate pull request number; required"`
    DuplicateOf int    `json:"duplicateOf" jsonschema:"pull request that stays open; required"`
    Confirm     bool   `json:"confirm,omitempty" jsonschema:"false returns a dry run; true performs close and branch delete"`
    DeleteBranch bool  `json:"deleteBranch,omitempty" jsonschema:"delete the head branch after closing; default false"`
}

type PRCloseDupOutput struct {
    Repo         string `json:"repo"`
    PR           int    `json:"pr"`
    DuplicateOf  int    `json:"duplicateOf"`
    Action       string `json:"action"` // dry_run, closed, noop
    BranchDeleted bool  `json:"branchDeleted"`
    Reason       string `json:"reason,omitempty"`
    WatchID      string `json:"watchID,omitempty"`
}
```

Где реализовать: новый `internal/infra/mcp/tool_pr_close_dup.go`. Порт `PRCleanup` с методами `ClosePR(ctx, repo, pr, reason) error` и `DeleteBranch(ctx, repo, branch) error` объявить в `Dependencies` (`internal/infra/mcp/server.go:404-493`). Адаптер в композиционном корне обязан использовать уже существующий GitHub-клиент, без `os/exec` в `internal/infra/mcp`. Output DTO в `schema.go` рядом с `OKOutput` (`:417-430`). Дескриптор с типом `kindDestructive` рядом с `beacon_cancel_watch` (`server.go:204-212`), аннотация `DestructiveHint: true` выбирается через `annotationsForKind` (`server.go:281-295`).

Шаги: всегда начинать с dry-run. Проверить, что `PR` и `DuplicateOf` различны и оба положительные. Прочитать связанный Watch через `deps.Snapshot`: если Watch жив по этому PR, отказать с причиной `active_watch`. Проверить состояние PR через существующий `domain.CIProvider`: MERGED отказать, CLOSED вернуть `noop`. Только при `Confirm=true` вызвать `ClosePR`, затем `DeleteBranch` если запрошено. Идемпотентность держать на паре `(repo, pr, duplicateOf)`: повтор после закрытия возвращает `noop` без второго вызова. Записать действие в observe с полями `repo`, `pr`, `duplicateOf`, `actor`.

Проверка: тест без `Confirm` фиксирует `action=dry_run` и нулевое число вызовов порта. Тест с живым Watch фиксирует отказ до закрытия. Тест с CLOSED PR возвращает `noop`. Тест с OPEN PR и `Confirm=true` фиксирует ровно один вызов `ClosePR` и один `DeleteBranch`, повтор не вызывает порт. Контрактный тест `tools/list` обновлён по замеру в CI, аннотация деструктивности отражена в golden.

Приёмка: владелец разрешил деструктивный MCP-инструмент. Агент закрывает дубль и удаляет ветку одним вызовом, не имея возможности сделать это случайно. Если решение отрицательное, уборка остаётся ручной и карточка закрывается как предложенная, но не принятая.

Ограничение: удаление ветки может задеть чужую работу, если head-ветку используют несколько PR. Инструмент обязан проверять это через провайдера до удаления или оставить `DeleteBranch` выключенным по умолчанию.
