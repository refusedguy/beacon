Goal: make notification evidence match what the operator actually received.
Evidence from audit: base-red and blocked notices repeat every 30 second tick because CreateIncident returns the existing incident and notify is still called; forced reconcile and daemon tick can both notify terminal state because finalizeExternal and closeOrphan carry no delivery claim; a failed parent post is logged then lost because the run is already terminal and FindByPR excludes terminal states; CLI and ACP NotifyParent return nil without sending while finalize records result notified; Telegram Notify returns nil with no log on missing token or chat ID; blocked notice text says state base_red: ci failed while the run is actually blocked with reason base_red; orphan notice says PR #0; notifyParent blocks reconcile for up to 10 seconds and parent post up to 30 seconds.
Steps: use ClaimDelivery per run and notice kind before sending; retry or record a failed delivery for terminal notices; make no-op harness implementations report that delivery is unsupported so the decision log does not lie; log missing Telegram config once at startup; build notice text from the run's actual state and omit PR when zero; move notifyParent off the synchronous reconcile path without losing the claim.
Accept: one notice per run and kind, no result notified when nothing was sent, and a slow notification endpoint cannot stall the daemon loop. Work in your own worktree off current main.
