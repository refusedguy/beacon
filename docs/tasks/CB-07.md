# CB-07. Позитивная проверка конфликтов и коды выхода при синхронизации

Цель: Дать оркестратору машиночитаемый исход слияния и проверять конфликт по данным, а не по тексту ошибки или коду возврата.

Контекст: Источник, реальный код beads. `cmd/bd/sync.go:26-46` задаёт пять кодов выхода: 0 успех, 1 ошибка, 2 конфликт, 3 транзиентные retry исчерпаны, 4 неразрешимая грязь в графе. Комментарий на `:26-31` объясняет, что две реплики на 60-секундном таймере различают три исхода без разбора вывода. Конфликт определяется позитивно на `:187-214` и `:247-301`: проверяются таблицы, захваченные merge, и живые строки `dolt_conflicts`. Код явно отказывается разрешать конфликт за оператора. Между pull и push безусловно вызывается `recompute` на `:325-326`; обоснование на `:216-236` говорит, что денормализованное поле готовности портится от чужого ребра зависимости, а проверка «изменился ли HEAD» ломает восстановление после ручного разрешения. Разрыв в beacon: путь слияния описан в `internal/infra/mcp/server.go:107-110` как `nextCommand` для rebase, а `waitFor` и `waitForMain` обрабатываются в `internal/app/orchestrator/orchestrator.go:325`. Отдельного исхода «конфликт данных» и позитивной проверки нет. Владелец каскада разблокировки остаётся за AN-02.

Шаги: Добавить тип результата слияния с классом исхода и структурированным списком конфликтующих объектов. Проверять конфликт по данным до и после merge. При конфликте останавливаться и отдавать отдельный nextAction, не предлагая автоматический выбор стороны. Отличать транзиентную гонку push от застрявшего состояния по отпечатку ожидающих правок между тиками. Пересчитывать зависимое состояние после успешного merge независимо от того, сдвинулся ли HEAD. Сохранить существующие nextAction для keep_working, rebase, retry и blocked.

Проверка: Измеримая. Для конфликтующего изменения графа результат содержит ровно один класс `conflict` и пустой список протолкнутых коммитов. Для гонки push с тремя неудачными попытками результат содержит класс `retries-exhausted` и `nextAction` со значением `retry`. Для успешного merge без сдвига HEAD поле зависимого состояния обновлено. Для транзиентной грязи отпечаток между тиками совпадает, и после третьего тика класс меняется на `stuck`. Существующие ветки `nextAction` проходят прежние тесты.

Приёмка: Новая механическая проверка не заменяет владельца AN-02. Карточка не предлагает менять хранилище карточек на Dolt. Конфликт никогда не разрешается автоматически.

Причина: ложный claim без cardID в PR #2234, код не писался.
