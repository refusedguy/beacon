Context: operator finds the Beacon sidebar panel text-heavy and wants graphs. Research of OpenCode v2.3.2 and @opentui/solid 0.8.4 found NO chart/sparkline/bar/gauge component. Built-in plugins draw bars as text: `packages/opencode/src/cli/cmd/stats.ts` uses `"█".repeat(barLength)` padded to 20. The sidebar is 42 columns. Best option with zero new data and one row: a stacked state bar from the snapshot's active[] states and metrics counts.

Goal: add a single compact, native-looking state bar to the panel header without new dependencies or per-frame work.

Steps:
1. In `ui_model.js` (or `ui_view.js`), build a state-bar item from the existing snapshot: counts for running, waiting_ci, blocked, merged (or the states already shown). Render one text row of up to 12 `█` cells distributed proportionally plus `░` for the remainder, with a short label such as `states` and the numeric counts. Use theme colors already used in the plugin (`text.base`, `text.muted`, `feedback.*.base`), no hardcoded hex.
2. In `ui_view.js`/`ui.js`, create the bar as a fixed text node once inside the render callback (same pattern as the row pool) and update only its `content` and `fg` in `apply()` during the 5s refresh. Never call `createElement`/`insert` in refresh(). Reuse the existing slot cache and inFlight guard.
3. Keep all current behavior: grouped detail, ✕ close button with esc hint, 20-decision cap, per-slot isDestroyed rebuild, configurable options, module split under 350 lines.
4. Add tests in `ui_setup_test.js`/`ui_test.js`: with known run states the bar string has the expected number of filled cells and the label/counts; refresh updates content without creating nodes.
5. Run `node --check` and `node --test .opencode/plugins/beacon-project/*_test.js`. Report pass count. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Check: the panel header shows a one-row text bar reflecting run states, and refresh does no node allocation.

Accept: only plugin JS files. No new npm deps. No Go code or AGENTS.md edits. Keep files under 350 lines.
