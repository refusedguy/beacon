## Подтверждение

PR #1146: https://github.com/refusedguy/beacon/pull/1146. Статус done относится к SLO-контракту замера: пороги, методика и автоматическое сравнение метрик с порогами.

- `tools/perf/measure.sh`. Добавлен `print_slo_report`. Он берёт худшее значение по каждой числовой метрике из всех прогонов, сравнивает его с теми же порогами `HWM_LIMIT_KB`, `P95_LIMIT_MS`, `POINT_LIMIT` и `RESTART_LIMIT_MS`, печатает таблицу и итог `PASS`, `FAIL` или `BLOCKED`. Отчёт идёт в stdout и в файл `<рабочий каталог>/slo-report.txt`, чтобы CI мог приложить его к PR.
- `docs/perf/README.md`. Раздел «Отчёт по SLO» описывает колонки, статусы и правило агрегации. Исправлена повреждённая фраза в настройке Go.
- Пороги уже были в скрипте и README до правки: 102400 КБ, 15000 мс, 500 поинтов/час, 5000 мс рестарта, ноль процессов `gh --watch`. Новый отчёт делает это сравнение явным и доступным для проверки в PR.

Проверки: `bash -n tools/perf/measure.sh` и `bash tools/perf/measure.sh --self-test` прошли. Отчёт проверен на синтетических строках PASS, FAIL и BLOCKED, статусы и итог совпали с ожидаемыми. `go test` и `go build` локально не запускались, Go-файлы не менялись. Живой прогон недоступен по ADR 0022, поэтому таблица результатов остаётся с прочерками до запуска в CI.

Исходная формулировка карточки просила сравнение двух версий на шести чередующихся arm по 100 creates с разбиением задержки на CLI, transport, daemon и insert. Этот контракт в PR #1146 не реализован.
