Goal: stop a single runner spike from erasing real optimizations, and make deterministic allocation and call-count evidence count as a gain.

Evidence: W2-5 worktree-remove moved 8.541 to 5.765 ms with 3 to 2 git calls but was called flat because one base sample hit 74.892 ms and spread used max minus min. W1R-6 dispatch-prompt moved 0.228 to 0.153 ms but was called flat because of a 66 percent head spread. Twelve of thirteen perf attempts were rejected while the benchmark artifact carries B/op and allocs/op columns that the comment never reads.

Steps, all in .github/workflows/ci.yml:
1. In 'Build comparison comment', sort the five medians of each side into s[0..4] and compute spread as 100 * (s[3] - s[1]) / median(s). Keep the spread rule as the decisive check. A single outlier in s[0] or s[4] must no longer force flat. Keep the range relation as supporting text only.
2. Read perf-results/compare.csv in the comment step. Parse the benchstat columns for B/op and allocs/op and add base and head values plus delta columns to the table. If work is equal, errs is zero, and allocs/op or B/op falls by at least 5 percent while median_ms does not rise by more than floorPct, set verdict to 'gain (allocs/bytes)' instead of flat. For worktree-remove, if base work is 3, head work is 2, errs is zero and median_ms does not rise by more than floorPct, set 'gain (calls reduced)'. For reconcile keys, if a deterministic counter such as lists-per-tick, observes-per-tick or gets-per-tick falls with equal work, errs zero and no median rise beyond floorPct, set 'gain (calls reduced)'. Preserve inconclusive for shape, work or err failures.
3. Remove or label-gate the warm-cache job so an ordinary PR does not spend about 1.5 minutes there when the test-modules legs already warm the cache. Compare wall-clock time of two unchanged PR runs in GitHub Actions and record the figure in the PR body.
4. Cap the calibrated floor in both the perf-noise-floor calibration and the advisory reader: if a single no-change run publishes a floor above 25 percent, clamp it to 25 percent for the verdict while still publishing the raw observed value and a short note. The trimmed spread and allocation or call-count rules above remain the decisive evidence for large single-outlier cases.

Accept: advisory stays advisory, exits zero, adds no required Criterion name. After merging, PR #2786 on unchanged code must show all rows flat with no gain or regression from the new allocation and call rules. The fix PR must NOT carry the perf label so mark-ready sets ready-to-merge. No local execution.
Protocol: Work in your own worktree and branch off current main. Never push to main. Never run go test, go build, go vet, linters, node tests or benchmarks locally. Open a PR and call beacon_watch_pr. Do NOT add the perf label. CI supplies every check.
