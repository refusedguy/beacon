Goal: a pure helper finds conflict markers in any task card and names the file and line.

Evidence: yaml.v3 rejects duplicate status keys and bare marker scalars. parseCardFields at internal/infra/tasksource/markdown.go:95-98 logs a warning and returns ok=false, buildCardIndex skips the file at cardindex.go:95-98, and ListAvailable filters it at markdown.go:43-46. The observed T-4de758ed card had `<<<<<<< Updated upstream`, `=======` and `>>>>>>> Stashed changes` around status, so it disappeared from SyncTasks and dispatch. Markers below frontmatter are not parsed as YAML and survive entirely.

Steps: add pkg/core/card_markers.go with CheckCardMarkers that walks .md files under a root and returns the first path and line whose text begins with `<<<<<<<`, `=======` or `>>>>>>>`. Scan the whole file, not just frontmatter. Keep the helper pure and read only the files it walks. Add pkg/core/card_markers_test.go covering markers in frontmatter, markers below frontmatter, a clean corpus and the reported path and line.

Accept: the helper reports the first marker by path and line, and a clean docs/tasks corpus returns no result.
