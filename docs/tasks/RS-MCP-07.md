Цель: Измерить размер бинарника и требования к toolchain перед решением о переходе с ручного JSON-RPC на github.com/modelcontextprotocol/go-sdk.
Контекст: Premise: проверено 2026-11-21, SDK не используется, ручной слой работает. baseline: `grep -c modelcontextprotocol go.mod` = 0, сейчас main=c9a0e3f. Правило репозитория «измерение до выбора» запрещает принимать подход без замера.
baseline: замер 2026-11-21 в docs/design/mcp-sdk-choice.md. `go version` = go1.27.4-X:nodwarf5 linux/amd64. beacon = 23 958 531 байт (коммит d3b1bfb, `stat` на `.opencode/bin/beacon`). Прототип на SDK v1.8.0 вне репозитория = 8 081 532 байт за 3 072 мс с флагами CI и тёплым кешем, 18 249 мс с пустым GOCACHE. Порог 100 МБ не превышен.
Решение: оставить официальный SDK. Premise карточки устарела: на c9a0e3f `grep -c modelcontextprotocol go.mod` = 1, SDK импортируется в `cmd/beacon/mcp.go` и `internal/infra/mcp/`. go.mod в этом PR не менялся.
Шаги: Записать текущий размер beacon и версию Go. Собрать минимальный прототип в отдельном модуле, не трогая go.mod основного репозитория. Измерить размер и время сборки. Сравнить с порогом 100 МБ. Зафиксировать решение и дату в docs/design/mcp-sdk-choice.md.
Проверка: Только текст. прототип живёт вне репозитория. Никаких изменений go.mod в этом PR.
Приёмка: Решение содержит числа и источник замера. При отсутствии выигрыша зафиксирован отказ с причиной.
