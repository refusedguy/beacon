Цель: Сделать воспроизведение исчезновения worktree повторяемым артефактом.
Контекст: Источник docs/research/research-worktree-gc.md, разделы 3 и 4. Сборщик удаляет чистый worktree без живого Watch с совпадающим HEAD. Защита по возрасту и маркеру активного агента отсутствует. В репозитории нет eval, который создаёт чистый detached worktree, регистрирует Watch для другого PR и проверяет, что worktree жив после merged. Без такого теста разрывы G1 и G2 возвращаются незаметно.
Шаги: Создать eval в отдельном пакете evals/worktree-gc с тремя сценариями из раздела 4 отчёта: detached-worktree-survives-unrelated-merge, local-commit-keeps-worktree и marker-blocks-collection. Использовать временный git-репозиторий и фейковый runner, который записывает вызов remove вместо удаления каталогов. Выводить результат в JSON с именами сценариев и фактами removed, remove_calls, reason и dir_exists. Негативный контроль прогоняет те же сценарии со старыми правилами и требует удаления во всех трёх. Добавить README с командой запуска и ожидаемым выводом. Не трогать evals/main.go: набор AUTOSP-10 уже влит и не дублируется.
Проверка: CI зелёный. Eval проходит на трёх сценариях и падает на негативном контроле со старым поведением. Код выхода равен 0 только при четырёх PASS: три сценария и негативный контроль.
Приёмка: Любой регресс в правилах удаления worktree ловится eval до релиза.
