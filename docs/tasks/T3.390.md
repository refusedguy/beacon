# T3.390. Единое решение Decide для blocked и waitFor
Статус: todo
Фаза: P3
Тип: task
Владелец файлов: internal/app/orchestrator/decision.go, internal/app/orchestrator/decision_test.go
Зависимости: T3.232
Ссылка: docs/adrs/0158-blocked-and-dependencies.md
Агент: executor
Время: нет
Цель: Свести блокировку исполнителя, граф waitFor и готовность проверок к одной чистой функции с пятью исходами.
Контекст: Blocked Watch может нести устаревший verdict=ready, а готовый Watch может иметь неудовлетворённый waitFor. Раздельные проверки дают ложный мерж и будят не того агента.
Шаги: Определить Decide(w Watch, deps DependencyResolver, ci CIState) Decision с исходами MERGE, WAIT_DEPENDENCY, BLOCKED_FIX_AGENT, RETRY_EXECUTOR, NOTIFY_ORCHESTRATOR. Соблюсти приоритет: blocked, затем неудовлетворённые ref, затем ready с авто-мержем, затем retry. Каждый исход несёт watchID, pr и revision. Не разрешать мерж при requireApproval, autoMerge=false, ошибке резолвера или nil резолвере. Не изменять Watch и не писать в журнал.
Проверка: go test ./internal/app/orchestrator/... в CI. Тесты покрывают приоритет, список неудовлетворённых ref, дедупликацию, fail closed и идентичность всех пяти исходов.
Приёмка: Blocked с verdict=ready даёт BLOCKED_FIX_AGENT с причиной и failedChecks. Готовый Watch с unsatisfied ref даёт WAIT_DEPENDENCY без мержа. Все ref найдены в main и verdict ready дают MERGE. Retry даёт RETRY_EXECUTOR. Остальное даёт NOTIFY_ORCHESTRATOR.
