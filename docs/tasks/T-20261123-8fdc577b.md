The MCP plugin starts `.opencode/bin/beacon`, which can be stale after a pull or a merged PR. That caused a 404 during automatic rebase because the daemon was running old REST code. Fix this in `.opencode/plugins/beacon-project/mcp.js` and a new `scripts/build-beacon.sh`. The script must run `go build -o .opencode/bin/beacon ./cmd/beacon` and write the current `git rev-parse HEAD` into `.opencode/bin/beacon.build-sha`. In `beaconCommand`, when a local binary exists but the sha file is missing or differs from current HEAD, run the build script once before returning the command path, then use the fresh binary. Keep the existing resolution order (BEACON_BIN, local binary, bin/beacon, PATH, go run fallback) and do not force `go run` on every start. Add a JS test with a fake filesystem/exec that simulates stale and fresh binaries. Document the build-sha file in .gitignore and AGENTS.md. Run node --check and targeted JS test, open a PR and call beacon_watch_pr.
