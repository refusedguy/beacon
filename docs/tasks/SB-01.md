Цель: Отвергать внешнюю проверку, которая вышла с кодом 0, но не запустила ни одного теста.
Контекст: Источник: docs/research/comp-swebench.md, карточка SB-01, `swebench/harness/grading.py:31-46`, `:155-160`. SWE-bench ищет в логе признаки реально запущенного набора через `SUITE_RAN` (`grading.py:31-46`) и возвращает отказ, если карта статусов пуста и признаков прогона нет (`grading.py:155-160`). Комментарий в `grading.py:27-30` фиксирует причину: без этой защиты набор, который не запустился, дал бы `RESOLVED_FULL` всем тестам F2P. В beacon `ExternalCheck` (`internal/domain/verdict.go:672-675`) хранит только имя проверки и целое `ExitCode`. `EvaluateExternal` (`verdict.go:728-775`) ставит `Passed: ok && exit == 0` (`verdict.go:762`). Поле `Observed` (`verdict.go:696-701`) означает лишь то, что адаптер доставил число. Аналога `SUITE_RAN` в `internal/domain` нет. baseline: `rg -c 'SUITE_RAN'` по `grading.py` даёт 2 строки, тот же поиск по `internal/domain` даёт 0. Два доказательства с кодом 0, пустым набором и строкой `collected 0 items` сейчас оба дают `ExternalPass`.
Шаги: Добавить в контракт внешнего доказательства признак того, что проверка выполнила тесты, и способ его передачи адаптером. Заполнять признак из лога проверки по образцу `SUITE_RAN` из `grading.py:31-46`, включая варианты для разных раннеров из `PARSER_REGISTRY` (`grading.py:22`). В `EvaluateExternal` (`verdict.go:728-775`) считать проверку проваленной с причиной `no_tests_ran`, если признаков прогона нет, даже при `ExitCode == 0`. Сохранить fail-closed поведение для необъявленных проверок и пустой декларации. Не менять формат `CheckOutcome` (`verdict.go:696-701`) для существующих адаптеров.
Проверка: Два набора доказательств для объявленной проверки `pytest`. Первый содержит код 0 и лог `collected 0 items` без признаков прогона, второй содержит код 0 и `12 passed`. Сейчас оба дают `ExternalPass`. Цель: первый даёт `ExternalFail` с причиной `no_tests_ran`, второй остаётся `ExternalPass`. Повторить для всех раннеров из `PARSER_REGISTRY`. Необъявленное имя и пустая декларация по-прежнему дают `ExternalFail`.
Приёмка: Пустой прогон с кодом 0 больше не проходит внешнюю проверку. Реальный прогон с кодом 0 проходит без правки адаптеров.
