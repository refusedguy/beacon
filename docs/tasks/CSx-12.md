Цель: Дать beacon режим, в котором конфигурация берётся только из явного источника, а файлы проекта и переменные окружения игнорируются.
Контекст: SDK задаёт `strict_mcp_config`, который отключает все иные источники MCP-конфигурации (`src/claude_agent_sdk/types.py:2477-2482`), и `setting_sources`, где пустой список включает режим изоляции, а обязательное присутствие `project` требует загрузки `CLAUDE.md` (`types.py:2759-2770`). Документация указывает, что файлы настроек проекта могут запускать хуки. Плагин beacon читает режим guard из `process.env.BEACON_SHELL_GUARD` без разграничения источников (`.opencode/plugins/beacon-project/index.js:63-81`), а адрес MCP-сервера берётся из локального файла (`internal/infra/mcp/client.go:79-97`). CS-01 добавляет fail-closed проверку способности, но не изолирует источники настроек.
baseline: `rg -n 'strict_mcp_config|setting_sources|strictMcpConfig' internal cmd .opencode` на `origin/main` 7244e15b даёт 0 строк; `rg -n 'BEACON_SHELL_GUARD' .opencode/plugins/beacon-project/index.js` даёт 3 строки.
Шаги: Добавить переключатель строгого режима в конфигурацию плагина и MCP-клиента. В строгом режиме читать только явно переданный список источников. Игнорировать переменные окружения и файлы проекта, которые не попали в список. Логировать каждую отвергнутую попытку загрузки с именем источника.
Проверка: Тест кладёт лишний инструмент в локальный файл настроек и включает строгий режим. Список инструментов содержит только записи из явной конфигурации. Измеримая проверка: различие числа инструментов между обычным и строгим режимом равно 1; `rg -n 'strictConfig|strictMcp|settingSources' <ветка> -- internal .opencode` даёт не менее 3 строк.
Приёмка: Строгий режим не зависит от содержимого каталога проекта и окружения.
