baseline: `failureExcerptLimit` равен 2048 байт, `failureExcerptAnnotationCount` равен 8 (`internal/infra/mcp/tool_get_result.go:69-84`). Кэш живёт по ключу `(watchID, headSHA, checkName)` (`:111-129`). Полного лога и смещения в MCP нет.

Цель: дать агенту инструмент, который читает полный лог упавшей проверки кусками с явным лимитом байт, не дублируя GitHub-клиент из `get_result`.

Контекст: `beacon_get_result` уже заменяет `gh run view --log-failed` для коротких ошибок. Он возвращает до 2 КБ redacted-аннотаций и ссылку на полный лог (`tool_get_result.go:504-578`). Когда текст обрезан, агент всё равно уходит в shell за полным логом. Нужен второй вызов того же источника с бюджетом и смещением.

Инструмент (сигнатура):

```go
type CIFailedLogInput struct {
    WatchID    string `json:"watchID" jsonschema:"Watch whose head SHA selects the check run; required"`
    CheckName  string `json:"checkName" jsonschema:"exact failed check name from failedChecks; required"`
    Offset     int    `json:"offset,omitempty" jsonschema:"byte offset in the sanitized log; zero starts from the beginning"`
    LimitBytes int    `json:"limitBytes,omitempty" jsonschema:"requested byte budget; zero uses 4096, ceiling 16384"`
}

type CIFailedLogOutput struct {
    WatchID     string `json:"watchID"`
    CheckName   string `json:"checkName"`
    Text        string `json:"text"`
    NextOffset  int    `json:"nextOffset"`
    TotalBytes  int    `json:"totalBytes"`
    Truncated   bool   `json:"truncated"`
    LogURL      string `json:"logUrl,omitempty"`
    FromCache   bool   `json:"fromCache"`
}
```

Где реализовать: новый `internal/infra/mcp/tool_ci_failed_log.go`. Источник `FailureExcerptSource` (`tool_get_result.go:61-67`) расширить вторым методом `FailureLog(ctx, repo, headSHA, checkName, offset, limit int) (string, int, int, error)` и реализовать его в `envFailureExcerptSource` (`:682-848`) через тот же `getJSON` и тот же список разрешённых хостов (`:712-737`). Второй клиент и второй набор переменных окружения создавать нельзя. Output DTO в `schema.go` рядом с `GetResultOutput` (`:130-178`). Дескриптор в `toolDescriptors` рядом с `beacon_get_result` (`server.go:167-177`).

Шаги: на входе взять Watch из `deps.Store`, проверить, что `checkName` есть в `failedChecks` этого Watch, и refuse с `CodeInvalidInput` иначе. Ограничить `LimitBytes` потолком 16384. Прогнать ответ через уже существующие `observe.Redact`, `escapeUntrusted` и `clampExcerpt` (`tool_get_result.go:603-666`). Кэшировать только полный санитизированный текст по расширенному ключу `(watchID, headSHA, checkName, "full")`, чтобы вторая страница не обращалась к GitHub повторно. Не возвращать сырые байты лога, которые могут содержать токены.

Проверка: тест с подставным источником возвращает 9 КБ лога. Первый вызов с `limitBytes=2048` отдаёт 2048 байт и `nextOffset=2048`. Второй вызов с этим смещением отдаёт следующие 2048 байт. Сумма `TotalBytes` равна длине санитизированного текста. Счётчик вызовов источника остаётся равным 1. Тест на строку вида `ghp_...` подтверждает redaction. Контрактный тест `tools/list` обновлён по замеру в CI.

Приёмка: агент читает упавший лог целиком за несколько вызовов MCP и не запускает `gh run view --log-failed`. Секундный предел источника и список хостов остаются прежними.
