Goal: record who launched a run and surface every dispatch result, so a failed run can never be hidden from the caller. No docs or layout edits.

Evidence: one MCP dispatch with n:5 saved five runs. Three appeared in the runs array. Two ACP children failed workspace creation and were returned only in the failures field. The assistant wrapper read only runs and skipped, then denied launching them. A read-only investigation of opencode.db and state.db confirmed one dispatch call produced all five runs.

Scope: pkg/core/run.go, internal/app/status.go, internal/app/status_test.go, internal/infra/mcp/tool_dispatch.go, internal/infra/mcp/tool_dispatch_test.go, .opencode/plugins/beacon-project/ui_view.js, .opencode/plugins/beacon-project/ui_view_test.js.

Steps:
1. Add a launch source field to core.Run with values mcp, cli, ui and daemon. Populate it where the dispatcher receives the parent from MCP metadata, from the CLI environment, or from an automatic path. Keep the existing parent session ID and add the agent identity when available. Do not store tokens.
2. Include the launch source in RunSnapshot and Metrics as a small counter or map. Show it in the existing metrics or technical line without changing sidebar layout.
3. Make the MCP dispatch result explicitly include failures in every caller-facing summary. Test a mixed case where one run starts and one fails, asserting both ids appear with state and reason.
4. Tests: launch source recorded for MCP, CLI and UI paths; snapshot and metrics serialize it; failed run appears in failures; existing dispatch tests keep passing.
5. Keep funlen <= 80 lines, statements <= 40, complexity <= 20. Run gofmt -w, targeted go test ./internal/app ./internal/infra/mcp, node --check on plugin JS and node --test .opencode/plugins/beacon-project/*_test.js. Open a PR, call beacon_watch_pr with the real run ID and PR number, do not self-merge.
