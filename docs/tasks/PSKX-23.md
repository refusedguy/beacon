Цель: Для нетривиальной работы строить инструмент, который делает её или доказывает: скрипт, codemod, генератор, повторяемую проверку; сначала один узел вручную, затем инструмент и проверка на том же узле.
Контекст: Источник: `pstack/skills/principle-build-the-lever/SKILL.md:9-13` (build the tool that does it). `AGENTS.md:61-67` описывает ветку, worktree и PR, но не требует, чтобы в PR нетривиальной работы лежал перезапускаемый инструмент. Правило наattro `baseline` в `AGENTS.md:27-35` требует измерения, а не скрипта. baseline: `git grep -i -E 'сначала вручную, затем инструмент|инструмент в PR' -- AGENTS.md | wc -l` = 0 на `origin/main`. Карточка фиксирует приём в дереве beacon, не создаёт новый глобальный скилл и не меняет протокол Watch. Не дублирует PSK-01 (кандидаты), PSK-02 (адверсарии), PSK-03 (TLA Watch), CP-01..05, CM-01..05 или закрытые дубли HD-099/HD-105/HD-109. Риск: низкий.
Шаги: Добавить в раздел «Своя ветка и PR» правило «Инструмент в PR»: первый узел сделать вручную, затем собрать минимальный скрипт, доказать его повтором на том же узле и committed-артефактом. Запретить заменять инструмент ручным проходом ради экономии времени. Фреймворк не строить.
Проверка: `git grep -n -E 'сначала вручную, затем инструмент|инструмент в PR' AGENTS.md` находит правило и требование артефакта.
Приёмка: В PR нетривиальной работы есть перезапускаемый инструмент или явное объяснение, почему работа тривиальна. Инструмент можно запустить второй раз.
