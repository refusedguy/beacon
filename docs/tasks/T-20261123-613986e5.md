Align the TUI half of the beacon-project plugin with the working pattern from streetturtle/opencode-better-sidebar. In `.opencode/plugins/beacon-project/ui.js`, import `Plugin` from `@opencode/plugin/tui` and make the default export `Plugin.define({ id: 'beacon-project-status', setup(ctx) { ... } })` instead of a plain object. In `.opencode/plugins/beacon-project/package.json`, pin `@opencode/plugin` to a v2 range and add peerDependencies for `@opentui/core`, `@opentui/solid` and `solid-js` with versions compatible with OpenCode 2.3.2; keep the `./tui` export. In setup, use the verified imperative OpenTUI API already in the file, but do not depend on the server RPC for first render: fall back to the existing CLI status source when `ctx.client.rpc` fails, so the panel always shows either live runs or a clear error line. Register the view in `sidebar.content` and also in `home.footer.status` so it is visible even when the sidebar scroll hides appended claims. Keep the existing BeaconStatusSource interface and tests. Update tests for the new default export shape and the CLI fallback. Run node --check and node --test, open a PR and call beacon_watch_pr.

UI POLISH REQUIREMENTS: The current panel wraps badly in a narrow sidebar and repeats task IDs and titles. Render at most two compact lines per active run: line one is a colored state marker plus a shortened task ID and a truncated title, line two is PR number plus reason truncated with an ellipsis. Use fixed-width truncation and wrapMode none so no line wraps mid-word. Never print the same ID or title twice. Show "No active runs" and "No recent runs" cleanly. Keep the separator between sections. Add tests asserting exact rendered lines for a long title, a long reason, empty state and a blocked run.
