# T-d1000004. Q3a: Cut status and no-daemon control startup cost

## Goal
Measure and remove the startup cost in the status read paths and in no-daemon control.

## Evidence
BenchmarkStatusCLIPaths drives the real cobra command end to end but emits no canonical row and has no registry key. wireReadOnly at commands.go:53 calls workspace.New, which runs git rev-parse and whose result the status branch discards. No-daemon control loads config twice: loadConfig at commands.go:158 and again through wireReadOnly at commands.go:169 and 181.

## Steps
1. Keep the status-cli-paths canonical row and its work and error assertions in status_cli_bench_test.go so each variant has a deciding row.
2. V1: skip workspace.New for status and status --snapshot while keeping it for gc.
3. V3: reuse the already loaded config in no-daemon control instead of loading it twice.
4. Work in your own worktree off current main. Never push to main. Never run go test, go build, go vet, linters, node tests or benchmarks locally. One variant is one commit and one push; read the beacon-pr-perf comment after each push; keep a variant only on gain including gain (allocs/bytes) with equal work, errs zero, non-empty limiter and warm cache; revert with git reset --hard HEAD~1 and git push --force-with-lease. Never add ready-to-merge before all variants are checked and the final table is in the PR body. Call beacon_watch_pr. CI supplies every check.

## Accept
Status and status --snapshot no longer pay for git rev-parse, gc still does, no-daemon control loads config once, and each kept variant shows gain on status-cli-paths with equal work and zero errors.
