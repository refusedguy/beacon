Goal: make the root app -race job pass so every PR can merge again.
Evidence: CI job 140869391350 on PR 2876 reports many WARNING: DATA RACE in internal/app/mocks_test.go. fakeWorkspace.Create at line 251 reads and increments f.creates from two goroutines started by Dispatcher.launch at dispatcher.go:393. fakeSource.MarkInWorkspace at line 54 appends to f.marked and calls f.log.add from the same parallel wave. The parallel launch came from T-d42d4241 merged in PR 2860; the worker for PR 2874 reproduced the same three failures on clean origin/main at 4aab1401, so this is a base-branch defect, not a branch defect. Every root app -race job now fails, which keeps PRs 2876 and later ones in needs_agent_fix or waiting_ci and blocks dispatch.
Steps: add a sync.Mutex to fakeWorkspace and fakeSource and guard every field the parallel launch touches, at minimum creates, pushes, commits, removed, forcedRemoves, claimed, complete, marked and the callLog wrapper; keep the createErrOnce first-call semantics intact under the lock; add a targeted -race test that launches several runs concurrently and asserts the counters and call log contain one entry per run; do not change production dispatcher code or the parallel launch behavior.
Accept: go test -race ./internal/app passes on main with no data race, and a PR branch with no other changes gets a green root app check.
