# T3.246. Проверка рендера в pane
Premise: проверено 2026-11-21, функционал в origin/main отсутствует, дубль не создан. Карточка просит различать доставку и подтверждение отображения по сравнению capture pane до и после: последние строки, удаление input box, сравнение конверта целиком или первых 40 символов. Это механизм OpenRig `--verify` над tmux pane. В `internal/infra/wake/deliver.go` нет захвата pane, нет исходов `rendered-unconfirmed`, `failed` и `retained`. Функция `verifyAck` в строке 358 проверяет подтверждение API, а не экран. Словарь статусов файла это T206 (started, queued, delivered, duplicate, closed, unsupported) и T210 (delivered, queued, enqueued, skipped, error). Ни один из них не описывает проверку рендера. Beacon доставляет сообщение в сессию `ses_` через ACP или API, tmux pane для захвата нет. Сестёрские карточки T3.266, T3.267 и T3.268 сняты в PR #394 по тому же основанию: tmux нет, OwnerFiles заглушка deliver.go. ADR 0062 берёт статус агента из событий жизненного цикла внутри процесса, а не из скрапинга экрана. Зависимость T3.245, вставка через paste-buffer в pane, в origin/main всё ещё todo. Настоящая проверка требует живого pane и OpenRig `--verify` с capture. Здесь доступны только gofmt и текст. Код не писал, OwnerFiles не менял, gofmt не применял. Статус todo сохранён, блокер возвращён оркестратору.
