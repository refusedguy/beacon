# T3.246. Проверка рендера в pane
Premise: перепроверено 2026-11-21 по свежему origin/main (389604e; база ветки fix/ad3 была 648bda2, с тех пор коммиты docs-перепроверок других карточек и fix(idx-11), OwnerFiles карточки не трогают). Функционал проверки рендера в pane в main отсутствует, дубль не создан. Проверил wake delivery и envelope по заданию оркестратора. Доставка wake есть: `OpenCodeDeliverer.Deliver` (`internal/infra/wake/deliver.go:104`) через `PromptFunc` (:36, :174) и CLI fallback (:195); envelope wake это `Envelope` (:274) и `T202Envelope` (:686), они кладут в текст пробуждения только идентификаторы. Но это доставка текста в существующую сессию `ses_` через ACP/API, а не захват экрана. Карточка просит различать доставку и подтверждение отображения по сравнению capture pane до и после: последние строки, удаление input box, сравнение конверта целиком или первых 40 символов. Это механизм OpenRig `--verify` над tmux pane. В origin/main нет ни `capture-pane`, ни tmux, ни исходов `rendered-unconfirmed`, `failed` и `retained`: `git grep -Ec 'rendered-unconfirmed|capture-pane' origin/main -- '*.go'` пусто, `grep -Eic 'capture-pane|tmux|rendered-unconfirmed|rendered|retained' internal/infra/wake/deliver.go` = 0. Вхождения `verify` в deliver.go это вызов :219 и `verifyAck` (:378, :381); он проверяет, что API admitтил промпт по id в ответе, а не экран. Словарь статусов файла это T206 (started, queued, delivered, duplicate, closed, unsupported, :798-803) и T210 (:859-862). Ни один не описывает проверку рендера. Beacon доставляет сообщение в сессию через ACP или API, tmux pane для захвата нет. Сестёрские карточки T3.266, T3.267 и T3.268 сняты в PR #394 по тому же основанию: tmux нет, OwnerFiles заглушка deliver.go. ADR 0062 берёт статус агента из событий жизненного цикла (`agent_start`, `agent_settled`) внутри процесса, а не из скрапинга экрана. Зависимость `docs/tasks/T3.245`, вставка через paste-buffer в pane, в origin/main всё ещё todo. Настоящая проверка требует живого pane и OpenRig `--verify` с capture. Здесь доступны только правка текста и gofmt, живой зонд поднять нельзя. Код не писал, OwnerFiles не менял, gofmt не применял, чужие файлы, wiring и .beacon не трогал. Статус todo сохранён, блокер возвращён оркестратору.
