# T3.23. RejectDuplicate и idempotency_key для идемпотентного старта
Статус: done
Фаза: P3
Тип: task
Владелец файлов: internal/domain/identity.go, internal/domain/identity_test.go, internal/infra/store/receipts.go, internal/infra/store/receipts_test.go, internal/infra/store/db.go, internal/infra/store/db_test.go
Зависимости: T3.21
Ссылка: ADR 0031
Агент: нет
Время: 2026-11-20T02:00:00Z
Цель: Повторный старт задачи с тем же idempotency_key возвращает уже существующую задачу, а не создаёт вторую; конфликт фиксируется как RejectDuplicate.
Контекст: ADR 0031, раздел 5; отчёт Q 1.4 (durable-mcp). Ключ пишется в одной транзакции с состоянием по ADR 0015 и не ломает правило ADR 0028 о clientRequestId. Владельцы ack.go и wait_result.go переданы T3.21, отсюда зависимость.
Шаги: Ключ идемпотентности в identity; запись ключа в одной транзакции в db; возврат существующей задачи при повторе; фиксация конфликта в receipts; проброс RejectDuplicate в ack и wait.
Проверка: Тесты повторного старта; вторая задача не создаётся; ключ и состояние пишутся в одной транзакции; clientRequestId из ADR 0028 не сломан.
Приёмка: Повторный старт с тем же ключом возвращает исходную задачу и помечает конфликт как RejectDuplicate.
