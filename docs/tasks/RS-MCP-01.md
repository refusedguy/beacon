Цель: Сделать листинг инструментов проверяемым артефактом CI: два соединения получают одинаковый список, имена уникальны, порядок детерминирован.
Контекст: Premise проверена 2026-11-21. Теста стабильности между соединениями в main не было. Ближайшие проверки живут в server_test.go и tool_*_test.go, но они читают одно соединение и не сравнивают байты двух листингов. baseline до правки: `grep -c '^func Test' internal/infra/mcp/contract_test.go` = 3, `grep -c 'listTools\|tools/list'` в том файле = 8, расхождение контракта 7 против 8 зафиксировано в evals/main.go:43 (`contractToolCount = 7`) против восьми имён в ToolNames. Замер сериализованного ответа tools/list на Go 1.26.0 (версия из go.mod, её же ставит CI): 16095 байт, SHA-256 `8324205f18b1b4c8e90843aeafcad90b8170c8c7ae7b49733a864b6a358f3aab`. Порядок ответа: beacon_ack, beacon_cancel_watch, beacon_defer_wiring, beacon_get_result, beacon_list_running, beacon_stats, beacon_wait_result, beacon_watch_pr. Два независимых соединения дали побайтово равные ответы в трёх повторах.
Шаги: Добавлен `TestToolsListStabilityAcrossConnections` в internal/infra/mcp/contract_test.go. Хелпер `toolsListRawBytes` поднимает новую пару сервер/клиент на собственном in-memory транспорте и возвращает сериализованные байты листинга. Тест сравнивает байты двух соединений, проверяет точный размер 16095, SHA-256, уникальность имён и фиксированный порядок. Размер и хеш зафиксированы константами с пояснением. Негативный контроль: перестановка двух инструментов меняет хеш даже при равной длине имён, поэтому тест падает. Проверка закрытия по мёртвому watchID из шагов карточки не вошла в этот PR: она проверяет поведение beacon_cancel_watch, а не листинг, и её естественный домен tool_cancel_watch_test.go не входит в OwnerFiles карточки.
Проверка: gofmt чистый. gofmt -w применён только к internal/infra/mcp/contract_test.go. `go test` локально не запускался по правилам AGENTS.md, зелёность подтвердит CI на PR. Негативный контроль обеспечен сравнением SHA-256 с эталоном.
Приёмка: Тест проваливает листинг при изменении набора инструментов, описаний или порядка без обновления констант. Тем самым расхождение 7 в evals/main.go и 8 в ToolNames больше не остаётся без проверки.
