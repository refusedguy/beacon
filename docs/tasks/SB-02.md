# SB-02. Код выхода тестов отделён от кода выхода очистки

Цель: Отличать код выхода тестовой команды от кода выхода обёртки с успешной очисткой.
Контекст: Источник: docs/research/comp-swebench.md, карточка SB-02, `swebench/harness/utils.py:222-241`, `:225-228`, `swebench/harness/grading.py:51-58`, `:162-175`. Скрипты оценки заканчиваются `git checkout`, который восстанавливает тестовые файлы, и работают под `set -uxo pipefail` без `-e`. Код выхода всего скрипта поэтому принадлежит очистке. `record_test_exit_code` (`utils.py:222-241`) сохраняет `$?` сразу после тестовой команды и печатает число после маркера окончания вывода. Грейдер читает его через `TEST_EXIT_CODE_RE` (`grading.py:51-58`) и отвергает расхождение (`grading.py:162-175`). В beacon `ExternalCheck` (`internal/domain/verdict.go:672-675`) хранит число без указания источника. `CheckOutcome` (`verdict.go:696-701`) записывает то же число в доказательство. Никакой контракт не обязывает адаптер сообщать код выхода тестов, а не обёртки. `EvaluateExternal` (`verdict.go:728-775`, решение на `:762`) не может заметить такую подмену. baseline: `rg -c 'TEST_EXIT_CODE_VAR|record_test_exit_code'` по `utils.py` даёт 5 строк. `rg -c 'ExitCode|exit_code'` по `verdict.go` даёт 13 строк, все без поля источника. Сейчас доказательство обёртки с падающими тестами и зелёной очисткой даёт `Passed: true` и `ExternalPass`.
Шаги: Добавить в `ExternalCheck` (`verdict.go:672-675`) отдельное поле с кодом выхода тестовой команды и признак того, что адаптер его сообщил. Пробрасывать это поле в `CheckOutcome` (`verdict.go:696-701`) и доказательство на диске. В `EvaluateExternal` (`verdict.go:728-775`) требовать код тестов, а не код обёртки, и давать `ExternalFail` при ненулевом коде тестов. Не менять существующее поле `ExitCode` и правило fail-closed для отсутствующего наблюдения. Зафиксировать контракт в тесте адаптера, чтобы обёртка с зелёной очисткой не перекрывала падение теста.
Проверка: Скрипт запускает падающий тест с кодом 1, затем успешную очистку с кодом 0. Итоговый код обёртки равен 0, доказательство хранит код тестов 1 и даёт `ExternalFail`. Негативный контроль: зелёный тест с кодом 0 и падающая очистка с кодом 1 не меняют вердикт на FAIL. Существующие тесты `EvaluateExternal` проходят без правок.
Приёмка: Ошибка адаптера больше не выглядит как зелёная проверка. Источник числа в доказателе виден из самого доказательства.
