# T1.3. Revision, ключ обязательства и идемпотентность watchID+revision+subscriberID
Статус: done
Фаза: P1
Тип: task
Владелец файлов: internal/domain/identity.go, internal/domain/identity_test.go
Зависимости: T1.1
Ссылка: ADR 0015
Агент: T1.3
Время: 2026-11-19T13:23:00Z
Цель: Обеспечить монотонный revision и один вычисляемый ключ обязательства для версии и подписчика.
Контекст: WORKER-PROMPT §4.2 задаёт revision uint64 и Obligation.id = f(watchID,revision,subscriberID); неварианты 2 и 3 требуют ключ идемпотентности watchID+revision+subscriberID и монотонный не переиспользуемый revision. ADR 0015 фиксирует в базе UNIQUE(watch_id, revision, subscriber_id). C §3 называет obligation ledger с ключом watchID+revision отсутствующим в Tirith и dibs.
Шаги: 1. Реализовать NextRevision(current uint64) uint64 с защитой от переполнения. 2. Реализовать ObligationKey(watchID string, revision uint64, subscriberID string) с детерминированным представлением. 3. Покрыть тестом стабильность ключа при повторном вызове и монотонность при перестановке событий.
Проверка: Юнит-тест на одинаковый ключ для одинаковой тройки, разные ключи при смене любого компонента и 1000 шагов NextRevision без повторов.
Приёмка: Один и тот же набор аргументов всегда даёт один obligationID, revision не уменьшается и не повторяется.
