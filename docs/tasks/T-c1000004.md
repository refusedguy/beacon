## Goal
Make a forced reconcile and the daemon tick converge on one run transition.

## Evidence
From T-5115e3a5: run writes are atomic but callers load, decide and save later, so a daemon tick and forced beacon_reconcile can both reconcile one PR and last writer wins. From T-7c7f30f9: beacon_reconcile returns noop with empty reason for an unbound PR. T-baadf270 scoped this file but gave it no separate retention step; retention stays in the store card.

## Steps
Use the store compare-and-swap primitive keyed by updated_at or head SHA on the reconcile save path. Return an explicit coded error for an unbound PR instead of an empty noop. Add tests in the new internal/app/reconciler_cas_test.go that a stale write is rejected and two reconcilers leave one transition.

## Accept
A forced reconcile cannot overwrite a concurrent daemon transition, and an unbound PR produces an explicit reason.
