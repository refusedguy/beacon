Goal: make the required-check set reflect the workflow at the head under evaluation, not the config snapshot from daemon startup.
Evidence: internal/infra/checksource/workflow.go:21-26 re-reads workflows on every call and is used only in tests; production main.go:344-355 freezes checksource.Config{Explicit: cfg.Merge.RequiredChecks} from config load; cmd/beacon/config_watch.go:141-149 hashes only the config file, so a workflow rename leaves the old required names until someone edits config. internal/infra/config/config.go:303-306 keeps the explicit list when detection is empty, and internal/infra/policy/configurable.go:108-111 returns noop for an empty list, which opens the gate. internal/infra/shared/workflow.go:16-25 returns empty on a glob error. verdict.go:168,179 counts CheckSkipped as pass even when a required job was skipped by an if condition, because configurable.go:115-119 waives on WorkflowSkipped.
Steps: wire checksource.Workflow into mergePolicy so each evaluation detects names from the workflow; make the config watcher observe workflow files and swap policy when they change; fail closed in workflow mode when detection yields zero names unless an explicit fallback was supplied; treat a skipped required job as pass only when the skip is declared acceptable for that diff; scope the failure invariant to required names so a non-required failure cannot block. Keep one result per check name chosen by newest CompletedAt, with cancelled and timed_out excluded from both success and failure sets, as already specified in T-8b02b25b.
Accept: a workflow rename changes the required set on the next tick without a config edit, zero detected names blocks instead of merging, and a non-required failed check cannot block a merge.
