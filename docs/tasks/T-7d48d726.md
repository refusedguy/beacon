Goal: Use one CliStatusSource and one process for the dispatch action and its follow-up read.

Evidence: dispatch-03 and dispatch-08. The RPC host and the TUI each hold a separate CliStatusSource, so a click spawns beacon dispatch then beacon status. enrichRuns re-reads cards that ListAvailable and ListReadyTasks already loaded.

Steps: Share one verified source, return the new run data from dispatch when possible, and let the refresh use it instead of a full re-read.

Check: One click performs one CLI process lifetime and the panel shows the new run.

Accept: No wire shape change.
