# T3.7. Шаблон задания исполнителя: сдал PR, завершил ход, ждёт вердикта

Статус: todo
Фаза: P3
Тип: task
Владелец файлов: docs/templates/executor-task.md
Зависимости: T2.6, T3.3
Ссылка: ADR 0004
Агент: нет
Время: нет

Цель: Дать исполнителю шаблон задания, по которому он регистрирует Watch, сдаёт PR, завершает ход с отчётом «waiting, watchID» и просыпается только на вердикты keep_working, rebase и retry.

Контекст: WORKER-PROMPT §4.7 задаёт цикл исполнителя: register, push PR, завершить ход с отчётом «waiting, watchID», просыпаться только на keep_working, rebase и retry, re-run делать своими правами через `gh run rerun --failed`. D4 определяет сон как завершение хода для OpenCode. ADR 0004 и WORKER-PROMPT §4.6 устанавливают, что Beacon read-only и только детектирует сброс suite, а повтор проверок делает агент. ADR 0001 сохраняет concurrency агентов без ограничений. ADR 0019 убирает TTL как причину закрытия Watch, поэтому долгий цикл rebase не обрывается по времени.

Шаги:
1. Создать `docs/templates/executor-task.md` с шагами register, push PR, finish turn.
2. Зафиксировать точный текст отчёта «waiting, watchID» как обязательный при завершении хода.
3. Перечислить вердикты, которые будят исполнителя: keep_working, rebase, retry. Для ready, watching, merged, closed и timeout пробуждения нет.
4. Добавить правило: re-run проверок выполняет агент своими правами, Beacon только детектирует сброс suite.
5. Добавить тест шаблона, который подаёт на вход набор вердиктов и проверяет, какие из них разрешают пробуждение.

Проверка: Тест разбирает шаблон и проверяет, что ready и watching не вызывают пробуждение, а keep_working, rebase и retry вызывают. Текст «waiting, watchID» присутствует в шаблоне. В шаблоне нет команды, которую выполнял бы Beacon от имени агента.

Приёмка: Шаблон описывает сон через завершение хода. Исполнитель просыпается только на три вердикта. Re-run делается правами агента. Нет TTL как причины выхода из цикла.

Гейт: G2. Шаблон входит в сниппет установки, который применяет владелец.
