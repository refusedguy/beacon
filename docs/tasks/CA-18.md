# CA-18. Версионируемый кэш тегов с проверкой mtime и fallback
Статус: todo
Фаза: P2
Тип: task
Владелец файлов: cmd/beacon/index.go, AGENTS.md
Зависимости: 
Ссылка: docs/research/comp-aider.md
Агент: нет
Время: нет
Цель: Кэшировать разбор файлов по версии и mtime с переходом на память при отказе хранилища.
Контекст: Источник: docs/research/comp-aider.md, дополнение к CA-01. aider хранит теги в SQLite-кэше с версией формата в имени каталога (`aider/repomap.py:35-43`), проверяет mtime файла перед использованием (`repomap.py:227-264`) и при ошибках SQLite пересоздаёт кэш, а при повторной ошибке падает на словарь в памяти (`repomap.py:177-215`). Рендер дерева тоже кэшируется по ключу `relative path + строки интереса + mtime` (`repomap.py:710-746`). В beacon индекс карточек пересобирается целиком (`cmd/beacon/index.go:33-71`), а инструментальная инструкция прямо запрещает править его вручную (`AGENTS.md:69-71`). Кэша разбора и graceful degradation нет. Baseline: полный пересбор на каждый запуск.
Шаги: Завести версионируемый кэш разбора с ключом по пути и mtime. При битом или недоступном хранилище переключаться на in-memory кэш без падения команды. Кэшировать рендер по набору строк интереса. Оставить `beacon index build` источником пересборки.
Проверка: Прогнать 100 запусков на неизменённом дереве. Требовать 0 повторных парсингов после первого, корректную инвалидацию после изменения mtime и успешный запуск с недоступным файлом кэша. Baseline 100 парсингов.
Приёмка: Повторные запуски не парсят файлы заново, изменение mtime инвалидирует запись, отказ хранилища не ломает команду.
