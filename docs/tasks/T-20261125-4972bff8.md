Goal: Add operation_id to all task mutation tools.

Evidence: Tool journal keys are derived per call and duplicate calls can race. The operator wants retry and cancellation to return the same result instead of re-writing cards.

Scope: internal/infra/mcp/server.go, internal/infra/mcp/server_test.go, internal/app/taskcreate.go, internal/app/taskupdate.go, internal/app/taskdelete.go.

Steps: Add optional operation_id to create, update and delete. Journal completed results bounded to 128 entries with a mutex. Return applied, duplicate or recovered status. Keep existing single-id results for compatibility.

Accept: A repeated operation_id returns the stored result without writing again, and no token or raw error is logged.

Closed as a duplicate. PR #2390 (T-20261124-3e3582cd) already added operation_id to create, update and delete, with a 128-entry mutex-guarded journal and applied, duplicate and recovered statuses. Targeted tests for internal/infra/mcp and internal/app pass on main.

Open a PR, call beacon_watch_pr, do not self-merge.
