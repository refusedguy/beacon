Context: PR #2311 removed the build-hash watchdog, the debounce timer and every ctx.mcp.reload() call from `.opencode/plugins/beacon-project/mcp.js`. Registration now happens once at session setup. Still, 9 `beacon mcp` processes are alive for this project root. The operator requires exactly one daemon, attached manually, with no automatic start or restart on commits, fetches, merges or task-card writes.

Goal: find why extra daemons spawn and make one daemon serve all sessions.

Steps:
1. Determine the source of the extra processes. Check whether the server-side `registerBeaconMcp` call in `.opencode/plugins/beacon-project/index.js` starts a daemon per session, and whether the others are orphans left by earlier reload storms.
2. Change the plugin so it does not start or restart a daemon on its own. Keep only what is needed for the operator to attach the MCP manually. Workers must still get beacon_dispatch, beacon_watch_pr, beacon_status, beacon_wait and beacon_control from their session MCP.
3. Make startup idempotent: repeated setup in the same project root must not create a second daemon.
4. Update tests. Assert repeated registration creates one server config, no timer or reload is scheduled, and no daemon command runs during setup.
5. Open a PR and call beacon_watch_pr with the real run ID and PR number.

Check: after a clean OpenCode restart, `pgrep -fc 'beacon mcp'` returns 1. After a git commit, fetch, merge and task-card creation it stays 1.

Accept: do not kill other workers' sessions or remove their worktrees. Do not edit another card's status by hand. Keep files under 350 lines. Do not edit AGENTS.md.
