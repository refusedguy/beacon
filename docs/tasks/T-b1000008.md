Goal: stop a daemon or MCP server from starting after its sources have changed.

Evidence: doctorBinaryFreshnessCheck at cmd/beacon/doctor.go:604-627 is advisory only. serve and mcp do not check freshness, so a pooled MCP process kept serving old policy until an operator restarted it by hand. A stale binary can also acquire the daemon lock.

Steps:
1. In newServeCommand and newMCPCommand, compare the embedded build hash from T-b1000007 with doctorBuildHash before acquiring a lock, binding a port or serving tools.
2. On mismatch, refuse to start and print the exact rebuild and restart command from T-b1000007. Do not write .beacon/connection.json and do not become lock owner.
3. Keep doctor as an advisory preflight. Do not change the success path of either command.
4. Add tests in cmd/beacon/stale_binary_test.go that a mismatched hash prevents both serve and mcp from starting and that a matching hash leaves startup unchanged.

Accept: no stale binary can become lock owner or MCP server after a rebuild, and the error names the command that fixes it.
