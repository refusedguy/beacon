Goal: A long-lived PR can chase a moving base without a hardcoded two-rebase cap.

Evidence: maxAutoRebases is a package constant of 2 in internal/app/reconcile_observation.go. PR #2541 used one automatic rebase at 11:20 and has been stuck for hours because main advances with every merged card. The reconciler returns needs_rebase but cannot spend a second attempt while checks or base keep changing. Card T-e86b55f7 unified the budget helpers but deliberately kept the cap itself fixed.

Steps: Add merge.max_auto_rebases to config with the current value 2 as default. Pass it into Reconciler and replace the constant with the configured cap. Keep the separate MaxAttempts budget untouched. Add a test that a configured cap of 5 lets a run rebase five times before blocking.

Check: A run behind a moving base exhausts only the configured number of attempts and records the same block reason.

Accept: Do not edit ci.yml or .beacon/config.yaml in this card. The operator sets the value after the code lands.
