# CA-15. Только фатальные ошибки линтера в быстром гейте
Статус: todo
Фаза: P2
Тип: task
Владелец файлов: internal/infra/mcp/schema.go
Зависимости: 
Ссылка: docs/research/comp-aider.md
Агент: нет
Время: нет
Цель: Отбирать для быстрого гейта узкий набор фатальных кодов вместо всего вывода линтера.
Контекст: Источник: docs/research/comp-aider.md, дополнение к CA-05. aider запускает flake8 с `--select=E9,F821,F823,F831,F406,F407,F701,F702,F704,F706` и `--isolated`, то есть берёт только ошибки, ломающие разбор или выполнение (`aider/linter.py:136-168`). Остальные замечания не блокируют ход. В beacon `FailedCheck` несёт `Required` и `FlakyMatched` (`internal/infra/mcp/schema.go:67-84`), но нет разделения по тяжести внутри проверки; любая найденная проблема считается причиной починки. Baseline: доля ложных починок по стилистическим замечаниям не измерена.
Шаги: Добавить классификатор тяжести для замечаний линтера и флаг `fatalOnly` в локальный предпроход. Все не-фатальные замечания уходят в информационный канал без wake. Сохранить поля `required` и `flakyMatched` без изменения.
Проверка: Подать на вход 100 замечаний, из них 5 фатальных. Требовать, чтобы в блокирующий канал попало ровно 5, а остальные 95 были отмечены информационными. Повторить на 10 наборах. Baseline 100 блокирующих.
Приёмка: В блокирующий канал попадают только фатальные коды, информационные замечания не будят исполнителя.
