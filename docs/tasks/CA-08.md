# CA-08. Структурный ответ при неудачном применении правки
Статус: todo
Фаза: P2
Тип: task
Владелец файлов: docs/templates/executor-task.md, internal/infra/batchapply/apply.go
Зависимости: 
Ссылка: docs/research/comp-aider.md
Агент: нет
Время: нет
Цель: Возвращать агенту причину неудачной правки и список похожих строк вместо общего отказа.
Контекст: Источник: docs/research/comp-aider.md, дополнение к CA-03. Если блок SEARCH/REPLACE не совпал, aider ищет похожие строки с порогом 0.6 (`aider/coders/editblock_coder.py:602-630`) и собирает причину: failed-блок, вариант «did you mean», «уже применено» и явный запрет пересылать успешные блоки (`:82-124`). Перед отказом блок пробуется на других файлах чата (`:55-65`). В beacon прикладного слоя правок нет: агрегат документных артефактов предлагает только `--check`, `--dry-run` и `--commit` (`internal/infra/batchapply/apply.go:96-105`), а агент редактирует файлы инструментами хоста (`docs/templates/executor-task.md:152`). Baseline: при искажённом блоке агент получает сообщение инструмента без похожих строк.
Шаги: Выделить слой применения структурированных правок с категориями отказа. Для каждого неудачный блок искать похожие строки по порогу 0.6. В ответе помечать успешные блоки и запрещать их повторную отправку. Добавить проверку «REPLACE уже есть в файле».
Проверка: Взять 20 искажённых блоков: сдвинутый отступ, лишняя пустая строка, многоточие, иное число пробелов. Требовать, чтобы для не менее 18 блоков ответ содержал похожую строку из файла, а все успешные блоки были помечены как применённые. Baseline 0 из 20.
Приёмка: Не менее 18 из 20 отказов дают причину с похожими строками, повторная отправка успешных блоков исключена контрактом.
