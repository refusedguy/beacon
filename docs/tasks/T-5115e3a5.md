Goal: give one process ownership of run, task and worktree writes so a CLI invocation cannot race the daemon.
Evidence from audit: beacon.lock is taken only by serve and standby MCP, while beacon dispatch, beacon control with no daemon, beacon gc and orchestrator MCP tools write without it. Two Dispatcher instances have separate slotsMu and reserved maps and can both select one ready card, create one worktree and save two runs. state.db schema preparation is a check-then-DDL sequence that two openers can both run. Run writes are atomic but callers load, decide and save later, so daemon tick and forced beacon_reconcile can both reconcile one PR and last writer wins. syncCache is process-local, so two processes keep different fingerprints for one tasks table. docs/tasks and worktrees have multiple writers with no cross-process coordination. runsCache is invalidated on PR broadcast before the reconciler saves, so a monitor can refill it with stale bytes.
Steps: make state.db the serialization boundary with compare-and-swap on run state keyed by updated_at or head SHA; record the run claim in the DB before creating a worktree; move schema preparation under one startup owner or a transactional migration guard; give the task graph a single writer, with dispatch reading only; make monitor invalidation happen after the save commits or carry a store-backed version; give daemon state files one owner and write errors with a process key so a loser's diagnostic is not cleared by the winner; add tests that open two instances against one temp DB and assert at most one run per task and one active owner per PR.
Accept: a CLI dispatch cannot race a daemon dispatch into two runs for one task, and a forced reconcile cannot overwrite a concurrent daemon transition.
