Goal: stop a hand-authored or tool-written title from silently dropping a card out of the index and state.db.
Evidence: five cards shipped with title: [perf] ... which yaml.v3 rejects as a malformed flow sequence; parseCardFields logs a warning and skips the card, so it never enters the index, SyncTasks or state.db, while the JS plugin regex parser still displays it. The regression test used a different YAML error so it did not catch this shape, and no test walks the real docs/tasks corpus. fieldValue at taskupdate.go:288-294 quotes on ': ', ' #', newline and quote but not on a leading '[', so beacon_task_update can emit the same broken YAML. Go uses yaml.Unmarshal without KnownFields, so unknown keys are dropped silently and only hurt when malformed.
Steps: add a corpus test that parses every card in docs/tasks and fails with file and line on any malformed frontmatter; add a test reproducing the [perf] title shape; change fieldValue to quote on the first non-space character when it is one of the YAML plain-scalar hazards or when the value starts with '- ', '? ' or ': '; decide explicitly whether perf belongs in cardSchema or must be removed from cards before any strict decode; document the five load-bearing field groups and the alias set in a short schema note so a future writer does not invent a new shape. Do not enable strict decoding in this card because issue bodies still arrive as v1 text.
Accept: another [perf] title or a leading '[', '{', '*' or '?' fails a visible CI test instead of dropping the card from the daemon index.
