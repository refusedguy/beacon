Goal: make panels readable at the width the operator actually has. No Go edits.

Evidence from live screenshots: the hero action row is a non-wrapping row with flexShrink 0 buttons, so the last button is clipped. badgeRow and card controls have the same problem. Long paths and phase text wrap under fixed padEnd markers. An epic with five children renders all children and dependency IDs at once, with duplicate ID lines. @opentui/core 0.8.4 supports flexWrap, rowGap and overflow hidden, and OpenCode itself uses flexWrap in its error and permission components.

Scope: .opencode/plugins/beacon-project/ui_detail_view.js, ui_card_view.js, ui_nodes.js, ui_view.js, ui.js, ui_polish_test.js, ui_native_test.js, ui_card_test.js, ui_view_test.js.

Steps:
1. Add flexWrap wrap and rowGap 1 to actions, badgeRow and card controls. Keep buttons flexShrink 0 with their existing padding and marginRight. Add overflow hidden to heroCard and minHeight 0 to the detail scrollbox.
2. Let the status cell of card metadata, dependency and child rows shrink with minWidth 0 and truncate, so long titles steal less width. Keep the label alignment and word wrap.
3. Collapse epics by default in the queue and in card children. Show a chevron and a child count, toggle on click, remember the state in storage. Do not draw dependency IDs twice.
4. Keep clickable dependency and child rows, the Back control, ctrl+g and the close button. Do not add or reorder heroCard children, because ui_polish_test asserts their order.
5. Tests for narrow wrapping, collapsed default, expand on click and unchanged controls. node --check every plugin JS file and node --test .opencode/plugins/beacon-project/*_test.js. Every file <= 350 lines. Open a PR, call beacon_watch_pr, do not self-merge.
