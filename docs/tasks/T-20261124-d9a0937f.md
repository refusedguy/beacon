Context: the Beacon TUI panel still throws `No renderer found` every 5s after a full OpenCode restart. Root cause: `createRowMount.apply()` lazily calls `createElement`/`insert` when the row count grows. `ensureNodes()` builds nodes inside a slot render callback, but `refresh()` runs from setInterval with no renderer context and reaches `apply()`, which throws. Subagent PR #2346 contains the fix and is green (lint blocked only by the separate wire funlen issue). This card recreates it through Beacon.

Steps: 1) In `.opencode/plugins/beacon-project/ui.js`, preallocate MAX_ROWS = 64 row slots during mount (inside the first render callback). `apply()` must only set props and toggle `visible`, never call createElement/insert after mount. 2) Keep compact rows, wrapMode none, truncate, selectable false, theme colors, onMouseDown, session.panel detail, and the 16 MB CLI buffer. 3) Add a regression test in `ui_test.js` that drives refresh() with a row count change and asserts no createElement happens without a render context. 4) Run `node --check` and `node --test`. 5) Open a PR and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Check: no `No renderer found` in logs after a TUI restart; panel refreshes with changing run counts.
