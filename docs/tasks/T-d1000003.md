# T-d1000003. Freeze registry keys and limiters for CLI and watcher rows

## Goal
Keep the registry keys and limiters for the CLI and watcher canonical rows resolvable so every variant has a deciding row.

## Evidence
BenchmarkStatusCLIPaths drives the real cobra command end to end but emits no canonical row and has no registry key. BenchmarkOpenPreparedDB and run-watcher-fp need the same treatment, and the current benchmark fixture has no generatedAt and only two runs, so it cannot show the idle fingerprint skip. P5 (T-df77d6ed) and P15 (T-7f5473b8) already landed the canonical rows, the moving generatedAt arm and the keys in registry.go and bench-registry.json. This card owns the Go side of that wiring and locks it with tests; it does not own the JSON or the workflow.

## Steps
1. Keep registry entries for status-cli-paths, open-prepared-db and run-watcher-fp with their statusCLIPathsLimiter and openPreparedDBLimiter limiters.
2. Extend registry_test.go so each key must resolve to an emitted metric, including the work and err metrics, and so the moving generatedAt arm has its own expected work if P15 did not already cover it.
3. Do not touch docs/perf/bench-registry.json, which the nightly gate card owns, or .github/workflows/ci.yml, which T-d1000001 owns.
4. Work in your own worktree off current main. Never push to main. Never run go test, go build, go vet, linters or benchmarks locally. Call beacon_watch_pr. CI supplies every check.

## Accept
Every variant row has a registry key and a test that fails when the key stops resolving, and the scope overlaps no other card.
