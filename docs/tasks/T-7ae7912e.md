Goal: The plugin starts on a fresh checkout without a manual npm install.

Evidence: package.json declares @opentui/solid, @opentui/core and solid-js as peerDependencies but ships no installed copies. OpenCode v2.4.2 no longer rewrites these bare specifiers for the local plugin folder, so ui/ui.js fails with Cannot find package '@opentui/solid'. Running npm install @opentui/solid@0.9.9 --no-save inside the plugin directory restores resolution and node -e "import('@opentui/solid')" passes.

Scope: plugin package.json, scripts/ensure-plugin-deps.sh, README.md and .gitignore.

Steps: Decide whether the peers belong in devDependencies or an explicit local install step. Pin versions that match the supported OpenCode CLI. Add a script that installs them from the repository root and call it from the documented setup path. Ignore generated node_modules. Keep the literal dynamic imports in ui/ui.js for the OpenCode rewriter.

Check: from a clean checkout without plugin node_modules, run the documented command, then `cd .opencode/plugins/beacon-project && node -e "import('@opentui/solid')"` succeeds. Restart the TUI and the panel loads. `node --test .opencode/plugins/beacon-project` passes.

Accept: No production Go code and no wire shape change.

Open a PR, call beacon_watch_pr, do not self-merge.
