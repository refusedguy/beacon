# T2.16. Фикстуры особых случаев GitHub
Статус: in_progress
Фаза: P2
Тип: task
Владелец файлов: internal/infra/github/testdata/
Зависимости: T2.11
Ссылка: ADR 0004
Агент: нет
Время: 2026-11-19T15:05:00Z
Цель: Подготовить записанные GraphQL и REST фикстуры для особых случаев, влияющих на вердикт.
Контекст: WORKER-PROMPT §4.6 объявляет фикстуры обязательными и перечисляет случаи: fork PR, у которого pull_requests пуст и привязка идёт по headSHA через GraphQL; missing required check, когда все видимые проверки зелёные, но обязательная ещё не создана, что ведёт к timeout и эскалации; SKIPPED и NEUTRAL допустимы; ACTION_REQUIRED, WAITING и QUEUED дают pending с причиной; DRAFT не готов; merged и closed терминальны. WORKER-PROMPT §6, задача T2.2, требует фикстуры для движка вердиктов, включая BEHIND при обоих значениях requireUpToDate. D-github-ci-options описывает missing required check как отдельный риск, который выявляется через isRequired или branch protection.
Шаги: 1. Записать ответы GraphQL и REST для fork, missing required, SKIPPED, ACTION_REQUIRED, DRAFT, BEHIND с requireUpToDate true и false, merged и closed. 2. Положить их в каталог testdata и описать ожидаемый вердикт для каждой фикстуры. 3. Проверить, что ответы валидны против наших структур разбора.
Проверка: фикстурный тест загружает каждый файл и сравнивает ожидаемый вердикт с результатом движка. Тест требует наличия всех восьми случаев и корректной привязки fork по headSHA.
Приёмка: все фикстуры присутствуют, каждая даёт ожидаемый вердикт, fork привязывается по headSHA, BEHIND проверяется при обоих значениях политики.
