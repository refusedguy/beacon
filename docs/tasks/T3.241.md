Цель: Ввести стабильный адрес роли и отдельную сессию.
Контекст: Seat в OpenRig имеет имя {pod}-{member}@{rig}, human-authored и system-validated, без генерации и slugification.
Шаги: Завести тип адреса, парсер и резолвер. Отделить идентичность роли от run id.
Проверка: Смена сессии за адресом не меняет владельца обязательства.
Приёмка: Маршрутизация работает по роли и переживает рестарт агента.

## Подтверждение
- Реализовано: `Seat` в internal/domain/capabilities.go рядом со словарём ролей. `SeatAddress`, `ParseAddress`, `ResolveAddress` и `ErrInvalidSeatAddress` в internal/domain/identity.go рядом с ключами идентичности. Адрес `member@rig` разбирается по ровно одному `@`, обе части проходят существующие правила identity value. Резолвер возвращает `Seat`, выведенный только из текста адреса, поэтому сессия не входит в идентичность.
- Тесты в internal/domain/identity_test.go: парс валидного адреса, отказ невалидного с `ErrInvalidSeatAddress`, детерминированный resolve и неизменный ключ владельца, построенный из seat. gofmt применён к трём .go.
- PR: https://github.com/refusedguy/beacon/pull/1139 (ветка fix/t3241-seat-model).
- Ограничение объёма: internal/infra/wake/deliver.go не тронут, маршрутизация владельца обязательства через seat ведётся в T3.248 отдельным PR. Локальные go test и go build не запускались по правилам репозитория, проверку выполняет CI.
