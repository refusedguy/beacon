# T2.2. Output schemas и единый формат ошибки
Статус: done
Фаза: P2
Тип: task
Владелец файлов: internal/infra/mcp/schema.go, internal/infra/mcp/schema_test.go
Зависимости: T2.1
Ссылка: ADR 0003
Агент: нет
Время: 2026-11-19T14:10:00Z
Цель: Вывести output-схемы инструментов из Go-типов и описать единый формат ошибки с полями ok, code, message, status, retryAfterMs и newWatchID.
Контекст: ADR 0003 указывает, что go-sdk выводит input и output схемы из Go-типов. ADR 0009 задаёт AppError с кодом и статусом и перенос в единый error shape на границе MCP. WORKER-PROMPT §4.1 задаёт коды INVALID_INPUT, WATCH_NOT_FOUND, HEAD_SHA_CHANGED, RATE_LIMITED, LIMIT_EXCEEDED, CANCELLED, GONE, PERSIST_FAILED и статусы 400, 404, 409, 429, 410, 503. HEAD_SHA_CHANGED всегда несёт newWatchID. RATE_LIMITED наполняется из GraphQL 200-with-errors, REST 403/429 и secondary retry-after.
Шаги: 1. Описать Go-типы ответов instruments и сгенерировать output schemas. 2. Описать struct ошибки с шестью полями и таблицу соответствия код и статус. 3. Сделать функцию преобразования AppError в error shape на границе MCP.
Проверка: schema_test.go таблично проходит все 8 кодов и сверяет статус, проверяет, что HEAD_SHA_CHANGED заполняет newWatchID, а RATE_LIMITED заполняет retryAfterMs. Отдельно сверяется, что schema сгенерирована из типов без ручного JSON.
Приёмка: каждому коду соответствует свой статус, HEAD_SHA_CHANGED всегда содержит newWatchID, все output schemas выводятся из Go-типов.
