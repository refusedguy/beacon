# CV-03. Jitter в backoff провайдера ghci

Premise: проверено 2026-11-22 по `origin/main` `2d34645b`. Источник: OpenHands `src/utils/rate-limit-retry.ts:31-49` удваивает задержку после 429 и добавляет полный jitter, чтобы параллельные вкладки не повторяли запросы синхронно.

Разрыв: `internal/infra/ghci/provider.go:25-28` задаёт `defaultBackoff = 5s` и `maxBackoff = 60s`. При ошибке `:211-219` удваивает `e.backoff` до потолка и записывает `e.nextAllowed = now.Add(e.backoff)`. Случайной составляющей нет. Два провайдера, увидевшие transient failure в одно время, получают одинаковый `nextAllowed` и снова обращаются к GitHub одновременно. При этом `internal/infra/github/errors.go:31-35`, `:165-195`, `:282-290` уже содержит `defaultJitter` и `jitterOr`, то есть механизм в репозитории есть, но до ghci он не дошёл.

baseline: `rg -n 'jitter|rand' internal/infra/ghci/provider.go` = 0; `rg -n 'defaultJitter|maxJitter|jitterOr' internal/infra/github/errors.go` = 8; `rg -n 'e.nextAllowed = now.Add' internal/infra/ghci/provider.go` = 2, строки 219 и 228.
