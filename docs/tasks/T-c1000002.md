## Goal
Route CLI and standby MCP writes through the daemon lock, and make CLI refusals and cleanup failures visible to callers.

## Evidence
From T-5115e3a5: beacon dispatch, beacon control with no daemon, beacon gc and orchestrator MCP tools write without the lock; docs/tasks has multiple writers with no cross-process coordination. From T-7c7f30f9: CLI control prints JSON only on success, so the plugin cannot show the reason. From T-a697580c: gc prints ForceRemove errors to stderr then returns nil, so automation sees a clean cleanup.

## Steps
Require the lock or delegate writes to the daemon for CLI dispatch, control and gc, and for standby MCP writes. Print ok false JSON with action, id and reason on a CLI refusal. Aggregate gc removals and failures into a returned error with removed and failed counts. Add tests in cmd/beacon/commands_test.go for the refusal payload and gc failure exit.

## Accept
No CLI or MCP write escapes the daemon's serialization, an operator sees the refusal reason on the wire, and gc exits nonzero when cleanup fails.
