Goal: avoid reflection on trivial JSON values and preallocate snapshot assembly.

Evidence: store.go:388 decodeJSON calls json.Unmarshal for '{}', '[]' and empty strings on every ListActive and ListDecisions row. store.go:372 collectRows starts without capacity. status.go collectRunIDs and groupHistory do not preallocate, and prLink reparses the repo string per run.

Variants: V1 skip json.Unmarshal for empty, '{}' and '[]' with explicit reset of dst, and add collectRowsCap for ListActive, ListRunEvents and ListDecisions. V2 preallocate maps by len(ids), compute the PR base URL once in Snapshot and use strconv.Itoa. V3 compare BenchmarkFullSnapshot and BenchmarkSQLiteSnapshot medians, bytes and allocs.

CI commands: BenchmarkFullSnapshot, BenchmarkSQLiteSnapshot. Limiter: SQLite VM, ListRunEvents sort and JSON reflection.

Protocol: Work in your own worktree and branch off current main. Never push to main. Never run go test, go build, go vet, linters, node tests or benchmarks locally. Open a PR, call beacon_watch_pr with your run ID, add the `perf` label, and do not add `ready-to-merge` until every variant is tried. One variant is one commit and one push. After each push wait for the `<!-- beacon-pr-perf -->` comment and check that work counts match, errors are zero, a limiter is named, ranges do not overlap and the head median is strictly better. Keep a winning variant and move to the next. Revert a losing or inconclusive variant with `git reset --hard HEAD~1` and `git push --force-with-lease`. Put a final table in the PR body with base median, head median, ranges, work, errors and limiter, then add `ready-to-merge`.
