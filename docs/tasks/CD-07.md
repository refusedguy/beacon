baseline: dmux создаёт каталог `.dmux-hooks/` с четырьмя документами и пятью исполняемыми примерами (`src/utils/hooks.ts:423-526`, файлы `.dmux-hooks/AGENTS.md`, `CLAUDE.md`, `README.md`, `examples/*`). В `origin/main` при отсутствии `HooksDir` вызов просто возвращается (`internal/app/taskcli/service.go:114-125`), bootstrap отсутствует.

Цель: Дать проекту рабочие примеры хуков и встроенную справку при первом использовании, без ручного копирования файлов.

Контекст: `initializeHooksDirectory` в dmux проверяет наличие всех файлов одним проходом, создаёт недостающие, копирует `AGENTS.md` в `CLAUDE.md` и выставляет бит исполнения примерам (`hooks.ts:433-513`). Ошибка инициализации пишется в лог и не ломает основной вызов (`hooks.ts:521-525`). Beacon после #1551 требует, чтобы каталог сценариев уже существовал, и молча пропускает событие, если его нет (`service.go:121-125`). Пользователь не знает о существовании точек расширения.

Шаги: Добавить в `internal/app/taskcli/hook_bootstrap.go` функцию, которая получает путь каталога и набор шаблонов, и создаёт недостающие файлы через внедрённый интерфейс файловой системы. Сделать инициализацию идемпотентной: повторный вызов не перезаписывает существующие файлы. Покрыть тестами первый вызов, повторный вызов и отказ записи. Не менять `service.go` и шаблоны `executor-task.md` в этом PR.

Измеримая проверка: После первого вызова создано 4 документа и 5 примеров с битом исполнения. После второго вызова число записей равно нулю. При отказе записи функция возвращает ошибку, но не паникует.

Приёмка: Новый проект получает справку по хукам без внешней документации. Существующие скрипты не перезаписываются при обновлении beacon.
