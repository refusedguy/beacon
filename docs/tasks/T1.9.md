# T1.9. persist_error и loadErrors в beacon_stats
Статус: done
Фаза: P1
Тип: task
Владелец файлов: internal/infra/store/observability.go, internal/infra/store/observability_test.go
Зависимости: T1.7, T1.8
Ссылка: ADR 0015
Агент: нет
Время: 2026-11-19T14:45:00Z
Цель: Отдавать для beacon_stats честное состояние персиста и список повреждённых строк журнала.
Контекст: WORKER-PROMPT §4.1 п.7: beacon_stats возвращает persist{seq,lastError} и loadErrors[]; §4.2: persist_error честно в ответе как PERSIST_FAILED, повреждённая строка не блокирует старт и видна в loadErrors, meta.json с seq пишется последним. C §1.D и ловушки 10 и 12: Progress{seq,error,failed_since}, ошибка записи видна вызывающему, seq фиксируется только после данных.
Шаги: 1. Завести таблицу persist_progress с seq и lastError и обновлять её только после успешной транзакции. 2. Собирать loadErrors при чтении журнала с номером строки и причиной, не прерывая загрузку. 3. Отдать read-метод, формирующий поля persist и loadErrors для инструмента stats.
Проверка: Тест: после искусственного сбоя записи lastError непустой и мутирующий вызов получает PERSIST_FAILED; повреждённая строка попадает в loadErrors и не мешает старту; seq не растёт при неудачной записи.
Приёмка: Слой store отдаёт seq, lastError и массив loadErrors, ни один read-метод не меняет эти поля.
