Goal: Required checks cannot drift from the workflow job names.

Evidence: merge.required_checks already lives in .beacon/config.yaml, but it is a static copy of CI job names. beacon init fills it through detectRequiredChecks once. When a PR rewrites ci.yml from build/vet/test/lint to verify plus matrix jobs, the config still names the old checks and a green PR is held forever. PR #2541 is exactly this case and T-42ae53b1 cannot fix it because it is blocked by the same active run on ci.yml.

Steps: Add a config mode where required_checks is resolved from .github/workflows/*.yml at load and on config watcher reload, using the existing detectRequiredChecks logic as the parser. Keep an explicit list as a manual override. Feed the resolved names into policy.Config.RequiredChecks so reconcile uses them. Add a test that changes workflow job names, reloads config, and asserts the policy accepts the new names without a config edit.

Check: A workflow rename from build/vet/test/lint to verify and matrix jobs no longer produces 'required checks not passed' after reload.

Accept: Do not edit ci.yml in this card. Keep doctor output meaningful for both modes.
