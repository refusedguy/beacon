Goal: replace the single global noise floor with a per-key floor so stable keys can report gains while noisy keys stay conservative.

Evidence: calibration run 45979034199 produced floorPct 47.7 from 15 samples. The advisory comment on PR #2786 then called every one of 15 rows flat at that floor. The spread comes from noisy keys such as card-local-parse with a base range of 1.111 to 12.537 ms and run-watcher-fp with 2.646 to 11.317 ms. noise-09-control.md specifies a per-key floor at a high quantile. The current implementation publishes one global number.

Steps, all in .github/workflows/ci.yml:
1. In the 'Calibrate the noise floor' step of perf-noise-floor, parse both sides into passes and keep one row per key per pass, taking the last row for duplicates from -benchtime=5x. For each key, pair base and head medians by pass index, compute the absolute percent delta per pass, and take the 95th percentile with a minimum of the registry default floor. Publish a `floors` object keyed by plan name alongside the existing global floorPct. Keep the artifact name bench-noise-floor and the other fields unchanged.
2. In the advisory 'Build comparison comment' step, read doc.floors when present and use floors[key] for that row's verdict, falling back to the global floorPct and then the registry default. Keep one global floorPct in the preamble for backward compatibility. Add one short note when a row uses an uncalibrated floor.
3. Keep the spread rule and the ratio columns as they are. Do not change any other job, threshold script or benchmark file.

Accept: after recalibration, stable rows on unchanged code still report flat, and the floor printed for a row comes from that row's no-change samples. The fix PR must NOT carry the perf label so mark-ready sets ready-to-merge. No local execution.
Protocol: Work in your own worktree and branch off current main. Never push to main. Never run go test, go build, go vet, linters or benchmarks locally. Open a PR and call beacon_watch_pr. CI supplies every check.
