Goal: stop the intermittent [WARN] scm base branch: unreachable from beacon doctor. No plugin or docs edits.

Evidence: doctor creates its HTTP client with a 2s timeout in cmd/beacon/doctor.go:68. Five sequential Go requests to https://api.github.com/repos/refusedguy/beacon/branches/main with the same token produced one timeout at 2.0008s and four successes around 0.6-0.85s. curl returned HTTP 200 in 0.73s. The GitHub API is healthy; the timeout is too tight. The warning appears and disappears on repeated doctor runs with no config change.

Scope: cmd/beacon/doctor.go, cmd/beacon/doctor_test.go.

Steps:
1. Raise the doctor HTTP client timeout from 2s to 5s, or make it configurable with a 5s default. Keep every check and its exit code unchanged.
2. Add a test with a fake server that delays 2.5s and then returns 200, asserting the SCM check reports HTTP 200. Keep the existing unreachable and HTTP-error tests.
3. Do not log tokens or credentials. Run gofmt -w, targeted go test ./cmd/beacon and root go test . for arch. Open a PR, call beacon_watch_pr with the real run ID and PR number, do not self-merge.
