Context: the Beacon sidebar panel disappears after opening any menu/panel and never returns. Root cause verified in OpenCode v2.3.2 binary: `packages/tui/src/component/session-frame.tsx` puts sidebar and right pane in mutually exclusive branches (`<Show when={rightPane()==='sidebar'}>`), so opening a panel unmounts `sidebar.content` and destroys the manually inserted nodes. The plugin's `ensureNodes()` in `.opencode/plugins/beacon-project/ui.js` caches nodes once via `if (nodes) return nodes` and returns destroyed nodes on remount. Verified flag name in the running binary is `isDestroyed` (internal `_isDestroyed`).

Goal: the run list reappears after closing a menu/panel.

Steps:
1. In `ui.js`, replace the single `nodes` cache with per-slot state and an `ensureSlot(key)` helper. For `key` in sidebar/footer/detail: if the cached node exists and `!node.isDestroyed`, return it; otherwise create a fresh node with makeList() or makeDetail(), mount it with the correct rows source (rows/footerItems/detailItems) and row limit (sidebar MAX_ROWS, footer FOOTER_ROWS, detail DETAIL_ROWS), apply it, and store it. Do NOT recreate all three when only one is destroyed, or refresh() will apply to unmounted nodes.
2. Change the `sidebar.content`, `home.footer.status` and `session.panel` render callbacks to use `ensureSlot('sidebar').node`, etc. Keep `refresh()` applying each slot's current `apply` with the inFlight guard.
3. Keep all existing fixes: MAX_ROWS pool, inFlight guard, 16MB buffer, configurable options, module split, the ✕ close button from PR #2352.
4. Add a test in `ui_setup_test.js`: stub nodes with `isDestroyed:false`; call `renderers['sidebar.content']()`; mark the returned node and its row nodes `isDestroyed = true`; call render again; assert the second node is different, the created-node count grew, and visible rows are present. Use `await new Promise(r => setImmediate(r))` before the first render so snapshot() has data.
5. Run `node --check` and `node --test .opencode/plugins/beacon-project/*_test.js`. Report pass count. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Check: open a panel/menu, close it, and the Beacon run list is visible again with current data.

Accept: only plugin JS files. Do not touch Go code or AGENTS.md. Keep files under 350 lines.
