# T3.385. Evals L01-L04 для сводки workload
Статус: todo
Фаза: P3
Тип: task
Владелец файлов: docs/evals/orchestrator-workload.md, evals/main.go, evals/README.md
Зависимости: T3.383, T3.384
Ссылка: ADR 0156
Агент: нет
Время: нет
Цель: Зафиксировать поведение сводки и авто-подписки на исполняемой модели.
Контекст: Сводка читается из store, а не из текста wake. Blocked из ADR 0155 считается отдельно от retry. Сценарии работают на модели в evals/main.go без сети, токенов и MCP-сервера.
Шаги: L01: активные Watch с вердиктами ready, retry, blocked и watching дают четыре счётчика по проекту. L02: blocked Watch с причиной и двумя failedChecks не попадает в retry и несёт причину. L03: второй проход SubscribeAll не добавляет обязательство и не двигает ревизию, а при лимите показывает uncovered. L04: сводка показывает ready, но beacon_get_result по старой ревизии даёт retry, и мерж запрещён.
Проверка: Каждый кейс имеет asserted-условие и негативный контроль. Раннер печатает четыре строки в общей таблице NAME | EXPECTED | ACTUAL | PASS/FAIL. Ослабление любого правила делает кейс красным и даёт код выхода 1.
Приёмка: docs/evals/orchestrator-workload.md содержит четыре сценария с командами воспроизведения и ожидаемыми строками ACTUAL. Счётчик базовых eval не меняется.
