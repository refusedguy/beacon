Goal: add a new orchestrator-only MCP tool `beacon_task_start` that starts ONE specific task by ID. This gives the orchestrator an explicit, auditable way to run a chosen card without calling broad beacon_dispatch and without cancelling or deleting unrelated cards.

Evidence: the current tool catalog at internal/infra/mcp/registry.go:38-49 has beacon_dispatch with an N count but no way to name a task. The orchestrator had to use beacon_dispatch with n=50 and then cancelled and deleted unrelated cards to free a slot for one high-priority card, requiring five git revert commits to restore. AGENTS.md states the orchestrator works from the default build agent and must keep the main checkout clean.

Steps:
1. Add a new orchestrator-only tool `beacon_task_start` to ToolSpec in internal/infra/mcp/registry.go, with input schema {task_id: string}. Description: 'Start one specific task by ID. Orchestrator only.'
2. Implement registerTaskStart in a new file internal/infra/mcp/tool_task_start.go following the pattern in tool_dispatch.go and tool_task_update.go. Resolve the task by ID from the task source. Refuse if the ID is unknown, already has an active run, or is not available/todo.
3. Check only this task's own dependencies. If any dependency is unresolved, return a structured refusal listing the blocking task IDs and their statuses. Do NOT cancel the blockers, do NOT delete other cards, do NOT modify statuses.
4. Check the global in-flight and agent budgets using the same limits as Dispatcher.planDispatch at internal/app/dispatcher.go:221-245. If no slot is free, return a refusal with the current active count. Never evict another run to make room.
5. Start exactly one run for this task through the existing Dispatcher or a narrowly scoped helper. Return {task_id, run_id, state, scope} on success and a structured reason on refusal.
6. Regenerate opencode.json permissions with go generate ./... so the new tool is allowed for the orchestrator build agent only. Run TestPermissionsUpToDate.
7. Add tests for: unknown ID, active run, unresolved dependency, full budget, and success. Assert that no other task or run is mutated in every case.

Accept: the orchestrator can call beacon_task_start with a single task_id and get a run, and a blocked call changes nothing. No unrelated card is ever cancelled, deleted, or reprioritized by this tool.
