baseline: dmux симулирует мерж командой `git merge-tree` и разбирает маркеры в выводе (`src/utils/mergeValidation.ts:166-205`), при отказе команды переходит к `rev-list --left-right` и `diff --name-only` (`:206-243`). Beacon обнаруживает конфликт только после попытки rebase и сохраняет список файлов в `ConflictError` (`internal/app/orchestrator/rebase.go:96-115`, `:374-383`).

Цель: Сообщить о конфликте до того, как рабочее дерево попадёт в состояние мержа.

Контекст: `detectMergeConflicts` в dmux вызывает `git merge-tree` с общим предком, ищет маркеры `<<<<<<<` и `>>>>>>>` и восстанавливает имена файлов по ближайшей строке `diff --git` (`mergeValidation.ts:172-203`). Если команда недоступна, fallback считает расхождение через `rev-list` и возвращает изменённые файлы (`:209-238`). Beacon при конфликте rebase пишет вердикт `rebase` и будит подписчика со списком файлов (`rebase.go:374-383`), но к этому моменту дерево уже изменено. Команды `merge-tree` в коде нет.

Шаги: Добавить в `internal/app/orchestrator/conflict_dryrun.go` тип результата и чистый разбор вывода `git merge-tree`. Вызов команды оставить на границе и передать вывод в функцию. Покрыть тестами вывода с маркерами, вывода без маркеров и отсутствияاسم файла. Отдельный fallback описать как чистую функцию по двум спискам изменённых файлов.

Проверка: Для фикстуры с двумя правками одной строки функция возвращает имя конфликтующего файла. Для линейной истории список пуст. После проверки тест подтверждает, что ни одна команда изменения дерева не вызвана. Fallback возвращает непустой список при расхождении `behind>0` и `ahead>0`.

Приёмка: Конфликт виден до записи в рабочее дерево. Контракт `rebase` и Sophia сообщения с файлами остаются прежними.

Причина: Уже влито в main через PR #1843, коммит 91d4cef4 (feat(orchestrator): detect merge conflicts before touching the tree). git merge-base --is-ancestor 91d4cef4 origin/main вернул exit 0. conflict_dryrun.go присутствует в origin/main. Дубль кода не создан.
