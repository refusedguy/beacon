# T2.7. beacon_list_running и beacon_stats как чистое чтение
Статус: done
Фаза: P2
Тип: task
Владелец файлов: internal/infra/mcp/tool_list_running.go, internal/infra/mcp/tool_stats.go, internal/infra/mcp/tool_list_running_test.go, internal/infra/mcp/tool_stats_test.go
Зависимости: T2.2, T1.2
Ссылка: ADR 0013
Агент: нет
Время: 2026-11-19T20:30:00Z
Цель: Отдавать список активных Watch и метрики без единой записи в состояние.
Контекст: WORKER-PROMPT §4.1 задаёт list_running с filters и ответом counts{watches,byVerdict,subscribers} и watches[]. stats не принимает аргументов и возвращает pointsThisHour, budget, activeWatches, persist{seq,lastError}, loadErrors[], ladder{pending,escalated}, version. Оба инструмента помечены как read. WORKER-PROMPT §4.2, невариант 9, прямо требует, чтобы list_running и stats не писали состояние. ADR 0013 определяет pointsThisHour как значение общего счётчика. ADR 0012 требует поля version в state.json.
Шаги: 1. Прочитать состояние через read-only метод хранилища. 2. Собрать ответ list_running со счётчиками и массивом Watch. 3. Собрать ответ stats, подставив значения счётчика, персиста, loadErrors и лестницы.
Проверка: тесты снимают снимок состояния до и после вызова каждого инструмента и сравнивают их содержимое и mtime. Отдельно проверяется наличие всех полей ответа и согласованность counts с массивом watches.
Приёмка: вызовы не меняют файлы состояния, все поля присутствуют, повторные вызовы дают тот же результат при неизменном состоянии.
