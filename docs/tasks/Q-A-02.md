# Q-A-02. Убийца сирот opencode serve и зависших процессов
Premise: проверено 2026-11-21 на origin/main 28db985. В коде не было Pdeathsig, записи PID spawn-сервера и dispatch для beacon gc. EnsureServer возвращал service.json без проверки живости, а при отсутствии файла каждый вызов поднимал новый процесс. Контекст карточки фиксирует 37 процессов opencode serve и 29 сирот до чистки. Текущий замер `ps -eo args | grep 'opencode serve --hostname' | grep -v grep | wc -l` даёт 0 после уборки, выполненной владельцем, исторические 37 остаются базовой точкой. Решение: хранить PID и конфиг своего сервера в `$XDG_STATE_HOME/beacon/opencode-serve.json`, ставить Pdeathsig SIGTERM при спавне и расширить beacon gc защитой по PID и порту из service.json, чтобы основная сессия не попадала под terminate.
baseline: `git show origin/main:internal/infra/opencode/server.go | grep -c Pdeathsig` = 0; `git show origin/main:internal/infra/opencode/server.go | grep -c opencode-serve.json` = 0; `git show origin/main:cmd/beacon/main.go | grep -c 'case "gc"'` = 0; `git show origin/main:cmd/beacon/watch.go | grep -c 'func runGC'` = 1, но команда не подключена к dispatch; `ps -eo args | grep 'opencode serve --hostname' | grep -v grep | wc -l` = 0 сейчас против 37 в контексте карточки. gofmt применён к пяти go-файлам. go test и go build локально не запускались по указанию владельца, проверка идёт в CI PR.

Цель: Не плодить серверы на вызов, переиспользовать живой, подчищать сироты через beacon gc --apply.
Контекст: Premise: за смену накопилось 37 процессов opencode serve, 29 сирот без живого beacon mcp. baseline: `ps -eo args | grep 'opencode serve --hostname' | wc -l` = 37 до чистки.
Шаги: Читать service.json, переиспользовать живой сервер, выставлять Pdeathsig SIGTERM при спавне, хранить PID, добавить beacon gc --apply с защитой основной сессии пользователя.
Проверка: gofmt, go test в CI.
Приёмка: Повторный вызов не создаёт второй сервер, сироты подчищаются, основная сессия не трогается.

Выполнено: EnsureServer сначала берёт запись своего сервера с живым PID, затем service.json и только после этого спавнит новый процесс. Спавн получает SysProcAttr{Pdeathsig: syscall.SIGTERM}, PID и конфиг пишутся в state с режимом 0600. GC сканирует /proc, terminate применяет только к сиротам и не трогает PID либо порт из service.json и PID своей записи. Мёртвая запись своего сервера удаляется с --apply. Тесты на моках лежат в gc_test.go и server_qa2_test.go. Ограничение: cmd/beacon/main.go и cmd/beacon/catalog.go не входят в OwnerFiles, поэтому dispatch и catalog-запись для `beacon gc` остаются за отдельной wiring-карточкой. Реализация подключена через RegisterGC. Catalog-запись была убрана после провала TestT06ListJSONCatalog в CI: тест жёстко ждёт 18 команд, а править чужой main_test.go вне OwnerFiles нельзя.
