baseline: dmux пишет промпт в файл с режимом 0600 и передаёт CLI команду, которая читает файл и сразу удаляет его (`src/utils/promptStore.ts:35-53`, `:93-99`), с отдельной веткой для fish. В `origin/main` промпт собирается как строка и уходит через API (`cmd/beacon/spawn.go:134-142`, `:219`).

Цель: Передавать промпт с любыми символами без ручного экранирования и без следов на диске после старта агента.

Контекст: `writePromptFile` в dmux создаёт имя из slug, времени и случайного суффикса, ограничивает права 0600 и возвращает путь (`promptStore.ts:35-53`). `buildPromptReadAndDeleteSnippet` читает файл в переменную и удаляет его, учитывая оболочку fish (`:93-103`). Если запись файла не удалась, `agentLaunch` откатывается к встроенному экранированию (`agentLaunch.ts:664-681`, `:700-717`). Beacon собирает текст промпта из task ID и заголовка (`spawn.go:137-142`) и отправляет его через `PromptWithOptions` (`:219`). Слой защиты от кавычек и обратных кавычек отсутствует.

Шаги: Добавить в `internal/app/session/prompt_file.go` функции записи промпта с ограниченными правами, сборки команды чтения и удаления, а также очистки файлов по префиксу slug. Все операции с диском внедрить через интерфейс. Покрыть тестами промпт с одинарной и двойной кавычкой, обратной кавычкой, долларом и переводом строки. Проверить, что fallback включается при ошибке записи. Не менять `spawn.go` в этом PR.

Проверка: Промпт из набора специальных символов доходит до агента побайтово. После чтения файл отсутствует. При ошибке записи вызывается встроенный путь экранирования и тест это фиксирует. Число файлов после очистки равно нулю.

Приёмка: Заголовок задачи не может сломать команду запуска. Временные файлы не остаются в каталоге состояния.
