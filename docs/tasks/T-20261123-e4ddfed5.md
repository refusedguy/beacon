Fix the plugin watchdog so ordinary git commits do not restart the Beacon MCP daemon. In `.opencode/plugins/beacon-project/mcp.js`, the HEAD poller currently calls `ctx.mcp.reload()` whenever `git rev-parse HEAD` changes. Because `beacon.build-sha` is just HEAD, every card commit, rebase or merge makes it stale and triggers a rebuild plus reload, which starts a new daemon without reliably stopping the old one. Change the freshness check to hash the binary's real build inputs instead of HEAD: Go sources under cmd, internal and pkg, go.mod, go.sum and go.work. Have `scripts/build-beacon.sh` write that hash to `.opencode/bin/beacon.build-sha`. The poller should rebuild only when that hash changes, then trigger one reload with a debounce of at least 10 seconds. Add a test with fake fs/exec/timers covering: HEAD-only change does not rebuild or reload, source change rebuilds once, rapid successive source changes cause one reload. Keep the existing resolution order and the explicit BEACON_BIN bypass. Do not change AGENTS.md in this card because another card owns it. Keep files under 350 lines. Run node --check and node --test, open a PR and call beacon_watch_pr.
