# SB-11. Три состояния патча в записи Watch

Статус: todo
Фаза: P1
Тип: task
Владелец файлов: internal/domain/types.go, internal/domain/verdict.go
Зависимости: 
Ссылка: docs/research/comp-swebench.md, раздел 1, строка «Измерение успеха»; исходник swebench/harness/grading.py
Агент: нет
Время: нет
Цель: Различать отсутствующий патч, неприменённый патч и применённый патч в одном отчёте.

Контекст: Источник: `swebench/harness/grading.py:347-376`, `swebench/harness/constants/__init__.py:42-43`. Отчёт по инстансу начинается с трёх раздельных флагов `patch_is_None`, `patch_exists` и `patch_successfully_applied`. Первый возврат происходит до чтения лога, если патча нет (`:358-362`). Флаг применения выставляется только после успешного разбора вывода (`:376`). В beacon `domain.Watch` хранит `MergeInfo` с полями `mergeable`, `mergeStateStatus` и `reviewDecision` (`internal/domain/types.go:163-168`, `:369-405`), но не имеет полей о патче. `ExternalEvidence` тоже их не несёт (`internal/domain/verdict.go:703-712`). Поиск `git grep -c 'PatchApplied' -- internal` даёт 0 файлов. Сейчас пустой PR, неприменённый diff и применённый diff различаются только косвенно через вердикт и результат мержа.

baseline: `rg -c 'patch_' swebench/harness/grading.py` даёт 6 строк; `git grep -c 'patch_applied\|PatchApplied' -- internal` даёт 0.

Шаги: Добавить в Watch или в связанное доказательство три флага с теми же значениями, что и в отчёте SWE-bench. Заполнять их на границе адаптера до расчёта вердикта. Не путать отсутствие патча с провалом проверки: первый случай возвращает отдельную причину. Не менять существующие поля `MergeInfo` и правила мержа. Передавать флаги в `beacon_get_result` как необязательные поля, чтобы не ломать байтовый контракт.

Проверка: Собрать три Watch с пустым diff, с diff, который не применяется, и с применённым diff. Сейчас все три дают один набор полей. Цель: флаги принимают значения `(true,false,false)`, `(false,true,false)` и `(false,true,true)`. Негативный контроль: пустой diff не порождает проверку и не даёт `PASS`.

Приёмка: Причина отказа видна из отчёта без чтения лога CI и без повторного прогона.
