OpenCode injects a full `<subagent>` report into the parent chat for every REST-created session that has `parentID`. Our workers get it from `Spawn` in `harnesses/opencode/opencode.go`. Remove `body["parentID"] = parent` from the POST /api/session payload. Keep `ParentSessionID` in `Harness`, `Run` and config unchanged, because `NotifyParent` addresses the orchestrator by ID directly and the quiet `Beacon: PR #N ... state merged` line must keep working. Update `harnesses/opencode/opencode_test.go`: assert that the spawn payload has no `parentID` key, and keep a test that `NotifyParent` still posts to the stored session ID. Do not change any other tool. Run gofmt and targeted tests, open a PR and call beacon_watch_pr.
