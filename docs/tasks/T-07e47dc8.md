Goal: make the readCard cache actually fire on the production CliStatusSource path and invalidate on same-size rewrites.
Evidence from audit: CliStatusSource sets readFileSync but no statSync, so enrichRuns calls readTitle with cacheable false and re-reads one card per run every 5 seconds. The A8 counter test injected both deps, a bag production never passes. Stamp mtimeMs:size misses same-size rewrites inside one mtime tick. The cache returns a mutable card object and has FIFO eviction at 512 entries, now below the 488-card count.
Variants, one commit each: V1 give CliStatusSource a statSync dependency derived from readFileSync or pass a read-only stamp provider so enrichRuns can cache; add a counter test driving CliStatusSource.snapshot with R title-less runs and no statSync, asserting reads stay at R on the second snapshot. V2 invalidate on content length plus a short hash or on a read of the file body when stat is coarse, and add a same-size same-mtime rewrite test. V3 return a defensive copy and promote on access with a real LRU.
