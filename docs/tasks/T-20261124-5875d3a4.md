Goal: fix the misleading CI duration in the run detail panel. No Go edits.

Evidence from the operator screenshot of the merged smoke-test run (PR #2378):
- Header shows "CI Checks  5/5 · 1m51s" with rows vet 28s, lint 20s, advisory 14s, build 23s, test 26s.
- .opencode/plugins/beacon-project/ui_alerts.js:163 sums every job duration: total = list.reduce((n,c) => n + (Number(c?.durationSeconds) || 0), 0).
- GitHub Actions runs build, vet, test, lint and advisory in parallel on separate runners with no needs: dependencies. The measured wall clock for PR #2378 was about 31 seconds. The 111-second sum is not the CI time and misleads the operator.
- The hero "Phase" line shows "CI 1m". That value comes from Beacon's own waiting-ci duration, not from CI runtime, so it also needs a clearer label.

Steps:
1. In ui_alerts.js checksSummary, report the longest job duration instead of the sum, and make the meaning explicit, for example "5/5 · longest 28s" or "5/5 · CI 28s". Keep the failed form "1 failed · 4/5" unchanged.
2. In ui_view.js phaseLabel or wherever the hero Phase text is built, label the waiting-ci phase as "CI wait" so it cannot be read as CI execution time. Keep the other phases as they are.
3. Tests: with durations 28, 20, 14, 23, 26 the summary contains 28s and not 1m51s or 111s; failed summary stays unchanged; the CI phase label contains "CI wait"; existing checkRow and detail tests still pass.
4. Run node --check on every plugin JS file and node --test .opencode/plugins/beacon-project/*_test.js. Keep every file <= 350 lines.
5. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Accept: only .opencode/plugins/beacon-project/**. No Go changes, no docs, no task card edits.
