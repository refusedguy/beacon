Goal: fix the misleading CI duration and the card detail panel issues found in the live screenshot. No Go edits.

Evidence 1: PR #2378 detail header showed "CI Checks  5/5 · 1m51s" with rows vet 28s, lint 20s, advisory 14s, build 23s, test 26s. .opencode/plugins/beacon-project/ui_alerts.js:163 sums all job durations. GitHub Actions runs these five jobs in parallel with no needs: dependencies, and the measured wall clock for that run was about 31 seconds. The 111-second sum is not CI time.

Evidence 2: opening a queued card shows a read-only panel with no ctrl+g hint and no close button, unlike the run detail panel. The body is cut off and the mouse wheel does not scroll. ui_card_view.js:58 gives the plate flexShrink: 0, so it grows to CARD_LINES (88) rows and the scroll box at line 61 never gets a bounded height. ui_card_view.js:49 shows only "read-only" in the header; ui_detail_view.js:32-37 has the working ctrl+g and ✕ controls to copy.

Evidence 3: the Path row shows the absolute path /mnt/projects/beacon-handoff/beacon-impl/docs/tasks/T-....md. The operator works from the project root and wants docs/tasks/<id>.md. ui_card_view.js:26 renders card.path verbatim, and fixPrompt at line 12 puts the same absolute path into the copied prompt.

Steps:
1. In ui_alerts.js checksSummary, report the longest job duration instead of the sum, with explicit wording such as "5/5 · longest 28s" or "5/5 · CI 28s". Keep the failed form "1 failed · 4/5" unchanged.
2. In ui_view.js phaseLabel or wherever the hero Phase text is built, label the waiting-ci phase "CI wait" so it cannot be read as CI execution time. Keep other phases unchanged.
3. In ui_card_view.js, make the plate and scroll box yield a bounded scroll area: remove flexShrink: 0 from the plate, give the scroll container minHeight: 0 and flexGrow: 1, and verify with a fake renderer that the scroll node stays bounded while the body has more lines than fit. Keep the rounded border and padding.
4. Add the same controls as the run detail panel to the card header: "ctrl+g" hint and a clickable "✕" that calls onClose. Pass onClose from ui.js where createCardMount is called. Keep "read-only" visible but not as the only control.
5. Show the path relative to the project root: docs/tasks/<id>.md. Use the root already available in ui.js or ui_model.js to derive it without touching the filesystem. Use the same relative path in fixPrompt. Keep the absolute path internally only for reading the file.
6. Tests: durations 28, 20, 14, 23, 26 produce a summary containing 28s and not 1m51s or 111s; failed summary unchanged; CI phase label contains "CI wait"; card panel has ctrl+g and ✕ wired to onClose; scroll node is bounded with more body lines than fit; Path row and fix prompt use docs/tasks/<id>.md with no absolute prefix; existing checkRow, detail and slot-rebuild tests still pass.
