# T3.2. Канал S2: чтение events.jsonl с курсором offset+epoch

Статус: in_progress

Агент: нет

Цель: Читать события Beacon из events.jsonl через `node:fs.watch` плюс polling с курсором offset+epoch, который переживает пересоздание потока без потерь и дублей.

Контекст: T0.3 выбирает канал. Если S1 не доходит без automations, используется S2 без экспериментальных механик (WORKER-PROMPT §4.4). Событие `filesystem.changed` не приходит само по себе: нужна регистрация через `POST /api/experimental/fs/watch`, которого нет в контексте плагина (ADR 0006, отчёт E §4). Поэтому детекцию делает `node:fs.watch` вместе с polling не реже 2 с. Курсор `offset+epoch` хранится в `ctx.storage` и переживает пересоздание файлового потока по образцу Centrifugo (WORKER-PROMPT §4.4, отчёт E §6.13). Канал несёт указатель `watchID`, `obligationID`, `revision`, а не содержимое (WORKER-PROMPT §4.4). Файл плагина принадлежит T3.1, эта карточка добавляет поведение через зависимость и владеет тестом и фикстурой.

Шаги:
1. Добавить в плагин чтение events.jsonl через `node:fs.watch` и резервный polling с интервалом не более 2 с.
2. Хранить в `ctx.storage` курсор `{offset, epoch}`. При пересоздании потока сравнивать epoch и перечитывать файл с последней полной строки.
3. Разбирать только полные строки. Повреждённую строку пропускать и писать причину в лог, не прерывая чтение.
4. Тест: записать несколько указателей в фикстуру events.jsonl, пересоздать поток, проверить отсутствие потерь и дублей.

Проверка: `node --test tests/adapter/s2-channel.test.js` проходит. Тест проверяет, что polling срабатывает в течение 2 с после append, а курсор после пересоздания потока возвращает каждое событие ровно один раз. В логе плагина нет обращений к `experimental.fs.watch`.

Приёмка: Канал S2 читает events.jsonl, курсор offset+epoch хранится в ctx.storage, пересоздание потока не теряет и не дублирует события, polling не реже 2 с, экспериментальные API не используются.

Гейт: G0. Канал выбран спайком T0.3, эта карточка переносит выбранный механизм в плагин P3.
