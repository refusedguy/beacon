# T3.245. Двухшаговая вставка
Premise: Проверено по origin/main до начала работы: двухшаговой вставки в `internal` не было, `paste-buffer`, `submitOnly` и отдельного шага Enter отсутствовали, дубля нет. Вставка реализована в новом файле `internal/infra/wake/paste.go` через интерфейс `PasteSender` и не зависит от tmux. Слой pane-capture остаётся в работе T3.249 и здесь не дублируется. Живой tmux-зонд в этой среде недоступен, поэтому порядок шагов, отсутствие текста на submit, смену pane и многострочность проверяет `paste_test.go` на фейковом отправщике.

Цель: Отделить вставку текста от подтверждения.
Контекст: OpenRig использует paste-buffer -d -r -p, ждёт около 200 мс и отдельно нажимает Enter в зарегистрированный pane.
Шаги: Сделать вставку в pane id с проверкой, что сессия всё ещё содержит этот pane. Ввести отдельный submitOnly путь.
Проверка: Если pane сменился, текст не пишется вообще.
Приёмка: Многострочные сообщения не попадают в аргументы shell.

## Решение

`InsertTwoStep` проверяет pane через `PastePaneGuard`, затем пишет весь текст в буфер вызовом `PasteSender.Paste`, ждёт `PasteSubmitDelay` (200 мс) и вызывает `SubmitOnly`. Метод `SubmitOnly` шлёт только Enter и не принимает текст, поэтому подтверждение не добавляет текст, а многострочное сообщение не становится аргументом shell. При смене pane `InsertTwoStep` возвращает `ErrPaneChanged` до первой записи. tmux-адаптер реализует `PasteSender` вне этого PR, в слое T3.249.
