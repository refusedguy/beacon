# T3.245. Двухшаговая вставка
Premise: перепроверено 2026-11-21 по свежему origin/main (65c53d4 на момент проверки; с тех пор main получает только docs-коммиты других карточек, OwnerFiles этой карточки не трогают). Двухшаговая вставка в main отсутствует, дубль не создан. Доставка wake живёт в `internal/infra/wake/deliver.go`: `OpenCodeDeliverer.Deliver` (:104) шлёт весь `Envelope` (:274) одним промптом через `PromptFunc` (:36, :175) или CLI fallback `deliverCLI` (:195) вызовом `opencode api POST /api/session/<ses_>/prompt --data <json>`. Ни paste-buffer, ни отдельного Enter, ни submitOnly, ни проверки «сессия всё ещё содержит pane» в wake нет. Baseline: `git grep -inE 'paste.buffer|submitOnly|paste_buffer|tmux' origin/main -- internal` пусто; `git cat-file -e` для `internal/infra/tmux/pane.go`, `internal/infra/wake/pane.go`, `internal/infra/wake/insert.go`, `internal/infra/session/pane.go` даёт ABSENT. PR #831 добавил Pi RPC адаптер в `internal/infra/wake/registry.go` (:175-294) и `cmd/beacon/deliver.go`: `PiRPCProbe.FollowUp` (:219) и `PiRPCProbe.Steer` (:214) отдают весь текст одним RPC-вызовом, без pane и без двух шагов. PR #845 добавил per-adapter circuit breaker в `internal/infra/cibridge/bridge.go` (:1536-1624), он считает отказы доставки и не имеет отношения к вставке текста. Зависимость T3.242 done (PR #725, аренда на цель), но она только сериализует доставку и pane не создаёт. Сёстры T3.266-T3.268 сняты PR #394 с формулировкой «tmux нет, заглушка deliver.go». Реализующего PR нет: `git log origin/main --oneline --grep=T3.245` даёт docs-коммиты c930acb (#945), e869afc (#728); `gh pr list --repo refusedguy/beacon --state all --search T3.245` — #945, #728, #940, #729 и др., все MERGED docs. diff HEAD..origin/main по OwnerFiles пуст. Приёмка требует живого tmux зонда: вставить текст через paste-buffer в зарегистрированный pane, выждать около 200 мс, нажать Enter отдельным шагом и доказать, что при смене pane текст не пишется, а многострочное сообщение не попадает в аргументы shell. Такого зонда нет: в Beacon нет tmux и pane, а слабый ПК допускает только правку текста и gofmt. Не стал писать спекулятивную функцию с выдуманным pane port: её нельзя проверить, она повторила бы снятый PR #394 и нарушила бы честность ADR 0026.
