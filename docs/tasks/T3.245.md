# T3.245. Двухшаговая вставка
Premise: перепроверено 2026-11-21 по свежему origin/main (389604e; база ветки fix/ad2 648bda2; с тех пор только docs-перепроверки других карточек и fix(idx-11), OwnerFiles карточки не трогают). Двухшаговая вставка в main отсутствует, дубль не создан. Доставка wake живёт в `internal/infra/wake/deliver.go`: `OpenCodeDeliverer.Deliver` (:104) шлёт весь `Envelope` (:274) одним промптом через `PromptFunc` (:36, :175) или CLI fallback `deliverCLI` (:195) вызовом `opencode api POST /api/session/<ses_>/prompt --data <json>`. Ни paste-buffer, ни отдельного Enter, ни submitOnly, ни проверки «сессия всё ещё содержит pane» в wake нет: `git grep -in tmux origin/main -- '*.go'` пусто, `git grep -in paste-buffer origin/main` находит только карточки. PR #831 добавил Pi RPC адаптер в `internal/infra/wake/registry.go` (:175-294) и `cmd/beacon/deliver.go`: `PiRPCProbe.FollowUp` (:219) и `PiRPCProbe.Steer` (:214) отдают весь текст одним RPC-вызовом, без pane и без двух шагов. PR #845 добавил per-adapter circuit breaker в `internal/infra/cibridge/bridge.go` (:1536-1624), он считает отказы доставки и не имеет отношения к вставке текста. Зависимость T3.242 теперь done (PR #725, аренда на цель), но она только сериализует доставку и pane не создаёт. Сёстры T3.266-T3.268 сняты PR #394 с формулировкой «tmux нет, заглушка deliver.go». Приёмка требует живого tmux зонда: вставить текст через paste-buffer в зарегистрированный pane, выждать около 200 мс, нажать Enter отдельным шагом и доказать, что при смене pane текст не пишется, а многострочное сообщение не попадает в аргументы shell. Такого зонда нет: в Beacon нет tmux и pane, а слабый ПК допускает только правку текста и gofmt. Не стал писать спекулятивную функцию с выдуманным pane port: её нельзя проверить, она повторила бы снятый PR #394 и нарушила бы честность ADR 0026.
baseline: `git grep -in -E 'paste.buffer|submitOnly|paste_buffer' origin/main -- '*.go'` пусто; `git grep -in tmux origin/main -- '*.go'` пусто; «two steps» в origin/main только в `cmd/beacon/sequential_giants_test.go:62,80` и относится к шагам wave-плана; `git cat-file -e origin/main:internal/infra/tmux/pane.go`, `internal/infra/wake/pane.go`, `internal/infra/wake/insert.go`, `internal/infra/session/pane.go` дают ABSENT; `git show origin/main:internal/infra/wake/deliver.go` содержит `Deliver` :104, `PromptFunc` :36/:175, `deliverCLI` :195, `Envelope` :274 и не содержит paste-buffer, submitOnly или pane; `git show origin/main:internal/infra/wake/registry.go` содержит `PiProbe` :175, `Steer` :214, `FollowUp` :219, `PiDeliverer.DeliverText` :282; `git show origin/main:internal/infra/cibridge/bridge.go` содержит circuit breaker :1536-1624; `git log origin/main --oneline --grep='T3\.245'` даёт e869afc (#728), это docs-коммит premise, а не реализация; `gh pr list --repo refusedguy/beacon --state all --search 'T3.245'` даёт #728 (MERGED, docs), реализующего PR нет; diff HEAD..origin/main по OwnerFiles пуст; `git rev-parse --short origin/main` = 389604e.
Блокер: Отсутствующий pane-слой для tmux. Файлы `internal/infra/tmux/pane.go`, `internal/infra/wake/pane.go`, `internal/infra/session/pane.go` ABSENT в origin/main. Двухшаговая вставка требует зарегистрированного pane, paste-buffer, задержки около 200 мс, отдельного submitOnly-шага Enter и проверки, что сессия всё ещё содержит pane. Внутри OwnerFiles `internal/infra/wake/deliver.go` (`Deliver` :104, `PromptFunc` :175, `deliverCLI` :195) отправляет весь Envelope одним промптом, поэтому ставить paste-buffer и Enter некуда: pane-слой живёт вне OwnerFiles, как зафиксировано в premise T3.246. PR #831 и PR #845 не закрывают этот пробел: Pi RPC шлёт текст одним вызовом FollowUp или Steer (`internal/infra/wake/registry.go:282-294`, `cmd/beacon/deliver.go`), а circuit breaker в `internal/infra/cibridge/bridge.go:1536-1624` считает отказы wake. Приёмка требует живого tmux зонда с paste-buffer, Enter и сменой pane, которого в этой среде нет. Приёмка: Многострочные сообщения не попадают в аргументы shell.
