# T3.245. Двухшаговая вставка
Статус: todo
Premise: проверено 2026-11-21, функциональность в origin/main отсутствует и не реализуема локально в OwnerFiles. Baseline: поиск по всем .go файлам origin/main дал 0 подходящих совпадений с submitOnly, paste-buffer, pane, Enter и двухшаговой вставкой; единственные совпадения "two steps" в cmd/beacon/sequential_giants_test.go относятся к шагам wave-плана, а не к вставке текста; diff HEAD..origin/main по обоим OwnerFiles пустой; карточки цепочки T3.241-T3.244 в main остаются todo, а сёстры T3.266-T3.268 сняты PR #394 с формулировкой "tmux нет, заглушка deliver.go". В internal/infra/wake/deliver.go доставка идёт через PromptFunc HTTP API и CLI fallback: весь Envelope уходит в сессию целиком, а не вставкой в pane с последующим нажатием Enter. Типа pane, paste-buffer, submitOnly и проверки "сессия всё ещё содержит pane" в wake нет. Приёмка требует живого зонда с настоящим tmux: вставить текст через paste-buffer в зарегистрированный pane, выждать около 200 мс, нажать Enter отдельным шагом и доказать, что при смене pane текст не пишется, а многострочное сообщение не попадает в аргументы shell. Такого зонда нет: в Beacon нет tmux и pane, а слабый ПК допускает только правку текста и gofmt. Не стал писать спекулятивную функцию с выдуманным pane port: её нельзя проверить, она повторила бы снятый PR #394 и нарушила бы требование baseline и честность ADR 0026. Статус todo сохранён, карточка остаётся непроверенным спайком до появления живого tmux зонда, блокер возвращён оркестратору. OwnerFiles не менял, код не писал, gofmt не применял, дубль не создал, правка только текстовая.
