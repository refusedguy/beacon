# T3.439. Логировать имена failedChecks в verdict_published
Premise: проверено 2026-11-21 по origin/main (c01c1b2). В observe.go событие verdict_published несёт verdict, watchID, pr и revision, но не несёт имён проверок. В bridge.go три точки публикации: publishActionable и applyBlocked знают имена упавших проверок, closeWatch работает с терминальным вердиктом и не имеет failedChecks. Сейчас имена проверок пишутся только в cycleEvent и в тексте wake для заблокированного Watch, поэтому по одному событию verdict_published нельзя понять, какая проверка уронила PR. Дубля нет, требование не закрыто. Требование локально реализуемо в OwnerFiles карточки: добавить поле в observe и передать его из bridge. Живой зонд не нужен, проверка сводится к просмотру структурированного лога в CI. Код и правки лежат только в OwnerFiles.
baseline: `git grep -c 'FieldFailedChecks\|VerdictPublishedWithChecks' HEAD -- '*.go'` = 0; `git show HEAD:internal/infra/observe/observe.go | grep -c failedChecks` = 0; `git show HEAD:internal/infra/cibridge/bridge.go | grep -c 'VerdictPublished('` = 3; `git log HEAD --oneline -- docs/tasks/T3.439.md` = 1 коммит (batch apply); `git log HEAD --grep='T3\.439' --oneline` = 0; открытые PR на момент выбора не трогают bridge.go и observe.go.

## Подтверждение
- Добавлено поле failedChecks в событие verdict_published. Новый observe.VerdictPublishedWithChecks принимает имена упавших проверок, сортирует их и пишет одним полем. Старый observe.VerdictPublished сохранил сигнатуру и вызывает новую функцию с пустым списком, поэтому остальные вызовы и тесты не меняются. В bridge.go имена передаются из publishActionable и applyBlocked; closeWatch оставляет событие без поля, так как терминальный вердикт не связан с упавшими проверками. Код не выходил за OwnerFiles, gofmt применён к изменённым .go-файлам, дубль не создан.
