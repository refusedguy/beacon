Context: the sidebar panel in `.opencode/plugins/beacon-project/ui.js` renders long wrapping lines, repeats task IDs and titles, has no timestamps or durations, and the font looks inconsistent. Rows are rebuilt every 5 seconds with `insert(box, () => lines.map(...))`, which destroys nodes, focus and click handlers. Detail data will come from the batched API in dependency card T-20261123-aaa92b59.

Goal: a compact, readable run list plus a detail view opened by clicking a row.

Steps:
1. Build stable row nodes once and update only their props with `setProp` when a new snapshot arrives. Never rebuild the list on every refresh.
2. Compact list: at most two lines per run. Line one: colored state marker, short task ID, truncated title. Line two: PR, age or elapsed time, and a short reason. Use `wrapMode: none`, `selectable: false`, fixed widths and one consistent font. No wrapping mid-word, no duplicate ID or title, no prose paragraphs.
3. Recent section: cap to 5 rows, dedupe by run ID, show elapsed time and final state. Drop verbose reasons from Recent unless the reason is a failure code.
4. Click a row with `onMouseDown` to select it and open `ctx.ui.panel.open("beacon.detail")`. Register a `session.panel` claim that renders only when `panel.name === "beacon.detail"`. Add a global keymap command, for example `ctrl+g`, and a slash command, to open the same panel.
5. Detail pane: show run ID, task ID, title, state, PR, branch, head SHA, timestamps, durations, blocked incident, attempts, full reason, per-run timeline and decisions from the batched snapshot. Show numeric metrics at the top. Sort timeline by time.
6. Store the selected run ID in `context.storage.store` so it survives slot re-renders. Clean up all timers and subscriptions in the `setup` return.
7. Update `ui_test.js` with exact-line tests for the compact list, dedupe, elapsed time, detail content and panel open call. Run `node --check` and `node --test` on plugin tests.
8. Open a PR and call beacon_watch_pr with the real run ID and PR number.

Check: the sidebar shows at most two lines per run with visible time and no repeats; clicking a row opens a populated detail panel; the list keeps focus across refreshes.

Accept: do not change Go code. Keep files under 350 lines. Do not edit AGENTS.md or another card.
