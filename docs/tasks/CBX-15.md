# CBX-15. Один общий валидатор запроса освобождения аренды до вычисления среза

Статус: todo
Фаза: P2
Тип: task
Владелец файлов: internal/app/taskcli/service.go, internal/app/taskcli/service_test.go
Зависимости: 
Ссылка: https://github.com/gastownhall/beads (коммит 78624109904655d7a4609f27d34eb0982cd8963f)
Агент: нет
Время: нет
Baseline: beads: internal/storage/issueops/lease_reclaimer.go:17-33, cap проверяется по Filter.IDs до дедупликации; в beacon ReapOptions в internal/app/taskcli/service.go:876-887 не проверяет ни список ID, ни исполнителя, а просто читает все карточки в ReapStaleCards на :930-994.

Цель: Одинаково отклонять неверные запросы reclaim из CLI, MCP и daemon и не читать данные до валидации.

Контекст: Источник, реальный код beads. ValidateReclaimRequest в internal/storage/issueops/lease_reclaimer.go:34-69 требует непустого и обрезанного исполнителя, неотрицательного older_than, не более MaxReclaimIDs ID до дедупликации (:17-20), непустых элементов во всех scope-списках и ограниченной длины исполнителя из-за VARCHAR(255) (:21-25). ExecuteReclaimInTx на :75-95 вызывает валидатор в единственном теле и вычисляет срез один раз из time.Now().UTC().Add(-OlderThan), чтобы все три legs работали с одними часами. Typed field errors отделяют places отказа от сообщений движка. Разрыв в beacon: ReapOptions в internal/app/taskcli/service.go:876-887 содержит Now, TTL и два порта живости; ReapStaleCards на :930-959 читает все карточки до какой-либо проверки запроса, а границы других вызовов не имеют общего правила.

Шаги: Выделить общую структуру запроса с исполнителем, возрастом и фильтром ID. Проверить cap по исходному списку до дедупликации. Проверить пустые элементы и длину исполнителя. Вернуть typed-ошибку с именем поля. Вычислить единый срез времени в одной точке и использовать его во всех путях вызова. Вызвать валидатор до чтения карточек.

Проверка: Измеримая. Запрос с 21 ID при cap 20 отклоняется до первого чтения, счётчик чтений равен нулю. Пустой исполнитель и пустой элемент scope дают ошибки с разными именами полей. Отрицательный возраст отклоняется. Три вызова с одинаковым запросом в разных путях дают один и тот же срез времени и один и тот же набор ID. Длина исполнителя 256 байт отклоняется до записи события.

Приёмка: Существующий MEM-06 reaper и его журнал остаются на месте; карточка добавляет только контракт запроса и общую валидацию.
