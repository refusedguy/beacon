Fix the stale-SHA loop in the reconciler. In `internal/app/reconciler.go`, `rebase()` currently sets `run.ObservedSHA = obs.HeadSHA` after a successful rebase, but `obs.HeadSHA` is the pre-rebase head. It must record the new head returned by `SCM.UpdateBranch`. After a failed rebase, record the attempted SHA as observed too, so one push does not burn all attempts in a tight loop. In the default wait branch of `Reconcile`, advance `ObservedSHA` with `run.ObserveSHA(obs.HeadSHA)` and save when it changes, so a run that never rebased does not keep a stale marker. Keep the existing guards that skip a duplicate rebase or wake for the same SHA. Add tests in `internal/app/reconciler_test.go` with a fake SCM whose `Observe` returns a changed head: assert that one head advance causes at most one rebase, that a successful rebase marks the new SHA, that a failed rebase does not retry the same SHA forever, and that a waiting run advances its observed SHA. Preserve merge and notification behaviour. Keep production files under 350 lines. Run gofmt and targeted tests, open a PR and call beacon_watch_pr.
