# BS.79. Глобальная установка в ~/.config/opencode
Premise: проверено 2026-11-21, требование закрыто в main, дубль не создан. Предложенная карточкой глобальная установка через ~/.config/opencode с mcpServers и фиксированным cwd отвергнута принятым ADR 0069 (docs/adrs/0069-opencode-plugin-project-boundary.md:11): глобальный opencode.json больше не задаёт сервер Beacon через mcpServers с фиксированным cwd, а раздел «Отклонённое» прямо запрещает оставлять хардкод cwd в opencode.json и править конфиг под каждый worktree. Регистрация MCP перенесена в локальный плагин и уже сделана в main. Карточка T3.177 в статусе done: .opencode/plugins/beacon-project/mcp.js регистрирует сервер через ctx.mcp.transform, корень берётся из ctx.location.project.canonical, в конфиге сервера нет жёстко заданного cwd, команда .opencode/bin/beacon mcp, явная переменная BEACON_PROJECT_ROOT. Карточка T3.176 в статусе done: плагин грузится из .opencode/plugins автоматически, без записи в глобальный конфиг, что закрывает проверку «новый проект видит сервер без локальной настройки» в части правки глобального конфига. Запись docs/ROADMAP_STATUS.md:54 уже отображает BS.79 на opencode.json и .opencode/plugins/beacon-project/mcp.js. Подтверждение BS.6 фиксирует, что MCP зарегистрирован по stdio плагином beacon-project, а writer для connection.json никогда не существовал. Отдельного шага «автозапуск демона» в глобальном конфиге в main нет и по ADR 0069 он не планируется: сервер поднимается по вызову MCP, фоновый процесс ведёт сервис OpenCode (ADR 0029, ADR 0092). OwnerFiles cmd/beacon/server.go содержит только serverRunner с lease, readiness и вызовом mcpRunner; глобальной установки там нет и добавлять некуда. Ссылка карточки на ADR 0188 ведёт к двум файлам про пул воркеров gh и SpoolSource/McpPullSource, ни один не про глобальную установку, как у соседних карточек с расхождением ссылок. Приёмка «ядро не importing opencode-specific API» уже соблюдена: опенкод-специфичный код лежит в плагине и в cmd/beacon, а не в internal/domain. Код не писал, OwnerFiles не менял, gofmt не применял, правка только текстовая. Статус изменён с todo на done.
