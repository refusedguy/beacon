# T3.393. OTLP-адаптер поверх Sink и SetTracer
Premise: проверено 2026-11-21, функционал в origin/main отсутствует, дубль не создан. Карточка просит OTLP-адаптер поверх Sink и SetTracer: чтение BEACON_OTEL_EXPORTER, батчевая отправка завершённых спанов по OTLP/HTTP, Shutdown на выходе и no-op при выключенном флаге, с выбором протокола через OTEL_EXPORTER_OTLP_PROTOCOL (grpc, http/protobuf, http/json). `git grep -Ei 'otlptracehttp|OTEL_EXPORTER_OTLP_PROTOCOL|BatchSpanProcessor' origin/main -- '*.go'` даёт 0 совпадений, go.mod не содержит opentelemetry. В internal/infra/observe/otel.go есть только локальный tracer на stdlib. ConfigFromEnv читает BEACON_OTEL_ENABLED и BEACON_OTEL_EXPORTER, константа ExporterEnv помечена как зарезервированная, SpanSink реализуют observeSink через slog и SpanRecorder в тестах, SetTracer подменяет процессный tracer. internal/infra/otel/local.go пишет спаны в NDJSON-файл рядом со stateDir и отделяет экспорт OTLP в отдельную задачу. cmd/beacon/observe.go только оборачивает команды спанами и поднимает /metrics, Shutdown экспортёра там нет. ADR 0185 описывает OTLP-адаптер как будущую работу и фиксирует текущее состояние без новых зависимостей. Проверка «при недоступном коллекторе команда завершается и не теряет Watch» требует живого коллектора и прогона CLI. Приёмка «переход на OTLP не меняет вызовы Tracer.Start» требует проверки всех трёх протоколов на работающем экспортёре. Здесь доступны только текст и gofmt на слабом ПК, живого коллектора и сборки с экспортёром нет. Статус todo сохранён, блокер возвращён оркестратору: нужны разрешённые зависимости или stdlib-кодировщик OTLP, живой коллектор и прогон CLI для проверки Shutdown и трёх протоколов. Цель: Подменить локальный tracer на экспортёр OTLP, не меняя вызовов Start.
Контекст: Sink получает завершённые спаны, SetTracer меняет процессный tracer. Исследование описывает otlptracehttp как простой вариант по умолчанию и OTEL_EXPORTER_OTLP_PROTOCOL со значениями grpc, http/protobuf и http/json.
