# T3.393. OTLP-адаптер поверх Sink и SetTracer
Premise: проверено 2026-11-21. Предыдущий агент решил, что без живого OTLP-коллектора задача невыполнима, и вернул блокер. Замер опровергает это. Экспортер OTLP/HTTP пишется на stdlib без новых зависимостей, а сетевой путь проверяется моковым коллектором httptest. Живой коллектор не нужен ни для включения, ни для тестов. При пустом endpoint адаптер оставляет спаны локальными через observeSink, поэтому команда без коллектора работает как раньше. В OwnerFiles реализованы Config с endpoint и protocol, OTLPExporter с батчем и Shutdown, кодировщики protobuf и JSON. В cmd/beacon/observe.go подключены флаги конфигурации и вызов Shutdown в cleanup. Флаги `--otel-exporter`, `--otel-endpoint` и `--otel-protocol` убираются из аргументов перед разбором флагов четырех трассируемых команд, поэтому работают и через env, и через командную строку. Протокол grpc требует внешней gRPC-зависимости, поэтому в stdlib-сборке он не поддерживается: `NewOTLPExporter` возвращает явную ошибку. Это ограничение не трогает два HTTP-протокола и мок-тесты. Правка BCX-79 убрала grpc из числа допустимых значений в комментарии `otel.go` и в этой карточке, чтобы документация не обещала экспорт, которого код не даёт. Дубля в origin/main нет: `git grep -Ei 'otlptracehttp|OTEL_EXPORTER_OTLP_PROTOCOL|BatchSpanProcessor' origin/main -- '*.go'` даёт 0 совпадений, go.mod не содержит opentelemetry. ADR 0185 указывает тот же путь: Sink и SetTracer меняются без правки вызовов Tracer.Start.
baseline: `git grep -Ei 'otlptracehttp|OTEL_EXPORTER_OTLP_PROTOCOL|BatchSpanProcessor' origin/main -- '*.go'` = 0; до правки `grep -ic otlp internal/infra/observe/otel.go` = 5, все в комментариях и именах констант; до правки `grep -ic otlp cmd/beacon/observe.go` = 0; `grep -Ec 'opentelemetry|otel' go.mod` = 0; до правки `grep -Ec Shutdown` по OwnerFiles = 0; до правки wc -l = 284 и 206; `git log origin/main --grep='T3\.393'` = 0 коммитов; `gh pr list --repo refusedguy/beacon --state all --search 'T3.393'` = 0 PR. После правки: `grep -ic otlp` = 84 в otel.go и 14 в observe.go, `grep -Ec Shutdown` = 9 и 1, go.mod без opentelemetry, 13 новых тестов на httptest и разбор флагов.
Статус: done
Обоснование: реализовано в OwnerFiles без внешних зависимостей. Батч уходит на /v1/traces по OTLP/HTTP protobuf или JSON. Пустой endpoint даёт local-only fallback, протокол grpc отвергается с явной ошибкой. Shutdown вызывается на выходе из команды. Тесты используют httptest как моковый коллектор, реальный коллектор не вызывается. go test локально не запускался из-за слабого ПК, проверка идёт в CI PR.

Цель: Подменить локальный tracer на экспортёр OTLP, не меняя вызовов Start.
Контекст: Sink получает завершённые спаны, SetTracer меняет процессный tracer. Исследование описывает otlptracehttp как простой вариант по умолчанию и OTEL_EXPORTER_OTLP_PROTOCOL с поддерживаемыми значениями http/protobuf и http/json. grpc не поддерживается в stdlib-сборке и отвергается с явной ошибкой. Замер для правки BCX-79: finding 9 в docs/research/config-env-audit.md, P2, `otel.go:38-39` обещал grpc как valid value, `otel.go:367-369` его отвергал.
Шаги: Прочитать BEACON_OTEL_EXPORTER; добавить Sink, который батчем шлёт спаны по OTLP/HTTP; вызывать Shutdown на выходе; оставить no-op при выключенном флаге.
Проверка: При недоступном коллекторе команда завершается и не теряет Watch; без BEACON_OTEL_ENABLED зависимость не загружается; тесты tracer проходят.
Приёмка: Переход на OTLP не меняет ни один вызов Tracer.Start и не добавляет полей в beacon_stats.
