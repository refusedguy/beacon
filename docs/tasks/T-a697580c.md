Goal: stop tools from reporting a clean result when an operation failed or was skipped.
Evidence: cmd/beacon/commands.go:224 gcc prints ForceRemove errors to stderr then returns nil, so automation sees a clean cleanup; cmd/beacon/doctor.go:332 prints only dead or stale and hides daemonStatus.Error; .github/workflows/ci.yml:1206 says No comparable rows see the artifact while the artifact step at 1213 permits no files; ci.yml:509 writes measurement trees differ then the pass step at 518 truncates perf-status so the note is lost; internal/infra/mcp/tool_wait.go:23 returns bare context deadline exceeded with no run ID or state; internal/app/taskcreate_batch.go:164 swallows a task source read error and treats every card as new, so a transient failure can overwrite existing cards; internal/infra/mcp/tool_dispatch.go:74 invents reason running from state.
Steps: aggregate gc failures into a returned error with a removed and failed count; append the recorded daemon error and a remedy to doctor output; create perf-status before the hash step, append rather than truncate, and put the comment-builder failure into the advisory comment; return a structured beacon_wait result with run_id, last_state, reason, timed_out and next; propagate a task source read error from existingBatchCards and fail before writing; leave reason empty in dispatch summary when the run has none; add tests for each changed contract.
Accept: no command or tool reports success when its main operation failed or its output was suppressed.
