Context: task cards currently accept only `id`, `title`, `status`, `scope`, `depends`, `depends_on`, `priority`, `source_ref`, `phase`, `kind`, `base_branch`, `require_review`, `plan`. Unknown keys are silently ignored (`internal/infra/tasksource/markdown.go:73-108`). A per-task prompt or agent override could let one card say 'use table-driven tests' or 'do not run local builds' without changing global config.

Goal: support optional `worker_agent` and `worker_prompt` frontmatter keys that override global worker settings for one task.

Steps:
1. Add `WorkerAgent` and `WorkerPrompt` to the `Task` struct in `pkg/core/task.go`, to `frontmatter` in `internal/infra/tasksource/markdown.go`, and add an additive migration plus INSERT/SELECT/scan in `internal/infra/sqlite/tasks.go` and `schema.go`. Do not rewrite existing rows.
2. In `internal/app/dispatcher.go`, when building the spawn prompt, append the task's `WorkerPrompt` after the global instructions. If `WorkerAgent` is set, put it in `core.SpawnRequest` and pass it as the `agent` field in `harnesses/opencode/opencode.go` session creation.
3. Apply the same override in `internal/app/base_red.go` fixer prompts when the fixer is a worker.
4. Tests: markdown parsing of both new keys and ignoring unknown keys; sqlite round-trip after `SyncTasks`; dispatcher test asserting the override appears in the captured prompt; `harnesses/opencode/opencode_test.go` asserting a per-task agent overrides the global one.
5. Run `gofmt -w`, targeted `go test` for changed packages, plus `go test ./harnesses/opencode`.

Check: a card with `worker_prompt` sends that text to its worker; a card without it keeps current behavior.

Accept: do not change AGENTS.md or another card. Keep production files under 350 lines.
