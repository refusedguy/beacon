# RS-CMP-06. Типированный human gate вместо needs_input
Статус: done
Фаза: P3
Тип: task
Владелец файлов: cmd/beacon/human.go, cmd/beacon/human_test.go
Зависимости: 
Ссылка: 
Агент: нет
Время: нет
Цель: Сделать human gate типированным: объявленные исходы, явный резюме после ответа и проверка, что решение владельца не подменяется текстом.
Контекст: Premise: проверено 2026-11-21, human gate описан в ADR и работает через needs_input без типизированных исходов. baseline: `grep -n 'input_type\|resume' cmd/beacon/human.go` пусто. Источник: OpenAI Agents SDK handoff с input_type и LangGraph interrupt с response_schema.
Шаги: Добавить схему ответа и проверку полей до вызова колбэка. Возвращать понятную ошибку при неверном ответе. Тест на корректный ответ, неверный тип и пропущенное поле.
Проверка: gofmt чистый. Тесты в CI. Слои не нарушены: cmd не читает файлы напрямую.
Приёмка: Ответ человека разбирается по схеме, а не как произвольный текст.

Решение: Добавлен тип humanOutcome с закрытым набором исходов и схема ответа humanResponse. Функция parseHumanResponse разбирает ответ, проверяет тип исхода и обязательное поле target до вызова колбэка. Неверный тип и пропущенное поле дают понятную ошибку. Текст note остаётся пояснением и не подменяет типизированное решение.
Измерение: до правки в cmd/beacon/human.go не было типизированных исходов и схемы ответа (grep 'humanOutcome\|humanResponse\|response_schema\|parseHumanResponse' пусто). Решение принято по этому замеру.
Результат: gofmt чистый. Тесты на корректный ответ, неверный тип, пропущенное поле и границу колбэка добавлены в cmd/beacon/human_test.go. Тесты идут в CI на PR. Слои не нарушены: cmd не читает файлы напрямую.
