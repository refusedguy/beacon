Make `opencode.json` permissions generated instead of hand-edited, so adding a Beacon MCP tool never requires editing permission lists by hand. Add `cmd/beacon-gen/main.go` that imports `internal/infra/mcp`, reads `mcp.ToolCatalog()` and rewrites only the generated permission entries in `opencode.json`. For every tool with `OrchestratorOnly` emit: global deny for both `beacon_<name>` and `<name>`, allow for both names under `agents.orchestrator` and `agents.build`, deny for both names under `agents.worker`. Preserve all other config keys, agent descriptions, modes and custom permissions unchanged. Write deterministic JSON with two-space indent. Add a `//go:generate go run ../../cmd/beacon-gen -out ../../../opencode.json` directive in `internal/infra/mcp/registry.go`. Add `TestPermissionsUpToDate` that runs the generator against a temp copy and fails if the committed `opencode.json` differs, so CI catches drift. Explain in AGENTS.md that permissions are generated at development time by `go generate ./...`, never at binary startup, and that the test enforces freshness. Keep production files under 350 lines. Run gofmt, go generate, targeted tests and full `go test ./...`, open a PR and call beacon_watch_pr.
