Goal: cut repeated GitHub provider requests without changing scm-observe work counts.

Evidence: github_etag.go caches PR ETags, but stubJSON at scm_bench_test.go:30-38 sets no ETag, so all ten PR GETs return bodies instead of nine 304s. FindOpenPRByBranch at github_base.go:32-46 paginates every page and uses prs[0]. changedFilesCapped at github.go:425-429 collects every files page before ignoredPathsOnly at :434-449 can decide on the first non-doc path. The deciding row is scm-observe with work held at 60.

Steps: test three variants, one commit each. V1 adds an ETag header to the benchmark stub so nine requests return 304 while work stays at 60. V2 stops FindOpenPRByBranch at the first result. V3 streams files pages to the predicate so it stops at the first non-doc path. Work in your own worktree off current main. Never push to main. Never run go test, go build, go vet, linters, node tests or benchmarks locally. Push one variant at a time and read the beacon-pr-perf comment after each push. Keep only a gain, including gain (allocs/bytes) and gain (calls reduced), with equal work, errs zero, a non-empty limiter and a warm cache. Revert a rejected variant with git reset --hard HEAD~1 and git push --force-with-lease. Add the perf label at PR creation with gh pr create --label perf. Do not add ready-to-merge before all variants are checked and the final table is in the PR body. Call beacon_watch_pr. CI supplies every check.

Accept: every kept variant holds scm-observe at 60 work units with zero errors, reduces provider calls or bytes, and leaves the resulting observations unchanged.
