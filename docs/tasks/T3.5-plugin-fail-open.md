# T3.5. Fail-open плагина: ошибка адаптера не ломает сессию

Тип: task
Владелец файлов: tests/adapter/fail-open.test.js
Зависимости: T3.1
Ссылка: ADR 0006
Агент: нет
Время: 2026-11-19T20:30:00Z

Цель: Гарантировать, что любая ошибка плагина остаётся в логе и не прерывает работу сессии OpenCode.

Контекст: ADR 0006 указывает, что плагин работает fail-open и любая ошибка адаптера не ломает сессию. Отчёт E §8 описывает тот же режим; T0.3 проверял его намеренной поломкой events.jsonl и ошибкой prompt. WORKER-PROMPT §4.4 повторяет требование fail-open для одного JS-файла без SDK хоста. Ошибка адаптера не должна порождать ложную квитанцию `posted`: квитанция пишется только после реальной попытки prompt (T3.6). Файл плагина принадлежит T3.1, эта карточка владеет тестом.

Шаги:
1. Обернуть обработчик событий, чтение events.jsonl и вызов `ctx.session.prompt` в обработчик ошибок, который пишет причину в лог и возвращает управление без исключения.
2. Проверить, что при ошибке не создаётся квитанция `posted` и не меняется курсор на непрочитанное событие.
3. Тест: сломать events.jsonl, заставить prompt бросить исключение, затем отправить следующий обычный prompt и проверить ответ сессии.
4. Тест: повторить с недоступным каталогом состояния и проверить, что сессия отвечает.

Проверка: `node --test tests/adapter/fail-open.test.js` проходит. После каждой искусственной ошибки сессия отвечает на следующий prompt. В логе плагина есть причина ошибки. В receipts/ нет ложной квитанции `posted`.

Приёмка: Ошибка адаптера не ломает сессию. Причина остаётся в логе. Ложная квитанция не пишется. Курсор не сдвигается на необработанное событие.

Гейт: P3. Обязательное условие перед G2.
