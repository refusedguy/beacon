Fix the real cause of runs stuck in waiting_ci when main advances but the PR head does not change. The four dedup guards in `internal/app/reconciler.go` compare only `run.ObservedSHA == obs.HeadSHA`, so after a base move `Decide` returns NeedsRebase and the guard returns before any rebase. Add `BaseSHA` to `core.Observation` (`pkg/core/verdict.go`) and populate it in both SCM adapters from the compare result used to set `Behind` (`internal/infra/scm/github.go`, `internal/infra/scm/gitlab_mr.go`). Add `ObservedBaseSHA` to `core.Run` (`pkg/core/run.go`) and persist it with a guarded column migration in `internal/infra/sqlite/schema.go` and `runColumns`/Save/scan in `internal/infra/sqlite/store.go`. Replace all four equality guards in `reconciler.go` (needs_rebase, needs_agent_fix, rebase, wake) with a head-plus-base comparison and update both observed fields wherever they are written. Keep the existing dedup tests that prevent double wake and double rebase for an identical observation. Add new tests: fixed head with a new BaseSHA and Behind=true causes exactly one UpdateBranch, and the mirror case for the wake path. Split code into a new `internal/app/reconcile_observation.go` if `reconciler.go` would exceed 350 lines. Keep production files under 350 lines. Run gofmt, full go test and go vet, open a PR and call beacon_watch_pr.
