Baseline: beads: cmd/bd/export_auto.go:28-33, порог 5000 изменённых ID, выше которого полный экспорт дешевле; в beacon нет export-state.json, а журнал событий живёт в самой карточке в internal/infra/taskstore/store.go:879-1003.

Цель: Делать автоэкспорт инкрементальным и самовосстанавливающимся, когда рабочее состояние между циклами возвращается назад.

Контекст: Источник, реальный код beads. cmd/bd/export_auto.go:28-58 задаёт incrementalExportThreshold, литерал WORKING для dolt_diff и exportAutoStateVersion со сноской: версию нужно поднимать при изменении смысла поля. exportAutoState на :60-83 хранит LastDiffAnchor как настоящий хеш коммита, а не рабочий хеш (:72-76), и LastDirtyIDs как самозалечивающийся перенос ID, чей diff против якоря не показывает сетевого изменения (:77-82). maybeAutoExport на :88-95 работает и в server mode, потому что без Dolt remote JSONL остаётся единственной git-сохраняемой копией. Разрыв в beacon: cmd/beacon/task.go:46-76 не содержит export, а TaskEventTx в internal/infra/taskstore/store.go:895-947 хранит исторические события в той же карточке; отдельного state-файла с якорем, версией и переносом ID нет.

Шаги: Завести отдельный файл состояния с полем версии. Хранить якорем хеш реального коммита, не хеш рабочего набора. Переносить ID, изменённые в предыдущем цикле, и отбрасывать их, когда новый цикл не нашёл изменений. При несовпадении версии отбрасывать файл состояния. При числе изменённых ID выше порога делать полный проход. Пропускать автоэкспорт при работе как git hook.

Проверка: Измеримая. Два цикла с возвратом рабочего значения между ними: ID из первого цикла всё равно перезаписан во втором. Файл состояния с версией 99 игнорируется и пересоздаётся. При 5001 изменённом ID вызывается полный проход и ноль инкрементальных запросов. При BD_GIT_HOOK=1 число записей равно нулю. Число сетевых вызовов во всех случаях равно нулю.

Приёмка: AN-05 про JSON round-trip не дублируется: здесь только состояние автоэкспорта и выбор инкрементального прохода.
