# T3.233. Конфликт ребейза, классификация красного и реестр адаптеров
Статус: done
Фаза: P3
Тип: task
Владелец файлов: internal/infra/merge/registry.go, internal/infra/merge/registry_test.go, docs/templates/executor-task.md, evals/main.go
Зависимости: T3.232
Ссылка: ADR 0072
Агент: нет
Время: нет
Цель: При ребейз-конфликте тулза шлёт wake подписавшемуся через subscriber.adapter и не разрешает конфликт; красный классифицирует сабагент.
Контекст: ADR 0072 п1, п3, п4, п5 и п7. Кейс W18 проверяет эталонную модель и реестр адаптеров. Ребейз делается только для watch-PR. Неизвестный adapter это ошибка доставки, а не повтор мержа.
Шаги: Объявить реестр адаптеров по имени subscriber.adapter и функцию доставки wake; на verdict=rebase с конфликтом слать один wake подписавшемуся и не трогать ветку; для не-watch PR не делать rebase; описать в шаблоне исполнителя, что сабагент классифицирует красный как флейк, сломанный main или ошибку своего диффа; написать unit-тесты; перенести W18 на реальный код с негативными контролями; приложить команду и вывод к PR.
Проверка: go test ./internal/infra/merge; GO=/tmp/opencode/go126/bin/go bash evals/run.sh
Приёмка: W18 зелёный с негативными контролями; при конфликте ребейза мержа нет и wake доставлен через реестр; неизвестный adapter и не-watch PR не мержат; локальный прогон приложен к PR.
