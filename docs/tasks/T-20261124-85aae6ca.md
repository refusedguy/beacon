Goal: make each blocked group in the queue collapsible, so the operator can expand only the group they care about instead of hiding all blocked work. No Go edits.

Evidence: the live queue stacks blocked group headers such as "blocked by 19651f36-01 · 1 task" above ready cards. A global hide is too coarse. The operator wants the groups themselves collapsable inside the queue, with the same pattern already used for epics.

Scope: .opencode/plugins/beacon-project/ui_view.js, ui_alerts.js, ui.js, ui_view_test.js, ui_alerts_test.js, ui_setup_test.js.

Steps:
1. Give every blocked group header a chevron: collapsed by default, click expands the task titles under that group. Keep the group count visible in the header.
2. Store per-group open state in the same storage mechanism used for epics, but ignore stale open values at startup so groups start collapsed.
3. Keep epic collapse, child cap, empty spacer before Recent and non-duplicated dependency IDs intact. Expanding one blocked group must not push Recent out of reach; cap expanded rows the same way epics are capped.
4. Add a small toggle in the Queue header that expands or collapses all blocked groups at once, with the persisted state shared per group.
5. Tests: default collapsed, click expands one group, global toggle switches all, stale storage does not auto-expand, Recent stays visible, no duplicated dependency rows. node --check and node --test. Open a PR, call beacon_watch_pr, do not self-merge.

Depends on the three plugin test cards so their scopes do not overlap.
