Goal: Produce a trustworthy delta, not a single head number.

Evidence: cibench-04 and cibench-01. GitHub checks out a synthetic merge commit by default. The real head is github.event.pull_request.head.sha and the comparison point is git merge-base of base.sha and head.sha. The six cheap plans are planner, prompt, MCP, redaction, TUI view and HTTP frames.

Steps: In the advisory job, build two detached worktrees at merge base and head on one runner. Copy harness test files into base when the PR changes them. Run A B B A B alternating passes, capture ns/op, B/op, allocs/op, median, range, work, errors and limiter, write per-side CSV with benchstat, and update the same PR comment with a delta table.

Check: A labeled perf PR reports both sides with identical work counts and no overlapping ranges for a claimed gain.

Accept: Overlapping ranges produce an inconclusive row, not a gain claim. Never compare GitHub-hosted and self-hosted numbers.
