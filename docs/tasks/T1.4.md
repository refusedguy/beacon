# T1.4. Fan-out подписчиков на один PR
Статус: done
Фаза: P1
Тип: task
Владелец файлов: internal/domain/fanout.go, internal/domain/fanout_test.go
Зависимости: T1.1, T1.3
Ссылка: ADR 0019
Агент: нет
Время: 2026-11-19T14:10:00Z
Цель: Дать одному Watch обслуживать исполнителя и оркестратора как независимых подписчиков с отдельными обязательствами.
Контекст: WORKER-PROMPT §4.1 п.1: тот же подписчик при повторном beacon_watch_pr означает renew, новый добавляется в subscribers, фан-аут исполнителя и оркестратора на одном PR. §4.2: невариант 1 ограничивает активные Watch на (repo,pr,headSHA) одной записью, лимиты 50 Watch на подписчика и 200 глобально. ADR 0019: при head_changed новый Watch создаётся для тех же подписчиков. ADR 0009 задаёт код LIMIT_EXCEEDED.
Шаги: 1. Реализовать Subscribe(w Watch, s Subscriber) с renew по subscriberID и добавлением нового подписчика. 2. Создать отдельное обязательство каждому подписчику через ключ T1.3. 3. Добавить проверку алиаса (repo,pr,headSHA) и лимитов 50 и 200 с ошибкой LIMIT_EXCEEDED.
Проверка: Тест с подписчиками executor и orchestrator на одном PR: одна Watch и два разных obligationID; повторный executor renew не добавляет обязательство; 51-й подписчик получает LIMIT_EXCEEDED.
Приёмка: Активных Watch на пару (repo,pr,headSHA) не больше одной, обязательства подписчиков независимы.
