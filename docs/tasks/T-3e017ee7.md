Goal: a daemon must never serve an old inode after a rebuild.
Evidence: doctorBinaryFreshnessCheck at cmd/beacon/doctor.go:604-627 compares recorded source hash with current sources but is advisory only; serve and mcp do not check it. After Go merges the pooled MCP process kept serving old policy until a manual restart.
Steps: embed the build hash with ldflags and compare it with doctorBuildHash before serve or mcp starts serving; refuse to start on mismatch with the exact rebuild and restart command; keep doctor as an advisory preflight; add a test that a mismatched hash prevents startup.
Accept: no stale binary can become lock owner or MCP server after a rebuild.
