# HD-071. Lock файл скиллов
Premise: проверено 2026-11-21, дубль. Требование карточки уже в origin/main. skills-lock.json версии 1 лежит в корне репозитория и содержит computedHash на каждый локальный скилл: night-shift и red-verdict-triage. verifySkillsLock в cmd/beacon/orchestrate.go:676 пересчитывает хеш по отсортированным именам файлов и sha256 их содержимого. Функция сообщает о незафиксированном скилле, отсутствующем lock файле, неверной версии и расхождении хеша. Тип findings описан в orchestrate.go:634. Демон вызывает verifySkillsLock в cmd/beacon/daemon.go:199 и публикует findings в stderr и метрику skills-lock, поэтому изменение хеша видно в gate. Тесты в cmd/beacon/skills_lock_test.go покрывают зафиксированные скиллы (TestSkillsLockAcceptsPinnedSkills, строка 44), изменение хеша (62), незафиксированный скилл (80), отсутствующий и неверный lock (95) и актуальность зафиксированного lock (TestRepoSkillsLockIsCurrent, 118). Это закрывает цель «Фиксировать хеши внешних скиллов», шаг «Завести skills-lock.json в beacon-impl» и приёмку «Хеш не зафиксирован проваливает карточку». Реализация вошла в коммит 883b1bf через PR #680, MERGED 2026-11-20. Назначенные OwnerFiles internal/infra/mcp/contract_test.go и docs/adrs/0094-seven-tools.md не менял. Контракт MCP из восьми инструментов не владеет lock файлом, а тесты блокировки уже лежат в cmd/beacon/skills_lock_test.go. Код не писал, gofmt не применял, дубль не создал.
