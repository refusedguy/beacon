# T3.178. Проектный контекст в сессиях через инструкции и хуки
Статус: dropped
Фаза: P3
Тип: task
Владелец файлов: .opencode/plugins/beacon-project/context.js, tests/adapter/beacon-project-context.test.js
Зависимости: T3.176
Ссылка: ADR 0069
Агент: нет
Время: нет
Цель: Сессии проекта получают открытые карточки и AGENTS.md без дублирования при повторе промпта
Контекст: ADR 0069, решение 4. По документации OpenCode V2 записи ctx.session.instructions.entry.put рендерятся как блоки <context key="..."> и объявляются на следующей границе шага без очереди сообщений. Хук context меняет только исходящий вызов к модели, хук prompt работает до admission и может добавить файлы. ctx.location описывает экземпляр плагина, а не каждую сессию, поэтому принадлежность сессии проверяется отдельно.
Шаги: Загружать открытые карточки и AGENTS.md из канонического каталога проекта; класть их в сессию через ctx.session.instructions.entry.put под фиксированными ключами и обновлять эти записи при изменении файлов; перед записью проверять, что сессия относится к локации плагина, через ctx.session.list или ctx.session.get; добавить хук context для текста, который нужен только в исходящем вызове; добавить хук prompt для подключения AGENTS.md как файла без побочных эффектов; написать тесты на ключи записей, на фильтрацию сессий другого проекта и на повтор промпта
Проверка: node --test tests/adapter/beacon-project-context.test.js
Приёмка: Открытые карточки и AGENTS.md видны в инструкциях сессии этого проекта, сессии другого проекта их не получают, повтор промпта не создаёт вторую копию контекста
