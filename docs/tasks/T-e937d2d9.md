Goal: beacon serve must be the only lock owner.
Evidence: cmd/beacon/mcp.go:37-69 takes the lock and runs a reconciler when liveDaemon fails. liveDaemon only dials connection.json and the standby never writes it, so every new MCP process retries the lock. acquireLock at cmd/beacon/lock.go:112-124 unlinks the lock file on a stale daemon record, allowing two owners on different inodes.
Steps: make beacon mcp fail fast with a recorded error when no live daemon exists and never take the lock; stop unlinking beacon.lock on contention and let the kernel release flock; keep daemon.json as diagnostics only; add tests that MCP without a daemon does not own the lock and that contention never removes the lock file.
Accept: after a daemon dies there is exactly one way to own the reconciler and no split-brain starter.
