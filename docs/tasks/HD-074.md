# HD-074. Гейт мержа с условиями
Статус: done
Premise: проверено 2026-11-20, функциональность уже в origin/main. Условия мержа собраны в OwnerFiles: internal/app/orchestrator/decision.go сводит Watch, резолвер и CI к единственному Decide с фиксированным приоритетом blocked → правка сгенерированного файла → неудовлетворённые waitFor/waitForMain → ready + авто-мерж → retry → эскалация; decisionVerdict читает вердикт из Watch (beacon_get_result), иначе из CIState, и DecisionMerge выставляется только при ready без hold-back (autoMerge=false, requireApproval). internal/app/orchestrator/orchestrator.go удерживает PR в wait с причиной через canAutoMerge, ошибка резолвера всегда fail closed и никогда не даёт ready, а mergeOne пишет ledger и закрывает Watch не более одного раза на (watchID, revision). Verdict=ready выставляется движком вердиктов только при зелёном прогоне без fail и pend (internal/domain/verdict.go), а in-scope diff проверяется через CheckSource/GeneratedFileEdits с отказом при ошибке источника. Production-гейт в cmd/beacon/orchestrate.go (ghMerger.MergeChecked) перед gh pr merge читает mergeable, mergeStateStatus и state: PR без MERGEABLE/CLEAN не мержится, а state=MERGED подтверждается до записи ledger и CloseWatch, поэтому зелёный CI без CLEAN мержа не даёт. Правила зафиксированы тестами TestDecideBlockedWinsOverReadyAndDependencies, TestDecideWaitDependencyFailsClosed, TestDecideMergeWhenReadyAndDependenciesSatisfied, TestDecideNeverMergesWhenAutoMergeIsHeldBack, TestCanAutoMergeResolvesEveryDependency, TestRunCheckedMergeHeldByGateDoesNotMerge и TestRunCheckedMergeRepeatedPassDoesNotRemerge. Реализация вошла в main коммитами c7f0559 (PR #373), 8671069 (PR #377), a3d134b и последующими правками гейта. Планировавшийся ADR в репозитории отсутствует, условия сверены с ADR 0072. Карточка уже была в статусе done, OwnerFiles не менял, дубль не создавал.
