Context: diagnosis found that `beacon mcp` has no liveness signal. `cmd/beacon/mcp.go:42-44` logs a lock failure but continues as a tool-only server with no reconciler. `mcp.go:51-55` logs a stopped reconciler loop but leaves the process serving. `cmd/beacon/serve.go` writes `connection.json` with a PID, but `mcp` mode never does. `beacon.lock` is a 0-byte flock with no PID. There is no persistent log file because slog writes to stderr, which OpenCode owns. `beacon status` reads sqlite directly and works with a dead daemon, masking the failure. The operator cannot tell a live daemon from a dead one.

Goal: make daemon liveness and lifecycle failures observable.

Steps:
1. In `cmd/beacon/mcp.go`, after acquiring the daemon lock, write a small state file under `.beacon/` containing PID, start time, project root and a heartbeat timestamp. Refresh the heartbeat on each reconciler tick or at a fixed interval. Remove the file on clean shutdown and when the lock is lost.
2. Make lock acquisition failure and reconciler loop exit visible to the operator: either fail fast with a non-zero exit and a clear message, or record the error in the state file with a timestamp. Choose one and document it in the card result.
3. Add `beacon status` output for daemon liveness: read the state file and report whether the PID is alive and how old the heartbeat is. Do not change the existing run fields.
4. Tests: state file is created and removed, heartbeat advances, stale PID is reported as stale, and lock failure produces a visible signal. Run `gofmt -w` and targeted `go test` for changed packages.
5. Open a PR and call beacon_watch_pr with the real run ID and PR number.

Check: `beacon status` reports daemon alive or dead with heartbeat age, and a failed lock or stopped reconciler leaves a visible record.

Accept: do not change dispatch or reconcile logic. Keep files under 350 lines. Do not edit AGENTS.md or another card.
