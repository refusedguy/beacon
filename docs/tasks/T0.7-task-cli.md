# T0.7. Бинарник beacon task: list, new, take

Статус: todo
Фаза: P0
Тип: task
Владелец файлов: cmd/beacon/task.go, cmd/beacon/task_test.go, internal/infra/taskstore/store.go, internal/infra/taskstore/store_test.go, internal/app/taskcli/service.go, internal/app/taskcli/service_test.go
Зависимости: T0.6
Ссылка: ADR 0020
Агент: нет
Время: нет

Цель: Реализовать подкоманду `beacon task` с тремя командами list, new и take по спецификации docs/beacon-task-cli-spec.md.

Контекст: ADR 0020 определяет обязательные поля карточки, правила ссылок и валидации. Спецификация docs/beacon-task-cli-spec.md даёт точный синтаксис, флаги, формат JSON, алгоритм выбора следующего ID и защиту от гонки двух агентов. ADR 0016 требует один бинарник без внешних модулей для гейтов, ADR 0011 определяет каталог состояния для счётчика и файла замка. ADR 0005 требует самотест с посаженным нарушением. Формат карточки зафиксирован в 52 существующих файлах docs/tasks.

Шаги:
1. Парсер карточек. Читать docs/tasks/*.md, извлекать поля по регулярному выражению в начале строки, брать ID из имени файла, заголовок из первой строки. Сохранять дополнительные поля, включая Гейт.
2. Команда list. Таблица для человека и `--format json` для агентов с полями id, type, status, phase, ownerFiles, dependencies, reference, agent, time, title. Фильтры --status, --phase, --agent, --file. Стабильная сортировка по ID.
3. Команда new. Шаблон со всеми обязательными полями из ADR 0020. Проверка ссылки на ADR или эпик, проверка пересечения владельцев файлов с карточками todo и in_progress, проверка формата. При провале файл не писать и вернуть код 1.
4. Выбор ID. Берём максимум из счётчика в каталоге состояния и максимума по файлам, прибавляем один, под файловой блокировкой, создаём файл через O_CREATE|O_EXCL. Счётчик не переиспользует номера удалённых карточек.
5. Команда take. Атомарная смена Статус: todo на in_progress, запись Агент и Время, переименование файла через temp и rename. Защита от гонки через файловый замок с PID и временем, до 50 попыток по 100 мс, выявление остатка после падения процесса.
6. Коды выхода 0, 1, 2 по ADR 0016. Машинный поток в stdout, шум в stderr.
7. Самотест с посаженным нарушением по разделу 7 спецификации, termasuk тест гонки не менее 20 повторов и тест остатка замка с мёртвым PID.

Проверка: `beacon task list --format json` возвращает валидный JSON массив из 52 объектов. `beacon task new --dry-run` не создаёт файл и печатает следующий ID. Два параллельных `beacon task new` с одинаковыми флагами создают два файла с разными ID, повтор 20 раз. `beacon task take T0.7` меняет статус и пишет Агент и Время. Второй take той же карточки возвращает код 1. `--self-test` проходит все кейсы из раздела 7 спецификации.

Приёмка: Все три команды работают по спецификации. Гонка двух агентов не даёт одинаковый ID и не даёт两 успешных take. Пересечение владельцев файлов блокируется. Коды выхода соответствуют ADR 0016. С外国них модулей в go.mod нет.

Гейт: G0. Входит в обязательные спайки вместе с T0.5 и T0.6. Выход общего G0 требует отчёта владельцу по всем P0 задачам и стоп до подтверждения.
