Context: `beacon_dispatch` returns `{"failures":[{"TaskID":"...","Err":{}}]}` when a run fails to start. The cause is invisible to the orchestrator. Diagnosis showed the real message only in the daemon log: `workspace: conflict: refusing to remove dirty worktree ...` and `spawn: Post ... context deadline exceeded`. `DispatchFailure.Err` is declared as `error` in `internal/app/dispatcher.go`; a wrapped error has no exported fields, so encoding/json marshals it to `{}`.

Goal: make every dispatch failure carry a readable message in the MCP response.

Steps:
1. Change `DispatchFailure.Err` from `error` to `string`, or add a `MarshalJSON` that emits `Error()`. Keep the internal error path for logging.
2. Preserve the full message including the worktree path and the spawn URL.
3. Update `internal/app/dispatcher_test.go` to assert the JSON contains the exact error string for both a workspace conflict and a spawn timeout. Test behavior, not internals.
4. Run `gofmt -w` on changed Go files and targeted `go test ./internal/app`.
5. Open a PR and call beacon_watch_pr with the real run ID and PR number.

Check: a forced dispatch failure returned by the MCP tool shows the concrete reason instead of `{}`.

Accept: do not change the dispatch decision logic or the skip reasons. Keep files under 350 lines. Do not edit AGENTS.md or another card.
