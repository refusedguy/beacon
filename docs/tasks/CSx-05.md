# CSx-05. Внутрипроцессный MCP-мост вместо только удалённого вызова
Статус: todo

Владелец файлов: internal/infra/mcp/client.go, internal/infra/mcp/server.go
Зависимости:

Цель: Дать beacon путь вызова MCP-инструментов внутри процесса без обязательного HTTP-запроса к удалённому серверу.
Контекст: SDK описывает встроенный сервер `McpSdkServerConfig` с полями `type`, `name` и `instance` (`src/claude_agent_sdk/types.py:933-948`) и мост `SdkMcpBridge.handle`, который направляет сообщения напрямую в экземпляр сервера (`src/claude_agent_sdk/_internal/sdk_mcp_bridge.py:343-379`). В beacon каждый вызов инструмента пересылается на HTTP-эндпоинт: комментарий в `internal/infra/mcp/client.go:1-2`, путь `/mcp` в `:32-35`, обработчики `AttachRemoteTools` в `:334-366`. CS-03 описывает сабзагентов как данные, а не транспорт MCP.
baseline: `rg -n 'SdkMcpBridge|InProcess|inProcess' internal cmd` на `origin/main` 7244e15b даёт 0 строк; `rg -n 'remoteMCPPath' internal/infra/mcp/client.go` даёт 5 строк.
Шаги: Ввести порт встроенного MCP-обработчика с методом handle, который принимает имя инструмента и аргументы. Зарегистрировать локальные инструменты в том же дескрипторном списке, что и удалённые. Выбирать локальный путь по конфигурации, сохраняя удалённый как значение по умолчанию. Не допускать одновременно двух обработчиков для одного имени.
Проверка: Тест вызывает локальный инструмент через мост и проверяет результат. Счётчик HTTP-вызовов в тесте остаётся равным нулю. Измеримая проверка: `rg -n 'InProcess|SdkMcpBridge|localMCP' <ветка> -- internal/infra/mcp` даёт не менее 2 строк, а число HTTP-запросов в тесте равно 0.
Приёмка: Локальный инструмент доступен вызывающему без запуска удалённого сервера, и имена инструментов не конфликтуют.
