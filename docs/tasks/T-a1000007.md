Goal: write observation identity in the same save that commits the decision, and only after every guard has passed.

Evidence: PR 2845 sat in waiting_ci for more than 100 minutes with head_sha and observed_sha c61447c while PR head was 9cf67fb. Audit at HEAD 08f3ea57 found the chain: internal/app/reconcile_observation.go:119-121 returns on HasPending and :122-124 returns on sameObservation before any NoteObservationIdentity; internal/app/reconciler.go:265 passes obs.HeadSHA as expectedHeadOid; on failure :268 stamps the observation before :271 calls wake, and wakeWithEvent at :294 sees sameObservation and drops the wake. Pending checks are a guard defer and must stay unstamped. A wake skipped for no slot or an incident must stay unstamped or the fix is lost.

Steps: keep the HasPending guard unstamped. Stamp the changed head and base in the same save that applies EvRebased or another committed decision from that observation. In the rebase failure path save EvRebaseFailed with a zero observation, then call wake with the original observation so the dedup check sees a changed identity and delivers the wake. Leave NoSlot, incident and no-attempt paths unstamped. Add internal/app/observation_stamp_test.go proving pending checks stay unstamped, a committed decision stamps identity once, and a failed rebase wakes the fixer on the first attempt.

Accept: after checks settle the run stamps the real head and UpdateBranch uses the current expectedHeadOid; a failed automatic rebase wakes the fixer once; a pending check does not consume a rebase or fix budget.
