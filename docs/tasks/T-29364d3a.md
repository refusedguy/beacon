Goal: let a monitor recover from drops and make event ids mean one thing.
Evidence: NewWireEvent sets only Type and RunID, so the golden fixture's id and time are not produced by the production mapper; the SSE envelope id and the payload id disagree; Last-Event-ID seeds numbering but no frame is replayed; ids are assigned at write time so three queues serialize in arbitrary order; five bounded queues drop without a gap marker, and the TUI ignores pings so an open connection that falls behind can stay stale forever; runsCache invalidation is not tied to a store revision; plugin watcher payload has no location so the bridge filter drops every live event while its test supplies a location; dedupe records a key before the callback accepts it and value-only keys lose repeated real transitions.
Steps: populate id and at in NewWireEvent and generate the golden fixture from the production mapper; assign one id at observation time and carry it in both envelope and payload; either replay frames for Last-Event-ID or stop claiming resume and emit an explicit gap frame; emit a resync notification on any queue drop and have both TUI and plugin force a runs read on it and on ping; key runsCache generations by store revision; include location in watcher payloads and use the production shape in the bridge test; move dedupe acknowledgement after the callback and add occurrence identity for repeated transitions.
Accept: a dropped frame or a reconnect converges within one poll interval, and no live event is silently dropped by the location filter.
