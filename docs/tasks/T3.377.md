# T3.377. Маппинг события на Watch по repo, PR и headSHA
Статус: done
Premise: проверено 2026-11-21, дубль. Функционал уже влит в origin/main через PR #483 (fix/bs27, commit ce91ff8): internal/infra/webhook/match.go и match_test.go. RoutingKey требует repo+PR+head_sha (Valid), чистая matchWatch сравнивает все три поля и не трогает состояние, MapEvent пишет намерение refresh через RefreshIntent.RecordRefresh и не публикует verdict; no-match и неполный ключ логируются на info (reasonNoMatch/reasonIncomplete) с nil-ошибкой. Тесты покрывают совпадение, чужой PR, устаревший head SHA, пустой source, ошибки source и intent, неполный ключ и чистоту matchWatch. internal/infra/cibridge/bridge.go уже содержит refresh-цикл Bridge и перечитывает состояние Watch перед публикацией вердикта (applyVerdict проверяет current.HeadSHA), поле NoChecksSince присутствует. Аналогичная карточка BS.27 уже помечена done с таким же обоснованием. Новый код в OwnerFiles создал бы вторую копию механизма. Дубль не создан.

Агент: нет

Цель: Находить нужный Watch по событию и отбрасывать устаревшие и fork-события.
Контекст: check_run и check_suite несут head_sha и pull_requests, но для fork push массив пуст. sender может быть ghost. pull_request.synchronize несёт before и after. cibridge.publish уже перечитывает Watch и проверяет Verdict и HeadSHA до записи.
Шаги: Написать чистую функцию matchWatch(repo, pr, headSHA) по ActiveWatches. Для check_run и check_suite брать pull_requests, при пустом массиве искать по head_sha. Для pull_request брать number и pull_request.head.sha. Помечать NoChecksSince как признак начала проверок, не трогая Verdict.
Проверка: Событие со старым head_sha игнорируется; fork-событие с пустым pull_requests находится по head_sha; sender ghost не участвует в решении; два матча для одного Watch дают один refresh.
Приёмка: Вердикт меняется только после перечитывания состояния, а не фактом доставки.
