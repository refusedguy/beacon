Refactor `internal/infra/mcp` so every tool lives in its own file and no tool registration block sits in a shared handler file. Keep `server.go` minimal: NewServer builds the msdk.Server and loops over a registration list. Move `Services` into `services.go`. Create `tool_dispatch.go`, `tool_watch_pr.go`, `tool_status.go`, `tool_wait.go`, `tool_control.go` and `tool_task_create.go`, each owning its args struct, its `msdk.Tool` spec and its `registerX(s *msdk.Server, sv Services)` function. Move existing tests into matching `tool_*_test.go` files. Keep `msdk.AddTool` generic with concrete arg structs so the SDK still generates parameter schemas; do not erase args to json.RawMessage. Add `ToolSpec{Name, Description, OrchestratorOnly}` and `ToolCatalog() []ToolSpec` in `registry.go` as the single declarative source used by the future permissions generator, marking only task creation as orchestrator-only for now. Preserve current tool names, behaviour and permission semantics exactly. Every production file stays under 350 lines. Run gofmt and the full mcp test suite, open a PR and call beacon_watch_pr.
