When Beacon merges a PR, the orchestrator only sees the worker subagent report saying the PR was opened. It never receives the merge result. Add a quiet notification to the parent session.

Implement:

1. Add `NotifyParent(ctx context.Context, sessionID, text string) error` to `core.AgentHarness`.
2. Implement it in `harnesses/opencode` by POSTing to `/api/session/{id}/prompt` with body `{id: "msg_...", text, delivery: "queue", resume: false}`. The `queue` delivery admits the message to the inbox without interrupting, and `resume: false` avoids waking the session. Redact the text.
3. Implement it as a no-op in `internal/infra/harness` CLIExec.
4. In `Reconciler.merge`, after a successful `SCM.Merge`, if `run.ParentSessionID` is not empty, send a short line: PR number, run ID, state merged.
5. Do the same in `finalizeExternal` for externally merged or closed PRs, with the actual state.
6. Add an httptest proving `delivery=queue` and `resume=false`, plus a reconciler test proving the call happens after merge.

Keep production files under 350 lines. Run gofmt and targeted tests only. Open a PR and call beacon_watch_pr.
