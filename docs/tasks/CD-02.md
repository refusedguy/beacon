baseline: в dmux проверка ahead и behind занимает `src/utils/resumeBranches.ts:557-575` и два отказа в `:748-769`. В `origin/main` beacon проверки расхождения при восстановлении нет, 0 точек вызова `rev-list --left-right --count` в `internal/infra/worktree`.

Цель: Не допускать потери локальных коммитов и перехвата чужого worktree, когда агент или человек открывает ветку повторно.

Контекст: Источник: docs/research/comp-dmux.md, приём 2. dmux ищет кандидатов на восстановление среди осиротевших worktree, локальных и удалённых веток в `src/utils/resumeBranches.ts:281-349`. Перед созданием worktree он обновляет remote, вызывает `worktree prune`, считает ahead и behind через `git rev-list --left-right --count` и отказывается действовать в двух случаях. Первый: ветка уже checkout в другом worktree, `:748-761`. Второй: ветка и опережает, и отстаёт от upstream, `:764-769`. Beacon бережёт worktree через `internal/infra/worktree/gc.go:125`, `:202`, окно отсрочки в `grace.go:5-8`, `:54-73` и маркеры агента в `marker.go:22-23`. Этого достаточно для GC, но при повторном открытии ветки beacon не сообщает о расхождении. Возобновление описано только как инструкция в `AGENTS.md:103-111` и `README.md:364`.

Шаги: Добавить в новый файл `internal/infra/worktree/resume_guard.go` чистую проверку по результатам уже полученных команд git. На вход подавать имя ветки, путь worktree, флаги `checkedOutElsewhere`, `ahead`, `behind` и путь существующего worktree. На выходе давать решение `open`, `reuse`, `refuse` с причиной. Покрыть тестами три случая: ветка отстала без локальных коммитов и не занята, ветка занята другим worktree, ветка расходится с upstream. Не добавлять вызовы `os/exec` и не менять `gc.go`, `grace.go` и `marker.go`. Подготовить точку подключения для вызова проверки на границе восстановления работы и передать его владельцу соответствующего файла через `beacon_defer_wiring`.

Проверка: CI зелёный. Тест на расходящуюся ветку даёт `refuse` и причину с упоминанием локальных коммитов. Тест на занятый worktree даёт `reuse` и путь существующего каталога. Новая проверка не вызывает git сама.

Приёмка: Повторное открытие ветки с локальными коммитами не перезаписывает их. Чужой worktree не пересоздаётся. Существующее окно отсрочки и маркеры агента остаются без изменений.

## Решение

`internal/infra/worktree/resume_guard.go` добавляет `CheckResume`. Функция принимает уже собранные Facts и возвращает `open`, `reuse` или `refuse` с причиной. git из проверки не вызывается. Вызов `{rev-list, --left-right, --count}` остаётся на стороне вызывающего кода.

Точка подключения: тип `ResumeFacts` в `resume_guard.go`. Проверку нужно вызвать на границе восстановления работы в `cmd/beacon/attach.go`. Подключение передаётся владельцу файла через отдельную карточку `WIRING-<PR>`.
