# T3.389. ADR 0157: оркестратор как доменная сущность
Статус: done
Фаза: P3
Тип: adr
Владелец файлов: docs/adrs/0157-orchestrator-entity.md
Зависимости: T3.387
Ссылка: docs/adrs/0157-orchestrator-entity.md
Агент: executor
Время: нет
Цель: Зафиксировать, почему оркестратор — отдельная доменная сущность, а не роль в Subscriber, и как она связана с workload и daemon.
Контекст: Роль RoleOrchestrator отвечает только за маршрутизацию wake. Лимит слотов и принадлежность к проекту живут вне домена. Требуется объяснить границу между Orchestrator и Watch и не подменять единицу работы.
Шаги: Написать ADR с контекстом, решением и последствиями. Описать поля сущности, контракт методов, связь с sessionID из _meta, реестром проектов (ADR 0090), циклом daemon (ADR 0072) и четырьмя состояниями workload. Явно указать, что Watch не заменяется и Subscriber-роль сохраняется.
Проверка: Документ лежит в docs/adrs/ и читается без правок кода; ссылки на ADR 0001, 0072, 0088, 0090 согласованы.
Приёмка: ADR объясняет мотив отдельной сущности, её ссылку на Watch по ID, источник лимита слотов из конфига и проектную изоляцию.
