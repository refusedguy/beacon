Make the Beacon cycle observable. Add `internal/app/decisionlog.go` with thin helpers over `slog.InfoContext` and emit Info events with snake_case names and fields: `dispatch.candidates` (candidates, active, limit, budget), `dispatch.skip` (task_id, code, blocked_by, blocked_by_run, overlap, reason), `reconcile.decision` (pr, run_id, task_id, head_sha, observed_sha, behind, state, verdict, reason, action), `transition.spawn`, `transition.watch_pr`, `transition.rebase` (attempt, new_sha, result), `transition.wake`, `transition.merge` (result), `transition.delivery_claim` and `transition.parent_notify`. Call them once per decision from the dispatcher and reconciler. Add `WithCycleID(ctx)` following the existing `WithParentSession` pattern and use run ID as the correlation key. In `cmd/beacon/mcp.go`, stop dropping errors: log lock acquisition failure and reconciler run failure instead of `else if`/`_ =`, so a dead loop is visible. Do not log prompts, config structs, tokens or raw failure excerpts; scalars and short reasons only, relying on the existing redaction handler. Add tests for the helper output using a test slog handler. Keep production files under 350 lines. Run gofmt and targeted tests, open a PR and call beacon_watch_pr.
