Goal: stop the interactive permission prompt and Permission.DeclinedError on the first beacon MCP tool call.
Evidence: OpenCode builds the checked action for an MCP tool as namespace_name from the server name and tool name. In the installed CLI, JI(server,tool) calls OP with namespace QL(server), and OP returns `${namespace}_${name}`. For server beacon and tool beacon_control the action is beacon_beacon_control. Current opencode.json lists beacon_control, beacon_reconcile and other unprefixed names only, so no rule matches and Permission.assert falls back to effect ask. The first call is declined, the retry succeeds after interactive approval. This is the CLI permission service, not Beacon policy or the shell guard. Commit 168eb72d from T-20261125-d576f1ed removed the double prefix and stated that unprefixed names are the real action names, which contradicts the installed CLI. MergePermissions at internal/infra/mcp/registry.go:138-145 still drops `beacon_` plus the action, so regeneration preserves the broken names.
Steps: verify the action name with the installed OpenCode CLI version before editing; change GeneratedPermissions to emit `beacon_` plus each catalog name; keep the stale-entry cleanup but stop dropping the correct namespaced entries; add beacon_beacon_control with allow for build, orchestrator and worker because control is a worker tool; run go generate ./... and keep TestPermissionsUpToDate passing; add a test that pins the namespaced action strings and a test that regeneration keeps them; update AGENTS.md if it lists the permission names.
Accept: a fresh beacon MCP tool call in this checkout runs without a permission prompt or Permission.DeclinedError, and a worker still cannot call orchestrator-only tools.
