## Факты

1. Бинарник лежит в git под версией. `git ls-files --stage tools/beacon-gates/beacon-gates` отдаёт запись `100755 565a68f5cb5f71f90400541cc87b317cd6c82052 0`, то есть файл исполняемый и отслеживаемый. `git check-ignore` не находит для него правила, поэтому `.gitignore` его не скрывает.
2. `.gitignore:19-21` прямо называет намерение: «Бинарники. Гейты коммитим намеренно, по Harbor и ADR 0016». Игнорируются только `/beacon` и `bin/`, не `tools/beacon-gates/beacon-gates`.
3. ADR 0016 в статусе accepted. Решение: один бинарник `beacon-gates` на Go, только стандартная библиотека, три кода выхода (0 зелёный, 1 нарушение, 2 не запустился), self-test у каждого гейта. Причина: владелец указал, что Harbor крутит гейты в GitHub Actions, где есть только Go, и четыре гейта Harbor уже собраны в один бинарник. Воспроизводимая сборка использует `CGO_ENABLED=0`, `-trimpath`, `-buildvcs=false`, `-ldflags="-buildid= -s -w"`.
4. `.github/workflows/gates-binary.yml` пересобирает бинарник из исходников теми же флагами и сравнивает байты через `cmp -s` с закоммиченной копией. Шаг завершается с кодом 1, если закоммиченного файла нет (`gates-binary.yml:48-51`) или байты расходятся (`gates-binary.yml:54-60`). Workflow срабатывает на push в main и на PR, меняющих `tools/beacon-gates/**` или `go.mod`, плюс `workflow_dispatch`.
5. `.github/workflows/ci.yml`, job `gates`, шаг «Check committed gates binary» (строки 208-216) выходит с кодом 2, если файл отсутствует или не исполняемый. Следующие шаги запускают тот же файл для self-test и прогона гейтов (`ci.yml:218-245`). Удаление файла ломает и сверку байтов в `gates-binary.yml`, и обязательный job `gates` в `ci.yml`.
6. `docs/research/deadcode-audit.md:17` и `:52` называют бинарник кандидатом на отдельное решение владельца. `docs/research/cleanup-plan.md:9` и `:37-39` советуют оставить файл: `.gitignore` и ADR 0016 предписывают коммитить, `gates-binary.yml` сверяет совпадение со сборкой, удаление сломает required check.

## Вариант решения владельца

Ответа владельца нет. Ниже два варианта, ни один не выбран.

Вариант A, по умолчанию. Оставить `tools/beacon-gates/beacon-gates` закоммиченным. Модель доставки не меняется: репозиторий несет готовый исполняемый файл, CI пересобирает его из исходников и сверяет байты. Это соответствует ADR 0016, `.gitignore:19-21` и обоим рабочим процессам. Действий не требуется, карточка остаётся `todo` до явного подтверждения владельца.

Вариант B, альтернатива. Убрать бинарник из git и перейти на сборку в CI. Тогда нужно в одном PR: добавить `tools/beacon-gates/beacon-gates` в `.gitignore`, изменить или удалить `gates-binary.yml`, заменить в `ci.yml` шаги «Check committed gates binary», self-test и прогон гейтов на сборку из исходников перед запуском, поправить ADR 0016 и связанные карточки. Меняется модель доставки гейта и исчезает проверка совпадения закоммиченного бинарника со сборкой. Этот вариант требует прямого решения владельца и не выполняется по умолчанию.

Бинарник в этой задаче не удалён ни при каком варианте.
