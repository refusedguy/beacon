# T3.176. Каркас V2-плагина OpenCode с границей проекта
Статус: todo
Фаза: P3
Тип: task
Владелец файлов: .opencode/plugins/beacon-project/package.json, .opencode/plugins/beacon-project/index.js, .opencode/plugins/beacon-project/location.js, tests/adapter/beacon-project-location.test.js
Зависимости: нет
Ссылка: ADR 0069
Агент: нет
Время: нет
Цель: Плагин загружается из .opencode/plugins и берёт корень проекта из ctx.location.project.canonical
Контекст: ADR 0069, решение 1 и 2. Сейчас проектность задаётся фиксированным cwd в opencode.json и os.Getwd() в stateDir(). Документация OpenCode V2 говорит, что плагины в .opencode/plugins загружаются автоматически, а ctx.location описывает место загрузки экземпляра плагина и содержит project.canonical.
Шаги: Создать локальный плагин с серверной частью через Plugin.define и экспортом по умолчанию; прочитать ctx.location.directory, ctx.location.project.id и ctx.location.project.canonical в setup; отделить модуль location, который возвращает корень проекта и каталог локации; обработать случай worktree, где directory и canonical разные; написать тест, который читает исходники через node:fs и проверяет создание плагина, отсутствие жёстко заданного cwd и использование canonical
Проверка: node --test tests/adapter/beacon-project-location.test.js
Приёмка: Плагин грузится без записи в глобальный opencode.json, корень берётся из canonical и совпадает с каноническим каталогом проекта при запуске из worktree
