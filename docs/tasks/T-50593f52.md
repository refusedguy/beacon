Goal: rebuilding a running beacon must not fail with ETXTBSY and must not leave a hash that describes a different binary.
Evidence: install-beacon.sh:14 copies over the executing binary and fails with Text file busy; line 15 writes the source hash after the copy so a failed copy leaves a stale hash. build-beacon.sh:48-50 writes straight to the executable path.
Steps: build and write to a temporary file in the same directory then mv -f over the destination; write build-sha only after the rename succeeds; keep the hash based on real build inputs and add a shell check that a failed replace does not update the hash.
Accept: install succeeds while beacon is running and build-sha always describes the binary on disk.
