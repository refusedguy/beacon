# T3.413. Проверять claimedAt в daemonWaker.Wake
Premise: проверено 2026-11-21. Дубля нет. Карточка просит вторую линию защиты: `daemonWaker.Wake` должен пропускать wake, если обязательство уже прочитано или взято в работу, и делать это через порт store. В origin/main такого кода нет. `daemonWaker` хранит только карту `deliveredKeys` в памяти и проверяет её внутри `Wake`. Порта store в структуре нет, строка `claimedAt` в daemon.go не встречается ни разу. Проверки `claimedAt` живут в других путях: `LadderStopped` в tool_ack.go:874 и `ladderStopped` в escalation.go:187. До daemon-пути эти проверки не доходят, поэтому повторная доставка остаётся возможной. Приёмка требует теста с реальным обязательством: `Wake` возвращает skip, когда `claimedAt` уже проставлен. Такой тест требует настоящего store и прогона демона. На слабом ПК доступны только текст и gofmt, интеграционные тесты идут в CI, поэтому живой зонд здесь недоступен. Добавление порта store в `daemonWaker` потребует правки композиции в cmd/beacon, а это вне OwnerFiles карточки. Статус todo сохранён, блокер возвращён оркестратору. Код не писал, gofmt не применял, OwnerFiles не менял, дубль не создал.

## Блокер: опциональный порт не подключается без правки cmd (2026-11-21)

Оркестратор спросил, можно ли добавить в daemon.go опциональный порт с интерфейсом из internal/infra/store и подключить его через существующий вызов, не трогая cmd. Ответ отрицательный. Замер и причины ниже.

Измерение на ветке fix/p5, origin/main:

- Единственный продакшен-вызов конструктора вейкера: cmd/beacon/daemon.go:359, `orchestrator.NewDaemonWakerWithRoute(lookup, route)`.
- Аргумент lookup имеет тип `orchestrator.DaemonWatchLookup` = `func(watchID string) (DaemonWatch, error)` (daemon.go:167). Это замыкание в cmd захватывает db, но возвращает только проекцию Watch. Поля claimedAt и readAt в DaemonWatch отсутствуют.
- Аргумент route имеет тип `orchestrator.WakeRoute` = `func(ctx, watch, revision, verdict, text) error` (daemon.go:222). Store через него недоступен.
- Интерфейса с методом `Obligation(id string)` в internal/infra/store нет. Метод есть только у конкретного типа `*store.DB` (db.go:461).
- Интерфейсы с `Obligation(id string)` живут в internal/domain/types.go:424 (`domain.Store`) и internal/infra/wake/deliver.go:46 (`wake.ObligationDeliveryStore`). Оба возвращают `domain.Obligation`.
- Матрица tools/beacon-gates/gate/config/layers.json разрешает ребро internal/app -> internal/infra, но запрещает internal/app -> internal/domain. Поэтому app не может назвать `domain.Obligation` в сигнатуре порта.
- Wake сам вычисляет `obligationKey(watchID, revision, subscriberID)` (daemon.go:331). Прочитать claimedAt можно только вызовом `db.Obligation(id)`. У daemonWaker ссылки на db нет.

Вариативный третий аргумент конструктора не решает задачу. Единственный вызов в cmd его не передаст, поэтому в продакшене порт останется nil и проверка claimedAt не выполнится ни разу. Защита станет мёртвым кодом.

Файл вне OwnerFiles, который нужен для реализации: cmd/beacon/daemon.go, строка 359. Передайте db в конструктор вейкера через узкий порт чтения обязательства либо расширьте Lookup так, чтобы он возвращал claimedAt и readAt. OwnerFiles карточки содержит только internal/app/orchestrator/daemon.go, одного файла недостаточно.

Статус todo сохранён. Код не писал, gofmt не применял, cmd не трогал. Блокер возвращён оркестратору: для реализации нужны OwnerFiles с cmd/beacon/daemon.go либо отдельная карточка на проводку.
