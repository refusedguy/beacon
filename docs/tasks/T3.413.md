# T3.413. Проверять claimedAt в daemonWaker.Wake
Premise: проверено 2026-11-21 по свежему origin/main (86ceaec). Дубля нет, но цель карточки уже достигнута другим путём. Карточка просит вторую линию защиты: wake подавляется, если обязательство прочитано или взято в работу. В origin/main эта защита влита через PR #920 (0e02fca, fix(daemon): gate wake by slot token and durable claim, карточка Q-B-04): в cmd/beacon/daemon.go живут узкий порт `daemonClaimSource` с методом `ClaimedAt(watchID, revision, subscriberID)` (:109), адаптер `dbClaimSource`, читающий claimedAt из store через `db.WatchObligations` (:116), и `daemonWakeGate` с проверкой `claimConsumed` (:149). Продакшен-вейкер строится как `NewDaemonWakerWithRoute(..., daemonWakeRouteWithGate(deliver, dbClaimSource{db: db}))` (:448), а `daemonWaker.Wake` вызывает `w.route` (internal/app/orchestrator/daemon.go:358), поэтому непустой claimedAt подавляет доставку wake. Сторона «прочитано» закрыта зависимостью T3.412: `ladderStopped` в internal/infra/ladder/escalation.go проверяет `!ClaimedAt.IsZero() || !ReadAt.IsZero()`. Буквально в `internal/app/orchestrator/daemon.go` строки claimedAt по-прежнему нет: добавление второй проверки внутрь `Wake` продублировало бы gate из PR #920 и потребовало бы правки cmd, что вне OwnerFiles карточки. Узкий порт `CardLinks` в internal/infra/cibridge/bridge.go:159 с подключением через `WithCardLinks` (:383) и type assertion на store (:424) показывает, что опциональные порты с примитивными полями рабочий паттерн, поэтому довод старого блокера о невозможности порта несостоятелен. ## Подтверждение
- Проверка 2026-11-21 по свежему origin/main (86ceaec). Premise исходной карточки устарел: вторая линия защиты с проверкой claimedAt уже влита в main через PR [#920](https://github.com/refusedguy/beacon/pull/920) (0e02fca, merge 2026-11-21) и записана в карточке Q-B-04 со статусом done. `daemonClaimSource` (cmd/beacon/daemon.go:109) и `dbClaimSource` (:116) читают claimedAt обязательства исполнителя через `db.WatchObligations`; `daemonWakeGate.claimConsumed` (:149) возвращает true при непустом claimedAt; `daemonWakeRouteWithGate` (:160) возвращает nil до вызова маршрута доставки. Продакшен-вейкер строится с этим маршрутом (:448), а `daemonWaker.Wake` вызывает `w.route` (internal/app/orchestrator/daemon.go:358), поэтому Wake возвращает skip при уже подтверждённом обязательстве, в том числе после рестарта демона, когда in-memory дедупликация пуста. Приёмка «Wake возвращает skip при уже прочитанном обязательстве» выполнена на уровне поведения: claimed-сторону закрывает gate PR #920, read-сторону закрывает `ladderStopped` из зависимости T3.412 (done). Зависимость T3.412 и Q-B-04 в main имеют статус done. Узкий порт `CardLinks` (internal/infra/cibridge/bridge.go:159, `WithCardLinks` :383, type assertion на store :424) подтверждает, что опциональные порты с примитивными полями подключаются без правки слоёв; довод старого блокера «порт не подключается» опровергнут. Добавление второй копии проверки в `internal/app/orchestrator/daemon.go` создало бы дубль gate и нарушило бы запрет internal/app -> internal/domain (ADR 0005), поэтому новый код не писал. PR #920 не добавил отдельного теста с реальным обязательством: проверка идёт в CI, как отмечено в теле PR. Статус todo изменён на done. Код не писал, gofmt не применял, OwnerFiles не менял, wiring, .beacon и чужие файлы не трогал.
