Goal: close the MCP edge cases where a tool reports success but changes nothing, coerces arguments silently, or lets a worker self-approve.
Evidence from audit: orchestrator-only tools have no server-side role check, only client-side opencode.json permissions; beacon_control nudge loses its message on the daemon path because cmd/beacon/mcp.go:80-84 marshals only action, run_id, pr and sha while control.go:345 rejects empty messages; tool_wait rewrites out-of-range timeout silently, tool_dispatch rewrites N<=0 to 1, tool_status rewrites negative limit; task_update accepts status and child body but drops both; batch create discards single-card fields; beacon_reconcile reports nil tool error when out.Error is set; Control.Approve does not check run state so a worker can self-approve.
Steps: carry message through the remote control wire shape; return explicit validation errors instead of coercing numeric arguments; reject conflicting single and batch shapes; set IsError when a reconcile or batch control reports an error; enforce orchestrator-only tools server-side or document that the MCP daemon is a trusted boundary; prevent self-approval by the run's own worker agent; add tests for every changed path.
Accept: no tool returns success for a dropped argument, a coerced value is visible to the caller, and a worker cannot approve its own run. Work in your own worktree off current main. Never push to main. Never run go test, go build, go vet, linters, node tests or benchmarks locally. Open a PR without the perf label so mark-ready sets ready-to-merge. Call beacon_watch_pr. CI supplies every check.
