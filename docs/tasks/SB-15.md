Цель: Проверять действие агента по трём формам запрета до его выполнения и возвращать причину отказа.

Контекст: Источник: `sweagent/sweagent/tools/tools.py:29-72`, `:353-367`, `sweagent/sweagent/agent/agents.py:946-947`. Политика содержит префиксы `blocklist`, точные совпадения `blocklist_standalone` и условные правила `block_unless_regex`. Проверка идёт до запуска команды. При запрете агент получает шаблон `blocklist_error_template` и может переформулировать действие (`agents.py:1125-1129`). В beacon запреты описаны прозой в `AGENTS.md` и частично проверяются хуком плагина: `AGENTS.md:12` и `:23-25` называют профиль `issue-scout` и хук `execute.before`, который отклоняет `grep -r`, `find /`, локальные `go test` и `beacon gates`. Список привязан к оболочке, а не к действию агента. Условных правил и шаблона ответа нет. Поиск `git grep -c 'blocklist' -- internal cmd` даёт 0 файлов.

baseline: `rg -c 'blocklist' sweagent/sweagent/tools/tools.py` даёт 5 строк; `git grep -c 'blocklist' -- internal cmd` даёт 0.

Шаги: Описать политику действий в машиночитаемом виде с тремя формами правил. Различать запрет по префиксу, по точному совпадению и по исключению из регулярного выражения. Возвращать агенту текст refuse с именем правила, чтобы он мог исправить действие. Оставить существующий хук оболочки без изменений и не дублировать его правила. Не добавлять новых инструментов MCP.

Проверка: Подать четыре действия: `nohup cmd`, отдельное `python`, `radare2 file` без флага `-c` и `radare2 -c cmd file`. Сейчас первое и второе не различаются политикой действий. Цель: первые три отклонены по трём разным правилам, четвёртое разрешено. Негативный контроль: разрешённая команда не порождает refuse, а запрещённая не доходит до выполнения.

Приёмка: Запрет действия подтверждается правилом, а не только текстом инструкции.
