Goal: after an operator nudge and a new decision, the run state must show the current reason instead of a stale branch-update error.
Evidence: Control.Nudge at internal/app/control.go:425-460 only calls HoldAgent, Store.Save and Harness.Wake. It never applies a state event, so State and Reason stay unchanged. Run.Apply clears Reason only on EvAgentFixed, EvChecksPassed or EvRebased with no explicit reason at pkg/core/run.go:392-395. In the live snapshot for run-ca9ae0df06c397f5cabe4923 and run-79d3aa2c9fc69bfeb51dac08 the latest decision is `required check failed: test-modules (root infra...)`, but run.Reason still reads `unavailable: update branch: Variable $sha of type GitObjectID! was provided invalid value`. handleNeedsAgentFix at internal/app/reconcile_observation.go:133-134 returns on sameObservation before any save, so a changed decision reason is logged but never written to the run.
Steps: make nudge write a visible state marker that operator guidance was delivered, without clearing a real failure reason incorrectly; when handleNeedsAgentFix sees the same observation but a different decision reason, save the run with that reason while keeping the no-wake guard and fix budget; never stamp observation identity on that save; add tests that nudge updates the run marker and that a changed decision reason replaces the stale reason without waking the agent twice.
Accept: after a nudge and a new decision the TUI shows the current reason, and a stale branch-update error no longer stays on the row after the decision has changed.
