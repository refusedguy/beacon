Context: the operator uses a weak PC. Worker agents currently run full `go build ./...`, `go test ./...`, `go vet ./...` and `golangci-lint` locally, which burns CPU. Heavy verification belongs in CI. There is no way to configure the instructions given to a worker without editing AGENTS.md by hand.

Goal: add a config field that prepends operator-defined instructions to every worker spawn prompt.

Steps:
1. In `internal/infra/config/config.go`, add a `harness.worker_instructions` string field (or `worker.instructions`), with a default that states the weak-PC rule: targeted package tests only, full builds/vet/all-tests/linters are CI-only. Keep the field optional so an empty value uses the default.
2. In `internal/app/dispatcher.go`, where the spawn prompt is built around lines 235-243, prepend the configured instructions. Keep existing prompt content intact. Apply the same prefix in `internal/app/base_red.go` fixer prompts if they are worker agents.
3. Add config tests in `internal/infra/config/config_test.go` for the default and a YAML override. Add a dispatcher test in `internal/app/dispatcher_test.go` asserting the configured text appears in `SpawnRequest.Prompt` and that omitting it still works.
4. Run `gofmt -w`, targeted `go test ./internal/infra/config ./internal/app`.
5. Open a PR and let the reconciler handle it.

Check: setting `worker_instructions` in `.beacon/config.yaml` changes the text sent to a worker on spawn; no code or AGENTS.md edit is needed.

Accept: do not change verdict rules or CI workflow. Keep production files under 350 lines. Do not edit AGENTS.md or another card.
