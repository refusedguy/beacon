# T1.11. Архивация закрытых Watch и контроль роста базы
Статус: done
Фаза: P1
Тип: task
Владелец файлов: internal/infra/store/archive.go, internal/infra/store/archive_test.go
Зависимости: T1.2, T1.7
Ссылка: ADR 0019
Агент: нет
Время: 2026-11-19T14:45:00Z
Цель: Ограничить рост активной части базы переносом закрытых Watch в архив без TTL как причины закрытия.
Контекст: ADR 0019: TTL 6 ч отменён, закрытие только по терминальному вердикту, отмене или head_changed; рост базы контролируется архивацией закрытых записей; долгие цепочки видны как число head_changed у одного issue. WORKER-PROMPT §4.2: закрытые Watch хранить 7 дней, затем архив. ADR 0015: одна база, поэтому архив это таблица в ней.
Шаги: 1. Добавить таблицу watch_archive со всеми полями Watch и closeReason. 2. Переносить строку при status=closed, сохраняя обязательства и историю доступными по watchID. 3. Применить удержание 7 дней из §4.2 как срок до переноса, не как TTL закрытия.
Проверка: Тест: закрытый Watch уходит в архив, активный остаётся; повторный прогон идемпотентен; история обязательств читаема после переноса; Watch без терминального вердикта не архивируется.
Приёмка: Число строк в активной таблице не растёт с числом завершённых PR, ни один Watch не закрыт по истечении времени.
