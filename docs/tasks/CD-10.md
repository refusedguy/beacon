baseline: dmux выводит slug из ветки, добавляет шесть символов SHA1 при коллизии и переиспользует worktree, уже содержащий ветку (`src/utils/resumeBranches.ts:429-442`, `:444-493`, `:495-519`). В `origin/main` путь и ветка выводятся из task ID и repo (`cmd/beacon/agents.go:949-961`), а занятый путь отвергается (`agents.go:1090-1099`).

Цель: Не создавать второй checkout той же ветки и не сталкивать имена worktree разных задач.

Контекст: `getAvailableSlug` в dmux резервирует имена активных pane и каталогов, а при конфликте добавляет `shortHash(branch:attempt)` (`resumeBranches.ts:500-516`). `hasReusableWorktreeForBranch` обходит вложенные каталоги и сравнивает текущую ветку (`:453-492`). Beacon привязывает worktree к паре task ID и repo, проверяет только занятость пути в своём реестре и всегда вызывает `git worktree add -b` (`agents.go:1050-1051`, `:1090-1099`). Если ветка уже checkout в другом worktree, эта проверка не поможет.

Шаги: Добавить в `internal/app/session/worktree_slug.go` чистые функции вывода slug, хеш-суффикса и решения о переиспользовании. Вход: имя ветки, занятые имена, список worktree с их ветками. Выход: имя и решение `create` или `reuse`. Не вызывать git и не читать каталоги внутри функций. Покрыть тестами двух веток с одинаковой последней частью, занятого slug и уже checkout ветки.

Измеримая проверка: Две ветки `feature/fix` в разных репозиториях дают разные slug с шестисимвольным суффиксом. Ветка, найденная в существующем worktree, даёт решение `reuse` без вызова `worktree add`. Повторный вызов с теми же входами даёт тот же результат.

Приёмка: Повторное открытие ветки не создаёт копию checkout. Суффикс детерминирован и не зависит от порядка обхода.
