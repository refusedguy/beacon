Goal: cut allocations in ParseTaskFields without changing any field value or card contract.

Evidence: the card-parse row in the advisory comment ranges from 0.018 to 0.749 ms on unchanged code, and the plan lists ParseTaskFields as a priority-two target. splitFieldLines currently builds a slice with strings.Split(strings.ReplaceAll(body, "\r", ""), "\n"), which allocates twice before any field is read. unique also allocates on every call.

Steps, all variants in internal/infra/tasksource/parse.go with tests in parse_test.go:
1. V1 trim carriage returns per line instead of copying the whole body with strings.ReplaceAll.
2. V2 scan lines without building the intermediate slice when callers only need a forward walk.
3. V3 tighten unique so a no-duplicate input does not allocate a result map or slice beyond what it returns.
4. Keep every alias, scope resolution, child plan and cache behavior identical. The advisory row that decides this card is card-parse from BenchmarkHotPaths; keep work and errs equal and the limiter string unchanged.
