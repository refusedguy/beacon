# BS.40. WS gateway как альтернатива SSE
Статус: done
Фаза: P3
Тип: task
Владелец файлов: internal/infra/server/ws.go
Зависимости: BS.17
Ссылка: ADR 0194
Агент: нет
Время: нет
Цель: Двусторонний канал для будущих клиентов.
Контекст: openrig использует createAppWithWebSocket и routes/terminal-ws.ts.
Шаги: WS endpoint поверх того же EventBus, реплей по курсору.
Проверка: Семь MCP-инструментов не зависят от транспорта клиента.
Приёмка: WS включается флагом, SSE остаётся 기본ным.

## Подтверждение
- Premise проверен 2026-11-20. Функциональность уже в main. WS-транспорт лежит в `internal/infra/server/ws.go`: `WebSocket` поднимает соединение над тем же `EventReader` через `NewProjection`, реплей идёт по курсору из `Last-Event-ID` или `?replay`, а кадр `{"type":"resume"}` сдвигает курсор. Флаг `Config.Enabled` выключен по умолчанию, `ServeHTTP` отдаёт 404 без апгрейда, и SSE в `events.go` остаётся основным каналом. MCP-инструменты живут в `internal/infra/mcp` и не привязаны к транспорту клиента. Новый код не добавлял. Реализация уже в OwnerFiles, дубль создал бы вторую копию протокола.
