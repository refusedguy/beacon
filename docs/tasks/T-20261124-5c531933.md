Goal: make the built-in MCP tools the only interface an agent needs. No agent should ever hunt for source files or an executable and invoke beacon through a shell. No plugin JS or docs edits.

Evidence:
- All ten beacon_* MCP tools are present and callable in the current session. beacon_dispatch takes only {"n": number}; nothing is missing from the tool schema.
- internal/infra/mcp/tool_dispatch.go:41-52 reads the orchestrator session ID from _meta and puts it into the context at line 27. The run then gets the correct parent_session_id and transition.parent_notify succeeds.
- The model is still resolved once at daemon startup in cmd/beacon/main.go resolveModel, using BEACON_PARENT_SESSION from the environment. The MCP daemon has no such variable. A worker spawned through MCP therefore gets OpenCode's default paid model and fails with "Add credits to continue, or switch to a free model".
- My workaround was to call the beacon CLI from a shell with BEACON_MODEL set. The operator is right: that is not acceptable. Other agents must not go looking for cmd/beacon/main.go or .opencode/bin/beacon and run it.

Steps:
1. Resolve the model per dispatch from the parent session that arrives in the MCP request. Use the existing OpenCode session lookup path in cmd/beacon/main.go resolveModel as the source of truth, but move or call it so the parent session from app.WithParentSession is used at dispatch time, not only at process start.
2. Carry the resolved model from the dispatcher into the spawn request and apply it in harnesses/opencode Spawn and configureSession. ParentID must stay set. Do not require BEACON_MODEL or a harness.model config string for MCP dispatch.
3. Add tests with a fake OpenCode server: MCP dispatch with a parent session resolves that session's model, the spawned worker has the same model and parentID, and no CLI invocation is needed. Keep existing parent-session, retry and wake tests passing.
4. Update the universal default worker instructions in internal/infra/config/config.go to state: use the beacon_* MCP tools only; never locate, build or execute the beacon binary or cmd/beacon source from a shell. Add a config test for the wording.
5. Keep funlen <= 80 lines, statements <= 40, complexity <= 20. Run gofmt -w, targeted go test ./internal/infra/mcp ./internal/app ./internal/infra/config ./cmd/beacon and go test ./... in harnesses/opencode. Leave full repo lint to CI.
6. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.
