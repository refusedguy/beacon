baseline: dmux устанавливает хуки агента при создании и повторном открытии pane: `codex` пишет JSON с pane ID, turn ID и transcript path в событийный файл (`src/utils/codexHooks.ts:53-127`), `claude` делает то же для события `Stop` (`src/utils/claudeHooks.ts:54-121`), установка происходит при возобновлении (`src/utils/reopenWorktree.ts:192-235`). Beacon знает статусы `active`, `idle`, `closed` в таблице сессий (`internal/infra/store/sessions.go:29-35`), но не имеет источника, который переводит сессию в `idle` по событию агента.

Цель: Получить факт окончания хода от самого агента вместо вывода по таймауту или опроса процесса.

Контекст: Хук в dmux получает JSON на stdin, отбирает событие `Stop`, проверяет pane ID и записывает файл с временной меткой (`codexHooks.ts:88-117`). Скрипт устанавливается в каталог агента и регистрируется в его конфигурации (`:120-127`). При повторном открытии worktree хуки ставятся заново вместе с выбором агента из метаданных (`reopenWorktree.ts:176-235`). Плагин beacon в `.opencode/plugins/beacon-project/index.js:78-80` обрабатывает события инструментов, а не конец хода агента. Карточка CD-13 хранит шаблоны запуска, но не источник статуса.

Шаги: Добавить в `internal/infra/observe/agent_turn_event.go` тип события, валидатор входящего JSON и функцию, которая превращает событие в переход статуса сессии. Читатель файла и установка хука остаются на границе. Покрыть тестами события `Stop`, чужого pane ID, неверного JSON и повторной доставки. Не расширять `TOOL_LIFECYCLE_EVENTS` из CS-01 и не менять схему таблицы сессий.

Измеримая проверка: Событие `Stop` с совпадающим pane ID меняет статус на `idle`. Чужой pane ID и неверный JSON отклоняются. Повторная доставка того же события не меняет статус и не пишет вторую запись. Число вызовов опроса процесса в тесте равно нулю.

Приёмка: Конец хода приходит как событие, а не как предположение по таймауту. Существующие статусы реестра сессий сохраняются.
