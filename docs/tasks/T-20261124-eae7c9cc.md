Context: operator says the Beacon sidebar panel is a meaningless wide block with no styling, no visual hierarchy and an unnoticeable close button. Current state in screenshots: a section header `Beacon`, then rows with state glyph + short task ID + title + PR + time + reason. The detail `session.panel` shows `Beacon run detail` plus a tiny muted ✕ at the far right. There is no compact card layout, no aligned columns, no color-coded states beyond a glyph, and no obvious close affordance.

Goal: make the panel look like a native, polished OpenCode sidebar widget instead of a wall of text.

Steps:
1. Study the native OpenCode v2.3.2 sidebar widgets (sidebar/mcp.tsx, sidebar/context.tsx, sidebar/footer.tsx from the installed binary or v2.3.2 source) and the reference plugins (streetturtle/opencode-better-sidebar, dskanakoglou/opencode-sidebar-plus). Copy their exact layout primitives: `box` with `flexDirection: row`, `gap: 1`, `minWidth: 0`; dot with `flexShrink: 0`; name with `flexGrow: 1 flexShrink: 1 minWidth: 0 wrapMode: none truncate`; status right-aligned with `flexShrink: 0`. Use `context.theme` colors only (`text.base`, `text.muted`, `feedback.*.base`, `background.raised.high`).
2. Compact list: at most two aligned lines per run, fixed column widths, no mid-word wrapping, no duplicate ID/title, at most 5 recent rows with elapsed time and only failure codes as reasons. Add a small header with counts (active, blocked, rebase, fix) and last update time.
3. Detail panel: a proper header box with a visible title, a clearly labeled close control (`✕` or `esc` label with higher contrast than muted, larger hit area via padding), and grouped sections (Identity, Timing, Attempts, Reason, Timeline, Decisions) with subtle separators. Cap decisions at 20 with the earlier-marker.
4. Make the close control obvious: either a styled `✕` with `fg={theme.text.feedback.error.base}` or a text `esc` label like OpenCode's dialog header. Keep `onMouseUp` + `selectable: false` per verified API. Keep the one-shot guard so closing does not instantly reopen.
5. Simplify the overall width: the panel should not look like a full-width wall. Use fixed column widths and truncation so it reads like a status widget. Keep all configurable options (statusPanelEnabled, statusPollMs, watcherEnabled, snapshot limits, etc.) working.
6. Split files as needed (ui.js, ui_view.js, ui_model.js, ui_bridge.js, ui_setup_test.js) so each stays under 350 lines. Add tests for rendered row shapes, header content, close control styling/firing, and the 20-decision cap.
7. Run `node --check` and `node --test .opencode/plugins/beacon-project/*_test.js`. Report pass count. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Check: panel reads as a compact, styled, aligned widget with obvious close control; no long unstyled paragraphs.

Accept: only plugin JS files. Do not touch Go code, AGENTS.md or task cards. Use only verified @opentui/solid props. Keep files under 350 lines.
