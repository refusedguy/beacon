Goal: when a new decision changes the reason, the run shows the new reason without a second wake.

Evidence: handleNeedsAgentFix at internal/app/reconcile_observation.go:133-134 returns on sameObservation before any save, so a changed decision reason is logged but never written to the run. In the live snapshot the latest decision reads `required check failed: test-modules (root infra...)` while run.Reason still reads `unavailable: update branch: Variable $sha of type GitObjectID! was provided invalid value`. Run.Apply at pkg/core/run.go:415-466 only changes Reason through Event.Reason and clears it on the recovery events at :392-395. The no-wake guard and fix budget in handleNeedsAgentFix must stay in force.

Steps: in handleNeedsAgentFix, when sameObservation is true but decision.Reason differs from run.Reason, set run.Reason to decision.Reason and call Store.Save. Keep the no-wake return and the fix budget unchanged. Do not call NoteObservationIdentity or NoteObservation on that save. Add internal/app/reconcile_reason_test.go proving that a changed reason replaces the stale reason with one save and no wake and no observation stamp, and that an unchanged reason still returns without a save.

Accept: after a new decision the TUI shows its reason, and the agent is not woken twice for the same observation.
