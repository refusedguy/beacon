# T2.12. Общий счётчик поинтов GitHub
Статус: done
Фаза: P2
Тип: task
Владелец файлов: internal/infra/github/points.go, internal/infra/github/points_test.go
Зависимости: нет
Ссылка: ADR 0013
Агент: T2.12
Время: 2026-11-19T12:37:50Z
Цель: Реализовать общий для REST и GraphQL счётчик поинтов с лимитом 500 в час, который при старте читает GET /rate_limit.
Контекст: ADR 0013 запрещает чистый in-memory счётчик. При старте Beacon читает потраченные поинты через GET /rate_limit, затем обновляет счётчик на каждый ответ и периодически сверяется с GitHub. После рестарта отсчёт не начинается с нуля. Лимит общий для REST и GraphQL, 500 поинтов в час. При достижении порога оба клиента увеличивают интервал. Заголовки x-ratelimit-* приоритетнее тела ответа. Secondary limit не измерим через /rate_limit и обрабатывается по retry-after. WORKER-PROMPT §4.6 задаёт жёсткий бюджет 500 pts/час с растяжением интервала при достижении. D-github-ci-options добавляет, что GET /rate_limit не тратит primary, но может учитываться в secondary.
Шаги: 1. При старте получить потраченные поинты через GET /rate_limit. 2. Открыть метод добавления стоимости каждого ответа для обоих клиентов. 3. Периодически сверять значение с GitHub и выставлять флаг достижения лимита, который читает T2.13.
Проверка: points_test.go подменяет /rate_limit и проверяет, что стартовое значение не ноль, что вызовы добавления стоимости увеличивают счётчик, что при 500 выставляется флаг лимита и что заголовки x-ratelimit-* перекрывают значение из тела.
Приёмка: после рестарта счётчик не начинается с нуля, лимит общий и равен 500, заголовки приоритетнее тела, secondary обрабатывается по retry-after.
