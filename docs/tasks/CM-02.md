Контекст: Источник: `skills/engineering/diagnosing-bugs/SKILL.md:78-86` требует сжимать репро по одному элементу и считает его готовым, когда удаление любого оставшегося элемента делает loop зелёным. Строки `:100-112` предписывают менять одну переменную, помечать логи префиксом `[DEBUG-a4f2]` и для регрессий производительности сначала замерять baseline. Строки `:130-138` требуют удалить теги и записать правильную гипотезу в commit или PR. baseline: `git grep -i -c 'falsifiable' -- AGENTS.md README.md GLOSSARY.md docs/templates .opencode docs/adrs internal cmd tools scripts` = 0, `load-bearing` = 0, `minimis` = 0. Частично есть `internal/domain/depth.go:98-115`: переход на слой глубже требует новые evidence, но там одна гипотеза на шаг, без ранжирования и без показа списка перед проверкой.
Шаги: Вписать в шаблон исполнителя четыре шага после получения красной команды из CM-01: сжать репро, составить ранжированный список с предсказаниями, показать его оркестратору или владельцу до инструментации, менять по одной переменной. Добавить требование тега `[DEBUG-...]` и его удаления перед завершением. Для perf указать замер baseline до правки. Не менять `depth.go` и не дублировать его проверки.
