# T2.11. GitHub GraphQL клиент на отдельном http.Client
Статус: done
Фаза: P2
Тип: task
Владелец файлов: internal/infra/github/graphql.go, internal/infra/github/graphql_test.go
Зависимости: T2.12, T2.17
Ссылка: ADR 0004
Агент: нет
Время: 2026-11-19T20:30:00Z
Цель: Реализовать GraphQL-батч на отдельном http.Client с алиасами, чанками и чтением rateLimit.cost из каждого ответа.
Контекст: ADR 0004 возлагает на отдельный http.Client точный контроль над алиасами, ценой запроса и полями statusCheckRollup, а также чтение rateLimit.cost и нормализацию ошибок. WORKER-PROMPT §4.6 задаёт чанк tier-1 не более 100 алиасов, пороги state-only 100 алиасов стоят 1 поинт, 150 стоят 2, и не более двух параллельных запросов к GitHub. D-github-ci-options фиксирует измеренные пороги: с contexts(first:10) 60 алиасов стоят 1 поинт, 80 стоят 2, один батч на 15 PR со статус-чеками стоит 1 поинт. GraphQL primary-лимит приходит как HTTP 200 с ошибкой в теле.
Шаги: 1. Построить запрос с уникальными алиасами по активным Watch. 2. Разбить алиасы на чанки с лимитом 100 для tier-1 и 50 для contexts. 3. Отправить запросы через отдельный http.Client с не более чем двумя параллельными вызовами, прочитать rateLimit.cost и отдать его в счётчик T2.12.
Проверка: graphql_test.go подаёт записанный ответ GraphQL и проверяет, что cost попадает в счётчик. Два теста на 100 и 150 алиасов сверяют число запросов и размеры чанков. Отдельно проверяется уникальность алиасов и предел в два параллельных запроса.
Приёмка: cost читается из ответа, чанки укладываются в измеренные пороги, используется отдельный http.Client, параллелизм не превышает двух.
