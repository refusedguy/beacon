Goal: cancel must not return a client deadline error after the state was saved and must not leave a dirty worktree.
Evidence: Control.Cancel saves EvCancel then calls Harness.Stop and Workspace.Remove synchronously through bestEffort with the caller context at internal/app/control.go:14-21 and 253-289. Remove refuses dirty trees, bestEffort only logs, and the batch loops per id with the same deadline. The operator sees context deadline exceeded although runs are closed. Other terminal paths already use ForceRemove at internal/app/dispatcher.go:895-901.
Steps: run cleanup with a detached bounded context so the RPC deadline cannot cut it short; call ForceRemove for a dirty terminal workspace and keep it best effort; add a test that cancel returns after state is saved while Stop and Remove are slow, and that a dirty tree is force-removed.
Accept: a batch cancel of several runs returns per-id results without deadline error and leaves no dirty worktree for the next dispatch.
