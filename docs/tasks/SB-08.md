Цель: Показывать долю прошедших проверок, когда часть проверок зелёная, а часть красная.

Контекст: Источник: `swebench/harness/grading.py:288-326`, `swebench/harness/constants/__init__.py:7-9`. Три значения `ResolvedStatus` различают полное решение, частичное решение и отказ. Частичный статус выставляется, когда все P2P зелёные, а F2P прошли не все (`:323-324`). Доли считаются отдельно и не округляются до одного бита (`:288-306`). В beacon `ExternalVerdict` имеет ровно два значения `PASS` и `FAIL` (`internal/domain/verdict.go:684-690`). `EvaluateExternal` ставит `PASS` только когда все проверки прошли (`:770-774`), а `CheckOutcome` хранит булево `Passed` (`verdict.go:696-701`). Промежуточного состояния нет, поэтому оркестратор не видит разницу между одной упавшей проверкой и всеми упавшими. Поиск `git grep -c 'RESOLVED_PARTIAL' -- internal` даёт 0 файлов.

baseline: `rg -c 'RESOLVED_PARTIAL|ResolvedStatus' swebench/harness/grading.py swebench/harness/constants/__init__.py` даёт 5 строк; `git grep -c -i 'resolved_partial' -- internal` даёт 0.

Шаги: Добавить третье значение внешнего вердикта и поле с долей прошедших проверок. Заполнять его, когда часть объявленных проверок прошла, а часть нет. Сохранять имена прошедших и упавших проверок в доказательстве. Оставить текущее правило автоматического мержа неизменным: частичный вердикт не открывает merge. Сохранить fail-closed поведение для пустой декларации и необъявленных имен.

Проверка: Объявить три проверки, две с кодом 0 и одну с кодом 1. Сейчас вердикт `FAIL` без доли. Цель: вердикт `PARTIAL`, доля 2/3, имена упавших проверок видны в доказательстве. Негативный контроль: три упавшие проверки дают `FAIL` с долей 0/3, пустая декларация остаётся `FAIL`.

Приёмка: Оркестратор видит прогресс проверок и выбирает между починкой и полным откатом по числу, а не по одному биту.

Причина: Реализация уже в main. Коммит 85199270c1409d05d0862a6cc2182f51602e131a вошёл через PR #1932. Проверка git merge-base --is-ancestor 85199270 origin/main вернула код 0. В internal/domain/verdict.go уже есть ExternalPartial, PARTIAL и Progress. Дубль кода не нужен.
