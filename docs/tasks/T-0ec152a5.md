Goal: stop stale editor worktree rows and MCP reconnect churn after a worktree removal.
Evidence: the live OpenCode log has 42 POST /api/location/reload responses with 503 and 6 with 499 between 10:57 and 17:31 on 27 Nov 2026. Harness.RefreshWorktrees at harnesses/opencode/opencode.go:394-396 logs the failure and returns nil with no retry. A single stale row whose directory is gone makes every later reload return DirectoryNotFoundError, which drops other live location services; the operator sees a worktree that cannot be opened and a panel that only a full OpenCode restart fixes. g.refresh at git_worktree.go:470-477 uses the caller's context, so a cancelled operator request can skip the refresh entirely. Create clears a stale path with removeForce and deliberately skips the refresh, so a failed add after cleanup leaves the editor unchanged.
Steps: retry POST /api/location/reload on 503 and 499 with a short bounded backoff using the status already returned by h.do, then return the last error after the cap; use context.WithoutCancel in g.refresh so a cancelled caller cannot skip the refresh; add a test that returns 503 on the first reload and 204 on the second and asserts two calls; verify a removed worktree no longer appears in the editor inventory after the retry succeeds. Keep removal best effort so a failed refresh never fails a worktree removal.
Accept: a transient 503 does not leave a stale editor row, and removal semantics do not change.
