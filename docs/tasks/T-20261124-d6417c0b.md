Goal: the sidebar must show the queue on the first render after an OpenCode restart. A manual plugin reload currently fixes it, so the data and cards exist. No Go edits.

Evidence: beacon status --snapshot returns six queue items and SQLite has six available tasks. On fresh startup the sidebar shows Queue 0 until the operator reloads the plugin. ui.js:84-88 computes root and creates the status source during setup, ui.js:258 calls refresh immediately, and ui_model.js:42-143 drops queue items whose card file cannot be read. The likely cause is that ctx.location or ctx.client.rpc is not ready at first setup, so root falls back to process.cwd() and readCard finds no docs/tasks files. Prove this from code and a fake ctx before changing anything.

Scope: .opencode/plugins/beacon-project/ui.js, ui_model.js, location.js, session_identity.js and their tests.

Steps:
1. Trace the first setup against a manual reload. Identify which ctx field is missing or late and quote the code path.
2. Defer status source creation or root resolution until ctx.location is available, then refresh. Do not cache an empty queue as the baseline. If RPC is selected before it is ready, fall back to CLI with a verified root rather than an empty source.
3. Keep readCard fail closed for genuinely missing cards, but do not let an unready root filter every card.
4. Tests with a ctx that has no location at setup and gains it later: queue becomes visible without a manual reload; existing reload, slot and toast tests keep passing.
5. node --check every plugin JS file and node --test .opencode/plugins/beacon-project/*_test.js. Open a PR, call beacon_watch_pr, do not self-merge.

Depends on the two plugin cards above so the scopes do not overlap while they run.
