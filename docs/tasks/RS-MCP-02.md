baseline: `grep -c '^func Test' tools/beacon-gates/gate/gate_test.go` = 6; `grep -c '^func Test' tools/beacon-gates/gate/tool_contract_test.go` = 9; `git grep -l -E 'TOOL-DESC|MinDescriptionWords|NearDuplicateThreshold' origin/main -- 'tools/beacon-gates/**'` = 0, отдельного гейта описаний в main нет; `git grep -n 'tools/list serialized to' origin/main -- '*.go'` = internal/infra/mcp/contract_test.go:182, живой тест считает байты и проверяет точный набор из восьми имён, но не проверяет качество описаний. Дубля нет.
Решение: `CheckToolContract` в новом файле `tool_contract.go` читает сохранённый ответ tools/list из байтов и возвращает `ToolContractResult` с точным размером в байтах и списком finding. Поддерживаются документ `{"tools":[...]}` и обёртка JSON-RPC `result`. Проверки: имя по шаблону `[a-zA-Z0-9_-]{1,64}`, уникальность имён, не менее восьми слов в описании, непустое описание каждого параметра, `required` только для объявленных параметров, `additionalProperties: false` и пустой `required` у инструментов без параметров, почти дубликаты описаний. Гейт не пишет в stdout, сводка доступна через `Report()`.
Граница: точный набор имён и бюджет в 16 KiB остаются в живом контракт-тесте `internal/infra/mcp/contract_test.go`. Новый гейт не повторяет эти правила и работает офлайн с сохранённым ответом.
Ограничение: почти дубликаты ищутся по коэффициенту Жаккара для множеств слов с порогом 0.8. Это ранжирование текста, а не оценка реальной модели или качества описаний для модели.
Цель: Перенести идею tool_design_check.py в гейт: проверять имя, уникальность, длину описания, описанность параметров, закрытый вид схемы и почти дубликаты.
Контекст: Premise: проверено 2026-11-21, отдельного гейта описаний нет. baseline: `grep -c '^func Test' tools/beacon-gates/gate/gate_test.go` = 6. Источник: https://modelcontextprotocol.info/docs/tutorials/writing-effective-tools/ дал рост с 22 pass до 62 pass на трёх наборах. Сайт неофициальный, переносится проверяемая механика, а не числа.
Шаги: Создать проверку поверх сохранённого ответа tools/list. Проверять имя по спецификации, уникальность, минимум восемь слов в описании, nonempty description у каждого параметра, required и additionalProperties false для инструментов без параметров. Печатать размер листинга в байтах. Негативный контроль на почти дублирующихся описаниях.
Проверка: gofmt чистый. Тесты гейта зелёные в CI. Гейт ничего не пишет в stdout ядра.
Приёмка: Гейт ловит расхождение имён из семи и восьми инструментов и дрейф описаний. Словесный ранкер не выдаётся за проверку реальной модели, это описано в карточке.
