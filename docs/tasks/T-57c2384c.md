Goal: a duplicate merge claim or a failed card publish must not leave the card available.
Evidence: internal/app/reconciler.go:215-219 returns early on a duplicate delivery claim and skips both Source.Complete and SetTaskStatus. finalize.go:510-514 uses else if so a failed Complete skips SetTaskStatus. Re-asserting done twice is harmless; skipping it causes duplicate dispatch.
Steps: remove the early return on claimed:false and call SetTaskStatus before returning; change the else-if in finalize.go to an independent call; add tests for duplicate claim and Complete error that assert the card ends done in SQLite.
Accept: every terminal merge path leaves the card status done in SQLite even when publish or claim handling fails.
