# T3.283. Уведомления ntfy и webhook
Статус: todo
Premise: проверено 2026-11-21, функционал в origin/main отсутствует, дубль не создан. Упоминаний ntfy в main нет ни в одном файле: сеть уведомлений оператора представлена только телеграм-синком `TelegramNotifySink` в `internal/infra/wake/telegram.go` и портом `NotificationSink`/`EventNotifySink` в `internal/infra/wake/notify.go`. Webhook в `cmd/beacon/mcp.go` (T3.376) — входящий подписанный приёмник из `internal/infra/webhook`, который дедуплицирует входящие события, а не исходящий адаптер уведомления оператора. diff HEAD..origin/main по OwnerFiles (`internal/infra/wake/deliver.go`, `internal/infra/wake/deliver_test.go`) пуст: после снятия PR функциональность не появилась. Карточка требует «тестовый endpoint» и приёмку «оператор узнаёт о вопросе вне TUI», то есть живую доставку до реального сервера ntfy или webhook-приёмника. В этой среде её нельзя проверить: живого ntfy/webhook-ендпоинта нет, доступны только правка текста и gofmt на слабом ПК. По архитектуре адаптеры уведомлений живут в `notify.go`/`telegram.go`, а триггеры human-gate и флага завершения verb с wiring — в `cmd/beacon/up.go`, то есть вне OwnerFiles; перенесение двух адаптеров в `deliver.go` дублировало бы порт `NotificationSink` и всё равно не закрыло бы приёмку. Зависимость T3.238 (единый контракт wake-бэкендов) в main сама остаётся todo. Не стал писать спекулятивный HTTP-код без живой проверки: это нарушило бы честность ADR 0026 и не доказало бы доставку оператору. Статус todo сохранён, карточка остаётся неподтверждённым спайком до появления живого ntfy/webhook-ендпоинта, блокер возвращён оркестратору. OwnerFiles не менял, код не писал, дубль не создал, правка только текстовая.
