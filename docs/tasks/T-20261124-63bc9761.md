Goal: fix five visual and functional defects found on live OpenCode TUI at main c13ab7bf. Baseline mock: /tmp/opencode/beacon-final-mock.html. Baseline plan: /tmp/opencode/beacon-final-plan.md. Do not edit Go files.

Root causes already identified:
1. Detail hero title: ui_detail_view.js creates heroTitle and sets content from model.title, but with wrap:true + grow:true inside a column card it collapses to zero height in the real host. Give it a stable layout: its own row with a short label or a dedicated non-growing wrapped text node that keeps height. It must show the full task title in bold, wrapped, without VALUE_WIDTH truncation.
2. Buttons: createDetailMount sets every action button visible=false at mount and apply() sets visible based on model.actions && Boolean(run). On a merged run the button row is not visible in the live host. Rebuild the action row so at least [⧉ Copy ID] is always visible for any selected run, and Retry/Approve/Cancel appear for blocked/waiting_ci/active runs with the existing confirm for Cancel. Do not rely on a false initial visible prop for Copy ID. Add tests for merged, blocked and waiting_ci runs.
3. Technical section open by default: ui.js merges detailStore[0] over DETAIL_OPEN, so a stale stored object with technical:true wins. Use a fresh storage key or sanitize stored values so technical is forced false on first load while Why/Blocker and Timeline stay open. Older storage must not migrate an open Technical section.
4. Compact header and hero layout: detail header currently renders "Beacon · Run & Control" which gets cut to "Beacon · R..." in ~45 columns. Change it to compact "Beacon" on the left and "ctrl+g ✕" on the right. In the hero card, line 1 must be "✔ MERGED" with a space after the marker plus a short right-aligned "#PR". Move Branch to its own key-value row with wrapMode word. Add a space after sidebar markers such as ✔ in Recent rows so text does not render as ✔Hotfix.
5. Header lies: ui_view.js stateBarItem computes "N needs work" from cumulative metrics.rebaseCount+fixCount, so with Active 0 it still prints "1 needs work · 3 done". Recompute the summary from the deduplicated active/recent runs only: active, in CI, blocked, done. No cumulative metric may create an active-looking badge when there are no active runs.
