# T1.7. Слой store на SQLite modernc: схема, миграции user_version, один writer
Статус: done
Фаза: P1
Тип: task
Владелец файлов: internal/infra/store/db.go, internal/infra/store/migrations/*.sql, internal/infra/store/db_test.go
Зависимости: T1.1, T1.3
Ссылка: ADR 0015
Агент: T1.7
Время: 2026-11-19T12:43:21Z
Цель: Дать ядру один SQLite-store с версионируемой схемой и единственным писателем в процессе Beacon.
Контекст: ADR 0015: одна база SQLite, драйвер modernc.org/sqlite, CGO_ENABLED=0, режим WAL, один writer; миграции через user_version и SQL файлы с //go:embed; квитанции остаются отдельным receipts.jsonl. Измерения отчёта G, записанные в ADR 0015: modernc v1.62.0, прибавка около 4,9 MiB после strip, пик RSS около 18,9 MB при 60 Watch и 60 000 записей, баг WAL reset исправлен до SQLite 3.51.3. ADR 0012 требует corpus старых файлов состояния для проверки миграций.
Шаги: 1. Создать схему таблиц watches, obligations, events и meta плюс миграционные SQL файлы с //go:embed. 2. Открыть базу с WAL и выставлять PRAGMA user_version только после успешного применения миграции. 3. Реализовать одного владельца записи с очередью и тестом последовательного доступа двух горутин.
Проверка: Тест миграции на зафиксированной фикстуре базы до миграции, проверка PRAGMA user_version и WAL, тест двух конкурентных writer без SQLITE_BUSY.
Приёмка: Схема поднимается с пустой базы и из corpus, user_version растёт только после успешной миграции, вся запись идёт через одного владельца.
