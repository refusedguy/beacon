Цель: Сделать видимым случай, когда красная проверка с `required:false` не меняет вердикт Watch.
Контекст: `internal/infra/ghci/provider.go:287` ставит `Required: true` каждому чеку из `gh pr checks`. GraphQL-путь читает `isRequired` в `internal/app/orchestrator/checkall.go:743`, а `informational()` на строке 460 помечает чек информационным. `internal/domain/verdict.go:216`, `:237` и `:333` намеренно выбрасывают такие чеки из вердикта. В логах демона нет ни одной записи об этом решении: обе записи со словом `required` относятся к `headSHA is required`. Branch protection на main отсутствует, что зафиксировано в `docs/research/ci-gates-gaps.md:22` и карточке `ATX-C01.md`.
Шаги: Добавить в `tool_watch_pr` проверку набора чеков при регистрации. Если все чеки информационные, писать `observe.Event` уровня WARN с полями `watchID` и `event=informational_checks_only`. В `verdict.go` при исключении чека по `required:false` писать отдельное событие `informational_failure_ignored` с именем чека. Не менять сам вердикт. Добавить eval на два сценария: informational-only и смешанный набор.
Проверка: `beacon logs --errors --json` содержит `informational_checks_only` для Watch с informational-only набора; для смешанного набора появляется `informational_failure_ignored` с именем красного чека; вердикт в обоих случаях остаётся прежним.
Приёмка: Информационная проверка не блокирует Watch, но её влияние видно в логах без чтения кода.
