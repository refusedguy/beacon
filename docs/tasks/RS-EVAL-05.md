# RS-EVAL-05. Разделение Red и Broken на уровне CI
Premise: проверено 2026-11-21 по origin/main (база 89276ef). Контракт `docs/RULES-CHECK-CONTRACT.md` задаёт три вердикта PASS, WARN и FAIL; кода выхода 2 и вердикта BROKEN в нём нет. Обязательной джобы, которая запускает `beacon gates rules`, в `.github/workflows/ci.yml` нет. `runRules` в `cmd/beacon/commands.go:49` при ненулевом коде внутренней команды ставит `status = "warn"` (строки 71-72), то есть отказ инструмента уходит в WARN. GitHub считает skipped и neutral прохождением required check. Часть шагов выполнима в OwnerFiles, проводка проверки в CI лежит в чужих файлах.

baseline: `head -20 docs/RULES-CHECK-CONTRACT.md` перечисляет три вердикта в строке 9 и строчные значения `pass`, `warn`, `fail` в строке 42; `grep -rn 'gates rules' .github/workflows/` не даёт совпадений; `sed -n '71,72p' cmd/beacon/commands.go` даёт `status = "warn"`. Измерение подтверждает расхождение: контракт и код не различают отказ инструмента.

Цель: Сделать отдельную обязательную проверку, которая падает на exit 2, и не дать CI свести Broken к skipped или neutral.
Контекст: Premise: проверено 2026-11-21, контракт rules gate знает PASS, WARN и FAIL, но отказ самого инструмента не выделен. baseline: `head -20 docs/RULES-CHECK-CONTRACT.md` перечисляет три вердикта. GitHub считает skipped и neutral прохождением required check.
Шаги: Зафиксировать код 2 как Broken в контракте. Добавить обязательную джобу, которая падает на код 2. Не использовать WARN для сокрытия настоящей красной проверки. Обновить примеры в контракте.
Проверка: Только текст и конфиг в OwnerFiles. Тесты гейта в CI.
Приёмка: Отказ инструмента не выглядит как зелёная проверка. SCAN-BLIND сохранён.

## Решение

- 2026-11-21. В контракте зафиксирован четвёртый вердикт `BROKEN` для кода выхода 2 по ADR 0016. Он блокирует наравне с `FAIL`. Добавлен раздел «Отдельная обязательная проверка»: отдельная джоба передаёт код выхода без изменений, код 2 делает джобу красной, запрещены `continue-on-error`, `|| true`, пропуск через `if:` и преобразование в `WARN`. Для кодового PR результат не должен быть `skipped` или `neutral`. Порог находок и `SCAN-BLIND` сохранены, `SCAN-BLIND` добавляется после подавления исключений в `gate.go`. Обновлены значение `status` и описание `blockers`, добавлен пример fence для `BROKEN`. Инвариант «исключения действуют только на findings, код 2 возвращается до подавления» зафиксирован в контракте, а не в комментарии кода.

- `exceptions.go` оставлен без правок. Любая правка нетестового Go-файла сдвигает номера строк в `pclntab` и меняет байты закоммиченного `tools/beacon-gates/beacon-gates`. `gates-binary.yml:42-60` требует побайтового совпадения с пересборкой, а локальный `go build` запрещён ADR 0022 и условием задачи. Пересобирать бинарник на локальном Go нельзя по ADR 0023. gofmt применять было не к чему. Локальные `go test`, `go build` и `beacon gates` не запускались.

## Блокер

- 2026-11-21. Шаг «Добавить обязательную джобу, которая падает на код 2» нельзя выполнить в OwnerFiles карточки.

  Джоба живёт в `.github/workflows/ci.yml` (джобы `build`, `test`, `js-test`, `gates`, `e2e`, строки 24-241). Вызова `beacon gates rules` и отдельной джобы для правил в workflow нет. Нужна правка `ci.yml`.

  Источник кода выхода: `runRules` в `cmd/beacon/commands.go:49`. Ветка `case key.code != 0, contract.code != 0` (строки 71-72) ставит `status = "warn"` при любом ненулевом коде, включая код 2. Чтобы код 2 давал `status = "broken"`, `blocking: true` и exit 2, нужна правка `cmd/beacon/commands.go`. Файл не входит в OwnerFiles.

  Для полноты согласованности схема в `docs/adrs/0237-untitled.md:11` перечисляет `status pass/warn/fail` и тоже требует обновления или нового ADR. Этот файл не входит в OwnerFiles.

  Статус todo сохранён. Контракт в OwnerFiles обновлён, `exceptions.go` оставлен без правок ради побайтового совпадения бинарника, чужие файлы, wiring и .beacon не трогал, дубль не создал. Блокер возвращён оркестратору с именами файлов `.github/workflows/ci.yml` и `cmd/beacon/commands.go`.
