# T3.386. Интеграция workload и авто-подписки в daemon
Статус: todo
Фаза: P3
Тип: task
Владелец файлов: internal/app/orchestrator/daemon.go, internal/app/orchestrator/daemon_test.go, cmd/beacon/daemon.go, cmd/beacon/daemon_test.go
Зависимости: T3.383, T3.384
Ссылка: ADR 0156
Агент: нет
Время: нет
Цель: Включить авто-подписку и сводку в штатный проход daemon.
Контекст: Daemon уже вызывает checkall, orchestrate и close-merged. Регистрация оркестратора сейчас привязана только к PR из checkall. Сводка должна печататься тем же кодом, что и CLI, и не подменять beacon_get_result.
Шаги: Добавить в DaemonPorts порты Subscribe и Summary. В cmd/beacon/daemon.go собрать Subscribe из SubscribeAll, а Summary из Summarize. Порядок прохода: checkall, subscribe, orchestrate, печать сводки, close-merged. Ошибка любого шага логируется и не роняет daemon. Повтор прохода идемпотентен по (watchID, subscriber).
Проверка: Флаг --once делает ровно один проход. Второй проход не создаёт второе обязательство. Лог содержит те же четыре счётчика, что beacon workload --format json. При ошибке subscribe шаг orchestrate всё равно вызывается.
Приёмка: Daemon подписывает оркестратора на все активные Watch до orchestrate и печатает сводку после него. Мерж по-прежнему требует verdict=ready из beacon_get_result.

# T3.386. Проекция store-наблюдаемости в OTel-инструменты
Статус: todo
Фаза: P3
Тип: task
Владелец файлов: internal/infra/store/observability.go, internal/infra/store/telemetry_bridge.go, internal/infra/store/observability_test.go
Зависимости: T3.381
Ссылка: ADR 0185
Агент: нет
Время: нет
Цель: Проецировать уже существующие durable-счётчики в метрики, не меняя beacon_stats.
Контекст: ObservedPersist.Write двигает seq только после успеха. StreamHealth хранит missing как JSON. LoadError.Reason содержит только ошибку декодера, без payload.
Шаги: Наблюдаемые счётчики beacon.persist.writes{outcome}, beacon.stream.chunks и beacon.wake.observations. Читать значения через PersistStats, StreamHealth и WakeObservations, не добавляя записей в store.
Проверка: PERSIST_FAILED увеличивает writes{outcome=persist_failed} и не двигает seq; ответ beacon_stats побайтово совпадает с текущим контрактом.
Приёмка: Ни одна метрика не содержит содержимого повреждённой строки журнала.
