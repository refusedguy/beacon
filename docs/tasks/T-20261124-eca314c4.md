Goal: give the UI real CI wall time instead of the longest single check. No plugin edits.

Evidence: pkg/core/verdict.go:19-25 stores StartedAt and CompletedAt. GitHub mapping in internal/infra/scm/github.go:117-123 keeps both. SQLite persists the full CheckResult. internal/app/status.go:497-505 drops both fields and sends only name, state and duration_seconds. GitHub jobs currently have no needs: dependencies, so longest happens to be close, but staggered starts or a future dependency chain break it.

Scope: pkg/core/verdict.go, internal/app/status.go, internal/app/status_test.go, pkg/core/verdict_test.go.

Steps:
1. Add a helper in pkg/core that computes wall seconds as max(CompletedAt) - min(StartedAt) over checks with both endpoints. Return 0 when there are no usable timestamps.
2. Add ci_wall_seconds to RunSnapshot and populate it in makeRunSnapshot. Keep checks and every existing field unchanged.
3. Tests for parallel checks, sequential checks, staggered start times, missing timestamps and an empty check list.
4. Keep funlen <= 80 lines, statements <= 40, complexity <= 20. Run gofmt -w, targeted go test ./internal/app and root go test . for arch. Leave full lint to CI.
5. Open a PR, call beacon_watch_pr with the real run ID and PR number, do not self-merge.
