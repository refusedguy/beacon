Goal: fix two live UX bugs found in screenshots on main 1ec506f8. No Go edits.

BUG 1: Sidebar shows "🔥 main RED (0) · Fixer" even though there is no open base incident. Go deliberately returns a stable zero-value BaseIncident object when no incident exists: {"id":"","base_branch":"","failed_checks":[],"fixer_run_id":"","attempts":0}. ui_alerts.js baseIncidentItem currently treats any object as a real incident and fabricates "main" and "Fixer".

BUG 2: Clicking a Queue row does nothing. queueLineItems in ui_view.js gives queue rows no runID or action, and ui_sidebar.js only opens detail for runID / dispatch. The operator wants to click a queued card and read what it is, including docs/tasks/<id>.md. Also a stale SQLite queue entry for a dropped card was visible until a manual dispatch 0 resynced; the UI should not show cards whose file is missing or whose status is done/dropped.

Steps:
1. In ui_alerts.js, make baseIncidentItem return null for a zero-value incident. Require at least one of: non-empty id, non-empty baseBranch, non-empty fixerRunID, or a non-empty failedChecks array. Keep a real incident clickable to its fixerRunID.
2. In ui_view.js queueLineItems, add cardID (the queue item id) and an action like "card:<id>" to each queue row. In ui_sidebar.js onItem, route that action to a new onCard(id) dependency from ui.js.
3. In ui.js, implement showCard(id): read docs/tasks/<id>.md through a new readCard helper in ui_model.js using the existing fs deps. Build a card detail model with id, title, priority, status, depends_on, path and the card body (first 80 lines, wrapMode word, no truncation). Open it in session.panel with a distinct panel name such as beacon.card. Keep per-slot isDestroyed rebuild and createElement only inside render callbacks. Add Copy ID and Copy path buttons with honest toasts using ctx.renderer.copyToClipboardOSC52.
4. In ui_model.js createStatusSource, filter queue items whose local card file is missing or whose frontmatter status is done/dropped. If the file cannot be read, fail closed by dropping the item so stale SQLite rows never masquerade as ready tasks. Use sync fs reads already available; no network calls.
5. Tests: zero-value base incident produces no banner; a real incident still produces the clickable RED banner; clicking a Queue row opens the card detail with full title, path, priority, depends_on and body; stale dropped/missing queue cards are filtered; Copy ID and Copy path call the clipboard API with a toast; existing run detail and slot rebuild tests keep passing.
6. Run node --check on every plugin JS file and node --test .opencode/plugins/beacon-project/*_test.js. Every JS file <= 350 lines.
7. Open a PR against main, call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Accept: only .opencode/plugins/beacon-project/**. No Go changes, no task card edits.
