Goal: give the binary a build hash it can compare with the current sources before it starts serving.

Evidence: doctorBinaryFreshnessCheck at cmd/beacon/doctor.go:604-627 compares the recorded source hash with the current sources, but it is advisory only. serve and mcp do not check it. After Go merges, the pooled MCP process kept serving old policy until a manual restart.

Steps:
1. Add a build-hash variable in cmd/beacon/buildinfo.go and set it through ldflags. Add a compare helper that reports the embedded hash and a mismatch against doctorBuildHash, with the exact rebuild and restart command to print.
2. Update scripts/build-beacon.sh to compute the source hash and pass it as an ldflags value on every build, so the recorded .build-sha and the embedded hash come from the same calculation.
3. Keep doctorBinaryFreshnessCheck in cmd/beacon/doctor.go as an advisory preflight. It should print the same fix command as the startup guard.

Accept: a binary built by scripts/build-beacon.sh carries the hash of its own sources, and doctor reports a stale binary without refusing to run.
