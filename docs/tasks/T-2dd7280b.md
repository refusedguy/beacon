Goal: an automatic rebase must never push conflict markers from a task card into main or silently drop the card from dispatch.
Evidence: GitWorktree.RebaseBase at internal/infra/workspace/git_worktree.go:471-474 treats zero exit status from git rebase --autostash as success. A probe showed the command exits 0 when the stash apply conflicts, leaves UU docs/tasks/T-1.md and conflict markers in frontmatter, and keeps stash@{0}. CommitPath at :515-520 stages and commits those markers with exit 0, and :527 pushes them. The observed T-4de758ed card had `<<<<<<< Updated upstream`, `=======` and `>>>>>>> Stashed changes` around status. yaml.v3 rejects duplicate status keys and bare marker scalars, so parseCardFields at internal/infra/tasksource/markdown.go:95-98 logs a warning and returns ok=false; buildCardIndex skips the file at cardindex.go:95-98 and ListAvailable filters it at markdown.go:43-46, so the card silently disappears from SyncTasks and dispatch. Markers below frontmatter are not parsed as YAML and survive entirely.
Steps: add a postcondition immediately after the rebase call requiring git ls-files --unmerged to be empty; on a nonempty result call abortRebase at :480-490 and return core.Errorf(core.CodeConflict, ...) naming the unmerged paths; add a pure CheckCardMarkers helper in pkg/core that walks .md files and returns the first path and line beginning with <<<<<<<, ======= or >>>>>>>; call it before CommitPath and before Reconciler.merge; extend TestTaskCardCorpusFrontmatter in internal/infra/tasksource/markdown_test.go to run the helper on docs/tasks and fail with path and line; add a test that a conflicting autostash returns CodeConflict and leaves no markers.
Accept: a rebase with unresolved paths aborts and never commits, a card with markers anywhere in the file fails CI, and no card can be silently dropped from the index by a conflict.
