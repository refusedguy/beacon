Goal: an automatic rebase must never push conflict markers from a task card into main.
Evidence: GitWorktree.RebaseBase at internal/infra/workspace/git_worktree.go:471-474 treats zero exit status from git rebase --autostash as success. A throwaway probe showed the command exits 0 when the stash apply conflicts, leaves UU docs/tasks/T-1.md and conflict markers in frontmatter, and keeps stash@{0}. CommitPath at :515-520 then stages and commits those markers with exit 0, and :527 pushes them. Callers in internal/app/cardpublish.go:75-81 and :117-120 assume a clean tree after RebageBase returns nil. The observed T-4de758ed card had `<<<<<<< Updated upstream`, `=======` and `>>>>>>> Stashed changes` around the status field after an automatic rebase.
Steps: add a postcondition immediately after the rebase call requiring git ls-files --unmerged to be empty; on a nonempty result call the existing abortRebase at :480-490 and return core.Errorf(core.CodeConflict, ...) naming the unmerged paths; add a test that a rebase whose autostash conflicts returns an error, leaves no conflict markers on disk, and that CommitPath is never reached.
Accept: a rebase with unresolved paths returns CodeConflict, aborts, and never commits or pushes a card containing conflict markers.
