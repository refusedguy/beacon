Context: PR #2315 raises `merge.max_attempts` default from 3 to 12 in `internal/infra/config/config.go` and the sqlite schema default. The worker reported that `cmd/beacon/init.go` still writes `MaxAttempts: 3` into configs generated by `beacon init`, which is outside that card's scope.

Goal: a freshly generated `.beacon/config.yaml` uses the same 12-attempt default as the code.

Steps:
1. Read `cmd/beacon/init.go` and change the generated `merge.max_attempts` value from 3 to 12.
2. If there is an init test that asserts the generated YAML, update it. Otherwise add a test that runs init against a temp dir and asserts the generated config parses with `Merge.MaxAttempts == 12`.
3. Run `gofmt -w` on changed Go files and targeted `go test ./cmd/beacon`.
4. Open a PR and call beacon_watch_pr with the real run ID and PR number.

Check: `beacon init` in an empty directory produces a config whose `merge.max_attempts` is 12.

Accept: do not change any other generated defaults. Keep files under 350 lines. Do not edit AGENTS.md or another card.
