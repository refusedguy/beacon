Goal: The sidebar never shows an empty queue when the store has ready cards.

Evidence: beacon status --snapshot returns 50 queue items with 18 ready, but the panel shows 'no tasks ready'. createStatusSource tries ctx.client.rpc(BeaconStatusRpc).snapshot first and only falls back to CliStatusSource when RPC throws. A stale or partially initialised RPC source returns a snapshot with an empty queue and no error, so the fallback never runs.

Steps: For the snapshot method, call CliStatusSource first and treat RPC as an optional accelerator for events and control. Keep the cardIsPending filter and location handling. Add a test where RPC returns an empty queue and CLI returns ready cards, and assert the panel shows the ready count.

Check: With a store that has ready cards, the rendered queue section shows the counted header and Dispatch plate.

Accept: No wire shape change. Keep RPC control and dispatch paths unchanged.
