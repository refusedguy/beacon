Контекст: rig exec в OpenRig держит connector в $OPENRIG_HOME/acp/runs с состояниями requested, started, finished, interrupted и одной run на строку. Beacon хранит состояние рядом с beacon.db в каталоге проекта (ADR 0086), а не в $OPENRIG_HOME.
Шаги: Добавить durable record и повторное чтение результата после рестарта.
Проверка: Повторный run той же строки возвращает существующий, а не создаёт вторую работу.
Приёмка: Долгие задачи не привязаны к открытому терминалу.

## Реализация
`internal/infra/store/acp_runs.go` хранит одну запись на строку задачи в beacon.db. Состояния requested, started, finished, interrupted переходят по правилам `CanTransitionACPRun`. `ClaimACPRun` вставляет запись и возвращает существующую, если строка уже запускалась. Завершённый run хранит последний снимок потока, который читает следующий вызов.

`internal/infra/store/sessions.go` добавил `FindSessionByTask`, `internal/app/session/registry.go` добавил `ResumeByTask`. Реестр находит сессию по строке задачи без непрозрачного sessionID из закрытого терминала.

`cmd/beacon/spawn.go` занимает run до запуска раннера, пишет состояния и убрал `defer rt.Close()`. Закрытие терминала отменяет локальный контекст, помечает run interrupted и оставляет раннер живым. Завершённый run при повторном вызове печатает sessionID и сохранённый результат, не создавая новый runner.

Юнит-тесты в `internal/infra/store/acp_runs_test.go` проверяют повторный claim, переходы состояний, чтение результата после переоткрытия базы и поиск сессии по задаче. Живой ACP-раннер тестам не нужен. gofmt выполнен локально, go test и go build выполняет CI.
