# T3.278. ACP exec connector
Premise: перепроверено 2026-11-21 по свежему origin/main @ 42af2b2, функционал отсутствует, дубль не создан. В `internal/infra/wake/acp.go` нет постоянной записи о run, машины состояний requested, started, finished, interrupted и повторного чтения результата после рестарта. Файл содержит внутрипроцессный `PersistentACPClient` с методами Initialize, NewSession, LoadSession, Prompt, Done и Close. Поле `c.started` описывает состояние клиента, а не run. `ACPCapSessionLoad` и `DeliverWake` передают промпт в существующую сессию или создают новую, но работают только с живым ACP-раннером и не сохраняют результат на диске. `beacon spawn --runtime acp` в `cmd/beacon/spawn.go:348` ждёт в `streamACPSession` до `ctx.Done()` и закрывает раннер через `defer rt.Close()`, поэтому закрытие терминала обрывает run. `recordSpawnSession` в `cmd/beacon/spawn.go:94` пишет сессию в постоянный реестр, но не ищет прежний run по строке задачи и не читает результат после рестарта. `internal/infra/store/sessions.go` хранит статусы active, idle, closed, а не состояния из карточки. `SessionRegistry.Resume` ищет по sessionID, а не по строке задачи. ADR 0086 предписывает хранить состояние рядом с beacon.db в каталоге проекта и не задаёт `$OPENRIG_HOME/acp/runs`; каталог `$OPENRIG_HOME` Beacon отклонил в PR #394 по карточке T3.297. Проверка «повторный run той же строки возвращает существующий» в main не проходит, потому что `runSpawnACP` создаёт новую сессию при каждом вызове. Постоянная запись о run и её подключение к команде живут в `cmd/beacon/spawn.go`, `internal/app/session` и `internal/infra/store`, то есть вне OwnerFiles карточки. Подтверждение требует живого ACP-раннера, закрытия терминала, рестарта и go test; здесь доступны только gofmt и текст. Код не писал, OwnerFiles не менял. Блокер возвращён оркестратору: нужна модель run с состояниями и живой зонд, либо расширение OwnerFiles и разрешение на тесты.

Постоянная запись о run с состояниями requested/started/finished/interrupted и чтение результата после рестарта требуют изменений в `cmd/beacon/spawn.go`, `internal/infra/store/sessions.go` и `internal/app/session/registry.go` (Resume ищет по sessionID, а не по строке задачи), которые вне OwnerFiles карточки (`internal/infra/wake/acp.go`, `internal/infra/wake/acp_test.go`); сам `internal/infra/wake/acp.go` содержит только внутрипроцессный `PersistentACPClient`, где `c.started` — состояние клиента, а не run.
