Goal: cut billable GitHub REST calls per reconciler tick and remove webhook burst amplification on the public-repo free tier.
Evidence: each active run with a PR issues about four GETs per 30-second tick, three always billable. At 10 active runs with moving heads that is roughly 4920 calls per hour against the 5000/hour PAT ceiling, and 20 runs exceed it. Checks and reviews are re-listed every tick despite changing only when the SHA or review set changes. CompareCommits is refetched every tick although base and head SHA are stable between changes. Webhook.Handler checks neither X-GitHub-Event nor X-GitHub-Delivery, so a synchronize plus labeled plus several check_run events can trigger a dozen full Observes in a minute, and a full channel waits two seconds and serializes into still more reconciles.
Steps: reuse the github_etag.go pattern for check runs keyed by SHA and approvals keyed by PR, send If-None-Match on later ticks and return the cached slice on 304; add a short-lived compare memo keyed by (base SHA, head SHA) with a size bound; deduplicate webhook deliveries by X-GitHub-Delivery with a bounded cache and ignore event types that cannot change a verdict; keep the existing deduplication and error ordering in Observe and keep the circuit breaker; add tests for the 304 path, the compare memo hit and duplicate webhook deliveries producing one Observe.
Accept: at 10 active runs with moving heads billable calls drop below about 1500/hour, a new check run still updates the verdict on the next tick, and a duplicate webhook delivery causes one Observe rather than one per event.
