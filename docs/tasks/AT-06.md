# AT-06. beacon_rerun_failed: повтор упавших проверок через MCP
Статус: todo
Фаза: research
Тип: task
Владелец файлов: internal/infra/mcp/tool_rerun_failed.go, internal/infra/mcp/tool_rerun_failed_test.go, docs/tasks/AT-06.md
Зависимости: решение владельца по ADR 0004
Ссылка: docs/research/research-agent-tooling-gaps.md, разделы 2, 4 и 7
Агент: нет
Время: нет
baseline: `RetryCommand` равен `gh run rerun --failed` (`internal/infra/mcp/schema.go:105-110`). Бюджет повторов считает `remainingRetryBudget` (`tool_get_result.go:995-1022`). Владельцем rerun сегодня является агент (`docs/templates/executor-task.md:293`). MCP-инструмента нет.

Цель: перенести повтор упавших проверок в MCP с сохранением бюджета и идемпотентности.

Контекст: агент сегодня сам выполняет `gh run rerun --failed` по подсказке `nextCommand`. Жалоба владельца про нехватку инструментов порождает предложение сделать rerun инструментом. Это конфликтует с ADR 0004: Beacon объявлен read-only по CI. Карточка фиксирует безопасный дизайн на случай, если владелец примет решение. Пока решения нет, инструмент не регистрируется.

Инструмент (сигнатура):

```go
type RerunFailedInput struct {
    WatchID   string `json:"watchID" jsonschema:"Watch whose failed checks are rerun; required"`
    CheckName string `json:"checkName,omitempty" jsonschema:"limit the rerun to one flaky matched check"`
    RunID     int64  `json:"runID,omitempty" jsonschema:"workflow run id from the check details URL; resolved from the Watch when omitted"`
}

type RerunFailedOutput struct {
    WatchID      string `json:"watchID"`
    Revision     uint64 `json:"revision"`
    RetryBudget  int    `json:"retryBudget"`
    Rerun        bool   `json:"rerun"`
    RunID        int64  `json:"runID"`
    ObligationID string `json:"obligationID,omitempty"`
}
```

Где реализовать: новый `internal/infra/mcp/tool_rerun_failed.go`. Порт `RerunPort` объявить в `Dependencies` (`internal/infra/mcp/server.go:404-493`). Адаптер в композиционном корне должен вызывать те же методы GitHub, что сегодня делает `gh run rerun --failed`, через уже существующий слой `internal/infra/github`. Не добавлять `os/exec` в `internal/infra/mcp`. Output DTO в `schema.go` рядом с `GetResultOutput` (`:130-178`). Дескриптор с типом `kindAdditive` рядом с `beacon_ack` (`server.go:187-203`).

Шаги: прочитать Watch и вычислить `remainingRetryBudget`. При нулевом бюджете вернуть `CodeLimitExceeded` без вызова провайдера. Разрешить rerun только для проверок с `FlakyMatched=true` в `failedChecks`. Идемпотентность держать на обязательстве с ключом `(watchID, revision, runID)`: повтор с тем же ключом возвращает `rerun=false`. После успешного вызова записать расход бюджета в существующий счётчик `Flaky.Used`, не создавая второй. Подсказка `nextCommand` в `get_result` остаётся прежней для агентов без нового инструмента.

Проверка: тест с бюджетом 0 фиксирует отсутствие вызова порта и код `CodeLimitExceeded`. Тест с бюджетом 2 и одной flaky-проверкой фиксирует ровно один вызов порта и запись расхода. Повтор того же вызова возвращает `rerun=false` и не трогает счётчик. Контрактный тест `tools/list` обновлён по замеру в CI.

Приёмка: владелец принял ADR, разрешающий запись в CI из MCP. После этого агент вызывает rerun одним инструментом и не превышает бюджет. Если ADR не принят, карточка остаётся в `todo`, а существующее поведение через `nextCommand` сохраняется.

Ограничение: без решения владельца инструмент не регистрируется. ADR 0004 и шаблон исполнителя сегодня закрепляют rerun за агентом.
