# T0.6. Бинарник beacon с шестью подкомандами

Статус: done
Фаза: P0
Тип: task
Владелец файлов: go.mod, go.sum, cmd/beacon/**
Зависимости: T0.5
Ссылка: ADR 0016
Агент: T0.6
Время: 2026-11-19T12:40:58Z

Цель: Дать владельцу и агентам один бинарник beacon, каталог команд которого доступен машиночитаемо через list --format json.

Контекст: ADR 0016 обязал команды жить в одном бинарнике beacon с подкомандами build, test, gates, list --format json, doctor и what. Машиночитаемый каталог нужен, чтобы агент не придумывал команды. Машинный поток идёт в stdout, шум в stderr. Сборка воспроизводимая: CGO_ENABLED=0, -trimpath, -buildvcs=false, -ldflags="-buildid= -s -w" (ADR 0016). Отчёт H §5 уточняет, что --format json и machine-readable stdout это требование ADR, а не Harbor; --list в beacon-gates остаётся человеческим. ADR 0007 определяет точку входа cmd/beacon. ADR 0003 требует Go 1.25.0 или новее, ADR 0015 поднимает требование до 1.26.0 из-за modernc, и doctor должен это проверять. Подкоманда gates вызывает бинарник из T0.5 и передаёт его exit code. ADR 0016 запрещает подменять бинарник командой go run ./tools/beacon, потому что оболочка не различает коды 1 и 2.

Шаги:
1. Создать корневой модуль и cmd/beacon/main.go с dispatch по шести подкомандам. Неизвестная подкоманда и неизвестный флаг дают ненулевой код и usage в stderr.
2. list --format json печатает в stdout массив объектов с полями name, summary и usage. По умолчанию list печатает таблицу. Порядок полей стабильный.
3. what <command> печатает описание одной команды из того же каталога, что и list, без второго источника истины.
4. doctor проверяет версию go, доступность бинарника beacon-gates и каталог состояния $XDG_STATE_HOME/beacon. Каждое поле печатает OK или FAIL с причиной.
5. build собирает воспроизводимый бинарник с флагами из ADR 0016. test запускает go test ./.... gates находит beacon-gates и передаёт его stdout, stderr и exit code без изменений.
6. Написать table-driven тест cmd/beacon, который проверяет каждую подкоманду отдельно.

Проверка: `go test ./...` в корне проходит. `beacon list --format json | jq -e 'length==6'` даёт true, stdout содержит только JSON, stderr пустой. `beacon doctor` на машине с Go 1.25 печатает FAIL для требования 1.26 из ADR 0015. `beacon build` и `beacon test` возвращают код связанного Go-вызова. `beacon gates` возвращает 1 на фикстуре с нарушением и 2 на неправильном вызове.

Приёмка: Шесть подкоманд работают, каталог в JSON полный и совпадает с usage. Машинный поток отделён от шума. Передача exit code из beacon-gates проверена на кодах 0, 1 и 2. Сборка воспроизводимая. go.mod и go.sum зафиксированы.

Гейт: G1. Не закрывает G1 один, а даёт агентам каталог команд и воспроизводимую сборку для shadow-прогона. Условия выхода G1 по ADR 0018: не менее 20 реальных PR, ноль расхождений вердикта с фактом gh, SLO в норме.
