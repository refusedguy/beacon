baseline: dmux хранит шесть полей метаданных и проверяет каждое при чтении (`src/utils/worktreeMetadata.ts:12-19`, `:30-68`, `:74-116`), запись идёт через temp файл (`atomicWrite.ts`). Beacon хранит в маркере три поля: путь, agentID, UpdatedAt (`internal/infra/worktree/marker.go:19-42`), запись идёт прямым `os.WriteFile` (`marker.go:51-69`).

Цель: Сохранить агента, режим прав, имя ветки и цепочку целей мержа рядом с worktree и читать их, не доверяя содержимому файла.

Контекст: dmux пишет `.dmux/worktree-metadata.json` при создании worktree (`resumeBranches.ts:985-989`) и читает его при повторном открытии, чтобы выбрать агента и режим (`reopenWorktree.ts:164-182`). Незнакомое имя агента, режим или запись цепочки целей отвергаются (`worktreeMetadata.ts:81-110`). Beacon хранит sessionID в `attach-sessions.json` (`attach.go:21-28`) и маркер активности в state dir (`marker.go:19-42`). Ни один из файлов не хранит ветку, режим прав и цель мержа, а прямой `WriteFile` оставляет усечённый файл при обрыве записи.

Шаги: Добавить в `internal/infra/worktree/worktree_meta.go` тип с шестью полями, валидатор при чтении и запись через временный файл с переименованием. Внедрить интерфейс файловой системы, чтобы тесты не трогали диск. Покрыть тестами round-trip, неизвестного агента, неверного режима и обрыва между записью и переименованием. Не менять `marker.go` и TTL маркеров.

Измеримая проверка: Round-trip сохраняет все шесть полей. Незнакомый агент и режим дают ошибку чтения. После симулированного обрыва файл содержит прежнее содержимое. Число прямых `os.WriteFile` в новом файле равно нулю.

Приёмка: Повторное открытие worktree знает агента и режим без внешнего реестра. Старый маркер активности и его TTL продолжают работать.
