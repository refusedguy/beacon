Context: after PR #2332 (commit 910e311c) the Beacon TUI plugin fails with `Cannot find package '@opentui/solid' imported from .../ui.js`. Diagnosis: `setup(ctx, deps = {})` defines `const load = deps.import ?? ((specifier) => import(specifier))` and calls `load("@opentui/solid")`, `load("solid-js")`, `load("@opentui/core")`. OpenCode v2.3.2 installs a runtime plugin that rewrites ONLY literal `import("...")` specifiers. A computed `import(specifier)` is invisible to it, and the plugin directory has no node_modules, so Bun cannot resolve the package. Before #2332 imports were literal and worked. Line 448 `await import("@opencode/plugin/tui")` is literal and must stay.

Goal: the panel loads in the real TUI again.

Steps:
1. In `.opencode/plugins/beacon-project/ui.js`, keep the injected-deps seam for tests but make the fallback contain literal imports. Replace the computed fallback with a function that branches on the specifier and returns `import("@opentui/solid")`, `import("solid-js")` or `import("@opentui/core")` literally, throwing for anything else. Do not change the call sites.
2. Leave `await import("@opencode/plugin/tui")` at line 448 as a literal.
3. Add a test in `ui_test.js` that calls setup with no injected deps and asserts the three literal specifiers are present. Keep the injected deps path working.
4. Run `node --check` and `node --test` on plugin tests. Open a PR and call beacon_watch_pr. Do not self-merge.

Check: TUI plugin loads with no `Cannot find package` and no `No renderer found`, and the compact panel renders.

Accept: one file for the fix plus its test. Do not change Go code or AGENTS.md. Keep files under 350 lines.
