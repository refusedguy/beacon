# T2.10. GitHub REST клиент на go-github: ETag, 304 и пинок mergeable UNKNOWN
Статус: done
Фаза: P2
Тип: task
Владелец файлов: internal/infra/github/rest.go, internal/infra/github/rest_test.go
Зависимости: T2.12, T2.17
Ссылка: ADR 0004
Агент: нет
Время: 2026-11-19T14:45:00Z
Цель: Реализовать REST-часть гибридного клиента на go-github с условными запросами по ETag и пинком ленивого mergeable=UNKNOWN через GET /pulls/N.
Контекст: ADR 0004 выбирает go-github для REST и возлагает на него ETag, 304 и пинок mergeable UNKNOWN. ADR 0004 также фиксивает риск смены пути импорта при мажорных релизах и требование зафиксировать версию в go.mod. WORKER-PROMPT §4.6 говорит, что GET /pulls/N с ETag нужен только как пинок, а /rate_limit используется для метрик. D-github-ci-options подтверждает, что условный GET с корректным Authorization и ответом 304 не расходует primary limit, и что ETAG меняется при каждом апдейте проверки, поэтому состояние CI надо читать отдельно. WORKER-PROMPT §2 требует токен только для чтения, без персиста и логирования. ADR 0013 делает заголовки x-ratelimit-* авторитетнее тела.
Шаги: 1. Создать клиент go-github с токеном из цепочки BEACON_GITHUB_TOKEN, GITHUB_TOKEN, gh auth token и режимом только для чтения. 2. Реализовать условный GET с сохранённым ETag и обработкой 304. 3. Реализовать пинок mergeable UNKNOWN и передачу стоимости ответа в счётчик T2.12.
Проверка: rest_test.go на httptest-сервере сначала получает 200 с ETag, затем повторяет запрос с If-None-Match и получает 304. Тест проверяет, что 304 не увеличивает счётчик, что пинок UNKNOWN вызывает GET /pulls/N и что токен не попадает в логи и состояние.
Приёмка: 304 не списывает поинт, UNKNOWN разрешается пинком, токен используется только для чтения и не персистится.
