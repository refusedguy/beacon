# T-d1000006. Q4a: Stop double normalization and generatedAt fingerprint churn

## Goal
Stop normalizing twice per changed tick and stop fingerprinting the changing generatedAt field.

## Evidence
index.js:116 passes CliStatusSource whose snapshot already normalizes at ui_model.js:399, then run_watcher.js:33 normalizes again. deps.normalizeSnapshot can be identity for this source. status.go:257 stamps GeneratedAt every snapshot, ui_model.js:228 carries it into the result, so run_watcher.js:30 serializes a different key each tick and the idle fingerprint skip never fires. P15 (T-7f5473b8) already fixed the fixture first, so its output is available and this card does not rebuild it.

## Steps
1. V1: pass an identity normalizeSnapshot from index.js while keeping the default for raw sources.
2. V2: fingerprint ordered run keys id, sha, state, updatedAt instead of the whole snapshot, with real normalized field names.
3. Keep run_watcher_test.js assertions for the identity normalizer on CliStatusSource and for the ordered-key fingerprint.
4. Work in your own worktree off current main. Never push to main. Never run go test, go build, go vet, linters, node tests or benchmarks locally. One variant is one commit and one push; read the beacon-pr-perf comment after each push; keep a variant only on gain including gain (allocs/bytes) with equal work, errs zero, non-empty limiter and warm cache; revert with git reset --hard HEAD~1 and git push --force-with-lease. Never add ready-to-merge before all variants are checked and the final table is in the PR body. Call beacon_watch_pr. CI supplies every check.

## Accept
One normalization per changed tick, the idle fingerprint skip fires on unchanged runs with a moving generatedAt, and kept variants show gain on run-watcher-fp with equal work and zero errors.
