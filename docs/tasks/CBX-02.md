# CBX-02. Один производный предикат GATED для всех поверхностей и поле gated_by

Статус: todo
Фаза: P1
Тип: task
Владелец файлов: cmd/beacon/task.go, internal/infra/taskstore/edges.go, cmd/beacon/task_test.go

Baseline: beads: internal/types/gated.go:20-22 фиксирует четыре поверхности одного предиката; в beacon whyEdgeKinds и whyExternalKind в cmd/beacon/task.go:83-96 задают два отдельных списка, общего gated_by нет.

Цель: Чтобы глиф в списке, заголовок карточки, вывод why и поле gated_by не могли разойтись по одному и тому же ребру.

Контекст: Источник, реальный код beads. internal/types/gated.go:5-32 объявляет главное правило: GATED не хранится, а выводится из ребра и статуса цели; waits-for намеренно исключён, потому что у движка есть своя ветка пересчёта. IsGateEdge на :52-54, SubjectCanBeGated на :64-69 и GateIsHolding на :75-83 складываются в GatesHolding на :94-110. GateRef и GateRefs на :124-147 проецируют результат в машиночитаемое поле gated_by с типом ожидания и причиной; GateReason на :170-185 читает причину по общему маркеру :158. Разрыв в beacon: cmd/beacon/task.go:83-96 хранит whyEdgeKinds и отдельный whyExternalKind, а внешний гейт печатается отдельным шагом; общего предиката и поля gated_by в internal/infra/taskstore/edges.go:32-53 нет.

Шаги: Вычислить набор гейтов одной чистой функцией из ребра блокировки и статуса цели. Исключить закрытую и закреплённую карточку-субъект. Не включать waits-for, если движок считает его отдельно. Использовать эту функцию в list, why и MCP-ответе. Добавить машиночитаемое поле gated_by с идентификатором, типом ожидания и причиной. Повторно использовать один маркер причины при записи и чтении.

Проверка: Измеримая. Для карточки с открытым гейтом все четыре поверхности выдают один и тот же набор из одного ID; после закрытия гейта все четыре одновременно выдают пустой набор. Закрытая карточку-субъект и ребро waits-for дают пустой gated_by при том же графе. JSON gated_by содержит ровно три ключа: id, type, reason. Число расхождений между поверхностями по 20 сгенерированным графам равно нулю.

Приёмка: AN-03 про внешние гейты и CB-04 про conditional-blocks не дублируются. Пять существующих типов рёбер и их валидация не меняются.
