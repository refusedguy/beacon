Цель: Не давать зависимой карточке навсегда оставаться скрытой, когда два блокировщика сняты параллельно.

Контекст: Источник, реальный код beads. internal/storage/issueops/blocked_recheck.go:15-40 объясняет дефект: пересчёт внутри транзакции читает её стартовый снапшот. Две записи, снимающие разных блокировщиков одной dependent-карточки, видят другой блокировщик ещё живым, оба оставляют флаг заблокированным и коммитятся без конфликтующей ячейки. BlockedRecheck на :63-82 запоминает dependent-карточки и источники шириной реcheckSourceLimit (:84-90); после коммита тот же набор пересчитывается на свежем снапшоте. internal/storage/issueops/blocked_recheck_report.go:23-39 задаёт контракт ошибки: проваленный recheck не возвращается как ошибка записи, а уходит в счётчик и строку лога с именами строк. Разрыв в beacon: internal/infra/taskstore/close.go:59-80 пишет статус закрытия под flock и AtomicWrite, internal/app/taskcli/service.go:64-71 объявляет HookUnblocked, но ни один из них не пересчитывает состояние dependent-карточки после коммита; internal/infra/taskstore/edges.go:108-137 только отклоняет цикл на добавлении ребра.

Шаги: Записать набор dependent-карточек, затронутых закрытием, снятием ребра и удалением, в транзакции записи. После успешной публикации карточки пересчитать этот набор по свежому прочитанному графу. Сделать пересчёт идемпотентным и направленным в обе стороны: снятие и добавление блокировщика меняют флаг. Ошибку после коммита не превращать в ошибку закрытия: писать счётчик и строку с ID карточками. Сохранить текущее поведение хука unblocked.

Проверка: Измеримая. Два блокировщика B1 и B2 снимаются двумя параллельными вызовами закрытия; после возврата обоих вызовов dependent-карточка A имеет снятый флаг заблокированности, число карточек с устаревшим флагом равно нулю. Повторный пересчёт тех же ID не меняет файлы. Один вычисляемый recheck на 50 закрытий подряд даёт 50 записей в отчёте и ноль ошибок записи. При искусственной ошибке архива закрытие возвращает успех, а в логе ровно одна строка с ID A.

Приёмка: AN-02 остаётся владельцем каскада разблокировки; карточка добавляет только post-commit recheck. Существующие nextAction и хуки не меняются.
