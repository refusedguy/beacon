Context: stale worktrees survive merged runs. `cleanupRun` in `internal/app/finalize.go:37-58` calls `Remove` only when `Clean` reports no changes. Beacon itself dirties the worktree by rewriting `docs/tasks/<id>.md` to `in_progress`/`done`, so `Clean` is often false and cleanup at lines 50-53 returns without removing anything. Failures are never retried because the reconciler only visits active runs. The operator had to remove four stale worktrees by hand, one of which held pre-#2313 plugin code that kept registering an MCP daemon.

Goal: terminal runs always leave no worktree behind, while active runs stay untouched.

Steps:
1. Add `ForceRemove` to the `WorkspaceManager` port in `pkg/core/ports.go` and implement it in `internal/infra/workspace/git_worktree.go` using the existing `ForceRemove` helper at lines 237-243.
2. In `cleanupRun` (`internal/app/finalize.go:50-53`), when `!clean`, call `ForceRemove` for a terminal run instead of returning. Keep normal `Remove` for clean worktrees. Do not force-remove a worktree whose run is still active.
3. Extend `fakeWorkspace` in `internal/app/mocks_test.go` with a `clean=false` flag and a forced-removal counter. Add a test in `internal/app/external_test.go` asserting that an external merge with a dirty worktree force-removes it, and that an active run is not removed.
4. Run `gofmt -w` and targeted `go test ./internal/app ./internal/infra/workspace ./pkg/core`.
5. Open a PR and call beacon_watch_pr with the real run ID and PR number.

Check: after a PR merges, its worktree is gone even when the task card is modified; no active run's worktree is touched.

Accept: do not change dispatch decisions or task card rewrite logic. Keep files under 350 lines. Do not edit AGENTS.md or another card.
