Context: PR #2315 added an early return in `internal/app/reconciler.go:71-74` for `VerdictNeedsRebase` when checks are green and there is no conflict. The intention was to skip needless rebases for independent module changes. The effect is that a behind PR with green checks neither rebases nor merges, so it hangs in `waiting_ci` forever. PR #2320 is stuck exactly this way. The running card T-20261123-ff7e111b fixes a different problem in `needs_agent_fix` and does not unstick a `waiting_ci` run.

Goal: a behind PR with green checks must still merge when GitHub reports it mergeable.

Steps:
1. In `internal/app/reconciler.go`, change the green-checks rebase decision so a `waiting_ci` run with green checks takes the merge path instead of returning. Keep the skip only when the PR is genuinely not mergeable.
2. Distinguish a behind-but-mergeable PR from a real conflict. If `obs.Conflict` is false and checks pass, let `Decide` return `VerdictMerge`. Do not reintroduce a rebase on every green PR.
3. Refresh `ObservedSHA`/`ObservedBaseSHA` on the merge path so `sameObservation` does not short-circuit the next tick.
4. Tests in `internal/app/reconciler_test.go`: a behind PR with green checks and mergeable true reaches `merged`; a PR with a real conflict still takes the rebase or fix path. Keep existing independent-module cases green.
5. Run `gofmt -w` and targeted `go test ./internal/app ./pkg/core`. TRIM `internal/app/reconciler.go` back under 350 lines by extracting a small helper if needed; the advisory threshold is 350.
6. Open a PR and let the reconciler handle rebase and merge. Do not call beacon_control on other runs.

Check: PR #2320 and any other behind-but-green PR merges on the next reconcile tick without operator action.

Accept: do not change verdict invariants or approval rules. Keep production files under 350 lines. Do not edit AGENTS.md or another card.
