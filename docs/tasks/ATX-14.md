# ATX-14. Заменить файловый замок taskstore на Flock
Статус: done
Фаза: P1
Тип: task
Владелец файлов: internal/infra/taskstore/store.go
Зависимости: 
Ссылка: 
Агент: нет
Время: нет
Цель: Убрать окно, в котором два процесса получают эксклюзивный доступ к карточкам.
Контекст: Источник: docs/research/security-audit.md, находка 6 и строка таблицы 154. internal/infra/taskstore/store.go:350-395 создаёт файл через O_CREATE|O_EXCL, но при ErrExist читает его отдельным вызовом lockState в :377 и :399-425 и удаляет через os.Remove в :379 и :386. Между чтением и удалением другой процесс может пересоздать файл. processAlive в :427-433 использует kill(pid, 0) с риском переиспользования PID. В internal/app/taskcli/service.go:1442-1447 уже описана эта гонка и применён syscall.Flock. Severity medium.
Шаги: Заменить AcquireLock на Flock(LOCK_EX|LOCK_NB) на открытом дескрипторе, как в lockHealing. Удалить эвристику stale и PID-файл. Оставить LockPath только как имя файла.
Проверка: CI зелёный. Тест с двумя процессами, захватывающими замок, показывает ровно одного владельца. В taskstore/store.go нет os.Remove на пути захвата.
Приёмка: Ядро снимает блокировку при смерти процесса. Два процесса не получают замок одновременно.
