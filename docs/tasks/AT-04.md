baseline: `beacon_get_result` строит ключ `(watchID, revision, sessionID)` и возвращает `obligation not found` при отсутствии строки (`internal/infra/mcp/tool_get_result.go:457-464`). Cibridge создаёт обязательства в пяти местах (`verdict_applier.go:257-269`, `:300-311`, `:358-368`, `:601-611`, `:823-834`). Read-инструмента по обязательствам нет. Готовый пример чтения есть в `bridge.go:607-625`.

Цель: дать агенту и оркестратору read-инструмент, который показывает, какие обязательства существуют у Watch и на какой ревизии.

Контекст: жалоба `obligation not found`. Обязательство для подписчика создаётся только когда cibridge публикует вердикт на новой ревизии. Если агент читает результат на другой ревизии или с другим sessionID, строки нет. Сегодня причину можно найти только чтением стора или логов. AGENTS.md прямо запрещает грепать логи.

Инструмент (сигнатура):

```go
type ObligationsInput struct {
    WatchID      string `json:"watchID" jsonschema:"Watch whose obligations are listed; required"`
    SubscriberID string `json:"subscriberID,omitempty" jsonschema:"optional opaque subscriber or session id filter"`
}

type ObligationRow struct {
    ObligationID   string `json:"obligationID"`
    Revision       uint64 `json:"revision"`
    SubscriberID   string `json:"subscriberID"`
    VerdictPointer string `json:"verdictPointer"`
    StagedAt       string `json:"stagedAt,omitempty"`
    ClaimedAt      string `json:"claimedAt,omitempty"`
    ReadAt         string `json:"readAt,omitempty"`
    DeliveredAt    string `json:"deliveredAt,omitempty"`
}

type ObligationsOutput struct {
    WatchID     string          `json:"watchID"`
    Revision    uint64          `json:"revision"`
    Obligations []ObligationRow `json:"obligations"`
    Found       bool            `json:"found"`
}
```

Где реализовать: новый `internal/infra/mcp/tool_obligations.go`. Порт `ObligationLister` с методом `WatchObligations(watchID string) ([]domain.Obligation, error)` уже используется в `bridge.go:611-618` как `activitySource`. Добавить его в `Dependencies` (`server.go:404-493`) и передать из композиционного корня. Output DTO в `schema.go` рядом с `GetResultOutput` (`:130-178`). Дескриптор рядом с `beacon_get_result` (`server.go:167-177`).

Шаги: handler читает текущий Watch для поля `Revision`, затем вызывает `WatchObligations`. Фильтр `subscriberID` применяется в памяти после чтения. Пустой результат это успешный ответ с `found=false`, а не ошибка. Не штамповать `readAt` и `claimedAt`: инструмент только читает. Ограничить размер ответа 200 строками по образцу `getResultMaxRecords` (`tool_get_result.go:82-85`), добавить флаг усечения если нужно.

Проверка: тест с подставным портом создаёт два обязательства на ревизии 3 и одно на ревизии 2. Вызов без фильтра возвращает три строки, с фильтром одну. Вызов по несуществующему `watchID` возвращает `found=false` и пустой массив без ошибки. Тест подтверждает, что `readAt` и `claimedAt` не изменились. Контрактный тест `tools/list` обновлён по замеру в CI.

Приёмка: агент видит, для какого sessionID и ревизии существует обязательство, и понимает причину `obligation not found` без поиска по логам. Состояние обязательств инструментом не меняется.
