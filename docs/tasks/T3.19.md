# T3.19. seq и счётчики missing/duplicates для потока событий
Статус: todo
Фаза: P3
Тип: task
Владелец файлов: internal/domain/types.go, internal/domain/types_test.go, internal/domain/fanout.go, internal/domain/fanout_test.go, internal/infra/store/observability.go, internal/infra/store/observability_test.go, internal/infra/mcp/meta.go, internal/infra/mcp/meta_test.go
Зависимости: нет
Ссылка: ADR 0031
Агент: нет
Время: нет
Цель: Каждое событие потока Beacon несёт монотонный seq, а финальное событие называет missing и duplicates и при потере чанков возвращает полный результат.
Контекст: ADR 0031, раздел 1; отчёт Q 1.2 (mcp-partials). Готовая модель надёжности для событий Beacon без нового брокера.
Шаги: Добавить seq в тип события и в fanout; вести счётчики missing и duplicates; экспонировать их в observability; прокинуть метаданные через meta.
Проверка: Юнит-тесты на восстановление порядка, потери и дубли; полный результат при недоставке чанков.
Приёмка: Клиент восстанавливает порядок по seq и получает полный результат, даже если доставка каждого чанка не гарантирована.
