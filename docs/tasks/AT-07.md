# AT-07. beacon_rebase: ручной rebase с жёстким бюджетом
Статус: todo
Фаза: P2
Тип: task
Владелец файлов: internal/infra/mcp/tool_rebase.go, internal/infra/mcp/tool_rebase_test.go, docs/tasks/AT-07.md
Зависимости: решение владельца по ADR 0004, проверка дубля с авто-rebase
Ссылка: docs/research/research-agent-tooling-gaps.md, разделы 2, 4 и 7
Агент: нет
Время: нет
baseline: `RebaseCommand` содержит `git fetch origin main && git rebase origin/main && git push --force-with-lease` (`internal/infra/mcp/schema.go:105-110`). Авто-rebase уже реализован в `WithAutoRebase` (`bridge.go:574-585`) и в `applyMerge` (`verdict_applier.go:440-470`). Бюджет равен 3 по умолчанию (`bridge.go:74-76`, `:594-665`).

Цель: оценить и, если владелец разрешит, реализовать ручной rebase через MCP с теми же лимитами, что и авто-rebase.

Контекст: карточка почти дублирует существующий механизм. Cibridge уже ребейзит один раз при held merge `BEHIND` и списывает бюджет через `spendRebase` (`bridge.go:639-665`). Агент делает rebase руками по `nextCommand`. Дополнительный инструмент имеет смысл только если владелец решил убрать силу-пуш из агентского shell и оставить один путь с аудитом.

Инструмент (сигнатура):

```go
type RebaseInput struct {
    WatchID          string `json:"watchID" jsonschema:"Watch whose head is rebased; required"`
    ExpectedHeadSHA  string `json:"expectedHeadSHA" jsonschema:"head SHA seen by the caller; required to make the call idempotent"`
}

type RebaseOutput struct {
    WatchID      string `json:"watchID"`
    Revision     uint64 `json:"revision"`
    OldHeadSHA   string `json:"oldHeadSHA"`
    NewHeadSHA   string `json:"newHeadSHA,omitempty"`
    Rebased      bool   `json:"rebased"`
    RebaseUsed   int    `json:"rebaseUsed"`
    RebaseBudget int    `json:"rebaseBudget"`
}
```

Где реализовать: новый `internal/infra/mcp/tool_rebase.go`. Порт `Rebaser` уже используется cibridge (`bridge.go:578-585`). Объявить такой же порт в `Dependencies` (`internal/infra/mcp/server.go:404-493`) и передать тот же адаптер из композиционного корня. Списание бюджета выполнять через ту же функцию `spendRebase`, вынесенную в общий слой без второй копии счётчика. Output DTO в `schema.go` рядом с `GetResultOutput`. Дескриптор `kindAdditive` рядом с `beacon_ack`.

Шаги: до действия сверить `ExpectedHeadSHA` с `w.HeadSHA`. При расхождении вернуть `CodeHeadSHAChanged` и новый `watchID` по образцу watch-lease. Проверить бюджет через общий `spendRebase`. При исчерпании вернуть `CodeLimitExceeded`. Вызвать `Rebaser.Rebase`, записать новый headSHA в Watch через существующий write-порт и вернуть `rebased=true`. Повтор с тем же `(watchID, revision, expectedHeadSHA)` возвращает `rebased=false` без второго force-push. Не изменять `RebaseCommand` в `get_result`, пока инструмент не принят.

Проверка: тест с бюджетом 0 фиксирует отказ без вызова `Rebaser`. Тест с бюджетом 1 фиксирует ровно один вызов и новый headSHA в Watch. Повтор того же входа не вызывает `Rebaser`. Регрессионный тест cibridge подтверждает, что общая функция списания возвращает прежние значения. Контрактный тест `tools/list` обновлён по замеру в CI.

Приёмка: владелец сравнил ручной инструмент с авто-rebase и явно выбрал один путь. Если выбран ручной, агент перестаёт выполнять force-push из shell и вызывает `beacon_rebase`. Если выбран авто-rebase, карточка закрывается как дубль без кода.

Ограничение: без решения владельца инструмент не регистрируется. Две точки, которыеrebasingют один Watch, недопустимы.
