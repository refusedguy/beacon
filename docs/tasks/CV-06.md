# CV-06. Повторный claim задачи тем же агентом возвращает ту же карточку

Premise: проверено 2026-11-22 по `origin/main` `e2f34a060579d452c1ca6ca7845560b78b8b7629`. Источник: OpenHands `src/utils/claim-client-tool-call.ts:4-8` объясняет, что неидемпотентный вызов инструмента нужно пометить до начала работы, иначе повтор ActionEvent после reconnect или гонки REST и WebSocket повторит реальное действие. `:10-33` хранит список уже обработанных toolCallId и возвращает false на повторе, в том числе когда первый вызов ещё в полёте. Код beacon не менялся.

Разрыв: `FileTaskClaimStore.Claim` в `internal/infra/mcp/tool_task_claim.go:231-356` берёт flock, ищет карточку по `cardID` или по приоритету и требует `Status == "todo"` на `:332`. Идентификатор агента используется только для записи поля `Агент`. Поиска уже выданных этим агентом карточек нет. После обрыва сессии повторный `beacon_task_claim` с тем же `agentID` не вернёт прежнюю карточку: она уже `in_progress`, поэтому агент возьмёт следующую `todo` или получит `CodeGone`. Другой `beacon_claim` в `internal/infra/mcp/tool_claim.go:83-94` имеет `IdempotencyKey`, но этот инструмент не используется агентами для карточек.

baseline: `rg -n 'IdempotencyKey|idempotency' internal/infra/mcp/tool_task_claim.go` = 0. `rg -n 'chosen.Agent|in.AgentID' internal/infra/mcp/tool_task_claim.go` = 3, все три строки относятся к проверке ввода и к тексту ошибки о чужом владельце. `rg -n 'records\[watchID\]|byKey' internal/infra/mcp/tool_task_claim.go` = 0.

Цель: Возвращать ту же карточку при повторном claim после обрыва сессии, не выдавая вторую задачу тому же агенту.
Контекст: Источник: docs/research/comp-devin.md и OpenHands claim-client-tool-call.ts:4-33: повтор ActionEvent после reconnect или гонки REST и WebSocket повторяет реальное действие, если вызов не помечен до начала работы. FileTaskClaimStore.Claim не ищет карточку по agentID и не имеет replay key. Риск: средний, flock и проверка todo для чужого агента остаются без изменений.
Шаги: Добавить в `FileTaskClaimStore` поиск карточки со статусом `in_progress` и полем `Агент`, равным `in.AgentID`, до выбора новой карточки. Возвращать сохранённый `TaskClaimOutput` без повторной записи файла. При указанном `cardID` возвращать прежний результат для того же агента вместо ошибки `already in_progress`. Оставить flock и проверку `todo` для чужого агента без изменений. Обновить описание инструмента фразой о повторе после обрыва.
Проверка: `gofmt -w` на своих .go, тесты в CI. Тест вызывает Claim дважды с одним `agentID` и проверяет одинаковый `CardID`, `ClaimedAt` и число изменённых карточек. Негативный контроль: другой `agentID` не получает чужую карточку.
Приёмка: Перезапущенный агент продолжает прежнюю карточку и не начинает вторую.
