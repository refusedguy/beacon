Eliminate the stale-binary 404 loop. The daemon runs an old binary until MCP is reconnected, and `scripts/build-beacon.sh` plus the `beacon.build-sha` check in `mcp.js` only run when the plugin registers the server. `registerBeaconMcp` already returns `setRoot` which calls `ctx.mcp.reload()`, so the reload primitive exists. Add a HEAD watcher in `.opencode/plugins/beacon-project/mcp.js`: poll `git rev-parse HEAD` in the project root every few seconds, keep the last SHA in module state, and when it changes call `ctx.mcp.reload()` so the command is resolved again and `beaconCommand()` rebuilds a stale binary before the daemon restarts. Guard against repeat reloads for the same SHA, skip the watcher when `BEACON_BIN` is set, and do not reload before the initial registration completes. Add a JS test with fake ctx, fake execFileSync and fake timers covering: no reload when HEAD is unchanged, one reload when HEAD advances, and no watcher with an explicit binary. Update AGENTS.md to state that MCP reload and binary rebuild are automatic after any main change, with no manual rebuild or reconnect needed. Keep files under 350 lines. Run node --check and node --test, open a PR and call beacon_watch_pr.
