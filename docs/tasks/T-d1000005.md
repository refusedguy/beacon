# T-d1000005. Q3b: Defer parent model resolution out of startup

## Goal
Remove the model-resolution GET from startup so the two largest one-shot CLI costs are both gone.

## Evidence
newHarness at main.go:406 resolves the parent model with a GET that can take three seconds when no model is configured. The status-cli-paths and open-prepared-db rows are the deciding rows; the generation cache and the single-GET guarantee must survive the change.

## Steps
1. V2: defer model resolution to the first spawn that needs it, preserving the generation cache and the single-GET guarantee.
2. Work in your own worktree off current main. Never push to main. Never run go test, go build, go vet, linters, node tests or benchmarks locally. One variant is one commit and one push; read the beacon-pr-perf comment after each push; keep a variant only on gain including gain (allocs/bytes) with equal work, errs zero, non-empty limiter and warm cache; revert with git reset --hard HEAD~1 and git push --force-with-lease. Never add ready-to-merge before all variants are checked and the final table is in the PR body. Call beacon_watch_pr. CI supplies every check.

## Accept
Startup issues no model GET, the generation cache and single-GET guarantee hold, and the kept variant shows gain with equal work and zero errors.
