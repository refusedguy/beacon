Цель: Держать короткие ID на маленьком бэклоге и автоматически удлинять их по мере роста, не допуская коллизий внутри пачки create.

Контекст: Источник, реальный код beads. `ComputeAdaptiveLength` в `internal/storage/issueops/helpers.go:643-654` выбирает минимальную длину, при которой `1 - exp(-N^2/(2*36^L))` не превышает порог 0.25. Порог и диапазон 3..8 заданы в `helpers.go:601-608`. Число карточек приходит из `GetAdaptiveIDLengthTx` на `helpers.go:578-592`. Цикл `helpers.go:326-340` перебирает длину и 10 значений nonce; `claimed` на `helpers.go:295-303` содержит ID, выданные пачке, но ещё не записанные. Хеш строится в `internal/idgen/hash.go:55-84`. Разрыв в beacon: `internal/infra/taskstore/store.go:564-575` возвращает `T<g>.<n>` по счётчику, а комментарий `store.go:597-600` фиксирует 234 коллизии с разным содержимым и прямо говорит, что хеш-суффикс не введён. AN-04 предлагает перейти на хеш-ID, но не описывает ни формулу, ни nonce, ни `claimed`.

Шаги: Вынести функцию расчёта длины по числу карточек и настраиваемому порогу. Перевести выдачу ID в пакетный путь с множеством `claimed`, чтобы две карточки одной пачки не получили одинаковый ID до первого INSERT. Добавить nonce во входные данные хеша. Сохранить `IsID` и формат `T<g>.<n>` для существующих карточек как совместимый путь чтения. Покрыть тестами формулу, рост длины на порогах и пачку из ста одновременно создаваемых карточек.

Проверка: Измеримая. Для N=100, 1000, 10000 выбранная длина L совпадает с первым значением, где формула даёт не более 0.25. При 100 параллельных create с одинаковым заголовком число уникальных ID равно 100, число коллизий равно нулю. Две принудительно одинаковые пары title/description/creator/timestamp дают разные ID за счёт nonce. Существующие карточки `T3.17` продолжают читаться.

Приёмка: Формат старых ID не ломается. Логика flock и atomic claim не меняется. Порог вероятности коллизии читается из конфигурации, а не захардкожен в двух местах.
