# T3.421. Проверить остановку демона без orchestrator-подписчика
Premise: проверено по коду в origin/main 2026-11-21. Отдельного интеграционного теста с живым демоном для подтверждения не нужно. Поведение уже есть в main, и blocked идёт отдельным путём без wake. В internal/domain/transition.go функции blockWatch и unblockWatch возвращают nil вместо эффектов, коммит 3e3709d. Эффект EffectWakeSubscribers создаёт только transitionVerdict, и он отклоняет Watch в статусе blocked. В internal/infra/store/db.go функция ActiveWatches отбирает только watching и notifying, коммит c1463d1, поэтому blocked не попадает в цикл пробуждения. В internal/app/orchestrator/orchestrator.go вызов wakeOne стоит только в ветке needsWake для verdict retry и fail, коммит dc3704f. Заблокированные Watch идут в handleBlocked, который wakeOne не вызывает. Единственная запись wake_requested в orchestrator.go:565 находится внутри wakeOne. Семейство blocked:not_mine и blocked:resolved реализовано в internal/infra/mcp/tool_ack.go с идемпотентностью повторов. Путь blocked проверен чтением кода, код не менялся. Статус done.
