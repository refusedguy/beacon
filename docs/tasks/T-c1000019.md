## Goal
Stop a load-decide-save control call from overwriting a concurrent transition.

## Evidence
From T-5115e3a5: run writes are atomic but callers load, decide and save later, so beacon control with no daemon and a daemon tick can both act on one run and last writer wins.

## Steps
Use the store compare-and-swap primitive keyed by updated_at or head SHA on the control save path. Retry or refuse a stale update with a reason. Add tests in internal/app/control_test.go for two concurrent control calls on one run.

## Accept
A stale control update cannot replace a newer run state.
