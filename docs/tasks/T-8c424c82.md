Goal: alert once when a non-terminal run sits too long in a state, before its rebase or fix budget is exhausted.
Evidence: the only wall-clock health check today is the orphan sweep in internal/app/idle.go:106, which acts on running runs with PRNumber zero after 90 seconds. A run in waiting_ci, needs_rebase, needs_agent_fix or blocked can keep a fresh UpdatedAt from observations and never alert. Card history records real cases of runs stuck in these states. The operator currently finds them by reading snapshot timelines.
Steps:
1. Add config section watchdog with per-state ages and enabled flag in internal/infra/config/config.go, with defaults that do not change behavior until enabled. Include waiting_ci, needs_rebase, needs_agent_fix and blocked. Keep the existing orphan timeout as the running-without-PR policy.
2. Add checkStateAges(runs) in internal/app/reconciler.go called from the ListActive branch of Reconciler.Run. For each non-terminal run whose time in state exceeds its configured age, send one notification containing run ID, task, state, age and last reason, and record a decision row.
3. Use ClaimDelivery with a per-run and per-state key, the same mechanism idle nudges use, so repeated ticks do not repeat the alert. Release or expire the claim when the run leaves the state.
4. Reuse the existing notifier and DecisionLogger. Do not add a new wire vocabulary or MCP tool.
5. Tests: no alert under default age, one alert after threshold, no duplicate alert on the next tick, alert clears and can fire again after the run returns to the state.
Accept: an operator learns about a stall while it is still cheap to fix, and a quiet daemon produces no repeated alerts.
