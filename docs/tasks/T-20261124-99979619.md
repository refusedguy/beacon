Goal: make Beacon instantly portable to any git project and language stack. No JS/plugin edits.

Baseline: main a9617d93. Do not break existing init, config, MCP registry, or permission generation.

Scope: cmd/beacon/init.go, cmd/beacon/init_test.go, cmd/beacon/doctor.go, cmd/beacon/doctor_test.go, cmd/beacon/main.go, internal/infra/config/config.go, internal/infra/config/config_test.go, internal/infra/mcp/registry.go, scripts/install-beacon.sh.

Steps:
1. Make config.DefaultWorkerInstructions language agnostic. Remove the hardcoded "go test ./internal/app" and golangci-lint wording. Use: "Worker environment: weak PC. Run targeted tests only for the files or packages you changed; leave full test suites, full builds and full repo linters to CI."
2. Upgrade beacon init into a wizard for arbitrary projects:
   - Support non-interactive flags --non-interactive / --yes with smart defaults, and interactive confirmation only when stdin is a TTY and no --yes.
   - Flags: --task-source default markdown, --harness-endpoint from OPENCODE_ENDPOINT or BEACON_OPENCODE_ENDPOINT or http://127.0.0.1:4096, --max-active-agents default 2, --weak-pc default true, --skip-plugin, --plugin-dir optional.
   - Detect stack by marker files in the target root: go.mod, package.json, pyproject.toml or requirements.txt, Cargo.toml, *.sln or *.csproj. Generate stack-specific harness.worker_instructions: Go targeted go test ./<pkg>; Node/TS targeted tests without npm run build; Python pytest path/to/test.py; Rust cargo test <module>; other stacks generic targeted tests.
   - Always write harness.command: worker, merge.max_attempts: 12, on_base_red.mode: spawn_fixer, concurrency max_in_flight 10 and max_active_agents from flag.
   - Auto-detect merge.required_checks from .github/workflows/*.yml by parsing job names and run steps; print the detected list for operator review.
   - Create docs/tasks/.gitkeep when docs/tasks is absent.
   - Append or create .gitignore covering .beacon/state.db*, .beacon/worktrees/, .beacon/connection.json, .beacon/*.lock, .beacon/daemon*, .beacon/config.yaml so tokens never leak.
   - Generate or safely extend the target opencode.json using mcp.ToolCatalog(): add agents.orchestrator, agents.worker, agents.build, global deny plus role permissions, and mcp.beacon with type local, command ["beacon","mcp"], environment BEACON_PROJECT_ROOT=abs_root, pool true. Never overwrite unrelated user keys.
   - Deploy .opencode/plugins/beacon-project/ into the target project unless --skip-plugin. Prefer copying from the current checkout or a --plugin-dir source, keeping files identical. Avoid go:embed in cmd that would break arch_test.go or duplicate the tree. If no clean source is available, print an explicit warning instead of silently skipping.
   - Print a four-step handoff: token envs GITHUB_TOKEN and BEACON_OPENCODE_TOKEN if needed, beacon doctor check, OpenCode restart, first dispatch.
3. Add beacon doctor in cmd/beacon/doctor.go, registered in main.go. It prints [OK], [WARN], [FAIL] and exits 1 on any FAIL. Checks: git repo, origin remote and base branch; .beacon/config.yaml parses, harness.command worker, SCM token present via env or file without printing it, required_checks set; docs/tasks exists; opencode.json exists with orchestrator, worker and mcp.beacon, and ToolCatalog permissions are in sync; beacon available in PATH or .opencode/bin/beacon; OpenCode HTTP GET /api/project with 2s timeout; GitHub/GitLab API light check on base branch; daemon state via readDaemonStatus.
4. Add scripts/install-beacon.sh: build beacon into BEACON_INSTALL_DIR or $HOME/.local/bin/beacon, refresh .opencode/bin/beacon when run inside this repo, and warn when ~/.local/bin is not in PATH.
5. Tests in init_test.go, doctor_test.go, config_test.go: stack detection for all markers, non-interactive config content, opencode.json merge preserves user keys, .gitignore safety, doctor exit codes and no token leakage.
6. Keep funlen <= 80 lines / <= 40 statements and complexity <= 20. Run gofmt -w, targeted go test ./cmd/beacon ./internal/infra/config ./internal/infra/mcp and go test . for arch. Leave full go test ./... and golangci-lint to CI.
7. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Accept: only the listed Go files and scripts/install-beacon.sh. No plugin JS edits, no task card edits.
