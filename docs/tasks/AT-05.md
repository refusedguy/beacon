baseline: `shipFactsFromWatch` пропускает проверку при `!check.Required` (`internal/infra/mcp/tool_get_result.go:910-926`). `collectFailedChecks` возвращает `Required` как поле, но не объясняет его роль (`:951-966`). Проверок с `required: false` в контракте вердикта нет ни одной.

Цель: показать агенту все проверки Watch с явным признаком, влияет ли каждая на вердикт.

Контекст: жалоба «required:false тишина». AGENTS.md говорит, что информационные проверки с `required: false` не являются блокерами. Код делает то же самое. Агент видит красную строку в `gh pr checks` и молчание бикона. `beacon_get_result` отдаёт упавшие проверки, но не показывает, почему одна из них не меняет вердикт, а другая меняет.

Инструмент (сигнатура):

```go
type ChecksExplainInput struct {
    WatchID string `json:"watchID" jsonschema:"Watch to explain; required"`
}

type CheckExplanation struct {
    Name            string `json:"name"`
    State           string `json:"state"`
    Conclusion      string `json:"conclusion"`
    Required        bool   `json:"required"`
    IsFailure       bool   `json:"isFailure"`
    CountsForVerdict bool  `json:"countsForVerdict"`
    ShipFact        string `json:"shipFact,omitempty"`
    Explanation     string `json:"explanation"`
}

type ChecksExplainOutput struct {
    WatchID  string             `json:"watchID"`
    Revision uint64             `json:"revision"`
    Verdict  string             `json:"verdict"`
    Checks   []CheckExplanation `json:"checks"`
}
```

Где реализовать: новый `internal/infra/mcp/tool_checks_explain.go`. Переиспользовать `failureConclusions` (`tool_get_result.go:48-54`), `isFailedCheck` (`:968-979`), `collectFailedChecks` (`:951-966`) и `shipFactsFromWatch` (`:910-926`) без копирования таблиц. Output DTO в `schema.go` рядом с `GetResultOutput` (`:130-178`). Дескриптор рядом с `beacon_get_result` (`server.go:167-177`).

Шаги: прочитать Watch из `deps.Store`. Для каждой записи `w.Checks` посчитать `isFailure` через существующую функцию. Поле `countsForVerdict` равно `check.Required && isFailure` для упавших проверок и `check.Required && isGreenCheck` для зелёных. Для информационной проверки записать объяснение `informational: required=false; verdict engine ignores this check`. Для обязательной упавшей проверки записать имя вердикта, на которое она влияет, например `required check failed: keep_working`. Не менять `domain.Verdict` и не штамповать обязательство. `ShipFact` заполнять только для required green-проверок по правилам `shipFactsFromWatch`.

Проверка: тест с двумя упавшими проверками, одна `required=true`, другая `required=false`, возвращает `countsForVerdict=true` и `false` соответственно. Третья проверка `required=true` и зелёная даёт `ShipFact=build` если имя содержит `build`. Тест подтверждает, что вердикт Watch и ревизия после вызова не изменились, а `readAt` не проставлен. Контрактный тест `tools/list` обновлён по замеру в CI.

Приёмка: агент видит разницу между обязательной и информационной проверкой прямо в ответе MCP и не поднимает блокер по `required: false`. Движок вердиктов остаётся прежним.
