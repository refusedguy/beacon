Goal: Worker sessions keep a parent binding even when a tool caller sends no session meta.

Evidence: Runs dispatched late in the session have an empty parent_session_id in .beacon/state.db while earlier runs carry ses_df8826282ffePOV721qcP709CV. The MCP server reads BEACON_PARENT_SESSION only at startup and its plugin registration sets only BEACON_PROJECT_ROOT. tool_dispatch.parentSession reads only ai.opencode/sessionID or beacon/sessionID from request meta, so a caller without that meta spawns top-level sessions.

Steps: Pass the plugin session id into the MCP server environment as BEACON_PARENT_SESSION, and accept additional session meta keys in tool_dispatch.parentSession. Keep per-call meta authoritative over the environment fallback.

Check: A dispatch call with no meta still creates a run whose parent_session_id equals the operator session. A dispatch call with meta still uses the meta value. Tests pin both paths.

Accept: No wire shape change. A config fallback was added in .beacon/config.yaml as an immediate workaround; this card makes it unnecessary.
