# T3.247. Проверка input box
Premise: перепроверено 2026-11-21 по свежему origin/main (1fc2baf на момент проверки; с тех пор main получает только docs-коммиты других карточек, OwnerFiles этой карточки не трогают). Функционал проверки input box в main отсутствует, дубль не создан. Карточка просит подтверждать наличие текста в поле ввода через transport.verify_input_box OpenRig: idle shape кадра, точное содержимое box и пустой box после Enter для Claude 2.1.296 и Codex 0.160.0, плюс matchеры кадров, сравнение по word boundary, 500 мс дедлайны на дополнительные чтения и unconfirmed для занятого или неопознанного seat. Это механизм OpenRig `--verify` над tmux pane с живым TUI-сеансом Claude/Codex. По заданию оркестратора проверил wake delivery, envelope и dedupe. Доставка wake есть: `OpenCodeDeliverer.Deliver` (`internal/infra/wake/deliver.go:104`) шлёт текст через `PromptFunc` (:174) с CLI fallback (:195). Envelope это `Envelope` (:274) и `T202Envelope` (:686), они кладут в текст только идентификаторы. Dedupe это `seen` map (:86), проверка `DeliveredAt` в store (:140), `DeliveryLeaseGuard` (:412, :450), `T211DeliveryRegistry` (:1105) и `CursorDeliverer` (:1501). Все три механизма решают доставку текста в сессию `ses_` через ACP или API и защиту от повторного пробуждения; ни один не захватывает pane и не подтверждает текст в поле ввода. `verifyAck` (:381) проверяет, что API принял промпт и вернул id, а не экран. Словарь статусов deliver.go это T206 и T210, ни один не описывает input box.
