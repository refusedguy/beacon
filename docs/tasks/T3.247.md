# T3.247. Проверка input box
Premise: проверено 2026-11-21, функционал в origin/main отсутствует, дубль не создан. Карточка просит подтверждать наличие текста в поле ввода через transport.verify_input_box OpenRig: idle shape кадра, точное содержимое box и пустой box после Enter для Claude 2.1.296 и Codex 0.160.0, плюс matchеры кадров, сравнение по word boundary, 500 мс дедлайны на дополнительные чтения и unconfirmed для занятого или неопознанного seat. Это механизм OpenRig `--verify` над tmux pane с живым TUI-сеансом Claude/Codex. В `internal/infra/wake/deliver.go` и `deliver_test.go` нет захвата pane, matchеров кадров, проверки input box, модели seat и исхода unconfirmed: шесть совпадений шаблона это комментарий "exact match" про точное совпадение target в реестре (строка 888) и пять строк про `Matches` в history search T3.250 (строки 1528-1604), ни одно не про input box; три вхождения `verify` это `verifyAck` (строки 217, 372, 375), проверка admission API, а не экрана. Словарь статусов файла это T206 (started, queued, delivered, duplicate, closed, unsupported) и T210 (delivered, queued, enqueued, skipped, errored). Ни один не описывает подтверждение рендера в pane или проверку input box. Beacon доставляет указатель в сессию `ses_` через ACP/API, tmux pane для захвата кадра у него нет. Сестёрские карточки T3.245, T3.246 и T3.266/267/268 сняты по тому же основанию: tmux нет, OwnerFiles заглушка deliver.go (PR #394, #728, #729). Зависимость T3.246, проверка рендера в pane, в origin/main всё ещё todo. Настоящая проверка требует живого pane и OpenRig `--verify` с конкретными версиями Claude 2.1.296 и Codex 0.160.0. Здесь доступны только gofmt и текст. Код не писал, OwnerFiles не менял, gofmt не применял. Статус todo сохранён, блокер возвращён оркестратору.
