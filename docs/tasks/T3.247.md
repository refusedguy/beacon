Цель: Подтверждать, что текст реально был в поле ввода, и не выдавать строку, застрявшую в очереди, за доставленную.

Контекст: transport.verify_input_box OpenRig проверяет idle shape кадра, точное содержимое box и пустой box после Enter. Проверка читает pane через порт `PaneCapturer`. Захват кадра живёт в слое pane-capture (`CapturePane` из T3.249) и здесь не дублируется: `PaneCaptureFunc` адаптирует его к порту без второй реализации `capture-pane`.

Что сделано:
- `verify_input.go`: `PaneCapturer`, `PaneCaptureFunc`, `ErrNoPaneCapturer`, `VerifyInputBox`, состояния `InputReady` / `InputNotReady` и чистый классификатор кадра `classifyInputFrame`.
- Классификатор берёт нижнюю строку с приглашением ввода, требует видимый курсор (`▌ █ ▏ ❚`), снимает ANSI через уже существующий `historyANSI`, сравнивает содержимое box по word boundary. Пустой `want` требует пустого box, что покрывает состояние после Enter и чистый промпт перед вводом.
- `verify_input_test.go`: фейковый `PaneCapturer`, таблица ready/not-ready, кадры с ANSI и глифами Claude/Codex, ошибка захвата, nil-порт, проверка адаптера. Живой tmux не нужен.

Шаги: Добавить порт захвата и проверку состояния input box, покрыть состояния тестом на фейке.

Проверка: Кадр без курсора, без приглашения ввода или с незавершённым текстом даёт `InputNotReady`. Ошибка захвата и отсутствие порта тоже дают `InputNotReady` с ошибкой.

Приёмка: Сообщение, застрявшее в очереди ввода, не выдаётся за доставленное: непустой box не даёт `InputReady`, а текст совпадает только по целому слову (`ship` не совпадает с `relationship`).

Ограничение: дедлайн 500 мс на дополнительные чтения и живой OpenRig `--verify` зонд с Claude 2.1.296 / Codex 0.160.0 в этой среде недоступны; в карточку входит минимальная проверка на порту и фейке. gofmt применён; `go test` и `go build` запускаются в CI.
