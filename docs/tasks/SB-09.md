# SB-09. Выбор парсера лога по типу проверки

Статус: todo
Фаза: P1
Тип: task
Владелец файлов: internal/domain/verdict.go, internal/domain/types.go
Зависимости: 
Ссылка: docs/research/comp-swebench.md, раздел 1, строка «Защита от пустого прогона»; исходники swebench/harness/log_parsers и swebench/harness/grading.py
Агент: нет
Время: нет
Цель: Разбирать вывод разных раннеров с помощью объявленного парсера, а не одного общего правила.

Контекст: Источник: `swebench/harness/log_parsers/__init__.py:69-135`, `swebench/harness/grading.py:113-154`. `PARSER_REGISTRY` связывает имя парсера из спецификации с функцией разбора. Грейдер выбирает её по `test_spec.log_parser` (`grading.py:125`), считывает вывод между маркерами и падает на весь лог, если карта статусов пуста (`:147-154`). В реестре 114 записей для Python, JavaScript, C, Go, Java, PHP, Ruby и Rust. В beacon `ExternalCheck` несёт только имя проверки и код выхода (`internal/domain/verdict.go:672-675`). Ни модель Watch (`internal/domain/types.go:369-405`), ни адаптер не имеют поля парсера. Поиск `git grep -c 'log_parser' -- internal` даёт 0 файлов. Два лога с одинаковым кодом 0 и разными failure-строками сейчас дают одинаковый вердикт.

baseline: `rg -c 'parse_log_' swebench/harness/log_parsers/__init__.py` даёт 114 строк; `git grep -c 'log_parser' -- internal` даёт 0.

Шаги: Добавить имя парсера в объявление внешней проверки и в сохранённое доказательство. Ввести реестр разборщиков с fail-closed поведением при неизвестном имени. Разбирать лог между маркерами, затем повторять разбор по всему логу, если карта пуста. Ограничить первую версию парсерами для раннеров, которые уже использует CI проекта. Не менять решение по коду выхода, пока карта статусов пуста.

Проверка: Подать два лога с кодом 0. Первый содержит `FAILED test_x` в формате pytest, второй содержит `✕ test_y` в формате jest. Без парсера оба дают `PASS`. Цель: объявленный парсер pytest даёт `FAIL` на первом, а объявленный парсер jest даёт `FAIL` на втором. Неизвестное имя парсера даёт отказ с причиной, а не `PASS`.

Приёмка: Вердикт зависит от содержимого лога и объявленного раннера, а не только от кода выхода обёртки.
