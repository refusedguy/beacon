Context: the plugin shell guard in `.opencode/plugins/beacon-project/index.js` has three frozen rules and no way to add patterns from config. Workers on a weak PC still launch full builds and linters locally. The operator needs those commands blocked or warned without editing plugin source.

Goal: make the shell guard rule list configurable, with ready rules for heavy commands.

Steps:
1. Read `ctx.options` or `ctx.config` in the plugin setup. Add a config key such as `shellGuardRules` with `{id, pattern, replacement}` entries and merge them with the built-in rules. Keep invalid regexes from crashing setup; log and skip them.
2. Add default rules that catch `go build ./...`, `go test ./...`, `go vet ./...`, `golangci-lint run ./...`, `npm ci`, `npm run build` and suggest the targeted alternative or CI. Do not block `go test ./internal/app`, `go test -run NAME ./pkg`, `gofmt`, `rg`, targeted `go build -o`, or `node --test`.
3. Keep `BEACON_SHELL_GUARD=warn` behavior. Add an `agent` check so rules apply only to the `worker` agent by default, configurable.
4. Update `.opencode/plugins/beacon-project/index_test.js` (create it if absent) with tests: a heavy command is blocked for worker, allowed for orchestrator, warn mode logs instead of throwing, and a malformed config rule is ignored. Run `node --check` and `node --test` on plugin tests.
5. Open a PR and let the reconciler handle it.

Check: a worker attempting `go test ./...` gets a clear message pointing to CI; a targeted package test still runs.

Accept: do not touch generated `opencode.json` or AGENTS.md. Keep files under 350 lines.
