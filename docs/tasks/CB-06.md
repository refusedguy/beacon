# CB-06. Компактинг без API-ключа через режимы analyze и apply

Цель: Разделить поиск кандидатов на сжатие и применение саммари, чтобы агент работал без ключа к внешней модели.

Контекст: Источник, реальный код beads. Справка `bd compact` в `cmd/bd/compact.go:45-56` перечисляет четыре режима. Analyze экспортирует кандидатов на проверку агенту и не требует ключа. Apply принимает готовое саммари из файла или stdin и тоже не требует ключа. Auto использует внешнюю модель и ключ. Dolt запускает garbage collection. Роутер на `cmd/bd/compact.go:130-136` требует ровно один из режимов analyze, apply или auto, а `:144-164` направляет analyze и apply в отдельные обработчики с прямым доступом к хранилищу. `Config.DryRun` в `internal/compact/compactor.go:17-23` и `:65-74` автоматически включает себя, если ключа нет. Разрыв в beacon: `cmd/beacon/task.go:46-72` не содержит ни одной из этих подкоманд, и в коде нет проверки взаимной исключительности режимов.

Шаги: Добавить подкоманды `compact --analyze`, `compact --apply` и `compact --auto` в роутер task. Analyze отдаёт кандидатов в JSON. Apply принимает ID и путь к файлу со саммари. Запретить одновременный выбор режимов. Сделать режим без ключа основным путём для агента, а внешнюю модель необязательной. Поддержать dry-run на случай отсутствия ключа.

Проверка: Измеримая. `beacon task compact --analyze --format json` возвращает валидный JSON со списком кандидатов и не обращается к сети. `beacon task compact --apply --id T3.17 --summary file` применяет саммари при пустом окружении ключей. Одновременный `--analyze` и `--apply` возвращает код валидации и не меняет файлы. Число сетевых вызовов в первых двух случаях равно нулю.

Приёмка: Режим analyze только читает данные. Приёмка саммари проходит через те же проверки размера и снапшота, что и CB-05. AN-05 про JSON round-trip не дублируется, новая команда нужна только для кандидатов сжатия.
