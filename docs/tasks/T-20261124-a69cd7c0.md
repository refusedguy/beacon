Context: the right-hand run detail panel in `.opencode/plugins/beacon-project/ui.js` renders every recorded decision with no limit. `detailLines()` at lines 371-397 emits one line per decision via `  ${stamp(d.at)} ${d.kind || "decision"} ${d.verdict || d.action || ""}` at lines 394-395. A long-lived run accumulates hundreds of identical `HH:MM:SS reconcile.decision merge` lines, filling the sidebar/panel and making it unusable. The operator cannot close it with the `x` button, which belongs to a separate toast.

Goal: detail panel stays readable regardless of run age.

Steps:
1. In `ui.js`, cap the decisions rendered in `detailLines()` to the most recent 20, for example `run.decisions.slice(-20).map(...)`. Keep chronological order. Add a short marker like `... N earlier decisions` when the list was truncated, so the count is visible.
2. Keep all other detail fields unchanged: run ID, task ID, title, state, PR, branch, head SHA, timestamps, durations, blocked incident, attempts, reason, timeline.
3. Add a test in `ui_test.js` with more than 20 decisions asserting only the last 20 render, the truncation marker is present with the correct count, and 20 or fewer decisions render all of them.
4. Run `node --check` and `node --test` on plugin tests. Report pass count.
5. Open a PR against main and call beacon_watch_pr with the real run ID and PR number. Do not self-merge.

Check: a run with hundreds of decisions renders at most 20 decision lines plus one summary marker.

Accept: one file plus its test. Do not change Go code or AGENTS.md. Keep files under 350 lines.
