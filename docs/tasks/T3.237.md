# T3.237. Reconcile обязательствов после рестарта процесса
Premise: проверено 2026-11-21, требование уже в main, дубль не создан. Сверка live-состояния и durable-записей лежит в OwnerFiles: `internal/infra/wake/deliver.go` (commit 06d74c6, PR #389) сравнивает in-memory `seen` с durable `Obligations` и не будит обязательство повторно после рестарта. Ключ доставки стабилен: obligationID фиксируется в SQLite через `MarkObligationDelivered`, явный interrupt доступен как `T202API.Interrupt` в том же файле. Retirement эффекта потерянного процесса закрыт карточкой BS.15 (commit e56761b, PR #597): `PlanRetire`/`Retirer` в `internal/app/worker/retire.go` снимает lease, закрывает heartbeat, ставит терминальный `RetireStatusRetired` и публикует событие. Повторный retire ничего не меняет. Повторная доставка с тем же ключом через рестарт закрыта BS.14 (commit f4c870f, PR #468): `EffectWorker.Drain` в `internal/app/worker/effect.go` пропускает уже выполненные ID, а ID эффекта стабилен между рестартами. Сверка registry после рестарта (ADR 0095, T5.10) идёт в `cmd/beacon/registry_sync.go` и идемпотентна. Критерий карточки «зависшее обязательство получает терминальный статус или явный interrupt, а не остаётся running» и приёмка «повторный reconcile идемпотентен» выполнены. OwnerFiles не менял, код не писал, правка только текстовая. Статус изменён с todo на done.
