Add a sixth MCP tool `beacon_task_create` that creates a markdown task card in one call. It must accept title, body, scope, depends and priority, generate an ID from date plus short hex, write YAML frontmatter with status available, commit and push the card so `beacon_dispatch` sees it, and return id/path/pushed.

Implement:

1. Add `Create(ctx context.Context, task Task) (Task, error)` to `core.TaskSource`. Implement it in markdown, GitHub issues and GitLab issues adapters. Markdown writes `docs/tasks/<id>.md`; remote adapters create an issue through their API.
2. Add `internal/app/taskcreate.go` with `TaskCreator` that builds the Task, calls `Source.Create`, then `Workspace.CommitPath(ctx, rootWorkspace, "docs/tasks", "beacon: create task <id>")` using the port added by E2E-03.
3. Register `beacon_task_create` in `internal/infra/mcp/server.go` and pass `TaskCreator` through `Services`.
4. In `opencode.json` add global permission deny for the normalized tool action `beacon_beacon_task_create` and also `beacon_task_create`, then allow it only for agent `orchestrator` and temporarily for `build`. Define agents `orchestrator` and `worker` there. Workers must not see this tool.
5. Update `AGENTS.md` and `.opencode/plugins/beacon-project/context.js`: five worker tools plus one orchestrator tool.
6. Document in README that workers must be spawned with `harness.command: worker` so they inherit the deny rule.
7. Add tests for markdown Create, TaskCreator and the MCP tool over in-memory transport.

Keep production files under 350 lines. Run gofmt on changed Go files and targeted go test for changed packages. Do not run full go test ./... locally. Open a PR and call beacon_watch_pr.
