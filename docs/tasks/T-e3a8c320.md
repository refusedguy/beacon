Goal: Make the TUI panel resolve OpenTUI and Solid from the host runtime, not from a local or dynamic import.

Evidence: Logs show `stage=read` succeeds but `stage=setup` fails with `Cannot find package '@opentui/solid' imported from ui/ui.js`. The failing statement is the literal dynamic `import("@opentui/solid")` inside `defaultImport`. OpenCode's rewriter does not apply to that dynamic import at setup time. Installing a local copy produces a second Solid and OpenTUI instance and fails with `No renderer found`.

Scope: new ui/ui_runtime.js, ui/ui.js, test_support doubles/loader, CI workflow.

Steps: Move all TUI peer imports into a runtime module with static top-level imports for `@opentui/solid`, `solid-js` and `@opentui/core`. Have ui/ui.js import that module at top level and use it as the default dependency. Keep a test-only injection seam, and register doubles for the three specifiers in the existing --import loader so plain Node tests still run. Do not add local @opentui dependencies to package.json.

Check: OpenCode TUI starts the panel with no Cannot find package and no No renderer found. `node --test .opencode/plugins/beacon-project` passes with the loader. `node --check` passes on changed files.

Accept: No production Go code and no wire change.

Open a PR, call beacon_watch_pr, do not self-merge.
