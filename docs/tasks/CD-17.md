baseline: dmux строит очередь из элементов со статусами `pending`, `in_progress`, `completed`, `failed`, `skipped` (`src/actions/merge/types.ts:41-46`) и отбрасывает элемент, у которого единственная проблема `nothing_to_merge` (`src/actions/merge/multiMergeOrchestrator.ts:26-57`). Beacon различает только идемпотентный пропуск «уже залито по этой revision» (`internal/app/orchestrator/orchestrator.go:491-499`), но не классифицирует «нет изменений». Мерж идёт по `verdict=ready` (`internal/infra/cibridge/verdict_applier.go:180-189`).

Цель: Не тратить попытку мержа на ветку, в которой нет новых коммитов и изменений.

Контекст: `buildMergeQueue` в dmux включает элемент, если у него есть исправимая проблема или он готов к мержу, и исключает только случай с единственной проблемой `nothing_to_merge` (`multiMergeOrchestrator.ts:41-52`). Статус элемента меняется в обработчике очереди (`:138-170`), а итог содержит счётчики `successful`, `failed`, `skipped` (`types.ts:51-61`). Beacon сериализует мерж через окно в две минуты (`internal/app/orchestrator/rebase.go:91`, `:159-173`) и не классифицирует элементы до вызова API. Эта карточка не повторяет CD-03: там порядок по графу и продолжение после конфликта, здесь фильтр пустых элементов.

Шаги: Добавить в `internal/app/orchestrator/merge_skip.go` чистую функцию классификации элемента по списку кодов проблем из CD-15. На выходе решение `merge`, `skip` или `hold` с причиной. Не читать store и не вызывать API. Покрыть тестами единственной проблемы `nothing_to_merge`, комбинации `nothing_to_merge` с другой проблемой и готового элемента. Не менять `verdict_applier.go` и `rebase.go`.

Проверка: Элемент только с `nothing_to_merge` получает `skip` и не попадает в список вызовов merge API в тесте. Элемент с `nothing_to_merge` и грязным main получает `hold`. Готовый элемент получает `merge`. Итоговый отчёт считает пропуски отдельно от ошибок.

Приёмка: Пустые ветки не занимают слот сериализации. Причина пропуска видна в отчёте и отличается от отказа.

Причина: Требование уже влито в main через PR #1842. Дубль кода не создан.
