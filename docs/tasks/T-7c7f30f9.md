Goal: stop dropping the refusal reason between the producer and the operator.
Evidence from audit: postControlJSON now preserves the daemon's structured 409 reason instead of returning a bare status code (fixed in T-ae45da04); beacon_dispatch returns cap_full with no skip when all slots are busy; failures and skips carry no next action; beacon_reconcile returns noop with empty reason for an unbound PR; beacon_wait timeout loses state and reason; batch control already marks a call failed when any item fails (fixed in 494e34ff); CLI control prints JSON only on success so the plugin cannot show the reason; plugin dispatch toast counts only runs.length and ignores skips and failures; ui_actions.js checks only ok false; TUI overwrites refusal status on next refresh.
Steps: decode WireControlRefusal and return action, id and reason in the result; emit a cap_full skip with requested n and active count; add a next field per dispatch outcome; return an explicit error for an unbound PR in reconcile; return a structured wait result with timed_out, state and reason; keep per-id failure marking in batch control (already done); print ok false JSON with reason on CLI refusal; show skip and failure counts and first reason in the plugin toast; keep the last refusal in a dedicated TUI field until the next action.
Accept: an operator sees the original reason at every boundary, and no tool reports success when its main operation failed.
