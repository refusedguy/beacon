Цель: Разделить набор доступных инструментов и список инструментов, которые выполняются без запроса разрешения.
Контекст: SDK задаёт три разных рычага. `tools` ограничивает доступный набор, причём пустой список отключает все встроенные инструменты. `allowed_tools` помечает инструменты, которые выполняются без запроса. `disallowed_tools` удаляет инструмент из контекста модели (`src/claude_agent_sdk/types.py:2433-2453`, `:2522-2527`). В beacon один список `toolDescriptors` задаёт и набор, и аннотации, и обработчики (`internal/infra/mcp/server.go:130-147`), а `ToolNames` и `AdvertisedToolNames` выводятся из него же (`server.go:251-276`). CS-02 добавляет режимы разрешений, но не разделяет доступ и автоматическое разрешение.
baseline: `rg -n 'allowed_tools|AllowedTools|DisallowedTools' internal cmd` на `origin/main` 7244e15b даёт 0 строк; `rg -c 'Name:' internal/infra/mcp/server.go` даёт 18 строк с объявлениями.
Шаги: Добавить в конфигурацию сервера два списка: доступные инструменты и инструменты без запроса разрешения. Фильтровать `tools/list` по первому списку. Применять второй список в обработчике `ack` как причину автоматического разрешения. Оставить текущий объявленный набор как значение по умолчанию, чтобы не сломать контракт tools/list.
Проверка: Два сервера с разными списками доступных инструментов возвращают разные `tools/list`. Вызов инструмента вне списка даёт ошибку неизвестного инструмента. Измеримая проверка: различие числа имён в двух ответах равно 1; `rg -n 'allowedTools|disallowedTools' <ветка> -- internal/infra/mcp` даёт не менее 2 строк.
Приёмка: Ограничение набора инструментов не меняет правила разрешения и наоборот.
