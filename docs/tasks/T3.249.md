# T3.249. Transcript rotation
Premise: проверено 2026-11-21, функционал в origin/main отсутствует, дубль не создан. В internal/infra/wake/deliver.go и deliver_test.go нет ни одного упоминания transcript, rotation, pipe-pane или capture-pane. По всему репозиторию нет кода захвата терминала через pipe-pane или capture-pane. deliver.go адаптирует wake-указатель к OpenCode: PromptFunc шлёт текст в существующую сессию через HTTP или CLI, а Runner делает резервный вызов opencode api. Ни один из этих путей не создаёт tmux-сессию, не читает pane и не пишет снимок терминала. Карточка предписывает запускать rotation сразу после создания tmux, группировать capture по 24 pane и писать atomically temp plus rename, а проверка требует, чтобы файл содержал хвост сессии, а не полный pipe-pane поток. Для этого нужен живой tmux-раннер с pipe-pane capture и замером потока 1000 строк за 2 с. Фейковый PromptFunc такой зонд не заменяет: он проверяет доставку wake-сообщения, а не захват терминала, и в deliver.go нет точки для работы с pane. Ссылка на ADR 0083 не соответствует теме: документ docs/adrs/0083-events.md описывает обработку событий и полное чтение состояния, а не ротацию транскрипта. По архитектуре capture терминала живёт в слое работы с tmux или сессиями, то есть вне OwnerFiles карточки. Перенос логики ротации в deliver.go создал бы дубль чужого слоя и не закрыл бы приёмку про хвост сессии. Статус todo сохранён, карточка остаётся неподтверждённым спайком до появления живого tmux-зонда или расширения OwnerFiles. OwnerFiles не менял, код не писал, правка только текстовая.
