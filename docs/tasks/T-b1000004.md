Goal: record a card that loses on a scope claim instead of dropping it for one cycle.

Evidence: planner.go:110-138 returns a skip for active and selected scope overlaps and logs the reason. readyTasksQuery sorts by priority then ID, so the same low-priority cards lose every cycle. 2446 active_scope_overlap skips and 241 selected_scope_overlap skips out of 3982 decisions show the effect.

Steps:
1. In the active conflict branch and the selected conflict branch of planner.go, call the waitlist store method added by T-b1000003 to insert or refresh an entry keyed by the overlapping scope path and card ID. Keep the SkippedTask result and its reason unchanged for the current cycle.
2. Keep the active-run guard and the batch conflict check. Do not change the skip codes active_scope_overlap or selected_scope_overlap.
3. Add tests in internal/app/planner_waitlist_test.go that a conflicted card leaves a wait entry, that a repeat conflict refreshes waiting_since rather than adding a second row, and that aging within equal priority follows waiting_since.

Accept: every conflicted card has a wait entry with a timestamp, and the planner still returns the same skip set it returns today.
