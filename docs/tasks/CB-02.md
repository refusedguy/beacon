Цель: При объединении двух деревьев карточек разрешать совпавшие ID автоматически и сохранять карту соответствий между старым и новым ID вместе со всеми ссылками.

Контекст: Источник, реальный код beads. `buildPrefixRepairPlan` в `cmd/bd/rename_prefix.go:470-512` группирует ID по корням и делает два прохода. `claimWantedRoots` на `:623-648` резервирует желаемый корень, если его не занял живой ID, другое семейство или отложенная очистка. `hashRoot` на `:666-689` подбирает новый корень через nonce и обновляет `plan.rootMap` на `:498-500`. Причины коллизии перечислены в `wantedRootConflict` на `:650-664`. Результат импорта содержит `IDMapping` и `CollisionIDs` в `cmd/bd/import_shared.go:76-106`, поэтому замена видна вызывающему. Разрыв в beacon: `MeasureIDCollisions` на `internal/infra/taskstore/store.go:601-640` только измеряет повторы. Функций перемещения ID, карты соответствий и перезаписи рёбер в `.go`-файлах `origin/main` нет. AN-04 фиксирует проблему, но не предлагает механизма разрешения.

Шаги: Добавить операцию слияния деревьев, которая группирует карточки по корню ID. Первый проход резервирует желаемые ID. Второй проход для конфликтующих семейств выделяет новый ID через nonce и записывает карту соответствий старого ID новому. Переписать все рёбра и текстовые ссылки по карте. Вернуть отчёт с числом конфликтов и списком изменённых ID. Предусмотреть dry-run.

Проверка: Измеримая. Два дерева с карточкой `T3.17` разного содержимого после слияния дают ноль неразрешённых дублей. Отчёт содержит ровно одну запись соответствия. Число висячих ссылок после перезаписи равно нулю. Dry-run не меняет файлы. Повторное слияние тех же деревьев идемпотентно и не создаёт вторую карту соответствий.

Приёмка: Формат `T<g>.<n>` сохраняется. Существующие worktree с уникальными ID не мигрируют. Карточка не трогает логику atomic claim.
