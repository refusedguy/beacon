# T5.55. Команда registry sync
Premise: проверено 2026-11-21 по свежему origin/main (4c811d8), функционал присутствует не в полном объёме, дубль не создан. Карточка просит команду `beacon registry sync`: сверять записи registry со списком живых сеансов, снимать stale, писать last_seen и worktree, быть идемпотентной и не отправлять сообщения (ADR 0095 accepted). Чистое сравнение и источник уже в main: PR #353 (commit dbee6d7, T5.30) добавил ровно OwnerFiles карточки cmd/beacon/registry_sync.go и registry_sync_test.go с reconcileStale, classifyStale, liveSessionIDs, syncRegistry, registryWakeAllowed и registryDBStore; тесты TestReconcileStaleIsIdempotent и TestRegistrySyncNeverStartsModel покрывают «Проверка: Синхронизация идемпотентна» и «Приёмка: Она не отправляет сообщения». Не хватает двух вещей, обе вне OwnerFiles карточки. Первая: самой CLI-команды. `case "registry"` теперь есть в dispatch (cmd/beacon/main.go:278, PR #809), но он ведёт к registryRunner, где подключён только `stop`; `git grep -nE '"stop"|"sync"|"check"' origin/main -- cmd/beacon/registry_stop.go` даёт только case "stop" на строке 221. PR #353 прямо говорит «новые файлы не меняют существующие команды и не подключают CLI», PR #809 оставляет sync-сеам неподключённым, а T5.55 подключает команду. По прецеденту T5.54 (PR #747, файл cmd/beacon/registry_check.go прямо указывает, что dispatch в cmd/beacon/main.go вне его OwnerFiles) регистрация dispatch живёт в main.go, который является OwnerFiles карточки T5.56, а не T5.55, поэтому внутри OwnerFiles T5.55 команду не подключить. Вторая: записи last_seen и worktree. registryDBStore.SetStatus пишет только status и updated_at; схема agent_registry в internal/infra/store/registry.go:48 не содержит колонок last_seen или worktree (`grep -En 'last_seen|worktree' internal/infra/store/registry.go` = 0), поэтому выполнение шага «писать last_seen и worktree» требует миграции и правки store вне OwnerFiles, а значение worktree берётся из session.list (Location.Directory) только на живом сервере. Проверка на идемпотентность уже зелёная в main, но приёмка «не отправляет сообщения» и полная сверка требуют живого прогона с opencode serve и session.list. Здесь доступны только текст и gofmt на слабом ПК, живой зонд и сборка с go test недоступны, поэтому prove-it-works для оставшейся части выполнить нельзя.
