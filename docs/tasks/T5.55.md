# T5.55. Команда registry sync
Premise: проверено 2026-11-21, в origin/main функционал присутствует не в полном объёме, дубль не создан. Карточка просит команду `beacon registry sync`: сверять записи registry со списком живых сеансов, снимать stale, писать last_seen и worktree, быть идемпотентной и не отправлять сообщения (ADR 0095 accepted). Чистое сравнение и источник уже в main: PR #353 (commit dbee6d7, T5.30) добавил ровно OwnerFiles карточки cmd/beacon/registry_sync.go и registry_sync_test.go с reconcileStale, classifyStale, liveSessionIDs, syncRegistry, registryWakeAllowed и registryDBStore; тесты TestReconcileStaleIsIdempotent и TestRegistrySyncNeverStartsModel покрывают «Проверка: Синхронизация идемпотентна» и «Приёмка: Она не отправляет сообщения». Зависимость T5.59 снята в PR #748 как дубль: живые сессии приходят из session.list через liveSessionIDs, отдельного cmd/beacon/opencode_bridge.go нет и не нужно. Не хватает двух вещей, обе вне OwnerFiles карточки. Первая: самой CLI-команды. `grep -En 'case "registry"|runRegistrySync|registrySyncRunner|SetRegistrySource' cmd/beacon/main.go cmd/beacon/registry_sync.go` даёт 0 совпадений, в dispatch нет case "registry", в catalog нет записи registry; PR #353 прямо говорит «новые файлы не меняют существующие команды и не подключают CLI», а T5.55 подключает команду. По прецеденту T5.54 (PR #747, файл cmd/beacon/registry_check.go прямо указывает, что dispatch в cmd/beacon/main.go вне его OwnerFiles) регистрация dispatch живёт в main.go, который является OwnerFiles карточки T5.56, а не T5.55, поэтому внутри OwnerFiles T5.55 команду не подключить. Вторая: записи last_seen и worktree. registryDBStore.SetStatus пишет только status и updated_at; схема agent_registry в internal/infra/store/registry.go:48 не содержит колонок last_seen или worktree (`grep -En 'last_seen|worktree' internal/infra/store/registry.go` = 0), поэтому выполнение шага «писать last_seen и worktree» требует миграции и правки store вне OwnerFiles, а значение worktree берётся из session.list (Location.Directory) только на живом сервере. Проверка на идемпотентность уже зелёная в main, но приёмка «не отправляет сообщения» и полная сверка требуют живого прогона с opencode serve и session.list. Здесь доступны только текст и gofmt на слабом ПК, живой зонд и сборка с go test недоступны, поэтому prove-it-works для оставшейся части выполнить нельзя. Статус todo сохранён, блокер возвращён оркестратору: нужны либо расширение OwnerFiles до cmd/beacon/main.go и store/миграции, либо регистрация registry dispatch в T5.56, плюс живой зонд с opencode serve и снятый/закрытый downstream T5.61 (PR #744 уже фиксирует T5.55 как todo и живой sync как блокер). Код не писал, gofmt не применял, дубль не создал, OwnerFiles не менял, правка только текстовая.
