Цель: Публиковать итог прогона как набор непересекающихся списков с версией схемы.

Классификация поломок добавочная: инстанс остаётся в `unresolved_ids` или `error_ids`, знаменатель не меняется (`:88-108`). Дополнительную классификацию из SB-03 некуда записать без изменения знаменателя.

baseline: `rg -c '_ids|schema_version' swebench/harness/reporting.py` даёт 47 строк; `git grep -c 'completed_ids|unresolved_ids' -- internal cmd` даёт 0.

Шаги: Добавить в ответ stats версию схемы и списки идентификаторов по исходам. Считать каждый Watch ровно в одном списке, кроме дополнительной классификации поломок. Публиковать те же списки через `beacon metrics` без второго источника истины. Оставить текущие счётчики и их имена без изменений. Отдельно зафиксировать правило, что classified-инстанс не убирается из основного списка.

Проверка: Собрать четыре Watch: зелёный, красный, с пустым PR и с ошибкой инфраструктуры. Сейчас отчёт даёт только агрегатные числа. Цель: каждый Watch попадает ровно в один основной список, инфраструктурный Watch дополнительно попадает в список классификации, версия схемы равна 2. Повторный вызов с тем же состоянием даёт побайтово равный отчёт.

Приёмка: По отчёту можно восстановить множество Watch каждого исхода и сравнить два прогона без чтения journal.
