# T4.1. Хаос тест: двойная доставка даёт один эффект, indeterminate не ретраится

Цель: Доказать на хаос-прогоне, что повторная доставка указателя не удваивает эффект, а недоставленное с indeterminate не порождает повтор.

Контекст: WORKER-PROMPT §5 требует, чтобы двойная доставка давала один эффект, и §7 выделяет chaos-уровень тестов. Невариант 2 из WORKER-PROMPT §4.2: уведомление at-least-once, эффект ровно один раз, ключ идемпотентности у получателя `watchID+revision+subscriberID`. Невариант 8: indeterminate-доставка никогда не ретраится. ADR 0017 закрепляет обе ветви, ADR 0014 объясняет, что нет квитанции это indeterminate. ADR 0001 убирает авто-мерж Beacon, поэтому один эффект это один мерж оркестратора по ключу из T3.8. WORKER-PROMPT §5 требует рестарт не более 5 с без потери обязательств.

Шаги:
1. Поднять изолированное окружение с фейковым GitHub, плагином из T3.1 и базой из T1.2.
2. Доставить один и тот же указатель дважды через канал T3.2 и проверить, что получатель выполнил действие один раз по ключу `(watchID, revision, subscriberID)`.
3. Создать обязательство без квитанции, выдержать окно проверки доказательства и проверить, что повторов нет, а эскалация из T3.10 сработала один раз.
4. Добавить рестарт посреди лестницы и проверить, что обязательства не потеряны и время старта не превышает 5 с.
5. Записать результаты и дату в `tests/chaos/README.md`.

Проверка: `go test ./tests/chaos/...` проходит. Тест считает эффекты по числу мержей и числу пробуждений: после двойной доставки эффект один. Для indeterminate число повторных отправок равно нулю. Рестарт укладывается в 5 с и сохраняет обязательства.

Приёмка: Двойная доставка даёт один эффект. Indeterminate не ретраится. Рестарт не более 5 с без потери обязательств. Числа и дата записаны.

Гейт: P4. Вход в T4.3 shadow-прогон.
