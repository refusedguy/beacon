# CV-05. Контракт асинхронного ответа человека в beacon_wait_result

Premise: проверено 2026-11-22 по `origin/main` `2d34645b`. Источник: OpenHands `src/api/request-secret-client-tool.ts:7-25`, `:47-53` кладёт в описание инструмента правило «ответ придёт позже, не жди в цикле, не спрашивай повторно» и объявляет `idempotentHint: false`.

Разрыв: `WaitResultService` уже делает правильное действие. При `needs_input` он возвращается до записи `readAt` и предлагает ответить через `ack(continueOf)` (`internal/infra/mcp/tool_wait_result.go:1197-1203`, `:1360-1364`). Но описание инструмента в `internal/infra/mcp/server.go:159` говорит только про bounded long-poll и 30-минутный lease. Агент, получивший `needs_input`, не видит в контракте правила прекратить ожидание и не задавать вопрос повторно. Поведение описано в коде и ADR, а агент читает только описание инструмента.

baseline: `rg -n 'do not wait|wait in a loop|follow-up|one call per' internal/infra/mcp/server.go` = 0; `rg -n 'needsInputOutput|WaitStopInputRequired' internal/infra/mcp/tool_wait_result.go` = 6; `rg -n 'Name:        "beacon_wait_result"' internal/infra/mcp/server.go` = 1, строка 159.
