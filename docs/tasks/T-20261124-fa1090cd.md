Goal: the queue must stay readable and the Recent section must remain reachable when an epic is expanded. No Go or docs edits.

Evidence from the live screenshot: opening an epic with five children fills the sidebar with child rows and repeated ID lines such as 51f36-01 and 51f36-02. The Recent section is pushed below the viewport and cannot be opened. The previous card #2391 added collapse, but the state is read from storage and an old open value keeps the epic expanded. Dependency IDs are still drawn both as child rows and as separate dependency lines.

Scope: .opencode/plugins/beacon-project/ui_view.js, ui_alerts.js, ui.js, ui_view_test.js, ui_alerts_test.js.

Steps:
1. Collapse epics by default. If a stored open value is present but stale, do not let it expand automatically on startup. Only an explicit click in the current session opens an epic.
2. Cap the number of rendered child rows so the queue cannot consume the whole sidebar. Show a short summary line such as "+N more" when children exceed the cap.
3. Render each dependency ID once. If a child is also a dependency, do not draw it again in a separate line. Shorten IDs to the readable suffix, not the full T-20261124-... string.
4. Keep the two-line row format: title first, compact status and dependency count second. Recent must stay visible and clickable with an expanded epic.
5. Tests: default collapsed even with stale storage; click expands; child count cap; no duplicate dependency rows; Recent still present after expansion; existing queue and slot tests pass.
6. node --check every plugin JS file and node --test .opencode/plugins/beacon-project/*_test.js. Every file <= 350 lines. Open a PR, call beacon_watch_pr with the real run ID and PR number, do not self-merge.
