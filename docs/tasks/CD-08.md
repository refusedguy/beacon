Цель: Дать проекту один способ вызвать проверку или команду разработки через тот же механизм хуков, что и события жизненного цикла.

Контекст: В dmux имена `run_test` и `run_dev` живут и в каталоге событий, и в реестре действий. `listAvailableHooks` возвращает только те имена, для которых найден исполняемый скрипт (`hooks.ts:401-417`). Вызов действия использует тот же `findHook` и профиль окружения, поэтому проект пишет один скрипт и получает оба входа. В beacon реестр событий ограничен `claimed`, `unblocked`, `closed` (`service.go:65-71`), а плагин OpenCode обрабатывает события инструментов `PreToolUse` и `PostToolUse` (`.opencode/plugins/beacon-project/index.js:78-80`). Команды уровня проекта через хуки недоступны.

Шаги: Добавить в `internal/app/taskcli/hook_actions.go` реестр имен действий с проверкой, что имя входит в разрешённый набор. Сделать функцию, которая по имени действия возвращает описание скрипта и режим запуска, не запуская процесс. Покрыть тестами перечисление доступных действий, неизвестное имя и действие без скрипта. ## Решение

Реестр действий живёт в `internal/app/taskcli/hook_actions.go`: ровно два имени (`run_test`, `run_dev`), каждое с режимом запуска. `HookActionNames` перечисляет имена, `DescribeHookAction` возвращает описание сценария и режим без запуска процесса, `RunHookAction` вызывает сценарий из каталога хуков и возвращает его вывод. Без сценария результат пустой, неизвестное имя отвергается. `TOOL_LIFECYCLE_EVENTS` не изменён.
