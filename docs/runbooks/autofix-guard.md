# Предохранитель автоисправления

`AllowAutofix` в `internal/app/orchestrator/autofix_guard.go` решает, можно ли запустить фикера для PR. Функция чистая. Она читает переданные факты и не обращается к CI. Результат имеет тип `AutofixSkipReason`: причина удержания, а не булевый флаг. Оркестратор видит, какое именно правило сработало.

## Правила удержания

| Условие | Поле фактов | Причина |
| --- | --- | --- |
| Владелец отказался от автоисправления | `OptedOut` | `AutofixSkipOptedOut` |
| Head-коммит запушил человек | `HeadPusherIsAgent == false` | `AutofixSkipHumanHead` |
| После последней попытки пришёл follow-up | `FollowUpSinceLastAttempt` | `AutofixSkipFollowUp` |
| Проверка уже красна на базовой ветке | `BaseFailedChecks` не пуст | `AutofixSkipBaseFailure` |
| Бюджет попыток исчерпан | `AttemptCount` | `AutofixSkipAttemptLimit` |

Правила идут в порядке таблицы. Первое совпадение даёт ответ, даже если выполнены несколько условий.

## Бюджет попыток

Предел равен 10 по умолчанию. Вызывающий код задаёт своё число вторым аргументом: `AllowAutofix(facts, attemptLimit)`. Нуль или отрицательное значение включает предел по умолчанию. Попытка с номером, равным пределу, удерживается.

## Отказ владельца PR

Владелец пишет комментарий в PR:

```text
@beacon autofix off
```

Код, который читает комментарии PR, выставляет `OptedOut = true` в фактах этого PR. Пока флаг поднят, фикер не запускается. Остальные правила в этом случае не проверяются.

## Снятие отказа

Владелец пишет комментарий в PR:

```text
@beacon autofix on
```

Порядок снятия отказа:

1. Проверить, что head-коммит всё ещё написан агентом. После push от человека guard удержит запуск по `AutofixSkipHumanHead`, даже если отказ снят.
2. Добавить комментарий `@beacon autofix on`.
3. Дождаться, пока код чтения комментариев выставит `OptedOut = false`.
4. Убедиться, что бюджет попыток не исчерпан и на базовой ветке нет красных проверок из набора `BaseFailedChecks`.

После снятия отказа зелёный PR с head-коммитом агента проходит guard. Дополнительных действий не требуется.

## Граница действия

Guard удерживает только spawn фикера. Wake оркестратору он не меняется. Проверка на базовой ветке остаётся в `internal/domain/verdict.go`. Guard получает готовый набор `BaseFailedChecks` и не читает CI повторно. Роль fixer из ADR 0260 остаётся прежней.
