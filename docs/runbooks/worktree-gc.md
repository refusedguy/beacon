# Уборка worktree

`beacon gc-worktree` убирает чистые worktree без живого Watch. Команда сначала строит план, потом удаляет кандидатов. Здесь собраны правила запуска и стопоры.

## Просмотр перед удалением

Запускайте с `--apply` только после просмотра dry-run. Без `--apply` команда печатает план и не меняет каталоги.

```
beacon gc-worktree --format table
beacon gc-worktree --format json
```

Проверьте список кандидатов. Если в нём есть чужой worktree, выясните причину до повторного запуска. Удаление выполняет только команда с `--apply`.

## Отсрочка и вторая проверка

Сборщик не удаляет только что найденного кандидата сразу. Кандидат ждёт окно `DefaultGrace` (30 с), затем проходит вторую проверку `git status --porcelain`. `git worktree remove` вызывается только когда статус совпадает с первым снимком. Любое изменение между проверками снимает кандидата.

Отсрочку реализует `internal/infra/worktree/grace.go`. `Guard.Grace` задаёт окно, `Guard.Status` читает статус, `Guard.Remove` удаляет каталог. Пока сборщик не вызывает `Guard.Check`, отсрочка не влияет на уборку. Защита по HEAD и живому Watch описана в карточках WG-02 и WG-01.

## Lock как ручной стопор

`git worktree lock <путь>` запрещает удаление одного worktree. Сборщик оставляет такой каталог с причиной `locked`. Когда работа закончена, снимите стопор командой `git worktree unlock <путь>`. Lock не заменяет просмотр dry-run.

## Откат при ошибке

Ошибка чтения статуса или удаления оставляет worktree на месте. Причина попадает в отчёт сборщика. Следующий проход начинается с нового снимка статуса.
