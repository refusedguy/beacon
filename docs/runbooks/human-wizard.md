# Визард ручных шагов

Beacon использует bash-визард только там, где шаг не может выполнить агент. Если агент сделает шаг командами репозитория, визард не нужен. Документ описывает порог применения, поля этапа и требования к скрипту.

## Порог применения

Визард нужен в четырёх случаях: подготовка инфраструктуры, создание учётных данных и секретов CI, работа в незнакомой панели, разовый cutover. Общий признак один: агент не имеет доступа или права выполнить шаг сам.

Перед расспросом владельца прочитайте репозиторий. Найдите уже существующие скрипты, конфиги и команды, которые закрывают этот шаг. Оставьте в визарде только действия, для которых источник значения известен и агент не может получить значение сам.

Список этапов должен быть конкретным. Визард хранит число этапов в `TOTAL_STAGES` и печатает прогресс как `Шаг 2 из 5`. Владелец видит, сколько шагов осталось, до начала ввода.

## Поля этапа

Каждый этап содержит четыре обязательных поля.

- Название. Короткое имя шага, которое владелец увидит в терминале.
- Источник значения. Откуда берётся значение: ответ владельца, вывод команды или файл конфигурации.
- Место записи. Куда попадает значение: `.env`, `gh secret set` или `gh variable set`.
- Секретность. Что можно вывести на экран, а что нужно скрыть.

Этап без источника значения или без места записи не готов. Такой этап нельзя запускать, пока владелец не заполнит оба поля.

## Требования к скрипту

- Скрытый ввод. Секреты запрашивает функция `ask_secret`, которая отключает эхо. Значение не попадает в аргументы команды, в трассировку и в логи.
- Идемпотентная запись. Повторный запуск не дублирует ключи в `.env`. Функция `write_env` обновляет существующий ключ на месте. `gh secret` и `gh variable` перезаписываются только после отдельного подтверждения.
- Подтверждение перед действием, которое нельзя откатить. Перед вызовом покажите команду и цель, затем дождитесь явного ответа владельца. Отказ прерывает визард без записи.
- Проверки перед сдачей. Запустите `bash -n <скрипт>` и `shellcheck <скрипт>`. Обе команды должны завершиться без ошибок.
- Статический trace. Вместо end-to-end прогона покажите трассировку шагов: какие команды визард вызвал бы и какие значения записал. Секреты в трассировке заменяются на `<hidden>`.

## Срок жизни визарда

Визард по умолчанию временный. Создайте его во временном каталоге, проведите шаги и удалите после завершения. Коммит в репозиторий допускается только когда скрипт нужен как повторяемый путь настройки, например для новых разработчиков. Разовый cutover коммиту не подлежит.

Флаг `BEACON_ALLOW_MAIN_COMMIT` из `README.md` задаёт режим разработчика и не заменяет этот порядок. Коммит и пуш остаются за владельцем шага.
