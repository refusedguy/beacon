# ADR 0004. GitHub клиент, гибрид

Статус: accepted

## Решение

Использовать `go-github` для REST и отдельный `http.Client` для GraphQL.

## Причина

Отчёт C показал, что `go-github` экономит сотни вызовов и умеет ждать лимиты GitHub. Отчёт D показал, что GraphQL батч требует точного контроля над алиасами, ценой запроса и полями `statusCheckRollup`. Готовые структуры `go-github` мешают такому контролю.

Владелец согласился на гибрид.

## Последствия

- `go-github` отвечает за REST ETag, 304 и пинок `mergeable=UNKNOWN`.
- Отдельный HTTP клиент отвечает за GraphQL батч, чтение `rateLimit.cost` и нормализацию ошибок.
- Оба клиента обновляют общий счётчик поинтов, лимит 500 в час.
- При достижении лимита оба увеличивают интервал опроса.

## Риск

`go-github` меняет путь импорта при каждом мажорном релизе. Версия фиксируется в go.mod.
