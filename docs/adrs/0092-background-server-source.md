# ADR 0092. Фоновый сервис как источник данных registry

Статус: accepted

## Контекст

Реестр исполнителей и таблица `beacon watch` должны показывать агентов, которые работают в живом OpenCode. ADR 0060 запрещает второй протокольный мост и выбирает `$XDG_STATE_HOME/opencode/service.json` как адрес уже работающего фонового сервиса. Там же зафиксировано, что `opencode api app.agents` на v2.3.0 возвращает `UnknownError: Operation not found: app.agents`. Вызов `opencode api session.list` работает и несёт поля `id`, `parentID`, `agent`, `model`, `title`, `time.*` и `location.directory`. Данные об исполнителях берутся из этого ответа, а не из второго моста.

## Решение

1. Основной источник агентов это поле `agent` ответа `session.list`. Дополнительные источники это `GET /api/agent` и вывод `opencode agent list`. Вызов `app.agents` не используется.
2. `beacon registry sync` читает `service.json`, получает `session.list` и обновляет в registry поля `session_id`, `worktree` и `last_seen`. Соединение строк идёт по непрозрачному sessionID из `_meta` `ai.opencode/sessionID`, см. `internal/infra/mcp/meta.go:8`.
3. Весь код чтения живёт в `cmd/beacon` за узким port. Порт объявляет только нужные команде методы чтения, например `Sessions` и `ListAgents`. Тесты подменяют реализацию, а composition root в `cmd/beacon/main.go` ставит живой клиент.
4. Адрес берётся из `service.json`. Порт 4096 не хардкодится, Basic-авторизация берёт `opencode` и пароль из того же файла. Транспорт `--stdio` для этой обвязки не применяется. Спавн `opencode serve` допускается только как fallback по ADR 0060, когда registration-файла нет.
5. Готовность задачи берётся из вердикта Beacon. Статус `idle` из OpenCode остаётся справочной колонкой и готовностью не считается.
6. Набор MCP-инструментов не меняется. Реестр живёт в CLI и в состоянии. Восьмой инструмент требует отдельного решения.

## Последствия

- Никакой HTTP-клиент не появляется в `internal/domain`, `internal/app` и `internal/infra/mcp`. Проверка карточки: `internal/domain` не импортирует `net/http`.
- Новый протокольный мост не создаётся. Клиент читает готовое HTTP API того же сервиса, не говорит по ACP и не переводит операции ядра. Границы ADR 0006 и ADR 0024 сохраняются.
- Адрес из `service.json` переживает рестарт сервиса. Свой фоновый сервер рядом с работающим сервисом не поднимается.
- `session.list` кэшируется с TTL по ADR 0060, чтобы цикл по событиям не делал лишний запрос на каждое событие.
- Расхождение между registry и живым списком сеансов после рестарта не фатально. Синхронизация помечает запись как `stale`, и wake по ней не идёт до повторной сверки.

## Отклонённое

Второй протокольный мост или широкий HTTP-клиент. Он дублирует шесть операций из ADR 0024 и возвращает код OpenCode в Go-ядро, чего запрещает ADR 0006.

`opencode api app.agents` как источник агентов. На живой версии v2.3.0 вызов недоступен.

Хардкод порта 4096 и собственный сервер вместо discovery через `service.json`.
