# ADR 0005. Архитектурные ограничения и гейты

Статус: accepted

## Решение

Переносить на Go вариант 2 из отчёта B:

- слои с направлением зависимостей только внутрь;
- два независимых гейта на импорты: один через `go list`, второй через AST `go/parser`;
- capabilities гейт на использование `os/exec`, файлов, сети в неположенных слоях;
- у каждого гейта посаженное нарушение, которое гейт обязан найти;
- расхождение между двумя гейтами считается ошибкой.

Все гейты написаны на Go.

## Причина

В Harbor почти каждое правило имеет машинный гейт, а каждый гейт доказывает невакуумность посаженным нарушением. Владелец назвал это защитой от долбоебства агентов и выбрал вариант 2. Вариант 1 оставляет проект без защиты, вариант 3 избыточен до появления кода.

## Последствия

- Правило без гейта считается долгом.
- Источник истины о слоях это матрица разрешённых рёбер в конфиге.
- Новый пакет без строки в матрице падает.
- Неиспользуемое разрешение тоже ошибка.

## Отклонённое

Вариант 1 без capabilities. Вариант 3 с полным набором правил Harbor и проверками публичного API.
