# ADR 185: OTel tracing

Статус: accepted

## Контекст

У Beacon есть durable-счётчики persist_progress, stream_health, wake_observations и контракт beacon_stats, но нет корреляции между процессами и дерева спанов. go.mod не содержит opentelemetry. Исследование рекомендует не тащить SDK в обычный запуск: t3code держит локальные спаны и включает OTLP только по env, Crush пишет локальный лог, OpenRig не экспортирует ядро.

## Решение

Ввести internal/infra/observe с интерфейсом Tracer { Start(ctx, name, attrs...) (ctx, end func()) }. Реализация на stdlib context без внешних зависимостей: W3C-идентификаторы, дочерний спан через контекст, строковые атрибуты и Sink для завершённых спанов. По умолчанию tracer нет-оп. BEACON_OTEL_ENABLED включает его только при точном true, BEACON_OTEL_EXPORTER пока только читается. Обёртки на командах daemon, orchestrate, ci и deliver дают спаны на границах процессов. Подмена на OTLP делается через SetTracer и Sink без изменения вызовов.

## Последствия

Нет новых зависимостей и изменений в beacon_stats и таблицах store. Спаны пока существуют только на границах CLI-команд: по-тиковые спаны внутри daemon, cibridge.Refresh и wake.T210Deliver требуют отдельных хуков. Нет экспорта в коллектор и межпроцессной корреляции до появления OTLP-адаптера. Локальный просмотр идёт через slog. Атрибуты только низкой кардинальности, без аргументов инструментов и текста промптов.
