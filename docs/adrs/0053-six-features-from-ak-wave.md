# ADR 0053. Шесть фич из отчёта AK-wave

Статус: accepted

Этот ADR фиксирует шесть фич из отчёта AK «AK-волна: новые проекты по долгим задачам и агентным сессиям» ([AK, строка 1](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L1)). Поиск шёл 18 запросами `gh api search/repositories`, из выборки удалены 345 репозиториев из отчётов A-AJ, затем ещё три проекта из отчётов N и S; дата коммита взята из поля `commit.committer.date` первого коммита в API, а не из `pushed_at`; все 18 вошедших проектов имеют коммит в 2026 году и не встречаются ни в одном отчёте папки ([AK, строка 3](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L3)). Фичи взяты из раздела «Фичи», пункты 3, 4, 5, 6, 7 и 17 ([AK, строки 30-51](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L30)). Здесь зафиксированы только те фичи, которых нет в ADR 0001-0052 и 172 карточках из `docs/tasks/`. Fencing, аренда, идемпотентность, outbox и wake уже есть: ADR 0028 задаёт идемпотентность по `clientRequestId` на вызовах MCP, T3.14 atomic queue, T3.51 fencing, T3.97 аренду с TTL, T3.109 heartbeat, T3.44 живость по артефактам и PID, T3.80 `wake_between`. Поэтому эти темы здесь не повторяются. Несколько пунктов похожи на существующие по имени, но различаются по уровню. Фича 1 это HTTP-вход и долгий idle до 86400 секунд, а не квитанция ADR 0028. Фича 2 это autoreclaim движка через `FOR UPDATE SKIP LOCKED`, а не сигнал heartbeat T3.109. Фича 3 это запись задачи в транзакции основной записи без отдельного outbox, а не атомарность очереди и событий T3.14. Фича 4 это продление аренды heartbeat'ом с переносом fencing-токена в результат, а не только потеря аренды T3.109 и не сама аренда T3.97. Фича 5 это событийный триггер «PR создан» для освобождения claim, а не определение живости T3.44. Фича 6 это debounce и курсор в `register_wake`, а не `wake_between` T3.80. Владелец велел принять отобранные идеи без дополнительных вопросов, поэтому статус `accepted`. По ADR 0020 карточки создаются только из принятого ADR. Карточки этим ADR не создаются, код, карточки и тесты в этой задаче не трогаются.

## Решение

Beacon получает шесть механизмов. Они описаны на уровне контракта и не привязаны к конкретному продукту.

1. Idle wait до 86400 секунд с мгновенным пробуждением и ключ идемпотентности на HTTP-входе. Ожидающий вызов может спать до 86400 секунд и просыпается сразу при появлении новой задачи, а не по истечении интервала опроса. HTTP-вход принимает ключ идемпотентности: повтор с тем же ключом и тем же payload возвращает 200 и прежний результат, повтор с тем же ключом и изменённым payload возвращает 409. Это HTTP-граница и долгий idle, а не `clientRequestId` из ADR 0028.

2. Автовозврат stale job в очередь через `FOR UPDATE SKIP LOCKED`. Движок возвращает зависшую задачу в очередь сам, без внешнего cleanup. Захват идёт через `FOR UPDATE SKIP LOCKED`, поэтому параллельные воркеры не блокируют друг друга и не берут одну и ту же строку. Ведущий воркер не вытесняется, пока его задача не признана stale. Это autoreclaim в движке, а не heartbeat T3.109.

3. Задача пишется в той же транзакции, что и основная запись. Строка задачи и основная доменная запись коммитятся одной транзакцией. Откат транзакции отменяет и задачу, поэтому отдельный outbox для неё не нужен. Это граница с основной записью, а не атомарность очереди и событий внутри task store из T3.14.

4. Продление аренды heartbeat'ом с fencing-токеном. Пока воркер жив, heartbeat продлевает срок аренды и сохраняет fencing-токен в силе. Каждая запись результата сверяет токен с текущим. Воркер с устаревшим токеном не пишет результат, даже если его вычисление завершилось. Это продление аренды, а не только возврат false при её потере из T3.109 и не сама аренда T3.97.

5. «PR создан → claim сразу освобождается». Событие создания PR считается триггером завершения работы агента: claim освобождается сразу, без ручной смены статуса. Это простой триггер завершения, а не проверка живости по артефактам и PID из T3.44.

6. `register_wake` с debounce 60 секунд и `cursorAnchor`. Пачка из 50 событий за окно даёт одно пробуждение, а не 50. Остальные события агент дочитывает по курсору от `cursorAnchor`, не теряя их. Это debounce и курсор внутри `register_wake`, а не `wake_between` из T3.80.

## Причина

1. green-gray-gaurav/RevMCP-Q это локальная обратная MCP-очередь: приложение кладёт задачу по HTTP, активная сессия забирает её инструментом `wait_for_job` ([AK, строка 13](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L13), [RevMCP-Q](https://github.com/green-gray-gaurav/RevMCP-Q)). Фича для Beacon это idle wait до 86400 секунд с мгновенным пробуждением и ключ идемпотентности на HTTP-входе: 200 при повторе, 409 при изменённом payload ([AK, строка 36](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L36), https://github.com/green-gray-gaurav/RevMCP-Q). ADR 0028 дедуплицирует повтор вызовов MCP по `clientRequestId`, но не описывает HTTP-вход с конфликтом по payload и не допускает ожидание на 86400 секунд. Берутся HTTP-ключ и долгий idle, а не один пользователь, loopback, отсутствие аккаунтов и авторизации, один процесс на базу и брокер с HTTP-сервером, MCP-сессиями и Python ([AK, строка 74](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L74)).

2. sidequestjs/sidequest это фоновая обработка задач без Redis: задачи лежат в уже имеющейся базе, в том числе в SQLite, и захватываются атомарно ([AK, строка 14](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L14), [sidequest](https://github.com/sidequestjs/sidequest)). Фича для Beacon это автоматическое восстановление зависших задач: движок сам возвращает stale job в очередь, а захват идёт через `FOR UPDATE SKIP LOCKED` ([AK, строка 37](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L37), https://github.com/sidequestjs/sidequest). T3.109 определяет, что heartbeat возвращает false при потере аренды, но не описывает, кто и как возвращает задачу в очередь. Берётся autoreclaim и неблокирующий захват, а не минимум Node.js 22.6.0, лицензия LGPL-3.0, четыре бэкенда и отдельный dashboard ([AK, строка 75](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L75)).

3. kvet/queuert это типизированные цепочки задач, которые коммитятся в той же транзакции, что и доменные данные ([AK, строка 15](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L15), [queuert](https://github.com/kvet/queuert)). Фича для Beacon это запись задачи в одной транзакции с основной записью: откат отменяет и задачу, отдельный outbox не нужен ([AK, строка 38](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L38), https://github.com/kvet/queuert). T3.14 и ADR 0030 объединяют очередь и события в одной SQLite-транзакции, но не описывают откат задачи вместе с основной доменной записью и отказ от outbox. Берётся транзакционная граница основной записи, а не вывод типов на этапе компиляции и конформационные тесты адаптеров, которые в Go не работают ([AK, строка 76](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L76)).

4. azaz2288/queueforge это локальная SQLite-очередь с идемпотентной отправкой, арендой, fencing-токеном и продлением аренды ([AK, строка 16](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L16), [queueforge](https://github.com/azaz2288/queueforge)). Фича для Beacon это продление аренды heartbeat'ом с fencing-токеном: worker с устаревшим токеном не может записать результат, даже если вычисление завершилось ([AK, строка 39](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L39), https://github.com/azaz2288/queueforge). T3.97 задаёт аренду с TTL и fencing, T3.109 сообщает воркеру о потере аренды, но не описывает продление живой аренды и перенос токена в запись результата. Берётся продление, а не версия 0.2.0, локальная доверенная модель и отсутствие гарантии ровно одного побочного эффекта ([AK, строка 77](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L77)).

5. mraza007/baton это оркестратор, который опрашивает GitHub Issues, делает worktree под issue и запускает Claude Code ([AK, строка 17](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L17), [baton](https://github.com/mraza007/baton)). Фича для Beacon это правило «PR создан, значит claim сразу освобождается»: простой триггер завершения работы агента без ручного статуса ([AK, строка 40](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L40), https://github.com/mraza007/baton). T3.44 определяет живость сессии по артефактам и PID, но не связывает освобождение claim с созданием PR. Берётся триггер, а не состояние в памяти с JSON-персистентностью, только GitHub Issues, только `claude` и отсутствие транзакций SQLite ([AK, строка 78](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L78)).

6. thejavapirate/model-context-stream это MCP-сервер на Redis Streams с задачами по Lua-скрипту и пробуждением спящих агентов через `register_wake` ([AK, строка 27](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L27), [model-context-stream](https://github.com/thejavapirate/model-context-stream)). Фича для Beacon это `register_wake` с debounce 60 секунд и `cursorAnchor`: пачка из 50 событий даёт одно пробуждение, остальное агент дочитывает по курсору ([AK, строка 50](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L50), https://github.com/thejavapirate/model-context-stream). T3.80 решает проблему thundering herd через `wake_between`, но не объединяет события в одно пробуждение с дочитыванием по курсору. Берутся debounce и курсор, а не обязательный Redis, TypeScript, Helm и Kubernetes и регистрация wake на произвольный URL ([AK, строка 88](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L88)).

## Последствия

- Из каждого пункта выходит одна небольшая карточка в `docs/tasks/` по правилам ADR 0020. Карточки этим ADR не создаются и будут созданы отдельными задачами. Владельцы файлов для будущих карточек:

  - Фича 4: `internal/domain/types.go`, `internal/infra/mcp/tool_claim.go`, `internal/infra/mcp/tool_ack.go`, `internal/infra/taskstore/store.go`, `internal/infra/store/db.go`, `cmd/beacon/watch.go` и тесты к ним.
  - Фича 5: `internal/domain/types.go`, `internal/infra/mcp/tool_watch_pr.go`, `internal/infra/mcp/tool_claim.go`, `internal/infra/github/rest.go`, `internal/app/taskcli/service.go`, `cmd/beacon/watch.go` и тесты к ним.
  - Фича 6: `internal/domain/types.go`, `internal/infra/mcp/tool_wake.go`, `internal/infra/mcp/tool_wait_result.go`, `internal/infra/taskstore/store.go`, `internal/infra/store/receipts.go`, `cmd/beacon/watch.go` и тесты к ним.
- Проверка карточек: idle wait держится до 86400 секунд и прерывается сразу при новой задаче, повтор HTTP-запроса с тем же ключом и payload отдаёт 200, с изменённым payload 409; зависшая задача возвращается в очередь движком, а захват через `FOR UPDATE SKIP LOCKED` не даёт двум воркерам взять одну строку; откат транзакции отменяет и основную запись, и задачу, отдельный outbox для задачи отсутствует; heartbeat продлевает аренду, а запись результата с устаревшим токеном отклоняется; создание PR освобождает claim без ручного статуса; пачка из 50 событий за 60 секунд даёт одно пробуждение, а пропущенное читается по `cursorAnchor`.
- ADR 0001-0052 с T3.14, T3.44, T3.51, T3.80, T3.92, T3.97, T3.103 и T3.109 не переписываются. HTTP-ключ фичи 1 не меняет `clientRequestId` ADR 0028. Autoreclaim фичи 2 не заменяет heartbeat T3.109 и не меняет модель владельцев аренды ADR 0049. Транзакция фичи 3 не отменяет atomic queue T3.14 и журнал ADR 0011. Продление фичи 4 не дублирует fencing T3.51, аренду T3.97 и heartbeat T3.109. Триггер фичи 5 не меняет живость T3.44 и артефакт ADR 0027. Debounce фичи 6 не заменяет `wake_between` T3.80, доставку ADR 0026 и курсор ADR 0025. Лестница ADR 0017 и проверка только в CI из ADR 0022 дополнительной не становятся.

## Отклонённое

Брать проекты целиком. Причины из отчёта сводятся к чужому рантайму, лицензиям, платформе и широкой поверхности ([AK, строки 70-89](/home/nbook/Projects/tmp/beacon-research/AK-wave.md#L70)). Beacon требует Go, один локальный бинарник и глобальную установку в `~/.config/opencode`. Ни один из восемнадцати проектов не годится как целый продукт.

Включать в этот ADR остальные идеи отчёта. Менеджером отобраны пункты 3, 4, 5, 6, 7 и 17 раздела «Фичи». Не отобраны: ext-tasks с durable task handle `io.modelcontextprotocol/tasks` (AK:34, https://github.com/modelcontextprotocol/ext-tasks); agent-wake с квитанцией и `delivery_unknown` (AK:35, https://github.com/Kandler3/agent-wake); shipyard с оркестрацией `prompt, wait, check, loop, hand off` (AK:41, https://github.com/cosscom/shipyard); rush с JSON-конвертом и кодом выхода 3 (AK:42, https://github.com/PHPCraftdream/rush); ISO-Framework с пятишаговой проверкой перед удалением worktree (AK:43, https://github.com/snehith01001110/ISO-Framework); QuorumGit с классификацией claim относительно аренд (AK:44, https://github.com/Deep-Sixed/QuorumGit); agent-handoff-kit с квитанцией `worker + token` (AK:45, https://github.com/ujwalpandey1/agent-handoff-kit); ghostback с привязкой сессии к `SurfaceView` UUID (AK:46, https://github.com/cristipufu/ghostback); agent-skills с навыком `/recover` (AK:47, https://github.com/conorbronsdon/agent-skills); lanes-sh/app с PTY-сессией на задачу (AK:48, https://github.com/lanes-sh/app); coder-mcp-bridge с ожиданием по revision через `afterRevision` (AK:49, https://github.com/Deslord319/coder-mcp-bridge); agent-runner с запретом менять журнал SQLite-триггерами (AK:51, https://github.com/HKXk7/agent-runner). Часть из них пересекается с уже принятыми решениями или с ADR 0001-0052, остальные менеджером в эту волну не отобраны.

Повторять уже принятые решения под новыми именами. Идемпотентность и квитанции зафиксированы в ADR 0028, atomic queue в T3.14, fencing в T3.51, аренда в T3.97, heartbeat в T3.109, живость в T3.44, wake в T3.80, курсор в ADR 0025. Фичи этого ADR работают на других уровнях: HTTP-ключ и долгий idle, autoreclaim, транзакция основной записи без outbox, продление аренды, событийный триггер по PR, debounce с курсором.
