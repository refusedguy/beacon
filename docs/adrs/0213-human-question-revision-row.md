# ADR 213: Вопрос человеку как ревизионная строка

Статус: accepted

## Контекст

В OpenRig вопрос это queue row с options, ответ записывается reply row и закрывает ask один раз. Ревизии и operation id защищают от stale retry и двойного ответа. Beacon эту модель не переносит.

Базовый замер: `docs/research/adr-consistency-audit.md`, строка 5 и раздел 0213. В main `operationId` встречается только в wake и относится к повтору длинной команды. Кода `question_changed` нет. Явного reply path для вопросов нет. Eval `docs/evals/w21-human-question-revision.md` описывал ожидаемое поведение без реализации.

## Решение

Beacon не обещает версионированную строку вопроса, operation id вопроса и явный reply path. Вопрос человеку живёт как состояние `needs_input` карточки или Watch с полем «Вопрос». Флаг `hasPendingQuestion` в wake и вердикт `needs_input` в Watch показывают, что ответ нужен человеку. Ответ приходит командой `beacon human <verb> <target>`: по HTTP при наличии соединения, иначе в локальное хранилище.

`operationId` в wake решает другую задачу. Повтор равного `prompt` во время работы возвращает уже выданный идентификатор и не запускает вторую задачу. Он не связан с вопросом человеку.

Отдельного кода `question_changed` и проверки изменения текста вопроса между чтением и ответом в main нет.

## Последствия

- Документация и eval описывают поведение, которое есть в main, а не неподнятую модель OpenRig.
- Идемпотентность на уровне operation id вопроса не обеспечивается: такого идентификатора для вопросов нет.
- Если появятся revision вопроса, код `question_changed` и reply path, это отдельная карточка с реализацией в коде и правкой этого ADR. Сценарий продолжения той же Watch после ответа человека ведёт BCX-57.
