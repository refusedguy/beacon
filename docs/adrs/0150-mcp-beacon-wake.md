# ADR 150: Один общий MCP-сервер Beacon и тонкие адаптеры wake

Статус: accepted

## Контекст

Владелец одобрил три решения: один общий MCP-сервер Beacon, тонкие адаптеры-плагины доставляют wake, Beacon не становится вторым протокольным мостом. Beacon хранит состояние, считает вердикт и выдаёт указатель на обязательство.

## Решение

Плоскость управления это MCP. Плоскость доставки принадлежит адаптеру. Адаптер получает указатель и вызывает родной API своей среды. Между Beacon и адаптером нет второго протокола. Beacon не вызывает API OpenCode, Pi, Kilo или Cursor и не переводит их протоколы.

## Последствия

Адаптеры находятся вне ядра и не знают друг о друге. Три реестра делают схему проверяемой: AdapterRegistry, SessionRegistry, DeliveryRegistry. Один beacon_watch_pr обслуживается двумя мостами без правки Go-кода. Указатель не несёт содержимого проверок, только идентификаторы.
