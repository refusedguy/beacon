# ADR 0025. Статус и курсор вместо полной истории событий

Статус: accepted

## Решение

MCP-ответ несёт текущий статус и курсор событий, а не всю историю. Ядро не хранит чужую историю целиком. Курсор непрозрачный и подходит для `Last-Event-ID`. Два вызова подряд с курсором возвращают только новые события. После терминального статуса вердикт получается без старых событий.

## Причина

Отчёт M3 в разделах «Общий знаменатель», «Предлагаемый интерфейс адаптера» и «Что нельзя унифицировать» перечислил три формы переноса событий: SSE с курсором `Last-Event-ID` у Cursor, NDJSON у Cline, Claude, Copilot, Kilo и Goose, JSON-RPC `session/update` в ACP. Во всех трёх случаях нужен курсор или запрос терминального статуса, потому что потоки не хранят всю историю. У Cursor поток имеет заголовок retention и может вернуть `410 stream_expired` ([документы Cursor](https://cursor.com/docs/cloud-agent/api/overview)). Клиент OpenCode прямо говорит, что подписки работают только вживую, без повтора прошедших событий и без автопереподключения ([документы OpenCode](https://opencode.ai/docs/build/client/#stream-events)). У Aider событийного API нет вовсе ([документы Aider](https://aider.chat/docs/scripting.html)).

ADR 0019 уже установил, что Watch закрывается по терминальному вердикту, а не по времени. Статус поэтому важнее накопленной истории. ADR 0020 требует, чтобы задача приходила из согласованного решения, поэтому карточка схемы появится только после статуса `accepted`.

## Последствия

- Схема MCP-ответа содержит `status` и `cursor`. Ядро сохраняет только курсор и терминальный вердикт.
- Подписчик, который потерял соединение, продолжает с курсора или запрашивает финальный статус.
- Из этого решения выходит одна небольшая карточка в `docs/tasks/` по правилам ADR 0020. Карточка затронет `internal/infra/mcp/schema.go`, `internal/infra/mcp/tool_watch_pr.go`, `internal/infra/mcp/tool_list_running.go` и тесты к ним.
- Проверка карточки: два вызова подряд с курсором возвращают только новые события, а после терминального статуса повторный вызов не требует старых событий и вердикт всё равно получается.

## Отклонённое

Хранение полной истории событий агента в ядре с последующим воспроизведением по запросу. Потоки не отдают такую историю, а для некоторых сред её нет никогда.
