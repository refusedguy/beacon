# ADR 81: deliveryId как сквозной идентификатор доставки

Статус: accepted

## Контекст

Cursor подтверждает доставку follow-up через deliveryId: свой, например ID webhook-доставки, или свежий dlv_. События nudge.delivered и message.received несут deliveryId и deliveryIds. X-Webhook-ID — уникальный ID доставки, Idempotency-Key даёт 422 при том же ключе с другим телом и возвращает первый run при совпадении. Steer при сетевой ошибке может доставить промпт дважды, повтор считается новым промптом.

## Решение

Ввести обязательный deliveryId во все бэкенды wake-адаптера. Для входящих webhook брать X-Webhook-ID, для Automations проверять Idempotency-Key. Хранить журнал доставок и не запускать вторую работу на тот же ID. Ключ идемпотентности фиксировать до внешнего вызова, как api.memo в Pi до park.

## Последствия

Дедупликация закрывает предупреждение Cursor про double delivery при повторе steer. В Pi повтор submit с тем же requestId возвращает ту же submission, а сигнал с занятым ключом даёт duplicate. Один ключ оценивается один раз, повтор требует нового ключа. В Kilo повторные сигналы схлопываются в pendingWake.
