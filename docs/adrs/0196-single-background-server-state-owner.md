# ADR 290: Один фоновый сервер как единственный владелец состояния

Статус: proposed

## Контекст

MCP, плагин и будущий TUI читают и пишут одно состояние напрямую.

## Решение

Все изменения идут через один долгоживущий beacon-server. Клиенты получают проекции по HTTP и SSE.

## Последствия

Появляется одна точка восстановления и один журнал. Требуется поддержка жизненного цикла процесса.
