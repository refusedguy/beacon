# ADR 0019. Время жизни Watch

Статус: accepted

## Решение

У Watch нет жёсткого TTL, привязанного к времени. Watch живёт, пока идёт работа по PR.

 Один сабагент может делать rebase множество раз в рамках software factory. Каждый rebase меняет head SHA, закрывает старый Watch и создаёт новый для тех же подписчиков. Число rebase не ограничено.

Orphan обрабатывается отдельно. Если подписчик неактивен более 30 минут и обязательство не подтверждено, это эскалация оркестратору, а не тихое удаление Watch.

## Причина

Владелец поправил предыдущую формулировку. Речь не о длительности одного rebase, а о множестве повторов в рамках одной цепочки. Лимит на rebase и TTL в шесть часов из раннего контракта привели бы к обрыву долгой работы.

## Предикат выхода

Каждый Watch несёт предикат выхода. Это проверяемое условие завершения работы по PR. Агент записывает предикат до первой итерации и держит его неизменным во всех ревизиях и ребазах.

На каждой ревизии агент пишет одну строку журнала. Строка содержит изменение, наблюдение и решение. Следующий шаг агент берёт из поля `nextAction` ответа `beacon_get_result`. Плато не переводит Watch в готовность и не ослабляет предикат.

Закрытие по терминальному вердикту, по отмене или по head changed остаётся прежним. Wake-механизм не меняется.

## Последствия

- В базе не используется TTL как причина закрытия Watch.
- Закрытие происходит по терминальному вердикту, по отмене или по head changed.
- Рост базы контролируется архивацией закрытых записей.
- Долгие цепочки видны в метриках как число head_changed у одного issue.
