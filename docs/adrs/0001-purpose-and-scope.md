# ADR 0001. Назначение и границы проекта

Статус: accepted

## Решение

Beacon это один глобальный процесс на машину. Он владеет фоновыми наблюдениями за PR, вычисляет вердикты и уведомляет подписчиков через тонкие адаптеры.

Ядро говорит только MCP. Оно не знает OpenCode, не знает формат sessionID и не содержит вызовов OpenCode API.

Оркестратор получает от владельца число задач, запускает сабагентов и принимает решение о мерже. Beacon выдаёт вердикт, а не фразу в чате.

## Причина

Пятнадцать сабагентов держали пятнадцать процессов `gh pr checks --watch`. Измерено 668,8 MB RSS плюс около 62 MB оболочек. Агент одновременно работал, наблюдал, судил и уведомлял.

## Последствия

- Один процесс вместо процесса на PR.
- Решение «можно мерджить» становится проверяемыми данными.
- Оркестратор перед мержем проходит свой чек: критерии приёмки, скоуп, ревью, branch protection.
- concurrency агентов не ограничивается. 15+ это потолок ёмкости Beacon, а не настройка ядра.

## Отклонённое

Простое увеличение интервала `gh --watch` или обход без сервиса вердиктов. Оставляет агента судьёй и не убирает процессы.
