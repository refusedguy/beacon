# ADR 0027. Артефакт это ветка, PR или файл в worktree

Статус: accepted

## Решение

Beacon читает результат из git-ветки, PR и изолированной директории worktree. Beacon не разбирает внутренние логи и базы агента. Источник результата фиксируется явно: ветка, PR или файл в worktree. Закрытый PR даёт терминальный вердикт без чтения логов агента.

## Причина

Отчёт M3 в разделах «Что нельзя унифицировать» и «Общий знаменатель» указал, что внутренние файлы состояния не являются публичным контрактом. Документы Claude прямо называют `~/.claude/jobs/<id>/` нестабильным интерфейсом ([Claude](https://code.claude.com/docs/en/agent-view.md#read-session-state-from-a-script)). Так же нельзя опираться на формат базы Goose или SQLite Cline. Читать нужно через поддерживаемые команды и API. Для менеджера важен не сам лог, а результат работы: ветка, PR, изменённые файлы и тесты. Изоляции при этом разные: worktree, облачная VM и контейнер дают разную защиту, поэтому один флаг `isolate: true` не может считаться одинаковым результатом.

ADR 0021 уже дал каждому агенту отдельную ветку, отдельный worktree и один набор файлов по карточке. Это даёт стабильное место, откуда читается артефакт. ADR 0020 требует, чтобы задача приходила из согласованного решения, поэтому карточка чтения артефактов появится только после статуса `accepted`.

## Последствия

- Квитанции адаптера и хранилище состояния не содержат путей к внутренним файлам агентов.
- Две параллельные карточки в разных worktree не видят файлы друг друга.
- Из этого решения выходит одна небольшая карточка в `docs/tasks/` по правилам ADR 0020. Карточка затронет `internal/infra/mcp/tool_watch_pr.go`, `internal/infra/github/points.go`, `internal/infra/store/receipts.go` и тесты к ним.
- Проверка карточки: один закрытый PR даёт терминальный вердикт без чтения логов агента.

## Отклонённое

Чтение транскриптов, логов и баз агента напрямую как источника результата. Формат меняется вместе с версией продукта, а документы Claude объявляют часть путей нестабильными.
