# ADR 0070. Универсальный wake-адаптер

Статус: accepted

## Контекст

Beacon держит один общий MCP-сервер. В `internal/infra/cibridge/bridge.go` мост читает активные Watch, считает вердикт из проверок и сохраняет новую ревизию с обязательствами подписчиков. Сам мост wake не шлёт. Пробуждение живёт в `.opencode/plugins/beacon-bridge.js`: S2-поллер читает `events.jsonl`, вызывает `ctx.session.prompt` с `delivery=steer` и пишет квитанции в каталог состояния. Есть ещё два описанных в репозитории пути доставки. Это HTTP OpenCode `POST /api/session/{id}/prompt` из ADR 0060 п4 и ACP-методы `session/prompt` и `session/resume`.

ADR 0069 в `docs/adrs/` нет. Карточек T3.175 и T3.176 в `docs/tasks/` нет. Этот ADR фиксирует решение по теме и создаёт карточки T3.179, T3.180, T3.181, T3.182 и T3.183.

Границы заданы раньше. ADR 0006 и ADR 0024 выносят код агента из Go-ядра в тонкий мост рядом с плагином. ADR 0026 требует честное поле `delivery` со значениями `steer`, `queue` или `unsupported`. ADR 0017 разрешает повтор только для `transport-failed` и запрещает его для неопределённого исхода. ADR 0060 называет `POST /api/session/:sessionID/prompt` путём доставки follow-up. ADR 0061 считает доказательством локальный прогон владельца и eval, а не зелёный CI.

## Решение

1. Общий интерфейс `Deliverer` живёт в `internal/infra/wake`. Он принимает указатель с полями `watchID`, `obligationID`, `revision`, `target`, `attempt` и `source`, а возвращает способ доставки по ADR 0026 и исход по ADR 0017. Пакет лежит в `internal/infra`, а не в `internal/domain`. Ядро по-прежнему говорит только MCP, и в нём нет имён агентов. Ни один MCP-инструмент не меняется.

2. Конкретные адаптеры лежат рядом с интерфейсом в `internal/infra/wake`. Адаптер OpenCode вызывает `POST /api/session/{id}/prompt` с `delivery=steer` по тому же контракту, что `beacon deliver` из ADR 0060 п4. Адаптер ACP вызывает `session/prompt`, а для продолжения той же сессии `session/resume`. Оба адаптера тонкие. Они не переводят шесть операций ядра и не становятся вторым мостом рядом с MCP. JS-плагин остаётся доставщиком внутри живой сессии OpenCode. Go-адаптер не заменяет его и не переносит его код в ядро.

3. `cibridge` вызывает `Deliverer` после терминального вердикта. Терминальный вердикт это любой вердикт, кроме `watching`, который `publish` уже записал в Store. Мост сначала сохраняет новую ревизию и обязательства, затем делает одну доставку на обязательство. Повтор пары `obligationID` и `attempt` не создаёт второй prompt. Ошибка транспорта пишется в журнал и даёт `transport-failed`, но не меняет вердикт и не запускает повтор из моста. Неопределённый исход не ретраится. Мост по-прежнему не мержит и не запускает проверки.

4. Evals считаются доказательством доставки. `evals/main.go` получает eval 12, который прогоняет доставку через `Deliverer` на подставных реализациях транспорта для OpenCode и ACP. Негативный контроль проверяет три факта: `unsupported` не считается успехом, повтор той же пары не даёт второй prompt, `transport-failed` не ретраится мостом. Приёмка это локальный прогон `bash evals/run.sh` с фактическим выводом и unit-тесты профильных пакетов. Зелёный CI один приёмкой не считается.

## Причина

У одного сервера несколько циклов доставки, и у каждого свой транспорт. OpenCode отдаёт готовый HTTP-маршрут, ACP определяет свои методы, а плагин внутри сессии работает с `ctx.session.prompt`. Общий интерфейс задаёт только контракт указателя и честный исход. Транспорт остаётся в конкретном адаптере, поэтому новый цикл добавляется без правки `cibridge` и MCP-сервера.

Выбор пакета `internal/infra/wake` следует ADR 0024. Мост переводит операции ядра, а `Deliverer` только доставляет уже выбранный указатель. В `internal/domain` не появляются HTTP-адреса и имена ACP-методов. В ADR 0006 сказано, что код OpenCode живёт вне Go-бинарника. Адаптер из п2 не отменяет это правило: он не содержит логики плагина, не меняет `.opencode/plugins/beacon-bridge.js` и не трогает ядро. Он повторяет тот же вызов, который ADR 0060 п4 уже разрешает в `beacon deliver`.

Привязка к терминальному вердикту убирает ручной шаг. Сейчас `publish` сохраняет вердикт и обязательства, а агент должен сам прочитать результат через `beacon_get_result`. Вызов адаптера из моста закрывает цикл в том же месте, где вердикт стал известен. Идемпотентность по паре `obligationID` и `attempt` и запрет повтора неопределённого исхода сохраняют правила ADR 0017. `unsupported` остаётся отказом по ADR 0026.

Eval выбран как доказательство по ADR 0061. Заглушка, которая всегда печатает `steer`, или тест, который подставляет `ready`, не подтверждают доставку. Негативный контроль в eval 12 обязан уронить прогон, если адаптер врёт о способе доставки или мост шлёт указатель дважды.

## Последствия

- Из решения выходят пять карточек в `docs/tasks/`. Все со статусом `todo` и ссылкой `ADR 0070`:
  - T3.179, unit и eval проверка доставки. Владельцы: `internal/infra/wake/deliver.go`, `internal/infra/wake/deliver_test.go`, `evals/main.go`.
  - T3.180, адаптер ACP. Владельцы: `internal/infra/wake/acp.go`, `internal/infra/wake/acp_test.go`.
  - T3.181, адаптер OpenCode. Владельцы: `internal/infra/wake/deliver.go` и `internal/infra/wake/deliver_test.go`. Тип `OpenCodeDeliverer` лежит в `internal/infra/wake/deliver.go`, отдельного файла адаптера в дереве нет.
  - T3.182, вызов адаптера из CI-моста по терминальному вердикту. Владельцы: `internal/infra/cibridge/bridge.go`, `internal/infra/cibridge/bridge_test.go`.
  - T3.183, project-scoped указатель wake. Владельцы: `.opencode/plugins/beacon-bridge.js`, `tests/adapter/fail-open.test.js`, `tests/e2e/fixtures/beacon-bridge.js`.
- Project-scoped указатель из T3.183 читается и пишется по тому же правилу, что `stateDir()` в `cmd/beacon/doctor.go`. Явный путь задаёт `BEACON_STATE_DIR`, иначе каталог равен `<XDG_STATE_HOME>/beacon/projects/<имя>-<хеш>`. Плагин берёт путь из `ctx.beaconStateDir` или из того же правила. Два проекта не делят один `wake-pointer.json`.
- ADR 0006, 0017, 0024, 0026, 0060, 0061 не переписываются. Живой цикл и гейт вердикта остаются за оркестратором. `beacon get_result` продолжает работать с тем же контрактом.
- Проверка карточек. Доставка честно называет способ, повтор пары не даёт второй prompt, терминальный вердикт вызывает адаптер один раз, а eval показывает негативный контроль на фактическом выводе.
- Тесты этого ADR не запускались, код не менялся. В PR на реализацию каждой карточки агент приводит команду прогона и фактический вывод.

## Отклонённое

Один универсальный протокол вместо интерфейса. ACP не заменяет MCP-сервер и не становится общим транспортом для всех циклов. ADR 0024 оставляет ядро на MCP, а ADR 0060 не добавляет второй мост.

Размещение `Deliverer` в `internal/domain` или в MCP-инструментах. Там появились бы HTTP-адреса и имена ACP-методов, что запрещает ADR 0006.

Повтор при неопределённом исходе и при `posted`. Такой повтор удваивает эффект и нарушает ADR 0017.

Замена JS-плагина Go-адаптером. Плагин доставляет wake внутри живой сессии и ведёт квитанции. Go-адаптер работает на стороне моста и не трогает этот файл.

Мокнутый eval как единственное доказательство. eval с подставным вердиктом или с заглушкой, которая всегда возвращает `steer`, не заменяет локальный прогон владельца из ADR 0061.
