# ADR 188: Фоновый сервер как владелец состояния

Статус: accepted

## Контекст

Beacon это один глобальный процесс на машину (ADR 0001). Наблюдение за PR, расчёт вердикта, лестница пробуждения и доставка указателя обязательства живут дольше одного хода агента. MCP-инструменты вызываются в ходе сессии и исчезают вместе с ней. Если состояние держать в инструментах, два клиента увидят разные копии, а фоновое наблюдение потребует активного хода. Карточки `docs/tasks/BS.1.md`, `docs/tasks/BS.2.md`, `docs/tasks/BS.4.md`, `docs/tasks/BS.5.md` и `docs/tasks/BS.7.md` связывают решение с одним процессом, loopback-сервером, read-only проекциями и единственным writer-ом.

## Решение

Владелец состояния это долгоживущий фоновый сервер. Он открывает один SQLite-файл, применяет миграции и держит единственного писателя в режиме WAL (`internal/infra/store/db.go`, карточка `docs/tasks/BS.5.md`). Фоновая петля в `cmd/beacon/daemon.go` и `internal/app/orchestrator/daemon.go` опрашивает CI, регистрирует Watches, считает вердикты, передаёт готовые PR оркестратору и закрывает завершённые. Сервер публикует read-only проекции состояния через loopback HTTP и SSE (`internal/infra/httpapi/server.go`) и принимает команды через свой канал, а не через инструменты.

MCP-слой не владеет состоянием. `NewServerWithDeps` в `internal/infra/mcp/server.go` получает порты через `mcp.Dependencies`: `domain.Store` из `internal/domain/types.go`, `CIProvider`, `ObligationStamper`, `SnapshotReader`, `Clock` и другие. Хендлеры только читают проекции или пишут через внедрённый порт. Ни один инструмент не открывает собственную базу и не считает процессную память источником истины. Позиция владельца: всё заложено на уровне фонового сервера, MCP остаётся проекцией его состояния.

На машине работает один сервер. Второй старт обязан отказаться через lease и pidfile в каталоге состояния (карточка `docs/tasks/BS.1.md`). Остановка прекращает приём, дожидается воркеров и закрывает базу, но оставляет неподтверждённые outbox-строки для рестарта (карточка `docs/tasks/BS.7.md`). Без внедрённых портов `NewServer()` регистрирует настоящие хендлеры, которые сообщают об ошибке порта, а не притворяются успешными.

## Последствия

Наблюдение идёт без активного хода агента, и все клиенты видят одно и то же состояние. Новый транспорт не создаёт вторую копию базы, а состояние восстанавливается из SQLite после рестарта. Цена решения: сервер должен быть единственным, иначе два writer-а удвоят wake и нарушат идемпотентность, поэтому отказ второго старта обязателен. MCP отделён от владения состоянием: инструмент не может прочитать чужой PR напрямую и не может сохранить вердикт в обход сервера. Добавление фоновой работы происходит в сервере, а не в новом инструменте (ADR 0189).
