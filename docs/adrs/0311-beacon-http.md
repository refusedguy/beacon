# ADR 311: Один живой экран Beacon поверх HTTP-проекции

Статус: proposed

## Контекст

Интерактивный Data Board из internal/tui/board.go:357 работает по статическому списку карточек. Текстовый дашборд из internal/tui/app.go:125 читает живой снимок, но не управляется клавишами. beacon watch --live из cmd/beacon/watch.go:499 уже печатает снимок через httpapi.ProjectionClient. Три реализации показывают разные части одного состояния. Матрица tools/beacon-gates/gate/config/layers.json:15 не разрешает cmd импортировать internal/tui, а PR #1111 уже добавляет это ребро для статического board.

## Решение

Один интерактивный экран собирается из живого снимка /api/v1/snapshot и SSE /api/v1/events. cmd получает узкий порт в новом файле cmd/beacon/tui.go и не содержит net/http. Bubble Tea программа остаётся в internal/tui. В матрицу добавляется одно ребро cmd к internal/tui с фикстурой и пересобранным бинарником гейта. Все глаголы оператора проходят через /api/v1/human/decide и ограничены списком сервера. Для вывода без TTY используется текстовый рендер.

## Последствия

Появляется один путь от клавиши до вердикта и один клиент контракта. Решение владельца по ребру матрицы обязательно до начала кода. PR #1111 проверяется перед любой правкой адаптера. Ручные spawn и kill остаются вне контракта human-decide, пока не появятся в домене.
