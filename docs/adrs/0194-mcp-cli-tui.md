# ADR 194: Тонкие клиенты: MCP, CLI и TUI читают одни проекции

Статус: accepted

## Контекст

В OpenRig CLI и TUI почти не содержат бизнес-логики: TUI имеет один HTTP-модуль, читает /api/ps, /api/rigs/summary, /api/queue/list и /api/activity/events. Агенты управляют TUI через control socket. MCP работает через тот же DaemonClient.

## Решение

Beacon-server отдаёт проекции и SSE; beacon CLI и будущий TUI не пишут в store напрямую. Агентский control socket добавляется как отдельный канал с bearer-аутентификацией. MCP остаётся одним из клиентов.

## Последствия

Убирается дублирование между MCP-вызовом, плагином opencode и TUI. Любая новая проекция появляется сразу во всех клиентах. Нужны контрактные тесты на форму ответов.
