# ADR 0050. Шесть фич из отчёта AH-wave

Статус: accepted

Этот ADR фиксирует шесть фич из отчёта AH «AH-волна: новые проекты» ([AH, строка 1](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L1)). Поиск шёл 20 ноября 2026 года и нашёл 18 новых проектов ([AH, строка 3](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L3)). Идеи собраны в разделе «Фичи» ([AH, строки 116-135](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L116)) и подтверждены описаниями проектов ([AH, строки 5-114](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L5)). Здесь зафиксированы только те фичи, которых нет в ADR 0001-0049 и 168 карточках из `docs/tasks/`. Идемпотентность, аренда, вердикт, курсор и лестница пробуждения уже есть: ADR 0028 задаёт идемпотентность и квитанции, ADR 0017 задаёт ступени пробуждения, ADR 0025 задаёт курсор, T3.51 и T3.97 задают fencing и аренду, T3.88 и T3.67 задают вердикт и формулу `ship`. Поэтому эти темы здесь не повторяются. Несколько пунктов похожи на существующие по имени, но различаются по уровню. Фича 1 это подписка на событие, а не команда с квитанцией из ADR 0028. Фича 2 задаёт контракт выдачи результата, а не порог синхронного вызова 30/120 секунд из T3.103. Фича 3 выносит вердикт до появления артефакта, а не completion gate с proof из T3.88. Фича 4 задаёт безопасное удаление worktree, а не цепочку блокировок `beacon why` из T3.104. Фича 5 различает exit code 0 и просмотр результата человеком, а не принятое намерение из T2.23. Фича 6 задаёт limiter пробуждений, а не разброс `wake_between` из T3.80. Владелец велел принять отобранные идеи без дополнительных вопросов, поэтому статус `accepted`. По ADR 0020 карточки создаются только из принятого ADR. Карточки этим ADR не создаются, код, карточки и тесты в этой задаче не трогаются.

## Решение

Beacon получает шесть механизмов. Они описаны на уровне контракта и не привязаны к конкретному продукту.

1. Подписка на событие с ключом аргументов и одноразовый `Once`, плюс встроенный `Watch` с backoff и общим ID на повторах. Инструмент регистрирует подписку по ключу аргументов и возвращает идентификатор задачи сразу. `Once()` снимает подписку после первого события. `Emit` будит всех подписчиков с этим ключом. `Watch` повторяет попытку с backoff и сохраняет один и тот же ID на всех повторах, чтобы повтор не создавал новую задачу. Это подписка и доставка события, а не команда с квитанцией из ADR 0028 и не новая ступень лестницы ADR 0017.

2. Вызов возвращает `job_id` сразу, финальный результат читается ровно один раз через `poll`. В ответе `poll` всегда есть `elapsed_s` и `error_id`. Успешная или упавшая задача удаляется из учёта в момент первого чтения результата, поэтому второй `poll` не выдаёт тот же финальный результат. Это контракт результата, а не порог 30/120 секунд из T3.103 и не квитанция из ADR 0028.

3. Вердикт до появления PR. N независимых судей оценивают diff по версионированному рубрикатору, прежде чем результат попадает в PR. Если рубрикатор провален, отдаётся полный отчёт судей и PR не публикуется. Стоимость может записываться собственным атрибутом рядом со стандартными `gen_ai.*`. Это вердикт до артефакта, а не completion gate с proof из T3.88 и не таблица `ship` из T3.67.

4. Удаление worktree только после повторной проверки. Кандидат на уборку проходит проверку, переносится в скрытое имя, получает запись об удалении и проверяется ещё раз. `git worktree remove` выполняется только после второй проверки и без `--force`. Любой провал проверки или любое изменение в worktree возвращает его на место и отменяет удаление. Это безопасный reclaim арендованного worktree, а не цепочка блокировок `beacon why` из T3.104.

5. Разделение «процесс вышел с кодом 0» и «результат просмотрен человеком». Запись о задаче несёт поля `needs_review` и `reviewed_at`. Exit code 0 сам по себе не снимает `needs_review`: отметка ставится только после просмотра результата человеком. Это просмотр результата, а не записанное намерение `ack` из T2.23, которое меняет `claimedAt` и не переводит Watch в терминальный вердикт.

6. Предохранители дешёвого watcher'а. Watcher будит сессию только по реальному изменению, после минимальной длительности наблюдения, с дедупликацией событий, cooldown, дневным лимитом пробуждений и тихими часами. Проверки условия не тратят вызовы модели. Это limiter и фильтр шума, а не разброс `wake_between` из T3.80 и не доставка follow-up из ADR 0026.

## Причина

1. wakeshift/wakeshift-go это SDK, где инструмент MCP подписывает вызвавшую его беседу на событие приложения и будит этого же агента, когда событие наступило ([AH, строка 9](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L9), [wakeshift-go](https://github.com/wakeshift/wakeshift-go)). Инструмент Mint-ит идентификатор задачи, подписывается один раз через `Once()`, а `Emit` будит всех подписчиков с этим ключом ([AH, строка 10](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L10)). Встроенный `Watch` работает с backoff и общим ID на повторах ([AH, строка 118](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L118)). ADR 0028 фиксирует идемпотентность и квитанции для команд, но не подписку на событие с ключом аргументов. Берутся подписка, `Once()` и `Watch`, а не облачный сервис Wakeshift с ключом `WAKESHIFT_KEY`, привязка к go-sdk v1.8 или mcp-go v1.0 и генерация из главного репозитория компании ([AH, строка 11](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L11)).

2. blwfish/mcp-jobs это реестр долгих асинхронных операций для MCP, где вызов возвращает `job_id`, а результат читается ровно один раз через `poll` ([AH, строка 15](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L15), [mcp-jobs](https://github.com/blwfish/mcp-jobs)). Завершённая или упавшая задача удаляется из учёта в момент первого `poll`, а в ответе всегда есть `elapsed_s` и `error_id` ([AH, строка 16](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L16), [AH, строка 119](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L119)). T3.103 задаёт порог синхронного вызова 30/120 секунд, но не описывает, как именно CLI выдаёт финальный результат длинной задачи. Берётся контракт результата, а не Python, планировщик Sequencing внутри одного процесса и кооперативная отмена без прерывания уже идущего кода ([AH, строка 17](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L17)).

3. Benja272/tollgate это учёт стоимости и pre-PR гейд для внешних кодинг-агентов: несколько независимых судей оценивают diff по версионированному рубрикатору до появления PR ([AH, строка 40](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L40), [tollgate](https://github.com/Benja272/tollgate)). CI-результат не сохраняется в PR, пока N судей не поставили оценку, а при провале отдаётся полный отчёт ([AH, строка 41](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L41), [AH, строка 123](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L123)). T3.88 даёт completion gate с proof поверх уже существующего артефакта, но не вердикт до публикации PR. Берётся вердикт до артефакта и запись цены собственным атрибутом, а не проект в фазе design без работающего продукта, заточенный под Claude Code headless с OpenTelemetry, Prometheus и Grafana через docker compose ([AH, строка 42](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L42)).

4. whiteheap/residue-cli убирает git worktree только тогда, когда ничего в нём не потеряно, по 15 проверкам в четырёх семействах ([AH, строка 46](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L46), [residue-cli](https://github.com/whiteheap/residue-cli)). Кандидат проходит повторную проверку, переносится в скрытое имя, получает запись об удалении, проверяется ещё раз, и только потом выполняется `git worktree remove` без `--force`. Любой провал или изменение возвращает worktree на место ([AH, строка 47](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L47), [AH, строка 124](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L124)). T3.104 описывает цепочку блокировок `beacon why`, но не безопасное удаление арендованного worktree. Берётся модель verdict до удаления, а не Rust, launchd/systemd и macOS-приложение с установочным скриптом ([AH, строка 48](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L48)).

5. DeepCogNeural/taskdone-runner это фоновые задачи с уведомлением о завершении, журналами и списком непрочитанных, без вызовов модели и hosted backend ([AH, строка 64](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L64), [taskdone-runner](https://github.com/DeepCogNeural/taskdone-runner)). `taskdone start` возвращает 32-символьный id, `list --unread` показывает новые, `logs` читает хвост, `ack` помечает просмотренным. В записи есть `needs_review` и `reviewed_at`, то есть exit code 0 не считается качеством ([AH, строка 65](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L65), [AH, строка 127](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L127)). T2.23 фиксирует `ack` как записанное намерение, а не готовый результат: `ack` пишет `claimedAt` и не меняет вердикт. Поэтому берётся разделение «процесс завершился» и «результат проверен», а не повторение ack. Не берутся ранний alpha, macOS как основная цель, отдельный спящий supervisor на задачу и отсутствие очереди с лимитом параллелизма ([AH, строка 66](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L66)).

6. hyprh/self-starter это локальный event layer для уже существующего кодинг-агента: агент один раз пишет probe, background service крутит его без вызовов модели и будит сессию только по реальному изменению ([AH, строка 106](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L106), [self-starter](https://github.com/hyprh/self-starter)). Движок сам проверяет real change, минимальную длительность, дедупликацию, cooldown, дневной лимит на пробуждения и тихие часы ([AH, строка 107](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L107), [AH, строка 134](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L134)). T3.80 задаёт `wake_between` против thundering herd, то есть разброс во времени, но не limiter частоты. ADR 0017 задаёт ступени пробуждения, но не дешёвого внешнего watcher'а. Берётся готовый набор предохранителей, а не Node 20+, patch-интеграции в пять харнессов, launchd/systemd, веб-консоль и десяток каналов уведомлений ([AH, строка 108](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L108)).

- Проверка карточек: подписка снимается после первого события, а повтор `Watch` сохраняет тот же ID; `poll` выдаёт финальный результат один раз и несёт `elapsed_s` и `error_id`; N судей выносят вердикт до PR, а провал даёт полный отчёт без публикации; `git worktree remove` вызывается только после второй проверки и без `--force`, а изменение откатывает удаление; `needs_review` снимается только после записи `reviewed_at`, а exit code 0 сам по себе его не снимает; watcher не будит сессию по шуму, по короткому наблюдению, повторно в cooldown, сверх дневного лимита и в тихие часы.
- ADR 0001-0049 с T2.23, T3.51, T3.67, T3.80, T3.88, T3.97, T3.103 и T3.104 не переписываются. Подписка из фичи 1 не меняет идемпотентность ADR 0028, квитанции ADR 0014 и доставку ADR 0026. Контракт из фичи 2 не меняет порог T3.103. Вердикт из фичи 3 не заменяет completion gate T3.88 и формулу `ship` из T3.67. Удаление из фичи 4 не отменяет модель владельцев аренды ADR 0049 и изоляцию worktree ADR 0021. Поля из фичи 5 не меняют `ack` из T2.23. Предохранители из фичи 6 не меняют лестницу ADR 0017 и `wake_between` из T3.80. Курсор ADR 0025 и проверка только в CI из ADR 0022 дополнительной не становятся.

## Отклонённое

Брать проекты целиком. Причины из отчёта сводятся к языку и размеру, внешней инфраструктуре, привязке к чужому харнессу и узкой задаче ([AH, строки 11-17, 23, 29-30, 36, 42, 48, 54, 60, 66, 72, 78, 84, 90, 96, 102, 108, 114](/home/nbook/Projects/tmp/beacon-research/AH-wave.md#L11)). Beacon требует Go, размер менее 100 MB и глобальную установку в `~/.config/opencode`. Ни один из восемнадцати проектов не годится как целый продукт.

Включать в этот ADR остальные идеи из раздела «Фичи» AH. Менеджером в волну отобраны шесть пунктов выше. Двенадцать кандидатов не вошли: повторный вход агента с результатом задачи как новым сообщением (AH:120, https://github.com/agent-of-mkmeral/strands-cli-agent), журнал задачи внутри процесса (AH:121, https://github.com/KartikBazzad/quacker), блокировка строки с токеном попытки и сроком аренды (AH:122, https://github.com/nabiatakhanov/durableq), демон владеет сессиями, а не терминал (AH:125, https://github.com/d0ugal/graith), восстановление контекста по идентификатору сообщения (AH:126, https://github.com/brewbytes-dev/hermes-agent-task), авто-vault на 25-й день (AH:128, https://github.com/ganesh-reddy-b/agent-session-manager), стабильная identity сессии при рестарте (AH:129, https://github.com/osteele/agent-launcher), ledger с состояниями reserve, commit, abort, TTL и uncertain (AH:130, https://github.com/joelvarun/effectkey), тест-сьют с нагрузкой про цену retry без ключа (AH:131, https://github.com/jigonyoo/agent-reliability-kit), три состояния доставки с `delivery_uncertain` (AH:132, https://github.com/agentmiddleware/agent-middleware), долговечный курсор с epoch и gap-кадром (AH:133, https://github.com/saphid/bugler), вердикты `gh-run` и `pr-checks` с FIFO-слотами (AH:135, https://github.com/kitlangton/skulk). Часть из них пересекается с уже принятыми решениями: идемпотентность ADR 0028, доставка ADR 0026, курсор ADR 0025, аренда T3.97, вердикт T3.88 и пороги гейтов. Остальные менеджером в эту волну не отобраны.

Повторять уже принятые решения под новыми именами. Идемпотентность и квитанции зафиксированы в ADR 0028, аренда и fencing в T3.51 и T3.97, вердикт в T3.67 и T3.88, курсор в ADR 0025, лестница пробуждения в ADR 0017, `wake_between` в T3.80, ack в T2.23, порог вызова в T3.103. Фичи этого ADR работают на других уровнях: подписка вместо команды, контракт результата вместо порога, вердикт до артефакта, уборка worktree, просмотр результата и limiter шума.
