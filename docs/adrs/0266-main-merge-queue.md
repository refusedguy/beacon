# ADR 266: Очередь мержа поверх свежего main (merge queue)

Статус: proposed

## Контекст

Сейчас Beacon мержит по снимку CI, который был снят до решения о мерже. Конфликт превращается в verdict rebase уже после попытки. Mergify и GitHub merge queue проверяют PR поверх свежего main до мержа. Источник: docs.mergify.com/merge-queue/ и docs.github.com merge queue.

## Решение

Перед мержем перечитывать baseRef. При расхождении с head main возвращать задачу на повторную проверку, а не ребаз после неудачи. Принимать merge_group как отдельный источник статуса. Workflow обязан слушать событие merge_group, иначе проверка не будет сообщена.

## Последствия

Появится дополнительный прогон проверок на временной ветке. Вердикт ready будет означать свежую проверку, а не старый снимок. Нужна настройка only merge non-failing pull requests, иначе красный PR пройдёт в зелёной группе.
