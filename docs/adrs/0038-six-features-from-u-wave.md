# ADR 0038. Шесть фич из отчёта U-wave

Статус: accepted

Этот ADR фиксирует шесть фич из отчёта U «U-волна: 15 новых проектов для Beacon» от 20 ноября 2026 года. Идеи собраны в разделе «Фичи» ([U, строка 188](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L188)) и подтверждены README конкретных проектов. Здесь зафиксированы только те фичи, которых нет в ADR 0001-0037 и 102 карточках из `docs/tasks/`. Fencing token уже в T3.51, capability matching в T3.47, failure contract вызова hook в T3.50, warning о совместном gate в T3.49, пороги лимитов плана в T3.52. Они сюда не входят. Владелец велел принять оставшиеся идеи без дополнительных вопросов, поэтому статус `accepted`. По ADR 0020 карточки создаются только из принятого ADR. Карточки этим ADR не создаются, код, карточки и тесты в этой задаче не трогаются.

## Решение

Beacon получает шесть механизмов. Они описаны на уровне контракта и не привязаны к конкретному продукту.

1. Инвалидация lease после краша. Аренда задачи привязана к живому владельцу и thread его сессии. После краша и восстановления задачи ядро объявляет старый lease недействительным. Даже если старый воркер вернётся с тем же идентификатором и непросроченным fencing token, он не продолжает задачу, пока не возьмёт новый lease. Это отдельный признак «источник восстановлен», а не номер аренды из T3.51.
2. Backpressure по внешней квоте GitHub API. Ядро учитывает бюджет внешнего API. При исчерпании квоты новые запуски откладываются с причиной `quota_exhausted`, а не уходят в слепой ретрай. Отложенный запуск возобновляется, когда лимит восстановился. Лестница пробуждения из ADR 0017 не меняется: backpressure управляет запуском задачи, а не исходом доставки.
3. Ранжирование воркеров по истории. Ядро ведёт локальную для репозитория историю прохождения, задержки и стоимости по воркерам. Сначала capability matching из T3.47 сужает множество кандидатов, затем ранжирование упорядочивает его по реальной истории, а не по жёсткому списку имён. Имя сессии остаётся ключом доставки по ADR 0034, но перестаёт быть критерием выбора.
4. Гейт независимого ревью. Перед завершением задачи ядро запускает ревьюера, который не писал код этой задачи, и принимает вердикт `SHIP`, `FIX-FIRST` или `BLOCKED`. `FIX-FIRST` возвращает задачу исполнителю, `BLOCKED` останавливает её с причиной. Вердикт фиксируется в журнале. GitHub и PR не становятся обязательным выходом.
5. Кворум из завершённых ревью. Решение считается принятым, когда набрано нужное число одобрений от ревью, дошедших до конца и выдавших вердикт. Маркеры от прерванных, незавершённых или завершившихся ошибкой ревью не считаются. Если максимально возможное число одобрений меньше порога, кворум отклоняется как недостижимый сразу, а не висит в ожидании. Вердикт `SHIP` из пункта 4 служит одним источником маркера одобрения.
6. Доставка в идущий turn с fallback. Адаптер сначала пытается доставить сообщение в уже идущий turn. Если агент не подтвердил приём, сообщение уходит следующим turn'ом. Если подтвердить не удалось и там, сообщение попадает в трей таска для повторной отправки. Поле `delivery` из ADR 0026 остаётся обязательным и честным: `steer`, `queue` или `unsupported`. Fallback не превращает `unsupported` в успех, а трей таска не имитирует доставку в текущий ход. Лестница из ADR 0017 сохраняется.

## Причина

1. digitaldrywood/detent инвалидирует аренду восстановленного источника: после краша старый lease признаётся недействительным и не может продолжить ([U, строка 44](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L44), [README.md, строка 58](https://github.com/digitaldrywood/detent/blob/develop/README.md)). В Beacon старый вызов после рестарта демона может вернуться живым. T3.51 защищает только от устаревшего номера аренды, поэтому нужен отдельный факт краша. Код detent не берётся: это процессный оркестратор с доской и лицензией FSL ([U, строка 46](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L46)).
2. aliengiraffe/vigilante ведёт учёт бюджета GitHub API и откладывает новые запуски при исчерпании квоты вместо слепого ретрая ([U, строка 79](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L79), [README, Guardrails That Matter](https://github.com/aliengiraffe/vigilante/blob/main/README.md)). При 15 параллельных агентах слепой ретрай на общей квоте создаёт шторм запросов. Отличие от T3.52: там жёлтый и красный пороги предупреждают о приближении к лимиту, здесь планировщик решает, запускать задачу или отложить. GitHub не становится обязательной зависимостью ядра.
3. fubak/ultraswarm ранжирует здоровых воркеров по репозиторий-локальной истории прохождения, задержки и стоимости вместо жёсткого списка имён ([U, строка 92](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L92), [README](https://github.com/fubak/ultraswarm/blob/main/README.md)). В отчёте есть таблица `est.` против `used`, но автор помечает её калибровочной эвристикой, а не замером ([U, строка 216](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L216)). Берём идею локальной истории, а не числа и не Node.js-код.
4. automagik-si/genie ставит гейт независимого ревью: агент, не писавший код, возвращает `SHIP`, `FIX-FIRST` или `BLOCKED` ([U, строка 127](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L127), [README, How it works](https://github.com/automagik-si/genie/blob/main/README.md)). При 15 агентах ревьюер не должен проверять собственный патч. Отличие от T3.49: там одна общая дорогая команда и фантомные таймауты, здесь роль ревьюера и три вердикта. PR как конечная точка из genie не переносится ([U, строка 129](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L129)).
5. nwiizo/ccswarm считает кворум только из маркеров одобрения завершённых ревью и отклоняет недостижимый кворум ([U, строка 138](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L138), [README](https://github.com/nwiizo/ccswarm/blob/master/README.md)). Без проверки завершённости прерванное ревью даёт ложный маркер. Без проверки достижимости задача висит, когда одобрений физически не набрать. Движок Herdr и полевые CLI не берутся ([U, строка 141](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L141)).
6. alamops/agetor доставляет сообщение в идущий turn, уводит его в следующий turn без подтверждения и кладёт в трей таска, если подтвердить не удалось ([U, строка 149](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L149), [README](https://github.com/alamops/agetor/blob/main/README.md)). ADR 0026 требует честного поля `delivery`, поэтому fallback дополняет адаптер, а не подменяет честность. Порог около 10 секунд в agetor это уставка его Stop, а не измерение ([U, строка 218](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L218)). Десктоп на Bun и tmux не переносятся ([U, строка 151](/home/nbook/Projects/tmp/beacon-research/U-wave.md#L151)).

## Последствия

- Из каждого пункта выходит одна небольшая карточка в `docs/tasks/` по правилам ADR 0020. Карточки этим ADR не создаются и будут созданы отдельными задачами.
  - Фича 1: `internal/domain/types.go`, `internal/infra/taskstore/store.go`, `internal/infra/mcp/tool_claim.go`, `internal/infra/mcp/tool_ack.go` и тесты к ним.
  - Фича 2: `internal/infra/github/errors.go`, `internal/infra/github/rest.go`, `internal/app/taskcli/service.go`, `internal/infra/store/observability.go` и тесты к ним.
  - Фича 3: `internal/domain/types.go`, `internal/infra/taskstore/store.go`, `internal/app/taskcli/service.go`, `cmd/beacon/agents.go` и тесты к ним.
  - Фича 4: `internal/domain/verdict.go`, `internal/domain/transition.go`, `internal/app/taskcli/service.go`, `internal/infra/mcp/server.go` и тесты к ним.
  - Фича 5: `internal/domain/verdict.go`, `internal/domain/transition.go`, `internal/infra/store/db.go`, `internal/app/taskcli/service.go` и тесты к ним.
  - Фича 6: `internal/infra/mcp/tool_wake.go`, `internal/infra/ladder/transitions.go`, `internal/infra/store/receipts.go`, `internal/infra/store/db.go` и тесты к ним.
- Проверка карточек: после краша старый lease не продолжает задачу даже с валидным fencing token; при исчерпанной квоте новый запуск отложен с причиной `quota_exhausted` и не уходит в ретрай, а после восстановления квоты возобновлён; получатель выбирается по возможностям, а внутри множества по истории, и переименование сессии не меняет выбор; ревьюер, писавший код, не проходит гейт, а вердикты FIX-FIRST и BLOCKED меняют состояние задачи; маркер от прерванного ревью не считается, а недостижимый кворум отклоняется; не подтверждённое сообщение уходит следующим turn'ом, а при неудаче попадает в трей таска с честным `delivery`.
- Т3.51, T3.47, T3.50, T3.49 и T3.52 не переписываются. Fencing token из фичи 1 это номер аренды, инвалидация из фичи 1 это факт краша. Ранжирование из фичи 3 работает после capability matching, а не вместо него. Гейт из фичи 4 и кворум из фичи 5 это разные уровни: один даёт вердикт, другой считает одобрения. Число MCP-инструментов остаётся равным семи, ADR 0003 и 0009 не меняются. Лестница из ADR 0017 и честная доставка из ADR 0026 сохраняются, только добавляется fallback. Байтово стабильный ответ из ADR 0036 пункт 2 не переставляется. Один мост на протокол из ADR 0024, изоляция worktree из ADR 0021 и проверка только в CI из ADR 0022 дополнительной не становятся.

## Отклонённое

Считать фичу 1 тем же fencing token из T3.51. Там номер переназначенной аренды, здесь факт гибели источника и отказ продолжить даже при валидном токене.

Слепо ретраить исчерпанную квоту или перенести polling GitHub из vigilante как архитектуру ядра. Beacon-event-driven сервер без привязки к GitHub.

Держать жёсткий список имён воркеров и брать таблицу `est.` против `used` из ultraswarm как замер скорости. Это калибровочная эвристика автора.

Пустить автора кода в ревью его же задачи или требовать PR как обязательный выход. Гейт нужен независимый, а Beacon headless.

Считать одобрение от прерванного ревью или ждать кворум, который уже нельзя набрать. Первое даёт ложное решение, второе вешает задачу.

Скрыть `unsupported` под успешной доставкой или выдать 10 секунд из agetor за измерение Beacon. ADR 0026 запрещает притворяться, а число из README это уставка чужого продукта.
