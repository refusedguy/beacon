# ADR 0270. Десятый инструмент beacon_task_close

Статус: accepted

## Контекст

ADR 0094 зафиксировал контракт из восьми инструментов и потребовал отдельного решения для девятого. ADR 0263 зафиксировал семь имён, потребовал отдельного ADR для восьмого и запретил тихую регистрацию обработчика вне контракта. ADR 0268 добавил девятое имя `beacon_task_claim`, поднял бюджет с 16 KiB до 20 KiB и записал замер 17922 байт.

Сейчас в `main` девять инструментов. Золотой контракт в `internal/infra/mcp/contract_test.go` хранит 18212 байт и SHA `ba0a9f42`. Eval `02_catalog` уже красный, потому что `evals/main.go` перечисляет восемь имён без `beacon_task_claim`.

Брейнштормы `docs/research/mcp-close-tool-brainstorm.md` и `docs/research/task-lifecycle-brainstorm.md` разобрали альтернативы. Они рекомендовали CLI-пути, чтобы сохранить золотой побайтово. Владелец выбрал десятый MCP-инструмент, поэтому этот ADR фиксирует решение и его цену. Десятое имя ломает список имён, размер и хэш одновременно. ADR 0268 требует на это отдельный ADR.

## Решение

Контракт MCP вырастает ровно до десяти имён. Десятое имя это `beacon_task_close`. Девять прежних инструментов сохраняют имена, сигнатуры и аннотации.

Вход инструмента содержит четыре поля. `cardID` задаёт конкретную карточку, инструмент не выбирает её сам. `status` принимает одно из четырёх значений: `done`, `dropped`, `blocked`, `duplicate`. `reason` обязателен и не должен быть пустым после обрезки пробелов. `duplicateOf` обязателен при `status=duplicate` и должен называть существующую карточку. Вызывающий агент берётся из идентификатора сессии в `_meta["ai.opencode/sessionID"]`, поэтому отдельного поля `agentID` нет.

Ключ идемпотентности это `(cardID, status, reason)`. Повтор с тем же ключом возвращает `ok=true` без записи. Повтор с другой причиной или другим статусом на карточке в терминальном статусе возвращает ошибку. Попытка закрыть чужую карточку в `in_progress` возвращает `CodeInvalidInput`. Этот ADR не вводит новый код ошибки, поэтому ADR 0009 не меняется.

Markdown-карточка в `docs/tasks` остаётся источником истины. Обработчик пишет строку статуса и причину закрытия под тем же flock и атомарным переименованием, которые использует `beacon_task_claim`. После записи композиционный корень пересобирает индекс командой `beacon index build`. SQLite остаётся производным индексом, который CI сверяет с деревом карточек.

Класс аннотации это `kindAdditive`: `DestructiveHint: false`, `IdempotentHint: true`. Закрытие пишет состояние карточки, поэтому инструмент не read-only. Ключ идемпотентности делает повторы безопасными, поэтому флаг идемпотентности честный.

Инструмент доступен через MCP, а не только через CLI `beacon task`, потому что исполнителю нужен один атомарный вызов с устойчивым ключом и машиночитаемым результатом в том же цикле, где он вызвал `beacon_task_claim`. CLI остаётся оркестратору для массовой чистки карточек.

### Снятые противоречия и устаревшие счётчики

ADR 0094 говорил «ровно восемь» и требовал отдельного ADR на девятый инструмент. Восьмой пришёл из самого ADR 0094, девятый из ADR 0268, десятый из этого ADR. Строка приёмки про девятый инструмент в ADR 0094 выполнена и больше не ограничивает контракт.

ADR 0263 говорил «ровно семь», требовал отдельного ADR на восьмой и запрещал тихую регистрацию вне контракта. Первые два утверждения заменены решениями ADR 0094, ADR 0268 и этого ADR. Запрет на тихую регистрацию остаётся в силе. Этот ADR даёт явное разрешение, которого требовал запрет. Десятое имя обязано появиться в `tools/list` и в контрактном тесте. Обработчик, зарегистрированный только через `AttachXxx` без дескриптора, по-прежнему запрещён.

ADR 0268 говорил о девяти именах и установил бюджет 20 KiB по замеру 17922 байт. Этот ADR поднимает счётчик до десяти. Константа бюджета в этом PR остаётся 20 KiB. CI измеряет ответ с десятью инструментами. Если результат превысит 20480 байт, следующий PR поднимет бюджет и запишет замер. Этот ADR не угадывает число.

### Золотой контракт и порядок имён

Имена инструментов, их порядок и классы аннотаций выводятся из `toolDescriptors`. Добавление десятого дескриптора само обновляет эти три проверки без правки теста. Отсортированный порядок десяти имён такой: `beacon_ack`, `beacon_cancel_watch`, `beacon_defer_wiring`, `beacon_get_result`, `beacon_list_running`, `beacon_stats`, `beacon_task_claim`, `beacon_task_close`, `beacon_wait_result`, `beacon_watch_pr`. Имя `beacon_task_close` стоит между `beacon_task_claim` и `beacon_wait_result`.

Число 18212 и хэш `ba0a9f42031cab8ff4733f89a8f6b3d1424be695367cbb6f305a3a0b60865f99` остаются в `contract_test.go` как заглушки с пометкой TODO. CI пересчитает оба значения в PR, где появится обработчик. Этот ADR не выдумывает ни число, ни хэш.

### Evals

`evals/main.go` добавляет `beacon_task_claim` и `beacon_task_close` в `contractTools`. Замороженный хэш пересчитан из списка имён, а не угадан. Eval `02_catalog` после этого совпадает с сервером о десяти инструментах. Кейсы `e05`, `w21` и `r03` не считают инструменты и остаются без изменения. Документы `e02-seven-tool-contract`, `r10-seven-tools` и `e04-executor-state-visible-through-seven-tools` переносят ожидаемое число на десять, а негативный контроль на одиннадцатый инструмент.

## Последствия

- Пока CI не запишет новое число байт и хэш, тест стабильности красный по замыслу. Это зафиксированный baseline, а не регрессия.
- Закрытие в `blocked` и `duplicate` требует, чтобы парсер карточек принимал эти статусы. Списки полей в `taskcli` и doc gate должны вырасти в том же PR, где появится обработчик. Первая версия включает все четыре статуса, поэтому эти списки меняются вместе.
- Разблокировка зависимостей работает только для `done`, потому что `FileDependencyResolver` считает зависимость выполненной лишь при статусе `done`.
- Десятый инструмент увеличивает поверхность MCP для каждого клиента. Явный ADR и производный контрактный тест не дают добавить одиннадцатый инструмент тихо.

## Проверка

`TestToolsListContract` принимает ровно десять имён, у каждого есть схема вывода и честная аннотация. `TestToolsListStabilityAcrossConnections` сверяет число байт и хэш, которые измерит CI. Замороженный хэш `contractTools` в evals совпадает со списком из десяти имён. gofmt применяется к изменённым Go-файлам. Остальные проверки идут в GitHub Actions на PR.
