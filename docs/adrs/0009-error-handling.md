# ADR 0009. Обработка ошибок

Статус: accepted

## Решение

Внутри кода используем `(value, error)` и общий тип `AppError` с кодом и статусом. Целевая форма ошибки инструмента MCP задана ниже в поле «Формат ответа MCP». На живом пути действует исключение, зафиксированное в разделе «Исключение: живой путь MCP».

Тип `Result[T]` не добавляется.

## Причина

Владелец согласился. `Result[T]` не приживается в Go и усложняет чтение кода.

## Исключение: живой путь MCP

Замер в ARDH-17 от 21 ноября 2026 года. В продакшен-коде нет ни одного вызова `ToErrorShape` на живом пути. Единственный вызов вне тестов находится внутри `ToRepairableErrorShape`, у которого тоже нет продакшен-вызовов. Тесты вызывают оба конвертера 13 раз. Хендлеры MCP возвращают сырую ошибку в 77 местах. Источник: docs/research/error-handling-audit.md, находка 4.

Хендлер возвращает `error` напрямую. Официальный go-sdk в `AddTool` ловит эту ошибку и вызывает `CallToolResult.SetError`. В ответе клиент видит `isError: true` и текст `err.Error()` в `content`. Коды и статусы `AppError` в живой ответ инструмента не попадают.

Это зафиксированное исключение, а не расхождение между документом и кодом. Формат ответов не меняется: агенты по-прежнему получают текстовую ошибку с `isError`. Типы `ErrorShape` и `ToErrorShape` в `internal/infra/mcp/schema.go`, а также `RepairableErrorShape` и `ToRepairableErrorShape` в `internal/infra/mcp/tool_wake.go` остаются в коде как описание целевой формы и покрыты тестами.

Подключение конвертера к живому пути заменит текстовую ошибку структурированной формой и изменит контракт MCP для агентов. Такой шаг требует отдельного решения владельца и в этой задаче не выполняется.

## Последствия

- Коды ошибок из контракта v2 сохраняются: `INVALID_INPUT`, `WATCH_NOT_FOUND`, `HEAD_SHA_CHANGED`, `RATE_LIMITED`, `LIMIT_EXCEEDED`, `CANCELLED`, `GONE`, `PERSIST_FAILED`.
- Статусы 400, 404, 409, 429, 410, 503 соответствуют кодам.
- Тип `ErrorShape` задаёт целевую форму с полями `ok`, `code`, `message`, `status`, `retryAfterMs`, `newWatchID`. Живой ответ инструмента при ошибке это текст с `isError`, как описано в исключении выше.
