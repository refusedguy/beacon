# ADR 182: Webhook как подсказка, GraphQL-батч как чтение состояния

Статус: accepted

## Контекст

GitHub отдаёт check_run, check_suite и pull_request webhooks с HMAC-SHA256 и уникальным X-GitHub-Delivery, но доставка может потеряться, а sender для check_run бывает ghost. Публичного SSE для check runs нет. Один GraphQL-батч на 15 PR стоит 1 поинт по проектному измерению. Kilo пишет намерение до таймера, openrig считает SSE подсказкой, t3code фиксирует receipt в одной транзакции.

## Решение

Принимать webhook на loopback, проверять подпись, дедуплицировать по delivery id и по revision Watch. Webhook только помечает obligation готовой и вызывает перечитывание. cibridge читает все активные Watch одним алиасированным GraphQL-запросом. Низкочастотный polling остаётся страховкой, локальный SSE раздаёт состояние с курсором по revision.

## Последствия

В покое расход около нуля поинтов, задержка вердикта 1-3 секунды по webhook и не более 60 секунд при fallback. Потеря доставки не теряет вердикт, устаревшая ревизия игнорируется. Никаких новых процессов и второго токена.
