# ADR 155: MCP не обещает пробуждения модели

Статус: accepted

## Контекст

notifications/message это уведомление логирования, клиент MAY показать его в интерфейсе. Расширение Tasks даёт долгоживущий handle и notifications/tasks через opt-in subscriptions/listen. Поддержка хостами различается.

## Решение

Спецификация MCP не требует ни передачи сообщения модели, ни подтверждения прочтения. Tasks это модель отложенного вызова, а не пробуждение агента. Пробуждение делает адаптер через родной API среды.

## Последствия

Спайк S1 через experimental.mcp.event не заработал: stream не открывался из-за 503 high demand и 400 Model is unavailable, событие не пришло ни разу. S2 на polling файла заработал без модели. Уведомления MCP можно использовать как подсказку, но не как доказательство доставки.
