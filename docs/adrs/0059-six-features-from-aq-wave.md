# ADR 0059. Шесть фич из отчёта AQ-wave

Статус: accepted

Этот ADR фиксирует шесть фич из отчёта AQ «AQ-волна: новые проекты для Beacon/CLI» ([AQ, строка 1](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L1)). Отчёт собран 20 ноября 2026 года. Поиск шёл через `gh api search/repositories`, 32 запроса по восьми темам брифа с сортировкой `updated` и фильтром `pushed:>2026-01-01`; после вычитания репозиториев из предыдущих отчётов осталось 563 кандидата, в отчёт вошли 20 проектов, и ни один из них не встречался в A-AP ([AQ, строки 3-11](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L3)). Даты коммитов взяты из commits API, а не из `pushed_at` ([AQ, строка 10](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L10)). Фичи взяты из раздела «Фичи»: пункты 213, 215, 222, 223, 225 и 232 ([AQ, строки 207-235](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L207)). Здесь зафиксированы только те фичи, которых нет в ADR 0001-0058 и 183 карточках из `docs/tasks/`. Hard lease, wake, verdict и replay уже приняты и здесь как новые не повторяются: ADR 0017 задаёт лестницу пробуждения, ADR 0021 изолирует агентов через worktree, ADR 0025 хранит курсор и статус в ответе MCP, ADR 0028 фиксирует идемпотентность и прерывание ожидания, T3.87 адресует wake к worktree, T3.97 даёт аренду worktree с TTL и fencing, T3.98 задаёт внешний вердикт с доказательствами. Похожие по имени пункты различаются по контракту. Фича 1 это блокирующее ожидание долгой задачи с task handle, а не прерывание `wait_result` из ADR 0028. Фича 2 это условие пробуждения, а не адресация wake из T3.87 и не ступени лестницы ADR 0017. Фича 3 это статус планировщика, который освобождает слот, а не содержание вердикта T3.98. Фича 4 это продолжение задачи на том же worktree, а не создание нового worktree из ADR 0021. Фича 5 это порядок очереди и управление ею, а не replay. Фича 6 это критерий закрытия задачи, а не квитанция ADR 0014.

## Решение

Beacon получает шесть механизмов. Они описаны на уровне контракта и не привязаны к конкретному продукту.

1. `agent_acp_wait` вместо polling. Инструмент ожидания блокируется до завершения долгой MCP-задачи или до запроса подтверждения и возвращает task handle. Beacon перестаёт повторять опрос состояния задачи циклом. ADR 0028 прерывает ожидание, когда агенту нужен человек, здесь ожидание не прерывается по флагу, а держит соединение до события в самой задаче.

2. Guarded heartbeat. Агент просыпается только если состояние изменилось ИЛИ открыт гейт `quota should-run`. Таймер сам по себе не служит триггером пробуждения. ADR 0017 ветвит повтор и эскалацию по истёкшим таймерам, здесь условие состояния или гейта решает, будет ли пробуждение вообще. T3.87 адресует wake к worktree, здесь проверяется предпосылка, до того как wake отправлен.

3. «Зелёный, но заблокирован» PR как отдельный вердикт. Pull request готов и зелёный, но пока открыта блокирующая задача, прогон приостановлен и не занимает слот выполнения. T3.98 хранит внешний вердикт с доказательствами, здесь новое свойство это статус задачи, который освобождает слот, а не текст вердикта.

4. `/fix-checks` как отдельная задача на том же worktree. Агент получает задачу «починить красные проверки» в уже существующем worktree, без пересоздания worktree и без перезапуска агента. ADR 0021 задаёт изоляцию агентов через worktree, здесь работа продолжается в том же рабочем пространстве после неудачной проверки.

5. FIFO с паузой, resume, cancel и crash-safe возобновлением из одного файла состояния. Очередь хранит порядок задач и команды управления в одном файле и продолжает с него после рестарта процесса. Replay из уже принятых решений восстанавливает выполнение шага, здесь восстанавливается сама очередь и её позиция. Аренда T3.97 защищает worktree, а не порядок задач в очереди.

6. Verified completion. Задача закрывается явной командой приёмки, а не фактом выхода процесса агента и не выставлением `done`-флага. ADR 0014 фиксирует квитанции адаптера, ADR 0028 идемпотентность, здесь новое свойство это критерий закрытия: команда приёмки должна выполниться успешно.

## Причина

1. creverse-ai-lab/agent_gateway это локальный MCP-сервер и ACP-шлюз с инструментом `agent_acp_wait`, который ждёт завершения задачи или запроса подтверждения вместо polling через `agent_acp_poll` ([AQ, строка 213](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L213), [commit v1.9.0](https://github.com/creverse-ai-lab/agent_gateway/commit/9669951), [README](https://github.com/creverse-ai-lab/agent_gateway#readme), пункт 100 в [AQ, строке 35](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L35)). Проект на JavaScript, 4 звезды, Apache-2.0, создан 30 июля 2026 года, последний коммит 10 октября 2026 года `9669951` с сообщением `release: v1.9.0 — agent_acp_wait instead of polling, working MCP Tasks` ([AQ, строки 29-33](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L29)). Отсюда берётся блокирующее ожидание с task handle вместо цикла опроса SQLite ([AQ, строка 35](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L35)). Берётся контракт ожидания, а не шлюз: проект завязан на ACP, запуск внешних агентов Claude Code, Codex и Grok, sandbox и approval-слой с токенами ([AQ, строка 36](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L36), [Что не брать, AQ, строка 276](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L276)).

2. LoopX Guarded Heartbeat просыпается только при изменении состояния или открытом гейте `quota should-run` ([AQ, строка 215](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L215), [README](https://github.com/loopx-project/loopx#readme), строка 305). Проект на Python, 6725 звёзд, Apache-2.0, создан 31 мая 2026 года, последний коммит 19 ноября 2026 года `8e9a28a` ([AQ, строки 19-23](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L19)). Отсюда берётся правило пробуждения по изменению состояния или по гейту квоты, а не по истечении таймера ([AQ, строка 215](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L215)). ADR 0017 поднимает агента по исходу доставки и эскалации, здесь пробуждение обусловлено состоянием и квотой. Берётся правило, а не фреймворк: LoopX несёт свой kernel, runtime-bridge и slash-команды для Codex и Claude, и встраивание целиком заменило бы планировщик Beacon ([AQ, строка 26](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L26), [Что не брать, AQ, строка 277](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L277)).

3. glorp держит отдельное состояние «PR готов и зелёный, но заблокирован другой задачей, поэтому не занимает слот» ([AQ, строка 222](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L222), [README](https://github.com/lsegal/glorp#readme), строка 226). Проект на Go, 6 звёзд, без лицензии, создан 15 июля 2026 года, последний коммит 19 ноября 2026 года `c5a21ae` ([AQ, строки 140-144](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L140)). Отсюда берётся отдельный вердикт, при котором зелёный PR ожидает блокировщика и освобождает слот выполнения ([AQ, строка 146](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L146)). T3.98 фиксирует вердикт с доказательствами, здесь критично поведение планировщика: задача в этом статусе не потребляет слот. Берётся модель статуса, а не продукт: у glorp нет лицензии, есть свой протокол handoff через комментарии, headless Chromium и rpc-сервер дашборда ([AQ, строка 147](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L147), [Что не брать, AQ, строка 271](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L271)).

4. Recur даёт команду `/fix-checks`, которая ставит задачу «починить красные проверки» на том же worktree ([AQ, строка 223](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L223), [README](https://github.com/celestiaorg/recur#readme), строки 62 и 68). Проект на Rust, 7 звёзд, `NOASSERTION` в API, создан 7 октября 2026 года, последний коммит 19 ноября 2026 года `22c2baa` ([AQ, строки 113-117](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L113)). Отсюда берётся продолжение работы в существующем worktree после красной проверки, без перезапуска агента ([AQ, строка 119](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L119)). ADR 0021 задаёт изоляцию через worktree, здесь та же изоляция сохраняется, а меняется только способ поставить следующую задачу. Берётся команда, а не программа: Recur это GUI с редактором, Language Server и оболочкой вокруг `gh`, тогда как Beacon это CLI и MCP-сервер ([AQ, строка 120](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L120), [Что не брать, AQ, строка 278](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L278)).

5. OpenBot держит FIFO-очередь сообщений с паузой, возобновлением, отменой и crash-safe сохранением ([AQ, строка 225](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L225), [README](https://github.com/nightly-labs/openbot#readme), строка 28). Проект на TypeScript, 9223 звезды, `NOASSERTION` в API, в README указана PolyForm Noncommercial 1.0.0, создан 12 августа 2026 года, последний коммит 19 ноября 2026 года `a9c174e` ([AQ, строки 38-42](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L38)). Отсюда берётся контракт очереди: порядок FIFO, три команды управления и один файл состояния, из которого очередь продолжается после рестарта ([AQ, строка 44](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L44)). Берётся контракт, а не десктоп: лицензия PolyForm NC запрещает коммерческое использование, а приложение построено на Electron с браузером и Computer Use ([AQ, строка 45](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L45), [Что не брать, AQ, строка 267](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L267)).

6. Continuity вводит verified completion: каждая задача несёт команду приёмки и считается законченной только после её успешного запуска ([AQ, строка 232](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L232), [README](https://github.com/yourhoneypomelo-cell/Continuity#readme), строки 41 и 44). Проект на Python, 22 звезды, MIT, создан 6 ноября 2026 года, последний коммит 18 ноября 2026 года `9055086` ([AQ, строки 86-90](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L86)). Отсюда берётся критерий закрытия задачи явной командой приёмки вместо выхода процесса ([AQ, строка 92](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L92)). ADR 0014 хранит квитанции адаптера, здесь же задача не закрывается без успешной команды приёмки. Берётся критерий, а не соглашение о файлах: у Continuity нет планировщика и блокировок, а параллельные сессии лишь заявляют задачи по пути файла ([AQ, строка 93](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L93)).

## Последствия

- Из каждого пункта выходит одна небольшая карточка в `docs/tasks/` по правилам ADR 0020. Карточки этим ADR не создаются и будут созданы отдельными задачами. Владельцы файлов для будущих карточек:
  - Фича 1: `internal/infra/mcp/tool_wait_result.go`, `internal/infra/mcp/server.go`, `internal/infra/mcp/schema.go`, `internal/domain/types.go` и тесты к ним.
  - Фича 2: `cmd/beacon/watch.go`, `internal/infra/ladder/transitions.go`, `internal/infra/store/observability.go`, `internal/domain/types.go` и тесты к ним.
  - Фича 3: `internal/domain/transition.go`, `internal/domain/verdict.go`, `internal/app/taskcli/service.go`, `internal/infra/mcp/tool_list_running.go` и тесты к ним.
  - Фича 4: `cmd/beacon/task.go`, `internal/app/taskcli/service.go`, `internal/infra/taskstore/store.go`, `internal/domain/transition.go` и тесты к ним.
  - Фича 5: `internal/infra/taskstore/store.go`, `internal/infra/store/atomic_write.go`, `internal/infra/store/db.go`, `internal/domain/types.go`, `cmd/beacon/task.go` и тесты к ним.
  - Фича 6: `internal/domain/transition.go`, `internal/infra/mcp/tool_ack.go`, `internal/infra/store/receipts.go`, `internal/app/taskcli/service.go` и тесты к ним.
- Проверка карточек: инструмент ожидания возвращается по завершении задачи или по запросу подтверждения; агент просыпается только при изменении состояния или открытом гейте; зелёный PR с блокировщиком не занимает слот; `/fix-checks` продолжает работу в том же worktree; очередь продолжается с одного файла после рестарта; задача закрывается только после успешной команды приёмки.
- ADR 0001-0058 с T3.87, T3.97, T3.98, ADR 0006, 0014, 0015, 0017, 0020, 0021, 0024, 0025, 0026, 0028, 0030, 0042 и 0044 не переписываются. Блокирующее ожидание фичи 1 не меняет прерывание ожидания из ADR 0028. Условие пробуждения фичи 2 не добавляет ступень в лестницу ADR 0017 и не меняет адресацию wake из T3.87. Статус фичи 3 не подменяет вердикт T3.98 и не снимает границу только в CI из ADR 0022. Продолжение фичи 4 не отменяет изоляцию worktree из ADR 0021. Очередь фичи 5 не заменяет аренду worktree T3.97 и не меняет fencing T3.116. Команда приёмки фичи 6 не отменяет квитанции ADR 0014 и идемпотентность ADR 0028. Один мост на протокол из ADR 0024 и идемпотентность из ADR 0028 дополнительной не становятся.

## Отклонённое

Брать все 20 проектов отчёта как целые продукты. Почти всё написано на TypeScript, Python, JavaScript и Rust, а не на Go, на котором написано ядро Beacon ([AQ, строки 17-194](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L17)). Отчёт прямо перечисляет причины в разделе «Что не брать» ([AQ, строки 261-282](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L261)): OpenBot это некоммерческая лицензия и Electron ([AQ, строка 267](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L267)); Invoker это source-available FSL-1.1-ALv2 ([AQ, строка 268](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L268)); Cosmon это AGPL-3.0 в ядре ([AQ, строка 269](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L269)); Workmatic, glorp и Power Queues не имеют лицензии ([AQ, строки 270-272](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L270)); distributed-scheduler требует MySQL и Cassandra ([AQ, строка 274](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L274)); AWS Durable SDK привязан к Lambda ([AQ, строка 275](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L275)); ACP Gateway это чужой ACP-брокер с sandbox и approval-движком ([AQ, строка 276](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L276)); LoopX это свой kernel и runtime-bridge ([AQ, строка 277](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L277)); dsh-douyin-watch это headless Chrome с anti-detection ([AQ, строка 279](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L279)); Nika Action проверяет формат `.nika`, а не конфиг Beacon ([AQ, строка 280](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L280)). Отдельно отмечено, что `NOASSERTION` в GitHub API означает «GitHub не распознал лицензию», а не «свободная лицензия» ([AQ, строка 282](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L282)). Ни один из 20 проектов не годится как замена Beacon целиком.

Включать в этот ADR остальные идеи отчёта. Менеджером отобраны пункты с фичами на строках 213, 215, 222, 223, 225 и 232. Не отобраны 14 проектов: aios с возобновляемыми ночными прогонами (AQ:48, https://github.com/rexleimo/aios); kyb с git-backed памятью (AQ:57, https://github.com/alex09x/kyb); AgentForeman с durable quota waiting (AQ:67, https://github.com/kumizeod/AgentForeman); distributed-scheduler с SKIP LOCKED (AQ:76, https://github.com/JoelTeoGom/distributed-scheduler); Invoker с merge gate отдельной задачей (AQ:95, https://github.com/Neko-Catpital-Labs/Invoker); Workmatic с `leaseMs` и requeue (AQ:104, https://github.com/litepacks/workmatic); Cosmon с контрактом `tackle` и `done` (AQ:122, https://github.com/noogram/cosmon); agent-sessions с поиском сессии по id (AQ:131, https://github.com/ginkcodex/agent-sessions); agent-runner с самопереоткрытием заблокированной задачи (AQ:150, https://github.com/FIZL0/agent-runner); Nika Action с одним комментарием-вердиктом (AQ:160, https://github.com/nika-open/nika-action); agent-kourier с расследованием по алерту (AQ:169, https://github.com/agentkourier/agent-kourier); dsh-douyin-watch с wake по внешнему событию (AQ:178, https://github.com/miqian-nomad/dsh-douyin-watch); AWS Durable SDK с replay и границей step (AQ:187, https://github.com/aws/aws-durable-execution-sdk-js); Power Queues с heartbeat lock (AQ:196, https://github.com/ihor-bielchenko/power-queues). Часть пересекается с уже принятыми решениями, остальные менеджером в эту волну не отобраны.

Повторять уже принятые решения под новыми именами. Hard lease, wake, verdict и replay зафиксированы в ADR 0017, ADR 0021, ADR 0025, ADR 0028, T3.87, T3.97 и T3.98, а также в T3.99, T3.116, T2.22 и T3.23. Дубли A-AP и предыдущих волн отсеяны на уровне поиска: из выдачи убраны репозитории всех предыдущих отчётов, а все 20 отобранных проектов имеют коммит в 2026 году ([AQ, строки 9-11](/home/nbook/Projects/tmp/beacon-research/AQ-wave.md#L9)). Шесть фич этого ADR проходят по контракту: блокирующее ожидание, условие пробуждения, статус освобождения слота, продолжение на том же worktree, очередь в одном файле и команда приёмки.
