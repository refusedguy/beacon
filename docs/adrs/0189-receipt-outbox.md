# ADR 189: Событие, проекция, receipt и outbox в одной транзакции

Статус: accepted

## Контекст

T3 EventSink коммитит события, проекции, принятый receipt команды и outbox-эффекты одной транзакцией SQLite; подписчики получают события после коммита, а EffectWorker делает сайд-эффекты позже. OpenRig имеет stream_items, queue_transitions, inbox_entries и outbox_entries с семью состояниями доставки. OMA хранит run store и leases.

## Решение

Фиксировать receipt, событие, проекцию и запрос эффекта в одной транзакции store. Публикация события идёт после коммита. Повтор по тому же clientRequestId возвращает сохранённый результат безpowторного эффекта.

## Последствия

Ack означает фиксацию намерения, а не завершение работы. Проекция не может обогнать лог. Потерянный ответ не создаёт второй run. Эффекты потерянного процесса списываются до admitted новой работы. Старые события можно резать, но receipts живут дольше history.
