# ADR 197: Один операторский чат как точка управления

Статус: proposed

## Контекст

Уведомления и delegation размазаны по сессиям и терминалам.

## Решение

Одна долговечная сессия оператора получает все wake, вопросы и результаты. Дочерние thread имеют lineage и linkage.

## Последствия

Человек видит одну историю. Требуется аккуратная маршрутизация, чтобы не заспамить чат.

# ADR 197: Вопрос человеку как ревизионная строка

Статус: accepted

## Контекст

В OpenRig вопрос это queue row с options, ответ записывается reply row и закрывает ask один раз. Ревизии и operation id защищают от stale retry и двойного ответа.

## Решение

Beacon моделирует вопрос как версионированную строку с идентификатором операции и явным reply path.

## Последствия

Повтор с тем же operation id возвращает записанный результат. Изменение вопроса между чтением и ответом даёт конфликт.
