# ADR 0040. Шесть фич из отчёта W-wave

Статус: accepted

Этот ADR фиксирует шесть фич из отчёта W «W-волна: 19 новых проектов для Beacon» от 20 ноября 2026 года. Идеи собраны в разделе «Фичи» ([W, строка 240](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L240)) и подтверждены разделами конкретных проектов. Здесь зафиксированы только те фичи, которых нет в ADR 0001-0039 и 115 карточках из `docs/tasks/`. Fencing и аренда уже в T3.51 и ADR 0038 пункт 1, backpressure по квоте в ADR 0038 пункт 2, capability matching в T3.47 и ADR 0038 пункт 3, кворум в ADR 0038 пункт 5, failure contract в T3.50, общий gate в T3.49, review gate в ADR 0038 пункт 4, `indeterminate` в ADR 0017 и ADR 0039 пункт 5, durable inbox в ADR 0039 пункт 6. Несколько новых пунктов похожи на существующие решения по имени, но различаются по уровню. Отмена в фиче 1 работает с деревом задач, а не с выбором воркера из T3.47. Формула в фиче 2 фиксирует правило, а verdict service из ADR 0001 этим правилом пользуется. Вердикт CI в фиче 3 меняет канал чтения, а не бюджет наблюдателя из ADR 0039 пункт 2. Аренда файлов в фиче 6 блокирует ресурс, а T3.46 планирует конфликт. Владелец велел принять оставшиеся идеи без дополнительных вопросов, поэтому статус `accepted`. По ADR 0020 карточки создаются только из принятого ADR. Карточки этим ADR не создаются, код, карточки и тесты в этой задаче не трогаются.

## Решение

Beacon получает шесть механизмов. Они описаны на уровне контракта и не привязаны к конкретному продукту.

1. Отмена вызова вместе с деревом задач по capability context. Каждый долгий вызов, включая `wait_result`, состоит в контексте capability вызвавшего агента. Когда вызвавший агент исчезает, отмена снимает не только сам вызов, но и всё дерево его задач. Потомки получают причину отмены и не продолжают работу после исчезновения инициатора. Причина отмены пишется в журнал. Таймаут процесса остаётся частным случаем, а не единственным способом остановки. Capability matching из T3.47 продолжает решать, какой воркер берёт задачу, и не меняется.
2. Формула вердикта внутри бинаря. Правило `ship ⇒ build ∧ audit ∧ (tdd ∨ trivial)` вкомпилировано и не настраивается конфигом или промптом. Модель не может его переспорить. На входе лежат факты Checks, на выходе детерминированный вердикт. Альтернатива `trivial` это явное условие в коде, а не свободное мнение модели. Это неизменяемость самого правила, а не замена verdict service из ADR 0001: сервис применяет формулу, но не может её изменить. Проверки по-прежнему происходят в CI по ADR 0022.
3. Вердикт CI в events ref. Результат проверки пишется в `refs/clarity/events`, а демон читает один ref для всех ожидающих вызовов вместо пятнадцати отдельных `gh pr checks --watch`. Если источник `exec` не одобрен вручную, наблюдатель возвращает `source degraded` и не выдаёт выдуманный статус проверки. Неизвестное состояние остаётся неизвестным и в events, и в ответе `get_result`. Лестница ADR 0017 и бюджет наблюдателя из ADR 0039 пункт 2 не меняются.
4. Тёплая песочница. После выхода агента песочница остаётся запущенной, и следующий запуск продолжается без повторной загрузки образа. Время жизни песочницы привязано к владельцу и дереву задач, у неё есть явная граница и явное освобождение. Состояние переживает выход одного агента и не переживает снятие задачи. Изоляция worktree из ADR 0021 сохраняется: тёплым является окружение задачи, а не общий хост.
5. Verified-only результат. В память results и в ответ `get_result` попадает только результат, прошедший проверку в CI по ADR 0022. Непроверенный или проваленный результат не публикуется как успешный и остаётся внутри задачи с причиной. `wait_result` не снимается с ожидания по неподтверждённому результату. Это правило хранения, а не доставка сообщения: durable inbox из ADR 0039 пункт 6 продолжает хранить удержанные сообщения до подтверждения по своим ключам.
6. Advisory file reservations. До правки агент берёт аренду на glob-ы файлов. Pre-commit guard блокирует коммит, который задевает файлы, арендованные другим агентом. Аренда advisory: guard это проверка на границе коммита, а не системная блокировка файла. Снятие аренды и явный обход guard фиксируются в журнале. T3.46 остаётся планированием конфликтов до запуска, а здесь решается блокировка ресурса на момент записи.

## Причина

1. fastmcp_rust привязывает область отмены к capability context и кооперативно отменяет долгий вызов вместе с деревом его задач, а не отдельным таймаутом процесса ([W, строка 22](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L22), [README](https://github.com/Dicklesworthstone/fastmcp_rust/blob/main/README.md)). Это нужная семантика для `wait_result`, когда вызвавший агент исчез. Код не берётся: нужен Rust nightly-2026-08-25, поддержка MCP 2026-07-28 не проверена, корневой `PROTOCOL_VERSION` остаётся 2024-11-05, а лицензия содержит райдер ([W, строка 24](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L24)).
2. evolve-loop вкомпилировал формулу вердикта в бинарь, и модель не может её переспорить настройкой ([W, строка 129](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L129), [README, What makes it different](https://github.com/mickeyyaya/evolve-loop/blob/main/README.md)). Это эталон детерминированного правила для `wait_result`. ADR 0001 описывает verdict service, а не неизменяемость формулы, поэтому пункт 2 его не повторяет. Весь конвейер доставки с worktree на цикл, таблицей маршрутизации CLI и требованием 100% покрытия изменённой функции не переносится ([W, строка 131](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L131)).
3. clarity хранит вердикт CI в events ref `refs/clarity/events` и показывает `source degraded`, когда источник `exec` не одобрен вручную ([W, строка 118](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L118), [README, The events ref](https://github.com/ezcdlabs/clarity/blob/main/README.md)). Один читатель refs заменяет множество отдельных опросов при пятнадцати параллельных агентах. Сейчас это пятнадцать `gh pr checks --watch`, дорогих по памяти и лимиту GraphQL ([W, строка 300](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L300)). ADR 0039 пункт 2 решает починку упавших проверок и общий почасовой потолок, а не канал вердикта. TUI с DORA-метриками и опрос remote раз в 5 секунд не берутся ([W, строка 120](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L120)).
4. brig оставляет песочницу запущенной после выхода агента, поэтому следующий `brig run` начинается сразу, без новой загрузки образа ([W, строка 94](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L94), [README, First run](https://github.com/brig-sh/brig/blob/main/README.md)). Это паттерн тёплого состояния для долгоживущего процесса. Beacon ждёт события, а не изолирует код, поэтому microVM, гостевые образы и hypervisor не переносятся ([W, строка 96](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L96)).
5. nomos открывает чистую SQLite-память через read-only stdio MCP и записывает урок «ошибка → исправление» только после прохождения проверки ([W, строка 140](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L140), [README, Verified-Only Episodic Memory](https://github.com/mgantlett/nomos/blob/main/README.md)). Results API не должен хранить неподтверждённый результат. ADR 0022 задаёт место проверки, а это правило задаёт границу записи. Gates на коммиты и ветки, хуки и worktree-песочницы nomos не берутся ([W, строка 142](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L142)).
6. mcp_agent_mail_rust держит advisory file reservations: аренду glob-ов до правки и pre-commit guard против файлов другого агента ([W, строка 234](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L234), [README, Why Use Agent Mail](https://github.com/Dicklesworthstone/mcp_agent_mail_rust/blob/main/README.md)). При пятнадцати агентах нужна простая блокировка ресурса на границе коммита. T3.46 планирует конфликт до запуска задач, а не удерживает файл во время правки. 45 инструментов, 16-экранный TUI, Git-архив, Tantivy и райдер в лицензии не переносятся ([W, строка 236](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L236)).

Числа в разделе «Перформанс» W-отчёта это заявления авторов проектов, а не измерения Beacon ([W, строка 270](/home/nbook/Projects/tmp/beacon-research/W-wave.md#L270)). Ни одно из них не переносится в контракт как показатель Beacon.

- Проверка карточек: исчезновение вызвавшего агента снимает `wait_result` и все дочерние задачи с причиной отмены, а capability matching из T3.47 продолжает работать по своим правилам; формула даёт один и тот же вердикт на одном наборе фактов и не меняется конфигом или промптом; один читатель events ref обновляет все ожидающие вызовы, а неодобренный источник даёт `source degraded` без выдуманного статуса; следующий запуск переиспользует тёплую песочницу без загрузки образа, а снятие задачи освобождает её; непроверенный результат не попадает в results и не снимает `wait_result`; коммит, задевающий чужую аренду, блокируется guard, а снятие аренды и обход фиксируются в журнале.
- ADR 0001 verdict service, ADR 0003, ADR 0009, ADR 0017, ADR 0021, ADR 0022, ADR 0024, ADR 0026, ADR 0028, ADR 0034, ADR 0036, ADR 0038 и ADR 0039 не переписываются. Набор MCP-инструментов не расширяется без отдельного решения. Fencing T3.51, lease, backpressure ADR 0038 пункт 2, capability T3.47, кворум ADR 0038 пункт 5, review gate ADR 0038 пункт 4, `indeterminate` ADR 0039 пункт 5 и durable inbox ADR 0039 пункт 6 остаются на своих местах. Ключи разные: владелец capability context определяет отмену дерева, владелец lease из T3.51 определяет аренду задачи, владелец glob-ов из фичи 6 определяет аренду файла, `PEER_NAME` из ADR 0039 определяет владельца inbox.

## Отклонённое

Отменять только процесс по таймауту и оставлять дерево задач живым после ухода вызвавшего агента. Первое не останавливает потомков, второе даёт осиротевшую работу.

Выносить формулу вердикта в конфиг, промпт или разрешать модели её переспорить, а также выдавать эту формулу за замену verdict service из ADR 0001. Неизменяемость правила и применение правила это разные уровни.

Выдумывать статус проверки, когда источник `exec` не одобрен, или сохранить пятнадцать отдельных опросов. Неизвестный источник даёт `source degraded`, а один ref заменяет пятнадцать опросов.

Загружать образ на каждый запуск или держать песочницу без владельца и границы времени жизни. Первое теряет выигрыш тёплого состояния, второе утекает ресурсы.

Писать непроверенный результат в results или смешивать verified-only с durable inbox из ADR 0039 пункт 6. Там сообщение хранится до подтверждения доставки, здесь результат публикуется только после проверки.

Сводить аренду файлов к T3.46 или делать её обязательной системной блокировкой без журнала обхода. Это advisory guard на границе коммита, а не планирование конфликта и не блокировка файла операционной системой.
