# ADR 0039. Шесть фич из отчёта V-wave

Статус: accepted

Этот ADR фиксирует шесть фич из отчёта V «V-волна: 15 новых проектов для Beacon» от 20 ноября 2026 года. Идеи собраны в разделе «Фичи» ([V, строка 196](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L196)) и подтверждены разделами конкретных проектов. Здесь зафиксированы только те фичи, которых нет в ADR 0001-0038 и 108 карточках из `docs/tasks/`. Fencing и аренда уже в T3.51 и ADR 0038 пункт 1, backpressure по квоте в ADR 0038 пункт 2, capability matching в T3.47, общий gate в T3.49 и ADR 0037 пункт 3, кворум в ADR 0038 пункт 5, failure contract hook в T3.50 и ADR 0037 пункт 4. `indeterminate` из ADR 0017 и T3.9 описывает исход доставки уведомления, а не исход задачи, поэтому фича 5 ниже его не повторяет. Владелец велел принять оставшиеся идеи без дополнительных вопросов, поэтому статус `accepted`. По ADR 0020 карточки создаются только из принятого ADR. Карточки этим ADR не создаются, код, карточки и тесты в этой задаче не трогаются.

## Решение

Beacon получает шесть механизмов. Они описаны на уровне контракта и не привязаны к конкретному продукту.

1. Парковка провала без слепого ретрая. Лимит, исчерпанный бюджет, краш исполнителя или ошибка внешнего шага кладут задачу в `parked` с полным текстом ошибки и причиной в журнале. Ничего не ретраится без человека. Из парковки выводит явное действие человека: устранение причины и новый запуск отдельной записью. Парковка относится к шагу исполнения задачи и внешнему вердикту. Отказ доставки уведомления остаётся на лестнице ADR 0017, а отложенный запуск по квоте остаётся в ADR 0038 пункт 2.
2. CI healing с общим сервисом вердикта. Один наблюдатель в демоне классифицирует упавшие проверки и применяет ограниченное число попыток починки. Почасовой потолок запусков агента считается на сервис целиком, а не на каждый из 15 агентов. Класс проверки, номер попытки и расход потолка пишутся в журнал. Исчерпание попыток или потолка переводит задачу в парковку по пункту 1, а не в новый круг починок. Вместо 15 процессов `gh pr checks --watch` работает одна точка ожидания.
3. Кросс-платформенный CI-адаптер. Один разбор статусов покрывает GitHub Actions, GitLab CI и Bitbucket Pipelines. Поля и форматы провайдеров остаются внутри адаптера, а ядро видит одно внутреннее представление проверки и структурированные коды ошибок. Ошибки проходят через `AppError` из ADR 0009 и единый error shape MCP. Состав проверок и ключ вердикта из T2.15 не меняются: адаптер готовит входные данные, а не переписывает оценку вердикта.
4. Реестр портов без коллизий. Каждая задача получает уникальный порт или диапазон из одного реестра. Порт, занятый задачей, повторно не выдаётся. Освобождение снимает процессы на выделенных портах и только после этого помечает порт свободным. Реестр лежит в состоянии Beacon, поэтому после рестарта порт не достанется второй задаче, пока первая его не освободила.
5. Честный `indeterminate` результата задачи. Когда внешнее действие выполнено, а ответ потерян, `get_result` возвращает `indeterminate` как исход задачи вместе со стойким ключом аренды. Ядро не утверждает ни успех, ни провал и не запускает повтор, потому что эффект мог наступить. Это исход самой задачи, а не ветвь лестницы доставки из ADR 0017. Поля и порядок ответа из ADR 0036 пункт 2 сохраняются, добавляется новое значение исхода.
6. Durable inbox вызванной сессии. Сообщение сохраняется в хранилище до подтверждения. Доставка идёт по схеме at-least-once, дубликаты ожидаемы и гасятся получателем по ключу `watchID+revision+subscriberID`. Рестарт с тем же `PEER_NAME` возвращает удержанное сообщение и сбрасывает stale leases, поэтому сообщение не остаётся за мёртвым арендатором. `PEER_NAME` это ключ владельца inbox, а не `event.id` из ADR 0034 пункт 4 и не sessionID. Сообщения от пиров считаются недоверенным вводом по T3.4.

## Причина

1. loope при лимите, бюджете, краше или любой ошибке кладет issue в парковку с полным текстом и не ретраит без человека ([V, строка 57](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L57), [README, Why loope](https://github.com/ngthluu/loope/blob/main/README.md)). Для `wait_result` это граница: внешний вердикт не должен сам порождать попытку. Решение завязано на GitHub labels, Claude Code и общей доске issue как единственном состоянии ([V, строка 59](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L59)), поэтому код не берётся.
2. patchdeck классифицирует упавшие проверки, ограничивает попытки починки и держит почасовой потолок запусков агента ([V, строка 68](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L68), [README, CI and Deployment Healing](https://github.com/jeremymcs/patchdeck/blob/main/README.md)). При 15 агентах отдельный наблюдатель на каждого даёт 15 независимых бюджетов и 15 процессов `gh --watch`. Node.js 22, GitHub-specific состояние в `~/.patchdeck/state.sqlite`, Tauri-оболочка и свои worktree не переносятся ([V, строка 70](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L70)).
3. `parsec ci --watch` работает одинаково для GitHub Actions, GitLab CI и Bitbucket Pipelines, а команды отдают `--json` и структурированные коды E001-E013 ([V, строка 79](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L79), [README, Top features](https://github.com/erishforG/git-parsec/blob/main/README.md)). Beacon не должен писать три разборщика и держать три формы ошибки. Это продолжает границу одного моста на протокол из ADR 0024. 33 команды, stacked PR, TUI и собственный MCP-сервер git-parsec не берутся ([V, строка 81](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L81)). Коды E001-E013 это контракт чужого CLI, а не готовый набор кодов Beacon.
4. workz выделяет непересекающиеся диапазоны портов, а `workz done` убивает процессы на выделенных портах ([V, строка 92](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L92), [README, таблица команд](https://github.com/rohansx/workz/blob/main/README.md)). При 15 параллельных агентах ручное планирование портов не масштабируется. Бинарь 3.9 MB и диапазоны `PORT 3000-3009` и `PORT 3010-3019` это заявленные автором числа ([V, строка 223](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L223)), а не измерения Beacon. CLI provisioning не переносится: ADR 0021 изолирует только worktree, не порты ([V, строка 94](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L94)).
5. tool-journal держит стойкий ключ аренды и явный `indeterminate`, когда инструмент выполнил внешнее действие, а ответ потерян ([V, строка 140](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L140), [README, Try the failure](https://github.com/RaycarlLei/tool-journal/blob/main/README.md)). Без такого исхода `get_result` вынужденно называет успех или провал там, где эффект неизвестен. ADR 0017 решает другую задачу: там нет квитанции о доставке уведомления. Демо с двумя HTTP-вызовами на один эффект это пример автора ([V, строка 225](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L225)), а не SLA. TypeScript, Node 24 и experimental SQLite API не берутся ([V, строка 142](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L142)).
6. agent-peers-mcp хранит сообщение до подтверждения брокером, а рестарт с тем же `PEER_NAME` возвращает удержанное сообщение и сбрасывает stale leases ([V, строка 177](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L177), [README, таблица What you get](https://github.com/Co-Messi/agent-peers-mcp/blob/main/README.md)). Это модель очереди уведомлений для вызванных сессий, которая переживает рестарт. ADR 0028 решает идемпотентность команд по `clientRequestId`, а не доставку сообщений по имени владельца inbox. Брокер на TypeScript, localhost и возможные дубликаты не переносятся ([V, строка 179](/home/nbook/Projects/tmp/beacon-research/V-wave.md#L179)).

## Последствия

- Из каждого пункта выходит одна небольшая карточка в `docs/tasks/` по правилам ADR 0020. Карточки этим ADR не создаются и будут созданы отдельными задачами.
  - Фича 1: `internal/domain/types.go`, `internal/domain/transition.go`, `internal/infra/taskstore/store.go`, `internal/app/taskcli/service.go`, `internal/infra/mcp/tool_wait_result.go` и тесты к ним.
  - Фича 2: `internal/domain/verdict.go`, `internal/app/taskcli/service.go`, `cmd/beacon/watch.go`, `internal/infra/github/rest.go`, `internal/infra/store/observability.go` и тесты к ним.
  - Фича 3: `internal/domain/types.go`, `internal/infra/ci/status.go`, `internal/infra/ci/github.go`, `internal/infra/ci/gitlab.go`, `internal/infra/ci/bitbucket.go`, `internal/infra/mcp/schema.go` и тесты к ним.
  - Фича 4: `internal/domain/types.go`, `internal/infra/ports/registry.go`, `internal/app/taskcli/service.go`, `cmd/beacon/agents.go` и тесты к ним.
  - Фича 5: `internal/domain/types.go`, `internal/infra/mcp/tool_get_result.go`, `internal/infra/mcp/contract_test.go`, `internal/infra/taskstore/store.go`, `internal/infra/store/db.go` и тесты к ним.
  - Фича 6: `internal/domain/types.go`, `internal/domain/identity.go`, `internal/infra/store/db.go`, `internal/infra/store/receipts.go`, `internal/infra/mcp/tool_wake.go`, `internal/infra/ladder/transitions.go` и тесты к ним.
- Проверка карточек: ошибка шага исполнения кладёт задачу в `parked` с полным текстом и без ретрая, а лестница ADR 0017 продолжает работать по своим исходам; упавшая проверка классифицируется, число починок и общий почасовой потолок не превышаются, а исчерпание границы ведёт в парковку; один и тот же статус из трёх провайдеров даёт одно внутреннее представление и один формат ошибки MCP; две задачи не получают один порт, а освобождение снимает процессы до пометки порта свободным; потерянный ответ внешнего действия даёт `indeterminate` без повтора и без перестановки полей ответа; рестарт с тем же `PEER_NAME` возвращает удержанное сообщение и сбрасывает stale leases, а дубликат гасится по ключу получателя.
- Число MCP-инструментов остаётся равным семи, ADR 0003 и 0009 не меняются. Лестница ADR 0017, честная доставка ADR 0026, байтово стабильный ответ ADR 0036 пункт 2, один мост на протокол ADR 0024, изоляция worktree ADR 0021 и проверка только в CI ADR 0022 сохраняются. Fencing, инвалидация lease после краша, backpressure по квоте и кворум из ADR 0038 не переписываются. Capability matching T3.47, общий gate T3.49, failure contract T3.50, fencing T3.51 и пороги плана T3.52 не переписываются. Ключи разные: `PEER_NAME` владеет inbox, `event.id` из ADR 0034 различает доставки, ревизия из ADR 0036 пункт 5 фиксирует версию задачи.

## Отклонённое

Слепо ретраить лимит, бюджет, краш или ошибку внешнего шага, либо только писать ошибку в лог. Первое удваивает эффект, второе теряет полный текст и причину.

Дать каждому агенту свой наблюдатель CI или неограниченное число починок. Пятнадцать наблюдателей дают пятнадцать бюджетов, а не один сервис вердикта.

Писать три разборщика статусов в ядре или выдать коды E001-E013 git-parsec за контракт Beacon. Ядро остаётся не зависящим от продукта по ADR 0024, коды чужого CLI не являются кодами MCP-ошибок Beacon.

Выделять порты вручную или помечать порт свободным, не сняв процессы. Следующая задача получит уже занятый порт.

Приравнять `indeterminate` из ADR 0017 к исходу задачи. Там нет квитанции о доставке уведомления, здесь неизвестен эффект внешнего действия. Нельзя выдавать успех или провал, когда ответ потерян.

Держать inbox только в памяти, терять его при рестарте с тем же `PEER_NAME` или считать сообщения пиров доверенным вводом. At-least-once даёт дубликаты, а текст от пира требует экранирования по T3.4.
