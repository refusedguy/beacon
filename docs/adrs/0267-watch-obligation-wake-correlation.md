# ADR 267: Единая схема корреляции Watch, Obligation и доставки wake (correlation)

Статус: proposed

## Контекст

В событиях цикла уже есть cycleID. Для диагностики требуется вручную сопоставлять watchID, obligationID, revision и квитанцию доставки. evals/README фиксирует разрыв между моделью в evals/main.go и production путём. ADR 0017, 0063 и 0072 задают контекст.

## Решение

Добавить в каждую структурированную запись цикла поля watchID, obligationID, revision, role, adapter, verdict и attempt. gen_ai.agent.name хранит роль низкой кардинальности, gen_ai.agent.id хранит watchID, gen_ai.conversation.id берётся только из адаптера. По умолчанию действует NO_CONTENT: текст wake, аргументы инструментов и diff PR в телеметрию не попадают. traceparent принимается только на доверенной границе и проверяется по длине.

## Последствия

Объём логов вырастет. Разбор инцидента станет дешевле. Смена политики содержимого требует нового ADR, а не правки принятого. Не следует тащить полный OTel SDK ради имён полей при цели меньше 100 МБ.
