# ADR 0013. Счётчик поинтов GitHub

Статус: accepted

## Решение

Общий счётчик поинтов не живёт только в памяти. При старте Beacon читает потраченные поинты через `GET /rate_limit`. Затем счётчик обновляется на каждый ответ и периодически сверяется с GitHub. После рестарта отсчёт не начинается с нуля.

## Причина

Владелец возразил против чистого in-memory счётчика и указал, что проверка делается при старте и затем обновляется. Это защищает от превышения лимита после рестарта.

## Последствия

- Лимит общий для REST и GraphQL клиентов, 500 поинтов в час.
- При достижении порога оба клиента увеличивают интервал.
- Заголовки `x-ratelimit-*` приоритетнее тела ответа.
- Secondary limit не измерим через `/rate_limit`, обрабатывается по `retry-after`.
