# ADR 185: Один чат это операторская сессия проекта, фоновый сервер единственный владелец состояния

Статус: accepted

## Контекст

Kernel rig в OpenRig состоит из advisor.lead (чат с человеком), operator.agent (управляет OpenRig), operator.human (общий TUI) и queue.worker. Человеческие решения идут по returnRoute или в human channel, а не в терминал. Beacon сейчас живёт внутри MCP-вызова и не имеет выделенной operator-сессии.

## Решение

Ввестиoperator-сессию на проект: одну долгоживущую сессию, куда приходят все уведомления и откуда идут команды управления. MCP, CLI и будущий TUI становятся тонкими клиентами одного HTTP-сервера. Сессия это ключ доставки, а личность и права идут из реестра.

## Последствия

Появляется single-instance lease и pidfile. Агент-исполнитель не может подменить проект: cwd и git root фиксируют project_key. Терминал и TUI перестают считаться адресом человека; адрес вида <id>@external остаётся каналóm для вопросов.
