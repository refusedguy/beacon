# ADR 185: Фоновый сервер как единственный владелец состояния

Статус: proposed

## Контекст

MCP, плагин opencode и будущий TUI читают и пишут одно состояние напрямую; демон --interval живёт отдельно.

## Решение

Все изменения идут через один долгоживущий beacon-server. SQLite, event log, outbox и проекции принадлежат ему.

## Последствия

Одна точка восстановления и один журнал. Требуется поддержка жизненного цикла процесса.
