# ADR 286: TUI как тонкий клиент HTTP и SSE

Статус: proposed

## Контекст

TUI может писать состояние напрямую и расходиться с MCP.

## Решение

TUI читает готовые проекции /api/v1 и шлёт команды REST. Прямых записей в БД нет.

## Последствия

Меньше дублирования. TUI требует работающего сервера или встроенного режима.

## Порты UI

Три порта и их DTO лежат в `internal/domain/projection`: `StateProvider`, `DecisionSink` и `EventSource`. HTTP в `internal/infra/httpapi` остаётся одним адаптером и использует эти определения через псевдонимы. TUI по-прежнему читает HTTP и не импортирует store, cibridge и mcp. ARCH-тест в `internal/domain/projection` проверяет это ограничение и отсутствие второй копии типов в адаптере. Будущий UI подключается к тем же портам без правки ядра. Ребро `internal/tui -> internal/domain` в матрице слоёв остаётся за решением владельца по TUI-06.
