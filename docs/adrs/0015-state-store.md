# ADR 0015. Хранилище состояния

Статус: accepted

## Решение

Состояние Beacon хранится в одной SQLite базе. Драйвер `modernc.org/sqlite`, сборка с `CGO_ENABLED=0`, режим WAL, один писатель в процессе Beacon.

Квитанции адаптера остаются отдельным файлом `receipts.jsonl` внутри каталога состояния. Плагин OpenCode дописывает строку, Beacon читает её и одной транзакцией переносит факт в базу.

## Причина

Владелец предложил SQLite вместо набора JSON файлов, чтобы не плодить файлы и не перечитывать большие JSON. Отчёт G подтвердил, что скорость при 60 Watch не решает и что `modernc` даёт статический бинарник без cgo.

Квитанции оставлены файлом по рекомендации отчёта G. Плагин работает в процессе OpenCode и не должен знать схему базы. Прямая запись через `bun:sqlite` технически возможна и проверена, но связывает два рантайма общей схемой и лишает режим `locking_mode=EXCLUSIVE`.

## Измерения из отчёта G

- `modernc.org/sqlite` v1.62.0, Go 1.26.0, BSD-3-Clause.
- Прибавка к бинарнику около 4,9 MiB после strip.
- Пик RSS около 18,9 MB при 60 Watch и 60 000 записей, в пределах цели 100 MB.
- SQLite 3.54.1 в драйвере, WAL reset баг исправлен в версии старше 3.51.3.

## Последствия

- Вердикт, обязательство и позиция лестницы пишутся в одной транзакции.
- Идемпотентность через `UNIQUE(watch_id, revision, subscriber_id)`.
- Миграции схемы через `user_version` и SQL файлы с `//go:embed`.
- Корpus миграций из ADR 0012 превращается в набор фикстур базы до миграции.
- Redaction из ADR 0012 работает на записи в базу.
- Граница с плагином остаётся файловой, как в ADR 0014.

## Отклонённое

`mattn/go-sqlite3` требует cgo. `ncruces/go-sqlite3` добавляет больше всего байт и держит соединение в WASM. Прямая запись квитанций из плагина в общую базу.
