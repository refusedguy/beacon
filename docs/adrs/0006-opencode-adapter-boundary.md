# ADR 0006. Отделение адаптера OpenCode от ядра

Статус: accepted

## Решение

Весь код, специфичный для OpenCode, живёт вне Go-бинарника. Адаптер это один JS файл в `.opencode/plugins/beacon-bridge.js` проекта. Go-ядро не содержит ни одного упоминания OpenCode.

## Причина

Отчёт E показал, что один JS файл загружается без `package.json` и без импорта SDK хоста. Плагин подписывается на события, читает события Beacon из файла и вызывает `ctx.session.prompt` с доставкой `steer`. Факт пробуждения это событие `session.execution.started`.

## Последствия

- Адаптер можно менять без пересборки ядра.
- Другие MCP клиенты подключаются по тому же контракту.
- Плагин пишет квитанции в каталог состояния Beacon, а не в конфиги OpenCode.
- Плагин работает fail-open, любая ошибка не ломает сессию.

## Риск

Событие `filesystem.changed` не приходит само по себе. Нужна регистрация через `POST /api/experimental/fs/watch`, которого нет в контексте плагина, поэтому используем `node:fs.watch` или polling. Проверить спайком T0.3.
