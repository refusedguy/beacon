# ADR 0022. Проверка только в CI

Статус: accepted

## Решение

Компиляция, тесты, гейты и бенчмарки не запускаются на локальной машине менеджера и агентов. Вся проверка идёт в GitHub Actions через pull request.

Локально допускаются только легкие операции: `gofmt`, чтение файлов, подготовка коммита.

Менеджер создаёт ветки и PR, смотрит результат CI и mergeит зелёные PR в main. При красном CI менеджер не чинит код локально, а возвращает PR агенту с причиной.

## Причина

Владелец прямо указал: «локально ничего компилиться, теститься не будет, всё как в Harbor, на удалёнке, через PR». Это повторяет правило night-shift-manager: оркестратор не запускает локальные сборки, тесты и тяжёлые проверки, предпочитает CI.

## Последствия

- Задания агентам содержат gofmt и подготовку PR, но не go test и go build как гейт приёмки.
- Приёмка задачи это зелёный CI в PR, а не локальный прогон.
- CI workflow обязателен до первой волны реальных фич.
- Спайки T0.* в tmp/ остаются локальным исключением, не коммитятся и не идут в PR.

## Исключение

Спайки P0 в `tmp/` это локальные измерения, зафиксированные в ADR 0001 и WORKER-PROMPT. Они не являются проверкой продакшн-кода и в CI не идут.
