# ADR 0086. Project-scoped конфиг и состояние реестра сабагентов

Статус: accepted

## Контекст

У Beacon есть только половина модели реестра. Состояние уже project-scoped: `cmd/beacon/doctor.go` выводит каталог как `<XDG_STATE_HOME>/beacon/projects/<name>-<8 hex sha256(abs cwd)>/beacon.db`, когда cwd содержит `.git`, иначе `<XDG_STATE_HOME>/beacon/beacon.db`. Переменная `BEACON_STATE_DIR` перекрывает выбор (ADR 0011, ADR 0069, ADR 0101). Проект определяется cwd MCP-клиента. Авторского конфига агентов нет: список живёт в OpenCode и в коде адаптера, а не в проекте, поэтому его нельзя ревьюить вместе с кодом и он не переносится между машинами как данные проекта.

В OpenRig эти два слоя разделены. [instance-layout.md](https://github.com/mvschwarz/openrig/blob/985991f5d5c31a5468cab21b8a74706655069dbd/docs/reference/instance-layout.md) описывает `$OPENRIG_HOME`, по умолчанию `~/.openrig`: там лежат `config.json`, `state/`, `context/`, `skills/`, `workspace/`, `specs/`, `topology/`, `plugins/`, `run/`, `logs/`, `transcripts/`, `backups/` и `secrets/`, а база `openrig.sqlite` в корне. Авторский конфиг живёт отдельно в bundle: `rig.yaml`, `agent.yaml`, `configurations.yaml`, startup-файлы и culture file. Реестр фиксирует bundle по commit, но не раздаёт его. Запись демона материализует объявление автора, а не наоборот.

## Решение

Разделить конфигурацию реестра на два слоя с разными владельцами и разным временем жизни.

1. Авторский файл лежит в проекте и коммитится: `<project>/.beacon/agents.yaml`. Он описывает роли, допустимые runtime, capabilities, ограничения, конфигурации и лимиты. В нём не бывает sessionID, watchID, токенов и путей к чужим каталогам. Это данные проекта, которые проходят ревью.
2. Выведенное состояние лежит рядом с `beacon.db` в уже существующем project state dir. Оно содержит конкретных исполнителей, привязки к Watch, capability index и историю регистрации. Это состояние переживает рестарт и не хранится в git.
3. Идентичность проекта остаётся `projectStateKey`: имя папки плюс первые восемь байт SHA-256 абсолютного пути. Запись из другого проекта не может попасть в этот state dir без явного `--project`. Явный `BEACON_STATE_DIR` сохраняет приоритет (ADR 0011).

## Последствия

- Граница файлов проверяема: конфиг можно прочитать и изменить в PR, состояние нельзя подменить правкой YAML. Секреты и идентификаторы сеансов не попадают в репозиторий.
- Реестр восстанавливается из базы после рестарта и сверяется с живым списком сеансов. Расхождение помечает запись `stale`, но не меняет вердикт Watch.
- Число MCP-инструментов остаётся равным семи (ADR 0003, ADR 0009, ADR 0094). Управление реестром живёт в CLI и в состоянии.
- Карточки реализации ссылаются на этот ADR: T5.2 задаёт configuration ID, T5.3 регистрацию исполнителя вместе с Watch, последующие карточки capabilities, состояний, останова, лимитов и сверки после рестарта.
- ADR 0011, 0049 и 0069 не переписываются. ADR 0101 сохраняет привязку состояния к resolved cwd. Проверки остаются в CI (ADR 0022).
