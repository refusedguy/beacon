# ADR 79: Негативный контроль для проверки факта побуждения

Статус: accepted

## Контекст

Нужно отличать реальный wake от совпавшей по времени фоновой активности сессии и от одного только beacon_ack.

## Решение

Негативный контроль: отправить prompt с delivery queue (или resume false) и не делать PATCH в steer - сессия не должна начинать новое выполнение. beacon_ack сам по себе тоже не будит. Для idle-сессии interrupt возвращает interrupted false.

## Последствия

Проверять GET /api/session/active: прерывание действует только на выполнение, которым владеет данный процесс. Подтверждать через GET /api/event: session.execution.started и session.idle. Это отделяет проверку wake от посторонних событий.
