# ADR 0094. Десять инструментов ядра

Статус: accepted

## Контекст

ADR 0003 выбирает официальный `github.com/modelcontextprotocol/go-sdk` и выводит схемы инструментов из Go-типов. ADR 0009 задаёт единую форму ошибки на границе MCP. Вместе они зафиксировали контракт из семи имён из WORKER-PROMPT §4.1: `beacon_watch_pr`, `beacon_wait_result`, `beacon_get_result`, `beacon_list_running`, `beacon_ack`, `beacon_cancel_watch`, `beacon_stats`.

Семь имён были версией контракта с момента принятия ADR и до W12-B. В PR #451 и #463 владелец добавил восьмое имя `beacon_defer_wiring` и обновил тесты и бюджет `tools/list`. ADR 0268 добавил девятое имя `beacon_task_claim`. ADR 0270 добавил десятое имя `beacon_task_close`. Сейчас `origin/main` держит один контракт из десяти имён.

## Решение

Контракт содержит ровно десять инструментов. Первые семь сохраняют сигнатуры и назначение. Восьмой инструмент `beacon_defer_wiring` записывает отложенную проводку. Девятый инструмент `beacon_task_claim` выдаёт карточку одному агенту по ADR 0268. Десятый инструмент `beacon_task_close` закрывает карточку с причиной и доказательством по ADR 0270.

`beacon_watch_pr` расширяется параметрами PR и подписчика: `repo`, `pr`, `headSHA`, `role`, `notify` с адаптером и целью. Он регистрирует или обновляет Watch по ключу идемпотентности и возвращает `watchID`, `revision`, `status`, `verdict`, `pollAfterMs`. Дескриптор `executor` должен быть известен до фразы `waiting, watchID` (ADR 0088). Инструмент аддитивный: он пишет состояние Watch, но не меняет проверки и не мержит PR. Он не помечается read-only.

### Необязательное поле executor (T5.32)

`beacon_watch_pr` принимает необязательный объект `executor` и возвращает его в ответе. Поле добавлено в T5.32. Вызов без этого поля сохраняет прежнюю форму запроса и ответа.

Объект содержит шесть подполей. Все подполя необязательные и помечены `omitempty`.

| Поле | Что несёт |
| --- | --- |
| `id` | непрозрачный идентификатор сессии исполнителя |
| `role` | объявленная роль, переносится без разбора |
| `runtime` | объявленный режим сессии |
| `agent` | непрозрачное имя агента |
| `capabilities` | объявленный список возможностей |
| `configId` | идентификатор конфигурации из ADR 0087 |

Ядро переносит значения без разбора. Имя агента, режим и возможности остаются данными вызывающей стороны (ADR 0088, ADR 0089). Ответ повторяет дескриптор в поле `executor` как указатель с `omitempty`. Если вызов не передал дескриптор, ключа `executor` в ответе нет.

Схема запроса выводится из `WatchPRExecutor`, схема ответа из `ExecutorMetadata`. Наличие шести подполей проверяют `TestWatchPRInputSchemaHasExecutorDescriptor` и `TestWatchPRSchemaExecutorMetadata`. `TestWatchPROutputExecutorValidation` проверяет, что ответ без дескриптора остаётся корректным.

Реестр читается через два существующих инструмента без записи состояния:

- `beacon_list_running` возвращает снимок активных Watch, счётчики `watches`, `byVerdict`, `subscribers` и курсор с событиями `WatchEvent`. Terminal-статус отдаёт вердикт без проигрывания старых событий (ADR 0025).
- `beacon_stats` возвращает `pointsThisHour`, `budget`, `activeWatches`, блоки `persist`, `loadErrors`, `ladder` и `version`.

Оба инструмента объявлены `ReadOnlyHint: true` и не пишут `readAt` или `claimedAt`. `beacon_wait_result`, `beacon_get_result`, `beacon_ack` и `beacon_defer_wiring` остаются аддитивными, `beacon_cancel_watch` остаётся единственным деструктивным инструментом. `beacon_task_claim` пишет состояние карточки один раз и не помечает идемпотентность, `beacon_task_close` аддитивный. Порядок имён в `tools/list` частью контракта не является.

### Восьмой инструмент (W12-B)

`beacon_defer_wiring` принимает `watchID`, `pr`, `title`, `reason` и `ownerFiles`. Он пишет запись в store отложенных проводок и возвращает `cardID`, `created`, `status` и готовый текст карточки `cardMarkdown`. Агент добавляет карточку `docs/tasks/WIRING-<pr>.md` в свой PR. Идемпотентность идёт по ключу `(watchID, reason)`: повторный вызов возвращает ту же карточку с `created=false` и не пишет в store. Инструмент аддитивный и не read-only: он пишет состояние отложенной проводки.

Владелец выбрал отдельное имя вместо поля в существующем инструменте. Отложенная проводка пишет в собственный store и создаёт артефакт с ключом идемпотентности `(watchID, reason)`. Поле в `beacon_watch_pr` или `beacon_ack` дало бы одному вызову два разных действия. Тогда нельзя однозначно определить класс аннотации и набор проверок инструмента. Явное имя в `tools/list` делает возможность заметной и оставляет сигнатуры семи существующих инструментов неизменными. Цена решения: контракт вырос до восьми имён, а тест бюджета `tools/list` обновлён под новый набор.

### Девятый и десятый инструменты

`beacon_task_claim` и `beacon_task_close` работают с карточками задач. Оба имени зарегистрированы в `toolDescriptors` в `internal/infra/mcp/server.go`. Таблица дескрипторов задаёт `ToolNames`, аннотации и схемы вывода, поэтому имя не может присутствовать в одной таблице и отсутствовать в другой. Решения зафиксированы в ADR 0268 и ADR 0270.

### Порядок вывода (HD-045)

Финальный отчёт инструмента строится по правилу Harbor (human-readable summary first, fence после, ADR 0301): сначала идёт человекочитаемое резюме, затем ровно один fence с машинночитаемым JSON. Человек читает резюме без разбора JSON, а оркестратор берёт результат из последнего корректного fence. До открывающего блока JSON в fence должен быть непустой текст. Шаблон, который печатает JSON первым, контракт нарушает.

Шаблон вывода:

````text
Gate verify: 4 checks passed, 0 failed. Watch w-1 is watching.
Machine-readable result follows.

```json
{"schema_version":1,"gate":"verify","status":"pass","blocking":false}
```
````

## Проверка

`tools/list` возвращает ровно десять имён. Контрактный тест сравнивает отсортированный список с эталоном, проверяет бюджет 20 KiB и сверяет размер и SHA-256 ответа с золотыми константами в `internal/infra/mcp/contract_test.go`. Схемы всех десяти инструментов выводятся из Go-типов, а не пишутся вручную. Порядок вывода закреплён тестом `TestToolOutputSummaryBeforeJSON` в `internal/infra/mcp/contract_test.go`: шаблон с непустым резюме до fence проходит, а negative control с JSON первым проваливает тест.

## Приёмка

Контракт насчитывает десять инструментов. Одиннадцатый инструмент требует отдельного решения, ADR и нового замера золотого ответа `tools/list`. Расширение `watch_pr` и чтение реестра через `list_running` и `stats` не увеличивают число имён. Шаблон вывода, который печатает JSON раньше человекочитаемого резюме, проваливает карточку.
