# ADR 0020. Инструмент работы с задачами

Статус: accepted

## Решение

Команды работы с задачами живут в бинарнике `beacon` как подкоманда `beacon task`. Бинарник читает файлы `docs/tasks/*.md` и требует от каждой карточки фиксированный набор полей.

Обязательные поля карточки:

- `Тип: epic` или `task`.
- `Статус: todo`, `in_progress`, `done` или `dropped`.
- `Фаза: P0` до `P4`.
- `Владелец файлов:` список путей.
- `Зависимости:` список ID или «нет».
- `Ссылка:` на ADR или на задачу-эпик.
- `Цель:`, `Контекст:`, `Шаги:`, `Проверка:`, `Приёмка:`.
- `Агент:` и `Время:` заполняются при взятии задачи.

Правила ссылок. Простая задача обязана ссылаться на ADR или на эпик. Эпик обязан ссылаться на ADR. Задача не может быть создана без согласованного решения.

Правила валидации при создании. Бинарник проверяет три вещи до записи файла: есть ссылка, владелец файлов не занят другой карточкой со статусом `todo` или `in_progress`, формат карточки читаем. При провале файл не пишется и печатается причина.

Правила взятия задачи. Команда меняет `Статус: todo` на `in_progress` и записывает `Агент:` и `Время:`. Занятыми считаются статусы `todo` и `in_progress`. Статусы `done` и `dropped` освобождают файлы.

## Причина

Владелец попросил быстрый инструмент, чтобы посмотреть задачи, создать задачу и взять задачу. Он же потребовал явное поле типа и обязательные ссылки на решения, чтобы все задачи приходили из согласованных ADR.

## Последствия

- Формат карточки становится контрактом. Все 52 существующие карточки приводятся к этому формату.
- `beacon task list` показывает текущие задачи с фильтром по статусу и фазе.
- `beacon task new` создаёт карточку из шаблона с валидацией.
- `beacon task take <id>` меняет статус и записывает агента и время.
- Бинарник не требует внешних пакетов и работает в CI.

## Отклонённое

Хранение статуса в отдельном JSON файле. Владелец выбрал переписывать карточку. Отдельная система статуса без записи и `just` как внешняя зависимость.
