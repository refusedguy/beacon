# ADR 259: Project config

Статус: accepted

## Контекст

У Beacon есть настройки уровня проекта: число ребейзов перед blocked:not_mine, идентификатор оркестратора, число слотов и цель wake. LoadProjectConfig был заглушкой, поэтому эти значения нельзя было задать и проверить. Без глобального дефолта каждый репозиторий обязан повторять одни и те же значения в собственном файле, а при отсутствии файла поведение остаётся неопределённым.

## Решение

Действуют три слоя. Встроенный дефолт задаёт maxRebases=3 в диапазоне 1..10, slotsTotal=4 по образцу domain.DefaultSlotsTotal, пустые orchestratorID и wakeTarget. Глобальный файл лежит в ~/.config/beacon/config.yaml, путь можно заменить через BEACON_CONFIG. Проектный файл лежит в <repo>/.beacon/config.yaml. Каждый файл перекрывает только те ключи, которые в нём заданы. Отсутствующий файл не считается ошибкой. LoadProjectConfig(dir) читает оба слоя, объединяет их и проверяет результат. Формат файла плоский: key: value, комментарии и кавычки допустимы. Неизвестный ключ, нецелое число, maxRebases вне диапазона, отрицательные слоты и цель без префикса ses_ дают ошибку. CheckAll вызывает LoadProjectConfig до проверки PR и возвращает ошибку конфигурации, если она не проходит.

## Последствия

Проект задаёт только отличия от глобального дефолта. Смена максимума ребейзов не требует правки кода. Поле MaxRebases пока не управляет блокировкой. Решение blocked:not_mine принимает beacon_ack в internal/infra/mcp/tool_ack.go, который не входит в владение этой задачи. Команда beacon config show не добавлена. Для неё нужен dispatch в cmd/beacon/main.go, вне владения задачи. Значение конфигурации доступно через LoadProjectConfig и DefaultConfig, в том числе в тестах.
