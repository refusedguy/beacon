# ADR 190: Одна транзакция на команду и outbox

Статус: accepted

## Контекст

ADR 0187 фиксирует: событие, проекция, квитанция и outbox пишутся в одной транзакции, подписчик уведомляется после коммита. В коде `internal/infra/store/db.go` держит единственного писателя: `Write` кладёт задание в очередь, `runJob` открывает `BeginTx` и коммитит; миграции тоже коммитируются одной транзакцией вместе с версией схемы. `internal/infra/store/atomic_write.go` уже пишет Watch, обязательство и намерение wake в один COMMIT через `CommitVerdictTx`, а `internal/infra/store/receipts.go` гасит повтор по паре `(obligation_id, attempt)`. Карточки `docs/tasks/BS.11.md` и `docs/tasks/BS.12.md` требуют долговечный журнал с монотонным seq и outbox в транзакции команды.

## Решение

Граница команды это одна транзакция SQLite на единственном writer-е. Обработчик команды не делает внешнего I/O: внутри транзакции он пишет событие, проекцию, квитанцию и строку outbox. Коммит это единственная точка, где намерение становится видимым. Роль outbox выполняют строка обязательства с `delivered_at = 0` (`PendingObligations()` в `internal/infra/store/db.go`) и намерение wake в таблице `events` (`CommitVerdictTx` в `internal/infra/store/atomic_write.go`).

Доставку выполняет воркер после коммита, читая только зафиксированные строки. Успех помечается через `MarkObligationDelivered` (`internal/infra/store/blockers.go`) и `markDelivered` в `internal/infra/wake/deliver.go`. Повтор использует тот же `obligationID`: ключ идемпотентности это `domain.ObligationKey(watchID, revision, subscriberID)`, а для квитанций пара `(obligation_id, attempt)`. Откат транзакции не оставляет ни строки outbox, ни события. Долговечный журнал с монотонным seq и универсальный обработчик команды реализуют карточки `docs/tasks/BS.11.md` и `docs/tasks/BS.12.md`. Этот ADR задаёт им контракт, а не новую схему.

## Последствия

Эффект не может опередить коммит, а рестарт не теряет намерение: неподтверждённые строки остаются в outbox. Доставка at-least-once и идемпотентна по ключу, поэтому повтор после падения не удваивает wake. Медленные вызовы GitHub и адаптеров идут вне транзакции, иначе один writer блокирует всю запись. Цена решения: транзакция должна быть короткой, каждая команда сериализуется через одного писателя, а квитанция `posted` не означает завершённый эффект (карточка `docs/tasks/BS.13.md`). MCP-инструменты не открывают транзакции сами: они вызывают сервер через внедрённые порты (ADR 0188).
