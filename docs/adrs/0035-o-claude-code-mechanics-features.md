# ADR 0035. Пять фич из отчёта O-claude-code-mechanics для ночной смены

Статус: accepted

Этот ADR фиксирует пять фич из отчёта O «Механики Claude Code, которые можно взять для Beacon и ночной смены» от 19 ноября 2026 года, раздел «Фичи для Beacon», строки 85-102 ([O, строка 85](/home/nbook/Projects/tmp/beacon-research/O-claude-code-mechanics.md#L85)). Из восьми фич отчёта в ADR 0028 вошли идемпотентность, квитанция и прерывание ожидания. Здесь разложены оставшиеся пять, пункты 1-5. Владелец велел принять их без дополнительных вопросов, поэтому статус `accepted`. По ADR 0020 карточки создаются только из принятого ADR. Карточки этим ADR не создаются, код, карточки и тесты в этой задаче не трогаются.

## Решение

Универсальный night-shift manager получает пять механизмов. Механизмы описаны на уровне формата файлов и контракта, не привязаны к продукту и работают поверх одного моста на протокол из ADR 0024.

1. Один формат инструкций для смены. Инструкция это папка с `SKILL.md`: в frontmatter записаны `name` и `description`, в теле идёт короткая процедура разбора issue. Минимальный файл `.opencode/skills/night-shift/SKILL.md` несёт описание «triage and clear GitHub issues in the night shift» и план разбора в теле. Один и тот же длинный промпт больше не вклеивается в каждый issue, модель сама решает, когда процедура нужна.
2. Явное управление авто-вызовом. Поле frontmatter задаёт, кто запускает процедуру: модель, человек или оба. Ручные операции получают `disable-model-invocation: true`, фоновый разбор идёт через отдельный скилл без этого поля.
3. Progressive disclosure со справочниками. `SKILL.md` держит только короткий маршрут. Правила комментариев и критерии готовности PR лежат в отдельных файлах рядом со скиллом, например `night-shift/references/comment-rules.md` и `night-shift/references/pr-readiness.md`. Скилл читает справочник по ссылке только перед действием.
4. Сабагент с узкими правами. Исследование issue и PR идёт в отдельном профиле без права записи: `.opencode/agents/issue-scout.md` с режимом `subagent` и запретами на `edit`, `shell` и `write`. Действия идут в другом профиле с полными правами. В родительский контекст возвращается только результат, поиск и логи остаются внутри сабагента.
5. Детерминированные проверки перед действиями. Перед комментарием и мержем проверяется условие «только при новом факте». В Claude Code это правило `PreToolUse` в `.claude/settings.json` с matcher на инструмент и со скриптом, который возвращает `permissionDecision: "deny"` при шаблонной фразе в тексте. Для Beacon на OpenCode эквивалент живёт в плагине `.opencode/plugins/beacon-bridge.js`: проверка отклоняет комментарий или мерж, если в тексте нет нового факта (хеш влитого PR, измерение, решение владельца или блокер), и пропускает действие при его наличии.

## Причина

Отчёт O называет эти пять механизмов применимыми к Beacon и ночной смене. Ни одна из пяти фич не разложена в ADR 0001-0034, поэтому для них по ADR 0020 нужны отдельные карточки.

1. Скилл это папка с `SKILL.md`, где frontmatter даёт `name` и `description`, а тело содержит инструкции. Формат открытый стандарт Agent Skills ([O, строка 87](/home/nbook/Projects/tmp/beacon-research/O-claude-code-mechanics.md#L87), [skills](https://code.claude.com/docs/en/skills.md), [anthropics/skills README](https://github.com/anthropics/skills/blob/main/README.md)). Один файл с процедурой вместо длинного промпта в каждом issue убирает копирование и позволяет модели выбрать момент вызова по описанию.
2. Поле `disable-model-invocation: true` запрещает автоматический вызов, `user-invocable: false` оставляет скилл только для модели ([O, строка 89](/home/nbook/Projects/tmp/beacon-research/O-claude-code-mechanics.md#L89), [skills](https://code.claude.com/docs/en/skills.md)). Без разделения ручных и фоновых скиллов случайная фраза в чате может запустить закрытие issue.
3. При старте в системный промпт загружаются только `name` и `description`. Полное тело `SKILL.md` читается при выборе скилла, дополнительные файлы читаются по ссылке из тела, когда они нужны ([O, строка 91](/home/nbook/Projects/tmp/beacon-research/O-claude-code-mechanics.md#L91), [инженерный пост Anthropic](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)). Ночная смена не платит токенами за правила комментариев на каждом шаге и читает их перед комментарием.
4. Сабэйджент работает в своём окне контекста со своими инструментами и разрешениями, назад возвращается только результат ([O, строка 93](/home/nbook/Projects/tmp/beacon-research/O-claude-code-mechanics.md#L93), [subagents](https://code.claude.com/docs/en/sub-agents.md), [OpenCode agents](https://opencode.ai/docs/agents/)). Исследование десятка issue не замусоривает основной контекст, а профиль без записи не может случайно нажать merge.
5. Хук на `PreToolUse` проверяет условие до того, как агент комментирует или мержит ([O, строка 95](/home/nbook/Projects/tmp/beacon-research/O-claude-code-mechanics.md#L95), [hooks](https://code.claude.com/docs/en/hooks.md)). Правило «писать только при НОВОМ факте» из инструкций ночной смены сейчас живёт в тексте инструкции. Детерминированная проверка делает его обязательным. ADR 0028 задал контракт квитанции, но не проверяет содержание комментария. ADR 0006 отделяет адаптер OpenCode от ядра, поэтому в Beacon проверка ставится в плагине адаптера, а не в конфигурации Claude Code.

## Последствия

- Из каждого пункта выходит одна небольшая карточка в `docs/tasks/` по правилам ADR 0020. Карточки этим ADR не создаются и будут созданы отдельными задачами.
  - Фича 1: `.opencode/skills/night-shift/SKILL.md` и тесты к нему.
  - Фича 2: `.opencode/skills/night-shift/SKILL.md` для фонового разбора, отдельный ручной скилл с `disable-model-invocation: true` и тесты к ним.
  - Фича 3: `.opencode/skills/night-shift/references/comment-rules.md`, `.opencode/skills/night-shift/references/pr-readiness.md`, ссылки на них в `.opencode/skills/night-shift/SKILL.md` и тесты к ним.
  - Фича 4: `.opencode/agents/issue-scout.md`, `.opencode/agents/night-shift-actor.md` и тесты к ним.
  - Фича 5: `.opencode/plugins/beacon-bridge.js`, тесты проверки в `tests/adapter/` и тесты к ним.
- Проверка карточек: скилл для смены лежит в одном формате и вызывается по описанию; ручная операция не запускается авто-вызовом; справочник читается только перед действием; профиль исследования не имеет права записи; комментарий и мерж без нового факта отклоняются до отправки.
- Число MCP-инструментов остаётся равным семи, ADR 0003 и 0009 не меняются. Один мост на протокол из ADR 0024, изоляция worktree из ADR 0021 и лестница пробуждения из ADR 0017 сохраняются. Проверка в CI по ADR 0022 дополнительной не становится: детерминированная проверка из пункта 5 работает до действия агента, а не вместо CI.

## Отклонённое

Вклеивать один и тот же длинный промпт в каждый issue вместо скилла. Текст дублируется, и модель не может выбрать момент вызова.

Разрешать авто-вызов ручных операций. Закрытие issue от случайной фразы в чате не проходит согласование.

Держать все правила комментариев и критерии готовности в теле `SKILL.md`. Ночная смена платит токенами за текст, который нужен только перед комментарием.

Использовать один профиль с полными правами и для исследования, и для действий. Поиск по десятку issue замусоривает контекст, а объединение профиля исследования с действиями даёт шанс случайного мержа.

Надеяться, что модель сама помнит правило «только при новом факте», или проверять текст после отправки комментария и мержа. Проверка после действия не предотвращает действие.

Вводить `.claude/settings.json` как единственный механизм проверки в Beacon. Проект работает на OpenCode по ADR 0006, поэтому правило PreToolUse из отчёта O воплощается в плагине адаптера.
