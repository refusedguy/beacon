# ADR 83: Events как подсказка, состояние как источник истины

Статус: accepted

## Контекст

Cursor в пуле воркеров прямо говорит: доставка best-effort, список — источник истины, потерянное событие не доставляется повторно; события применяются идемпотентно, расхождения исправляет следующий list. В Kilo wake не источник истины, истина в durable-записи, сигнал только советует перечитать состояние. Chord в Pi: events доставляются один раз, не fold'ятся, не хранятся и не идут поздним подписчикам.

## Решение

Обрабатывать events как подсказку, полное чтение состояния как источник истины. Применять события идемпотентно по ID, делать периодическое полное чтение с джиттером, не хранить курсоры между процессами, на cursor_expired или 410 делать ре-list. Для Kilo-подобных потоков клиент хранит последний seq и переоткрывает подписку с after.

## Последствия

Потеря webhook или события не теряет обязательство. Автоматический reconnect ненадёжен: Kilo events.subscribe не восстанавливается сам, курсор Cursor живёт пять минут с момента list и не продлевается heartbeat. Восстановление идёт через чтение с курсора и повторный list, а не через ожидание доставки всех пропущенных событий.
