# Учебный откат и возврат (rollback drill)

Дата подготовки: 2026-11-19.
Гейт: G2. Повторяемо на G3 и G4, по ADR 0018 откат доступен на каждом гейте.
Зависимость: T4.4 (G2 canary). На момент подготовки PR по T4.4 ещё не влит, поэтому фактические поля раздела «Результат» не заполнены.
Ссылки: ADR 0018, ADR 0019, ADR 0022, T4.4, T4.5, T3.3, T3.7, T3.8.

## Суть проверки

Откат это переключение инструкции агентов обратно на `gh pr checks --watch`. Данные Beacon при этом не удаляются. Возврат это переключение инструкции на шаблоны T3.7 и T3.8 и пробуждение агента по вердикту.

По ADR 0019 orphan это эскалация оркестратору, а не тихое удаление Watch. Откат не должен чистить базу, закрывать Watch или стирать квитанции. По ADR 0018 ни один гейт не проходится самовольно, решение о продолжении принимает владелец.

## Предусловия

1. Группа агентов уже живёт по новому циклу. Для G2 это три canary-агента из T4.4.
2. Известен каталог состояния `$XDG_STATE_HOME/beacon` и каталог квитанций плагина из T3.6.
3. Известен путь к логу, в котором T3.3 ловит `session.execution.started`.
4. Окно отката выбрано так, чтобы в нём не было новых вердиктов для тестовой группы. Иначе суммы разойдутся из-за нормальной записи состояния, а не из-за потери данных. При расхождении откат повторяют в тихом окне.
5. Владелец применяет и откатывает конфиг сам. Воркер не редактирует `~/.config/opencode`, чужие конфиги и shell rc-файлы.

## Порядок

1. Зафиксировать состав группы и версию инструкции до отката (шаблоны T3.7 и T3.8).
2. Снять контрольную сумму каталога состояния и сохранить вывод как evidence:

   ```sh
   STATE="${XDG_STATE_HOME:?}/beacon"
   ( cd "$STATE" && find . -type f -print0 | LC_ALL=C sort -z | xargs -0 sha256sum ) > /tmp/rollback-before.sha256
   sha256sum /tmp/rollback-before.sha256
   ```

3. Переключить инструкцию группы на `gh pr checks --watch`. Не удалять данные Beacon, не останавливать и не чистить сервис ради удаления состояния.
4. Дать группе поработать по старому механизму. Проверить, что агент видит статус CI через `gh`, а не через вердикт Beacon.
5. Повторно снять сумму тем же набором команд в `/tmp/rollback-after.sha256` и сравнить агрегированные хеши. Ожидается полное совпадение. При расхождении приложить оба списка файлов и прекратить откат до выяснения причины.
6. Вернуть группу на шаблоны T3.7 и T3.8. Спровоцировать вердикт по тестовому PR и проверить в логе `session.execution.started` с sessionID агента и указателем `watchID`, `obligationID`, `revision`. Наличие только `session.inbox.delivered` пробуждением не считается (T3.3).
7. Записать в таблицу ниже дату, гейт, обе суммы, факт пробуждения и решение владельца. Решение фиксирует владелец, а не воркер.

## Ожидаемый результат из расчёта

- Агрегированная сумма каталога `$XDG_STATE_HOME/beacon` до и после отката совпадает.
- Число удалённых или изменённых файлов состояния равно нулю.
- После возврата в логе есть `session.execution.started` по вердикту.
- В отчёте указаны дата и гейт.
- Воркер не удалял состояние и не менял чужие конфиги.
