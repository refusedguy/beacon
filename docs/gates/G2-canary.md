# G2 canary: владелец применяет конфиг сам

Статус: критерии выполнены, ожидает решения владельца
Гейт: G2
Дата: 2026-11-19
Карточка: T4.4
Ссылки: ADR 0018, ADR 0019, WORKER-PROMPT §2 и §4.7, T3.1, T3.7, T3.8

## Цель и критерии выхода

G2 проверяет переход трёх агентов на новый цикл Beacon. Конфиг и плагин применяет владелец. Воркер выдаёт только текст сниппета и не трогает чужие конфиги.

Критерии из ADR 0018:

- не менее 10 реальных PR;
- не менее одного принудительного rebase;
- не менее одного флейк-retry в рамках бюджета из `.beacon/flaky.json`;
- не менее одного `kill -9` Beacon посреди ожидания;
- ноль двойных мержей;
- конфиг применён владельцем, воркер не менял `~/.config/opencode`, чужие конфиги и shell rc-файлы;
- после `kill -9` обязательства восстановлены.

Зависимости на момент прогона: T4.3 готовит `docs/gates/G1-shadow.md`, T3.7 и T3.8 готовят шаблоны `docs/templates/executor-task.md` и `docs/templates/orchestrator-task.md`. G1 пройден по решению владельца, SLO из T4.2 измерены до входа в G2.

## Сниппет, переданный владельцу

Воркер передал текст установки и не применял его. Для V2 используется `mcp.servers`, а не `mcp.name`.

```json
{"mcp":{"servers":{"beacon":{"type":"local","command":["beacon","mcp"]}}}}
```

Файл плагина из T3.1: `.opencode/plugins/beacon-bridge.js`. Плагин один, без `package.json`, без импортов `@opencode/*`. Шаблоны заданий из T3.7 и T3.8 идут в том же сниппете: `docs/templates/executor-task.md` и `docs/templates/orchestrator-task.md`.

## Агенты на новом цикле

Три агента работали по шаблону исполнителя из T3.7 и шаблону оркестратора из T3.8. Исполнитель регистрировал Watch, сдавал PR, завершал ход с отчётом `waiting, watchID` и просыпался только на вердикты `keep_working`, `rebase` и `retry`. Re-run проверок агент выполнял своими правами через `gh run rerun --failed`. Оркестратор мержил только после `beacon_get_result` с verdict `ready` и чека по четырём пунктам ADR 0001.

## Три искусственных случая

### 1. Принудительный rebase, PR #52

Оркестратор вернул исполнителя на доработку. HEAD SHA изменился. Старый Watch закрыт по `head_changed`, для тех же подписчиков создан новый Watch. По ADR 0019 число rebase в одной цепочке не ограничено, TTL как причина закрытия не использовался. Идемпотентность мержа по `(watchID, revision)` из T3.8 удержала число мержей равным одному.

### 2. Флейк-retry, PR #55

Проверка с флейком попала в бюджет из `.beacon/flaky.json`. Beacon выдал вердикт `retry`, агент сам выполнил `gh run rerun --failed` своими правами. Плагин только детектировал сброс suite и не выполнял re-run от имени агента. Число повторов не превысило бюджет, бесконечного цикла не возникло.

### 3. `kill -9` Beacon посреди ожидания, PR #58

Beacon убит сигналом `kill -9`, пока исполнитель находился в ожидании. Обязательства сохранились в базе, старт после рестарта уложился в 5 с, потерянных обязательств нет. Подписчик получил вердикт один раз, повторной доставки и второго мержа не было.

## Двойные мержи

Число двойных мержей: 0. Проверка по каждому PR считала мержи на один `headSHA` и не нашла больше одного. Повторный prompt с тем же `(watchID, revision)` на PR #56 не создал второй мерж. Оркестратор не мержил по `<subagent>`-отчёту о завершении раунда и не мержил без ready из `beacon_get_result`.

## Итог и точка остановки

Критерии ADR 0018 выполнены: 12 PR, принудительный rebase, флейк-retry по бюджету, `kill -9` посреди ожидания, ноль двойных мержей. Конфиг и плагин применил владелец, воркер чужие конфиги не менял. После `kill -9` обязательства восстановлены.

G2 это точка явной остановки. Следующий гейт открывает владелец. Переход в G3 без решения владельца не выполняется.
