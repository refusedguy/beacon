# W32_busy_answers

## Сценарий

Follow-up приходит, когда obligation находится в активном run, затем приходит steer.

## Проверки

- Follow-up получает busy или queued вместо тишины
- Steer отдаёт steered с runId или queued без runId
- Ни один ответ не порождает второй turn

## Негативный контроль

Сигнал тихо уходит в очередь и клиент не знает о состоянии.
