# W24_auto_merge_once

## Сценарий

PR с автором из конфига и зелёными проверками получает verdict=ready. Адаптер вызывается дважды с одним expectedHeadOid, затем с новой ревизией Watch.

## Проверки

- первый вызов включает авто-мерж
- повтор с тем же expectedHeadOid не создаёт второй запрос
- новая ревизия создаёт новую запись
- при включённой merge queue адаптер не обещает конкретный mergeMethod

## Негативный контроль

Вызывать enablePullRequestAutoMerge на каждом тике без журнала. Второй запрос создаётся, и прогон обязан упасть.
