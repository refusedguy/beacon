# CI-only probe живого CIProvider

## Зачем

`R01_accepted_skip` честно помечает, что сетевой CIProvider не опрашивается: headSHA в eval задан заглушкой. Без отдельной проверки этот пропуск становится постоянной слепой зоной. Джоба `ci-provider-probe` в `.github/workflows/ci.yml` закрывает зону. Она берёт токен из секрета `BEACON_CI_PROBE_TOKEN`, запускается вручную через `workflow_dispatch` и не блокирует merge через `continue-on-error: true`. Локальный прогон `evals/run.sh` эту джобу не содержит.

## Что проверяет

Probe повторяет два вызова `gh`, которые делает `internal/infra/ghci.Provider` вживую: `gh pr view` с полями `headRefOid,baseRefName,state,isDraft,mergeable,mergeStateStatus,reviewDecision` и `gh pr checks` с полями `name,state,link`. Переменная `BEACON_GITHUB_TOKEN` из секрета совпадает с токеном, который читает `github.ResolveToken` перед запросом к GitHub. headSHA не подставляется, ответ приходит из сети.

Позитивный контроль фильтрует три условия.

- Фикстурный PR открыт, `state=OPEN`.
- `headRefOid` из ответа имеет формат 40 hex. Значение взято из GitHub, а не из заглушки.
- В `gh pr checks` есть хотя бы одна проверка с `state=PASS` или `state=SUCCESS`.

Негативный контроль ловит ложное срабатывание. Вызов `gh pr view` для `PROBE_NEGATIVE_PR` обязан завершиться ошибкой. Если несуществующий PR разрешается, probe слеп и его зелёный результат ничего не значит.

## Переменные окружения

| Переменная | Где задана | Значение |
| --- | --- | --- |
| `BEACON_CI_PROBE_TOKEN` | GitHub secret | Токен чтения фикстурного репозитория |
| `PROBE_REPO` | env джобы | Slug фикстурного репозитория |
| `PROBE_PR` | env джобы | Номер открытого фикстурного PR |
| `PROBE_NEGATIVE_PR` | env джобы | Номер несуществующего PR |

Текущая фикстура: `refusedguy/beacon-ci-fixture`, PR `1`, негативный PR `999999`.

## Как обновлять фикстуру

1. Держи фикстурный PR открытым. Не мержи его и не закрывай.
2. Держи в репозитории фикстуры одну зелёную проверку. Имя не важно, важен `state=PASS` или `state=SUCCESS`.
3. Если PR закрыли или репозиторий переименовали, создай новый PR и проставь `PROBE_REPO` и `PROBE_PR` в `ci.yml`. Правка конфига и этой страницы идёт в одном PR.
4. `PROBE_NEGATIVE_PR` остаётся номером, которого в репозитории нет.
5. headSHA сравнивается по формату, а не по конкретному хешу. Новые коммиты в фикстурном PR не требуют правки конфига.
6. Обнови секрет `BEACON_CI_PROBE_TOKEN`, если истёк срок его действия. Токен читает только GitHub Actions, в логи он не попадает.
7. Проверь джобу вручную: Actions, `ci-provider-probe`, Run workflow. Обе контрольные строки должны быть `ok`.

## Владелец

Слепую зону R01 ведёт владелец файлов `.github/workflows/ci.yml` и этой страницы. Обновление фикстуры и токенов делает владелец секретов репозитория.
