# INTG control plane integrity

## Сценарий

На чистом state dir собрать диспетчер, реестр генераций и хранилище расписаний. Вызвать beacon server через dispatch, выдать генерацию владельцу, пересоздать ledger, попытаться предъявить старую генерацию, записать расписание через SQLite и прочитать его после повторного открытия store.

## Проверки

- dispatch по имени server находит runnerFor[server] и вызывает serverRunner
- после пересоздания ledger старая генерация отвергается
- расписание, записанное через Create, читается через Get и присутствует в List
- повторный Create того же ID возвращает ошибку
- удаленное расписание отсутствует в List

## Негативный контроль

Убрать ключ server из runnerFor и вернуть реализацию генераций к картам процесса. Каждая проверка должна упасть на соответствующем утверждении.
