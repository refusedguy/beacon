# W07: матрица ролей ACP

## Сценарий

Тип рантайма определяет, можно ли использовать ACP как канал wake. Целью побуждения может быть только агент ACP. Клиент ACP не поднимает сервер ACP, поэтому его сессию нельзя разбудить запросом.

## Baseline

Источник: docs/research/e2e-coverage-audit.md, строка 9 таблицы. До изменений матрица ролей была описана только в этом документе. Живой тест не различал агентов и клиентов.

## Матрица

| Рантайм | Роль ACP | Цель wake |
| --- | --- | --- |
| OpenCode CLI | агент | да |
| Cursor CLI | агент | да |
| Claude, Codex, Pi | агент | да |
| Zed | клиент | нет |
| Cursor desktop | клиент | нет |

Для редактора сохраняется отдельный адаптер под его собственный API. Клиент ACP не становится целью wake.

## Проверки

- SupportedACPRuntimes содержит агентов opencode, claude, codex и pi.
- Клиенты zed, cursor и cursor desktop отсутствуют в списке агентов.
- ResolveACPRuntimeCommand отклоняет клиента ошибкой unsupported runtime.

Тест: TestACPRoleMatrix в internal/infra/wake/acp_smoke_test.go. Он не требует бинарника и выполняется в CI.

## Негативный контроль

Попытка разбудить сессию внутри Zed средствами ACP не приводит к новой работе, потому что у Zed нет сервера ACP. Резолвер рантаймов возвращает ошибку для клиентской роли, поэтому wake не отправляется.
